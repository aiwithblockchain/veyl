# Veyl 界面规范

Veyl 是一个**常驻菜单栏的桌面网络工具**。界面主体是**中间的网络控制台**，AI 对话在右栏。

它不是仪表盘堆砌页，不是营销页，也不是一个聊天应用。

先读同目录 `../product-designer/SKILL.md`（信息架构与 UI 基础）与 `../frontend-design/SKILL.md`（设计方法）。
与本文件冲突时，**本文件的硬规则优先**。

## 1. 架构：四列

```
┌────┬──────────────┬────────────────────────────┬──────────────┐
│ 图 │ 配置列表 240 │        中间控制台            │  AI 对话 400  │
│ 标 │              │                            │  默认隐藏     │
│ 56 │ 家里·本机代理 │  ┌──────────────────────┐  │              │
│    │ 2 个节点·7890 │  │ 启动 VPN        状态  │  │  消息流       │
│    │ ─────────    │  ├──────────────────────┤  │              │
│    │ 公司·接管全部 │  │                      │  │              │
│    │ 5 个节点·自动 │  │    AI 编排区          │  │              │
│    │              │  │                      │  │              │
│    │ ＋ 新建配置   │  ├──────────────────────┤  │              │
│    │              │  │ 东京01▾·1.2.3.4:20343│  │  输入框       │
│    │              │  │ [切换到此节点][测试]  │  │              │
│    │              │  └──────────────────────┘  │              │
└────┴──────────────┴────────────────────────────┴──────────────┘
```

### 1.1 中间是控制台，不是对话

中间区域**永远是网络操作台**，三段固定骨架：

| 位置 | 内容 | 谁能改 |
|---|---|---|
| **顶部** | 一个主按钮（`启动 VPN` / `断开 VPN`）+ 连接状态 + 线路图 | 谁都不能改 |
| **中间** | AI 编排区，按用户情况挑块、排序、填参数 | 只有 AI 能改 |
| **底部** | 选中节点详情 + 节点名下拉 + `切换到此节点` + `测试连通` | 谁都不能改 |

中间的对话**不存在**。用户要说话去右栏。这条不要妥协——一旦中间能聊天，控制台就会被消息流吃掉。

**中间大部分时候是空的，这是对的。** 它只在 AI 有话说时才有内容。空着时要给一句空态文案，让人看出是「没什么要说的」，不是「没加载出来」。

### 1.2 右栏是 AI 对话，默认隐藏

- 承载对话消息流、输入框、会话历史、AI 设置。
- **启动时不出现在屏幕上。** 关闭状态存 `localStorage["veyl.ui.panelOpen"]`，默认 `false`。
- 首次配置 AI 成功后**自动展开一次**；用户手动关过之后不再自动打开。
- 宽屏（≥1100px）停靠，中间区域随之收窄；窄屏（<1100px）浮层，Esc 关闭。
- 默认宽 400px，可拖 360–560。

**打开入口：中间顶部最右侧的一个对话图标按钮**，展开/收起同一个按钮。

- 不放进 activity bar——那里是「我在看哪个列表」的导航，面板开关混进去会让两件事分不清
- 不放进设置页——AI 是主功能，不是配置项
- 它挨着内容区，视觉上从属，不抢顶部主按钮的权重
- AI 在面板关闭期间有新消息或新动作时，这个按钮上出现一个小圆点

### 1.3 最左是 activity bar，其次是配置列表

**activity bar**：窄条图标列，本期只有「客户端」一项。服务商、自建站**不显示**——点了没反应的空图标只会让用户以为坏了。

**配置列表**：每行 = 配置名 · 节点个数 · 端口。配置的切换入口在这里，不在中间顶部。

左栏**不放**对话历史、不放问题列表、不放服务商。对话历史在右栏的二级页面；问题列表在中间区域的二级页面。

## 2. 三条不变量

### 2.1 同一屏幕只有一个主按钮

主按钮 = 视觉权重最高的实心按钮。

| 屏幕 | 主按钮在哪里 |
|---|---|
| 首次安装 | 引导页内的「保存并验证」 |
| 主界面 | **中间控制台顶部，永远是它** |
| 设置页 | 各分区的保存按钮（设置页是独立屏幕，不受此限） |

中间顶部那个按钮**任何情况下都只有一个**，两个状态之间切换。不要在它旁边加第二个同级按钮。

截图眯眼看，主界面只有一个实心色块。

### 2.2 每个事实只有一个住处

| 事实 | 唯一住处 |
|---|---|
| 连接状态 | 中间顶部状态区 |
| 出口国家 | 中间顶部状态区；详细 IP 进底部或问题卡 |
| 当前节点 | 中间底部 |
| 全部节点 | 中间底部的节点下拉 |
| 配置列表 | 左栏 |
| 端口、加密方式 | 中间底部 |
| 对话 | 右栏 |
| 问题与诊断 | 中间的问题卡；完整列表是中间的二级页面 |
| 默认配置版本、日志、AI 服务商 | 设置页 |

### 2.3 引导只对没学会的用户出现

`hasEverConnected` 为真后，不再出现建议问题、提示条、空态说明。
高级配置只能从设置页进入，不主动出现。

## 3. 视觉

**一句话：浅色、克制、信息密度低、边界靠留白不靠线框。**

默认浅色，跟随系统 `prefers-color-scheme` 切换深色。两套都必须是完整可用的。

### 3.1 颜色 token

```
浅色（默认）
--bg           页面底色        #FAFAF9
--bg-panel     侧栏 / 右栏      #F5F5F3
--bg-card      卡片 / 输入框     #FFFFFF
--bg-hover     悬停            #EDEDEA
--line         分隔线          rgba(0,0,0,.07)
--line-strong  边框            rgba(0,0,0,.14)

--ink          主文字          #1B1B1A
--ink-2        次要文字        #5C5C58
--ink-3        弱化 / 标签      #8B8B85

--accent       强调（链接、选中） #2C6BE0
--ok           已连接          #1C8A57
--warn         异常            #A96A00
--err          失败            #BE3A2E

深色（prefers-color-scheme: dark）按同样角色反相，不要单独发明色相
--bg #16181B / --bg-panel #1C1F23 / --bg-card #22262B
--ink #E9E9E7 / --ink-2 #A5A5A0 / --ink-3 #77776F
```

**用色规则**
- 主按钮用 `--ink` 实心 + `--bg` 文字（浅色下是深色按钮，深色下是浅色按钮）。**不用彩色实心按钮。**
- `--ok/--warn/--err` 只用于状态点、状态文字、描边，**不做按钮填充**。
- 危险操作一律 `.btn--danger-ghost`（描边 + 危险色文字），包括二次确认里的最终按钮。重量靠二次确认给。
- 一屏出现的彩色不超过 2 种。

### 3.2 字体

离线硬约束：**不加载外部字体、不用 CDN**。

- 正文与标题：系统 sans（`-apple-system` / `PingFang SC` / `Segoe UI`）。
- **数字与标识符用 mono**（端口、IP、PID、版本、耗时、哈希），套 `.num`，`font-variant-numeric: tabular-nums`。

字号阶梯（只有这 6 档）：
```
22px/600  页面与引导主标题
17px/600  区块标题
15px/500  卡片标题、按钮
14px/400  正文、消息
13px/400  次要说明
11px/500  小标签（--ink-3，中文不加 letter-spacing）
```
标题行高 1.35，正文 1.65。

### 3.3 间距与圆角

4px 网格：`4 / 8 / 12 / 16 / 24 / 32 / 48`。
页面左右边距 24–32；区块间距 24；卡片内边距 16。
圆角两档：`--r-sm: 8px`（按钮、输入、行）、`--r-lg: 12px`（卡片、浮层）。
**不用大圆角胶囊化的按钮**，那是营销页的做法。

### 3.4 签名元素：线路图

在中间顶部状态区出现一条水平线，从「本机」到「出口」，编码真实连接状态：

- 未连接：中断，`--ink-3`，中间 6px 缺口
- 连接中：从左往右生长，`--accent`
- 已连接：连续，`--ok`，极慢的流动虚线
- 失败：缺口处一个 2px 断点标记，`--err`

这是全产品唯一的装饰性元素，其余一律不加动效。

### 3.5 动效

只有三类：状态过渡 120ms、线路流动 3s 循环、浮层 160ms（透明度 + 4px 位移）。
`prefers-reduced-motion: reduce` 全关。

## 4. 场景

### 4.1 首次安装

全屏一屏，三个入口，不分成多步向导：

| 顺序 | 内容 | 样式 |
|---|---|---|
| 1 | DeepSeek API Key + `保存并验证` | 视觉重点 |
| 2 | `使用 Google 登录` | 次按钮 |
| 3 | `我懂网络，不用 AI` | 最轻，最下面 |

第 1 项下方两个文字链接：`获取 DeepSeek API Key ↗`（系统浏览器打开，不内嵌）与 `使用其他 AI 服务 →`。

### 4.2 主界面，还没有配置

- 左栏：空态，一句话 + `新建配置`
- 中间顶部：按钮在，但按不了
- 中间中部：AI 编排区空态
- 右栏：AI 已经问起来了

### 4.3 已有配置，未连接

- 中间顶部：`启动 VPN`
- 中间中部：按用户类型不同（见下）
- 中间底部：选中节点详情

| 用户 | 中间放什么 |
|---|---|
| 一级 | 一行说明：点上面的按钮就能用 + 哪些网站会直连 |
| 二级 | 一行说明。授权走**系统级弹窗**，不占中间 |
| 三级 | 本机代理地址卡（`127.0.0.1:7890`，可复制） |

### 4.4 已连接

- 中间顶部：`断开 VPN` + 出口国家
- 中间中部：可达性检查（用户提过的目标逐个确认）
- 中间底部：节点详情

### 4.5 熟练用户

不显示任何引导、建议问题、空态营销文案。中间只剩状态与操作。

## 5. 高级配置的 AI 解释

每个高级项旁一个统一的文字链接 `问 AI`。点击以固定前缀开一条会话：

```
我在 Veyl 的高级设置里调整「{项名}」。当前值是 {值}。
请用三句话说明：这项设置实际改变了什么、什么时候该改、改错会有什么后果。
不要给通用教程，只说这个设置本身。
```

覆盖：接管方式、本地端口、默认配置源、API 类型与 Base URL、模型选择。
这是唯一的高级解释入口，不另做帮助文档页。

## 6. 文案

- 中文。按钮用动词短语 2–6 字；说明用完整句子。
- 按钮说的词，结果消息用同一个词（「启动」→「已启动」）。
- 不用「请」堆客套，不用感叹号。
- 错误三段式：**发生了什么 → 为什么 → 现在做什么**。
- 空态写用户能做的动作，不写「暂无数据」。

**界面里不出现这四个词：`proxy`、`TUN`、`分流`、`规则集`。**
三级用户也一样——给他数值和行为，不给术语。「全部软件自动走 VPN」「直连范围：中国大陆的网站和地址」「监听 127.0.0.1:7890」。

`selector`、`mixed`、`geosite` 这类实现词只出现在设置页高级区和日志里。

---

## 7. 实现约束

- 样式集中在 `src/styles/app.css`，按区块注释分组。不引入 CSS-in-JS 或 UI 框架。
- 状态文案与状态色映射集中在 `src/ui/status.ts`，不在组件里重复 switch。
- 删组件同时删它的 CSS 段。
- 中间区域的块只能从 `docs/center-panel.md` §2.5 的词汇表里取，不能新增未登记的块。
