# Veyl 界面规范

Veyl 是一个**常驻菜单栏的桌面网络工具**。界面主体是**中间的网络控制台**，AI 对话在右栏。

它不是仪表盘堆砌页，不是营销页，也不是一个聊天应用。

先读同目录 `../product-designer/SKILL.md`（信息架构与 UI 基础）与 `../frontend-design/SKILL.md`（设计方法）。
与本文件冲突时，**本文件的硬规则优先**。

## 1. 架构：三栏

```
┌──────────────┬────────────────────────────┬──────────────┐
│ Veyl      ＋ │        中间控制台            │  AI 对话 420  │
│ ▪ 配置 1      │  ┌──────────────────────┐  │  消息流        │
│   2 个节点 · TUN 模式 │  │ 启动 VPN        状态  │  │               │
│ ─────────    │  ├──────────────────────┤  │               │
│ ◇ 配置 2      │  │                      │  │               │
│   5 个节点 · Proxy 模式 │  │    AI 编排区          │  │               │
│              │  │                      │  │               │
│              │  ├──────────────────────┤  │  输入框        │
│              │  │ 东京01▾·1.2.3.4:20343│  │               │
│              │  │ [切换到此节点][测试]  │  │               │
│              │  └──────────────────────┘  │               │
│ 设置          │                            │               │
└──────────────┴────────────────────────────┴──────────────┘
```

**没有独立的 activity bar。** 最左就是配置列表；只有一个图标的窄列会让用户以为还有别的页面，实际点了没反应。

### 1.1 中间是控制台，不是对话

中间区域**永远是网络操作台**，三段固定骨架：

| 位置 | 内容 | 谁能改 |
|---|---|---|
| **顶部（hero）** | 一个主按钮（`启动 VPN` / `断开 VPN` / `重新连接`）+ 连接状态 + 计时器；第二行是「流量范围」开关（智能 / 全局），与按钮同一视觉块 | 谁都不能改 |
| **中间** | AI 编排区，按用户情况挑块、排序、填参数 | 只有 AI 能改 |
| **底部** | 选中节点详情 + 节点名下拉 + `切换到此节点` + `测试连通` | 谁都不能改 |

中间的对话**不存在**。用户要说话去右栏。这条不要妥协——一旦中间能聊天，控制台就会被消息流吃掉。

**中间大部分时候是空的，这是对的。** 它只在 AI 有话说时才有内容。空着时要给一句空态文案，让人看出是「没什么要说的」，不是「没加载出来」。例外：AI 明确输出 `blocks: []` 时中间保持空白，这是合法状态，不加「暂无内容」。

### 1.2 右栏是 AI 对话

- **宽屏默认展开，窄屏收成右边缘 56px tab。** 桌面宽度决定初始形态：
  - ≥1200px：停靠，宽度 420（1200–1439 为 380）。
  - 1024–1199px：默认收起为 56px tab；点开是右侧浮层（宽 400，最大 `calc(100vw - 80px)`），Esc 关闭。
  - <1024px：同 1024 档，配置栏同时收成 72px 抽屉。
- **开关状态持久化**：`localStorage["veyl.ui.panelOpen"]`，并带版本号（`veyl.ui.panelVersion`）；界面大改版后旧选择作废，按当前宽度重新给默认值。
- **首次配置 AI 成功后自动展开一次**；用户手动关过之后不再自动打开。
- **零配置时保证可见**：没有配置且 AI 可用时自动展开，让助手能开始配置；用户在本次运行里关过则不再强制。
- 打开入口是**右边缘 56px tab**：图标 + 竖排「助手」+ 未读点；宽屏停靠时收起按钮在助手标题右侧。不放进左栏（那里是配置导航），不放进设置页（AI 是主功能，不是配置项）。
- 宽度可拖 320–640，默认 420；配置栏可拖 220–360，默认 280。偏好分别存 `veyl.ui.railWidth.v1` / `veyl.ui.assistantWidth.v1`。

### 1.3 最左是配置列表

**配置列表**：每行 = 名称（前置 6×6 标记：TUN 实心方块 / Proxy 空心圆环，只用 `--ink-3`）· 节点个数 · 接管方式小字（`TUN 模式` / `Proxy 模式`）。配置的切换入口在这里，不在中间顶部。小字与标记**只由接管方式决定**，不随流量范围变化；单击选中、双击名称改名，悬停出现「重命名 / 删除」。选中靠左竖条 + 卡底 + 名称加粗，标记不变色不变形。

- 选中行：`--card` 底 + 左侧 2px `--cobalt` 竖条，名称 600。
- 删除按钮只在 hover / 键盘 focus 时出现，不能常驻。
- 底部是「设置」入口。
- 空态：一句话 + `新建配置`；读取失败：错误文本 + `重新读取`。

左栏**不放**对话历史、不放问题列表、不放服务商。对话历史在右栏的二级页面；问题列表在中间的二级页面。

## 2. 三条不变量

### 2.1 同一屏幕只有一个主按钮

主按钮 = 视觉权重最高的实心按钮。

| 屏幕 | 主按钮在哪里 |
|---|---|
| 首次安装 | 引导页内的「保存并验证」 |
| 主界面 | **中间控制台顶部，永远是它** |
| 设置页 | 各表单的保存按钮（设置页是独立屏幕，不受此限） |

中间顶部那个按钮**任何情况下都只有一个**，两个状态之间切换。不要在它旁边加第二个同级按钮。

截图眯眼看，主界面只有一个实心色块。助手输入框的「发送」是描边按钮，不是实心。

### 2.2 每个事实只有一个住处

| 事实 | 唯一住处 |
|---|---|
| 连接状态 | 控制台 hero 的 H1（状态词，或已连接时的状态标签 + 计时器） |
| 出口 IP | 控制台读数行「出口」，可复制 |
| 当前节点 | 底部节点卡 |
| 全部节点 | 底部节点卡打开的节点面板 |
| 配置列表 | 左栏 |
| 节点地址、节点端口、加密方式 | 底部节点卡的一行等宽事实 |
| **流量范围（智能 / 全局）** | **控制台 hero 第二行的开关**。未连接读数里不再有「范围」一行；设置里不出现。 |
| 地区 | 系统推断 + AI 在对话里决定并写入的值，供开关说明与生成使用；设置与审视页都**不提供选择控件**（审视页只有一行只读展示） |
| **本地代理地址 / 端口** | **设置 → 连接**：只在 `Proxy 模式` 配置下出现，可复制、可就地编辑；`TUN 模式` 配置下这一行整行不显示（没有要填的地址） |
| 对话 | 右栏 |
| 问题与诊断 | 中间只出现 `issue_card`；修网络与诊断入口在设置「遇到问题」 |
| 默认节点包版本、日志、AI 服务商、应用版本 | 设置页 |
| 启动 / 断开 / 重连 | 控制台 hero 的唯一主按钮 |

### 2.3 引导只对没学会的用户出现

`hasEverConnected` 为真后，不再出现建议问题、提示条、空态说明。
高级配置只能从设置页进入，不主动出现。

## 3. 视觉

**一句话：浅色、克制、信息密度低、边界靠留白不靠线框。**

默认浅色，跟随系统 `prefers-color-scheme` 切换深色。两套都必须是完整可用的。

### 3.1 颜色 token

实际使用的 token（`src/styles/app.css`）：

```
浅色（默认）
--canvas       页面 / 左栏底色   #EFEBE1
--paper        控制台纸面        #FAF8F2
--panel        右栏 / 助手        #F6F2E9
--card         卡片 / 输入框      #FFFFFF
--ink          主文字            #171614
--ink-2        次要文字          #5B5850
--ink-3        弱化 / 标签        #6E6A5F
--ink-4        只用于线条 / 点 / focus 描边   #746F63
--hair         分隔线            rgba(23, 22, 20, 0.10)
--hair-strong  边框              rgba(23, 22, 20, 0.18)
--cobalt       强调 / 选中 / 链接  #1F46B8
--green        已连接            #1B7A4E
--amber        异常              #946200
--red          失败              #A8382D

深色（prefers-color-scheme: dark）
--canvas #16181B / --paper #1C1F23 / --panel #191B1E / --card #22262B
--ink #E9E9E7 / --ink-2 #A5A5A0
--ink-3 #90908A（修正值：在卡片上 ≥4.5:1；不要写回 #8A8A82）
--ink-4 #77776F（只用于线条 / 点 / focus；深色卡片上仅 3.37:1，不能当文字）
--hair rgba(255,255,255,.10) / --hair-strong rgba(255,255,255,.16)
--cobalt #5B8DEF / --green #5FBF8A / --amber #D9A44E / --red #E0705F
```

**用色规则**

- 主按钮用 `--ink` 实心 + `--canvas` 文字（浅色下是深色按钮，深色下是浅色按钮）。**不用彩色实心按钮。**
- `--green / --amber / --red` 只用于状态点、状态文字、描边、图表线与极低透明度面积，**不做按钮填充**。
- **`--ink-4` 不是文字色。** 只用于 1px 线、2px 选中条、点、focus 描边；所有小字用 `--ink-3` 起步。
- 危险操作一律 `.btn--danger-ghost`（描边 + 危险色文字），包括二次确认里的最终按钮。重量靠二次确认给。
- 一屏出现的彩色不超过 2 种。

### 3.2 字体

离线硬约束：**不加载外部字体、不用 CDN**。

- 正文与标题：系统 sans（`-apple-system` / BlinkMacSystemFont / `SF Pro Display` / `Segoe UI` / `PingFang SC` / `Hiragino Sans GB` / `Microsoft YaHei` / system-ui）。
- **数字与标识符用 mono**（端口、IP、PID、版本、耗时、哈希），套 `.num`，`font-variant-numeric: tabular-nums`。

字号阶梯（实际在用的档位）：

| 字号 / 行高 / 字重 | 字体 | 用途 |
|---|---|---|
| 64 / 1.0 / 400，-0.03em | mono | 已连接计时器 |
| 44 / 1.1 / 600，-0.02em | sans | 未连接 / 连接中 / 失败的状态词 |
| 22 / 1.35 / 600 | sans | 引导页 / 页面主标题 |
| 20 / 1.3 / 500 | sans | 已连接 / 降级状态标签 |
| 20 / 1.2 / 400 | mono | 读数主值（流量 / 延迟 / 出口） |
| 20 / 1.3 / 600 | sans | 卡片 / 区块标题 |
| 17 / 1.35 / 600 | sans | 节点名、复杂弹窗标题 |
| 15 / 1.55 / 500 | sans | 主按钮（控制台 hero）、配置名、卡片标题、文字型读数 |
| 15 / 1.55 / 400 | sans | 正文 |
| 14.5 / 1.65 | sans | 助手消息正文（提案目标；当前实现为 14，按 ui-refresh-plan P1-5 落地） |
| 14 / 1.65 | sans | 正文、消息流正文、节点行名称 |
| 13 / 1.6 | sans | 普通按钮、次要说明 |
| 12 / 1.45 | sans | 元信息、读数标签 / 副值、设置说明 |
| 11 / 1.3 / 500 | sans | 小标签、节点事实、时间 |
| 10.5 / 1.2 / 500 + 0.14em | mono / sans | 英文眉标、技术标签 |
| 9.5 / 1.2 | mono | 速率图两端 |

标题行高 1.35，正文 1.65。64px 计时器与 44px 状态词是**显示级**，不进入正文阶梯。正文最小 12px。

> 代码里仍有 24 / 18 / 16 / 13.5 / 12.5 / 10 等遗留值（`.proxy__addr`、`.settings-row__chevron`、`.reset-result__title`、`.card__action`、`.reach__status`、`.ai-panel__model`）。**新代码不再使用**，按 `docs/design/ui-refresh-plan.md` P1-7 收敛到上表。

### 3.3 间距与圆角

4px 网格：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64`。

- 控制台左右内边距 40（窄屏 28），上下 24–40。
- 左栏内边距 16–20；右栏内边距 24。
- 区块之间 32–40；卡片内 20–24；读数行上下 17–18。
- 圆角三档：`--r-sm: 6px`（按钮、输入、行）、`--r-md: 10px`（卡片、节点卡）、`--r-lg: 14px`（弹窗、浮层）。
- hero 第二行「流量范围」：状态行下 16，说明行再下 6；标签 12px `--ink-3`，开关高 32、段文字 13/500、两段各 ≥72 宽；开关是描边分段控件，不用实心、不用主按钮色，也不与主按钮并排。
- **不用大圆角胶囊化的按钮**，那是营销页的做法。

### 3.4 签名元素：计时器

全产品唯一的装饰性视觉中心是**已连接时长**：

- 已连接 / 不稳定：H1 内是 20px 状态标签 + 64px mono 计时器（tabular-nums）。
- 未连接 / 连接中 / 失败：44px 状态词；没有计时器。
- **已连接但没有流量：44px 状态词 `已连接，不通`；没有计时器**——计时器只属于「流量确实在走」的时段，边跑秒边说健康是第二种谎。LED 琥珀。
- LED 6×6px（状态词内 8×8px），圆角 2px：已连接绿、连接中蓝、降级琥珀、失败红；只作装饰，`aria-hidden`。
- **线路图已删除，不再恢复。** 出口 IP、流量、延迟在计时器下方作为读数行，各有唯一住处。

### 3.5 动效

- 状态过渡 120ms；浮层 / 弹窗 160ms（透明度 + 4px 位移）。
- 加载与进度指示可以循环（骨架、旋转、不确定进度条），只表达「正在进行」。
- 除上述外不加动效：不做文字呼吸、不做装饰性脉动、不做营销式滚动/视差。
- `prefers-reduced-motion: reduce` 全关（全局动画时长降到 0.01ms，循环动画停止）。

## 4. 场景

### 4.1 首次安装

全屏一屏，三个入口，不分成多步向导：

| 顺序 | 内容 | 样式 |
|---|---|---|
| 1 | DeepSeek API Key + `保存并验证` | 视觉重点 |
| 2 | `使用其他 AI 服务`（展开 OpenAI / Anthropic 兼容表单） | 次按钮 / 文字链接 |
| 3 | `我懂网络，不用 AI` | 最轻，最下面 |

第 1 项下方两个文字链接：`获取 DeepSeek API Key ↗`（系统浏览器打开，不内嵌）与 `使用其他 AI 服务 →`。

**第二入口按需求是 `使用 Google 登录`；本轮账号体系未接，暂缓实现，不得放入点了没反应的入口。接入时恢复为第二入口。**

### 4.2 主界面，还没有配置

- 左栏：空态，一句话 + `新建配置`（标题行 `+` 或空态就地按钮）。
- 中间：零配置引导——标题 + 三步说明；AI 可用时主按钮「让助手帮我配」，不用 AI 时「我自己配置」；助手正在提问、刚引导完时只给说明，不放按钮。不放一个不可点的「启动 VPN」。
- 右栏：宽屏默认展开并开始第一轮；窄屏收成 tab，零配置时自动展开（本次运行关过除外）。

### 4.3 已有配置，未连接

- 中间顶部：`启动 VPN`
- 中间 hero 第二行：「流量范围」开关（智能 / 全局）+ 一行说明；与主按钮同一视觉块
- 中间中部：按用户类型不同（见下）
- 中间底部：选中节点详情

| 用户 | 中间放什么 |
|---|---|
| 一级 | 一行说明：点上面的按钮就能用 + 哪些网站会直连 |
| 二级 | 一行说明。授权走**系统级弹窗**，不占中间 |
| 三级 | 本机代理地址卡（`127.0.0.1:7890`，可复制） |

### 4.4 已连接

- 中间 hero：`已连接`（或「连接不稳定」）+ 64px 计时器 + `断开 VPN`
- 中间读数行：流量 / 延迟 / 出口（出口可复制）
- 中间底部：节点详情

**已连接但没有流量**（`state === "running"` 且 `health.data_plane === false`，判定函数见 `docs/contracts/runtime.md` §4.3）：

- 状态词 44px `已连接，不通`，8px 琥珀点；**不显示计时器**。
- 状态词下方 15px / `--ink-2` 一句行动：`网页打不开时，点上面的「重新连接」；还是不行，就换下面的节点再试。`
- 同一个主按钮换成 **`重新连接`**，不是「断开 VPN」——状态是「还连着」，叫断开自相矛盾，也多一次点击。
- 读数行保留；中间区**不加卡片**：重连在 hero、换节点在底部节点卡，再放卡就是第三个入口做同一件事。
- 与「连接不稳定」（`degraded`，20px 标签 + 计时器 + 30s 自动重启）是两回事，两个状态词不叠加。

### 4.5 熟练用户

不显示任何引导、建议问题、空态营销文案。中间只剩状态与操作。

### 4.6 新建配置（两问 + 审视）

弹窗只问两件事，问完直接进审视页，不再有「AI 协助 / 我自己配置」两张卡：

| 步 | 内容 | 关键约束 |
|---|---|---|
| ① 怎么接管 | 两张整卡可点的单选：`TUN 模式（接管全部流量）` / `Proxy 模式（只给代理地址）`，每张常驻场景解释 | 默认 TUN；命中区 ≥64 高；`radiogroup` + 方向键 |
| ② 节点从哪来 | `Veyl 免费节点` / `其它节点`（带 `预览` 标记，进入「供应商广场」静态页） | 卡面不显示节点数量；免费池为空时**按下一步才联网**；失败只给三段式 + 重试 |
| 审视 | 名称 / 接管方式 / 节点来源 / 流量范围 / 地区，五行只读 | 名称自动生成、不可改；地区只展示、无确认；主按钮未连接 `创建并连接`、已连接 `创建配置` |

- 完整文案、失败路径与契约见 `docs/design/simplified-config-create.md`，版式见 `simplified-config-create-ui.md`。
- AI 不在这个弹窗里：AI 仍走工具建配置；地区由 AI 在对话里决定，弹窗不追问、不给控件。
- 「AI 协助」不再是弹窗第一问；零配置引导的「让助手帮我配」是另一条入口，保留。

## 5. 高级配置的 AI 解释

只在**设置 → AI 助手**的新增 / 编辑服务表单里，对以下两项提供统一的文字链接 `问 AI`：

- API 类型与 Base URL
- 模型选择

点击以固定前缀开一条会话：

```
我在 Veyl 的高级设置里调整「{项名}」。当前值是 {值}。
请用三句话说明：这项设置实际改变了什么、什么时候该改、改错会有什么后果。
不要给通用教程，只说这个设置本身。
```

前缀逐字固定，与 `src/ai/advancedPrompts.ts` 一致，不要改写措辞或追加教程。触发入口在「设置 → AI 助手」的服务表单里。

其余高级项不再挂 `问 AI`：接管方式只读，默认配置源是纯动作，固定提示词会写成「我正在调整」，是假话。这是唯一的高级解释入口，不另做帮助文档页。

---

## 6. 文案

- 中文。按钮用动词短语 2–6 字；说明用完整句子。
- 按钮说的词，结果消息用同一个词（「启动」→「已启动」）。
- 不用「请」堆客套，不用感叹号。
- 错误三段式：**发生了什么 → 为什么 → 现在做什么**。
- 空态写用户能做的动作，不写「暂无数据」。

**界面里不出现这四个词：`proxy`、`TUN`、`分流`、`规则集`。**

**例外（2026-11-13 扩写，均为产品决定，不是笔误）**：

- 新建配置的手动表单（无 AI 兜底）两张接管方式卡标题：`TUN 模式（接管全部流量）` / `Proxy 模式（只给代理地址）`（`docs/design/simplified-config-create.md` §5.3）；
- AI 对话里同一问的选项：`TUN 模式` / `Proxy 模式`；
- **左栏每行的接管方式小字**：`TUN 模式` / `Proxy 模式`；
- **中间区未连接读数「方式」的值**：`TUN 模式` / `Proxy 模式`（副标题仍是「所有软件都走节点」/「需要手动填地址」）。

正文、按钮、状态、设置页仍不得使用，也不要把禁词规则整条删掉。

固定用词：流量范围的选项叫 `智能模式` / `全局模式`；种子池对外叫 `Veyl 免费节点`；节点来源卡叫 `其它节点`，打开的页面叫 `供应商广场`。界面不出现 `指定服务`。

三级用户也一样——给他数值和行为，不给术语。「全部软件自动走 VPN」「直连范围：中国大陆的网站和地址」「监听 127.0.0.1:7890」。

`selector`、`mixed`、`geosite` 这类实现词只出现在设置页高级区和日志里。

## 7. 实现约束

- 样式集中在 `src/styles/app.css`，按区块注释分组。不引入 CSS-in-JS 或 UI 框架。
- 颜色只用 §3.1 的 token；状态色映射不散落在组件里。
- 状态文案各有唯一出处：hero 在 `Console.tsx`，中间块在 `ui/middleArea.ts`，设置状态在 `Settings.tsx`；不要在多个组件里重复同一句。
- 删组件同时删它的 CSS 段；同一选择器不要留两份定义。
- 中间区域的块只能从 `docs/center-panel.md` §2.5 的词汇表里取，不能新增未登记的块。
