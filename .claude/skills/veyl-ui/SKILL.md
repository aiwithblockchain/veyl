# Veyl 界面规范

Veyl 是一个**常驻菜单栏的桌面网络工具**：用户在这里看连接状态、连上一个节点、出问题时让 AI 解释原因。
它不是一个聊天玩具，也不是一个仪表盘。界面的全部任务只有三件：

1. 让我知道我现在的网络是什么状态。
2. 让我一步连上 / 断开。
3. 出问题时告诉我下一步该做什么。

读这份规范前先读同目录的 `../frontend-design/SKILL.md`（通用设计方法）。两者冲突时，**本文件的硬规则优先**。

---

## 1. 三条布局不变量（违反任何一条都算返工）

### 1.1 同一屏幕只有一个主按钮

主按钮 = 视觉权重最高的实心按钮。

| 主区显示什么 | 主按钮在哪里 |
|---|---|
| 控制台（总览） | **主区**。右栏此时不渲染主按钮。 |
| 对话 | **右栏**。对话区不渲染任何连接按钮。 |
| 首次引导 | **引导页**。主界面不渲染。 |

判定方法：截图后眯眼看，应该只有一个实心色块。

### 1.2 每个事实只有一个住处

同一个数据不允许在两个地方同时显示。归属如下：

| 事实 | 唯一住处 |
|---|---|
| 连接状态（已连接/未连接/失败） | 右栏状态头 + 顶栏胶囊（胶囊只说状态，不给按钮） |
| 出口 IP、直连 IP、连接时长、延迟 | **右栏** |
| 节点名 / 当前节点 | **右栏**（主区只在"上次使用"语境里提一次） |
| 本地端口、系统代理、连接数、PID、版本、配置哈希 | **右栏「详情」折叠区** |
| 默认配置版本与更新时间 | **主区控制台底部一行** |
| 错误摘要 | 右栏常驻一行；完整原因进「详情」或诊断浮层 |

### 1.3 引导只在需要时出现

界面上的引导性文字（提示条、空态说明、建议问题）**只对还没学会的用户出现**。
判定：`hasKey && profileCount > 0 && 完成过一次成功连接` 之后，不再出现任何引导条。
熟练用户看到的应该只有：侧栏、主区、右栏三个静态区域。

高级配置**永远不主动出现**，只能通过设置页的「高级」进入，或从 AI 对话里被解释。

## 2. 视觉方向

**一句话：深色仪器面板。近乎单色，颜色只用在状态上。**

不做：渐变按钮、玻璃拟态、发光边框、插画、装饰性图标、emoji、彩色标签墙。

### 2.1 颜色 token

所有颜色只在 `:root` 定义一次，组件里不许写裸色值。

```
--bg            近黑底            #0B0C0E
--bg-raise      一级抬升（侧栏/右栏）  #111316
--bg-card       卡片               #16181C
--bg-hover      悬停               #1C1F24
--line          分隔线             rgba(255,255,255,.06)
--line-strong   边框               rgba(255,255,255,.12)

--ink           主文字             #E8E9EB
--ink-2         次要文字           #9BA0A8
--ink-3         弱化文字/标签       #6A7079

--signal        唯一强调色（信号青）  #6FD3C7
--signal-dim    强调色弱底          rgba(111,211,199,.12)

--ok            已连接（绿）        #63C98A
--warn          异常（琥珀）        #D9A44E
--err           失败（红）          #DE6B6B
```

**用色规则**：`--signal` 只用于可点击的主操作与当前选中项；`--ok/--warn/--err` 只用于状态，不得用于按钮。
一组界面里出现的彩色元素不能超过 2 种（状态色 + signal）。

主按钮：实心 `--ink` 上的深色字（近白按钮），**不用彩色实心按钮**。`--ok` / `--warn` / `--err` 不得出现在任何按钮的填充色上。

**危险操作的唯一例外**（破坏性操作必须有视觉重量，否则用户点得太快）：

| 位置 | 用哪个 |
|---|---|
| 列表行内的删除/清除入口 | `.btn--danger-ghost` 描边 + 危险色文字 |
| 二次确认框里的最终确认按钮 | `.btn--danger` 实心危险色 |

同屏最多出现一个实心危险色按钮，且只出现在确认框里。

### 2.2 字体

离线可用是硬约束：**不加载任何外部字体，不用 CDN**（应用要在没网时正常工作）。

- 正文与标题：系统 sans（`-apple-system` / `PingFang SC` / `Segoe UI`）。
- **所有数字与标识符用 mono**：端口、IP、PID、版本号、耗时、哈希、协议名。
  这不是装饰，是让一列数据能对齐、能一眼比对。用 `.num` 工具类统一包装。

字号阶梯（只允许这 6 档）：

```
28px / 600  页面主标题（控制台 headline、引导页大标题）
19px / 600  区块标题
15px / 500  卡片标题、按钮
14px / 400  正文
13px / 400  次要说明
11px / 500  全大写式小标签（letter-spacing: .08em，中文不用大写，用 --ink-3）
```

行高：标题 1.3，正文 1.6。中文不要用 `letter-spacing` 拉开。

### 2.3 间距与圆角

8px 网格：`4 / 8 / 12 / 16 / 24 / 32 / 48`。组件内边距 12–16，区块间距 24，页面边距 32。
圆角只有两档：`--r-sm: 8px`（按钮、输入、行）、`--r-lg: 14px`（卡片、浮层）。

### 2.4 签名元素：线路图（link line）

右栏状态卡里有一条水平线，从「本机」到「出口」。它是整个界面唯一被记住的东西，并且必须**编码真实状态**：

- 未连接：线是断的（中间留 6px 缺口），`--ink-3` 色。
- 连接中：线从左往右生长，`--signal` 色。
- 已连接：线连续，`--ok` 色，上面有极慢的流动虚线（`prefers-reduced-motion` 下静止）。
- 失败：线在缺口处有一个 2px 的断点标记，`--err` 色。

除此之外不许再加任何装饰动画。这条线是唯一的"动效预算"。

### 2.5 动效

只允许三类：状态过渡（120ms ease-out）、线路流动（3s 循环）、浮层出现（160ms，透明度 + 4px 位移）。
`prefers-reduced-motion: reduce` 时全部关闭。

## 3. 布局

```
┌────────────┬────────────────────────────────┬──────────────────┐
│  侧栏 232  │            主区                 │     右栏 288     │
│            │                                │                  │
│  Veyl      │   ┌──────────────────────────┐ │  已连接 · 东京01  │
│            │   │                          │ │  ┌────────────┐  │
│  总览      │   │      控制台 / 对话         │ │  │ 本机 ── 出口 │  │
│            │   │                          │ │  └────────────┘  │
│  对话      │   │                          │ │  [   断开   ]    │
│   · 会话   │   └──────────────────────────┘ │  节点  东京 01 ▾  │
│   · 会话   │   ┌──────────────────────────┐ │  出口  203.0.113.7 │
│            │   │  输入框                   │ │  时长  00:12:31  │
│            │   └──────────────────────────┘ │  详情 ⌄          │
│  设置      │                                │                  │
└────────────┴────────────────────────────────┴──────────────────┘
```

- 主区宽度 < 720px 时右栏自动收起为顶栏胶囊，点击展开浮层（同一个组件）。
- 右栏可手动收起，状态存 `localStorage["veyl.ui.panelOpen"]`。
- 顶栏只放：当前视图标题（左）、状态胶囊（右，只读）。不放开窗按钮、不放开日志。

## 4. 四个场景的具体形态

### 4.1 首次安装（没有 Key、没有配置）

全屏引导，**两步**，不打断、可跳过：

```
┌──────────────────────────────────────┐
│  Veyl                                │
│                                      │
│  先连上，再聊。                        │
│  用官方提供的节点，点一下就能用。        │
│                                      │
│  [ 连接测试节点 ]     导入我的配置文件    │
│                                      │
│  ──────────────────────────────      │
│  下一步：配置 AI（可选）→              │
└──────────────────────────────────────┘
```

要点：
- **连接优先于 AI**。用户是来用网络的，不是来配 API 的。
- 第 2 步才出现 DeepSeek Key：说明「AI 用来做什么 / 不做什么」，一个输入框、一个「保存并验证」、一个「稍后再说」。
- 平台链接用一行文字链接，不在首屏做大按钮（`https://platform.deepseek.com/`）。
- 全程不显示完整 Key，不写日志。

### 4.2 有 Key、没有会话（主区 = 控制台）

```
        Veyl 已就绪

        点一下连接到测试节点。           ← 28px，随状态变化
        出口位于东京，免费试用。          ← 13px --ink-2

        [     连接     ]                 ← 唯一实心按钮

        · 连接到最快节点                  ← 建议问题，点击即开新会话
        · 为什么我打不开某个网站？
        · 检查我的网络配置

  ─────────────────────────────────────
  默认配置 v2026-09-26 · 4 个节点 · 检查更新
```

建议问题只在「从未成功连接过」或「从没有过会话」时出现，最多 3 条。点击 = 以该文案开新会话并发出去（现有 `onConsoleSend` 已支持）。

### 4.3 对话中

主区是消息流，右栏承担全部连接控制。对话区**不出现任何连接按钮、状态条、端口信息**。
空会话时主区显示一行 `问点什么，或者让我诊断网络`，不给按钮。

### 4.4 熟练用户

- 不显示任何引导条、建议问题、空态营销文案。
- 高级入口只在设置页，且默认折叠在「高级」标题下。
- 设置页分区：`账号与 AI` / `网络` / `高级` / `关于`。

## 5. 高级配置的 AI 解释

每一个高级项旁边有一个统一的小链接：`问 AI`。点击后以固定的提示词前缀开一条会话，让 AI 结合当前值解释。

提示词前缀（**必须逐字使用**，写在 `src/ai/advancedPrompts.ts`）：

```
我在 Veyl 的高级设置里调整「{项名}」。当前值是 {值}。
请用三句话说明：这项设置实际改变了什么、什么时候该改、改错会有什么后果。
不要给通用教程，只说这个设置本身。
```

覆盖项：代理模式（系统代理/TUN）、本地端口、默认配置源、API 类型与 Base URL、模型选择。
这些是**唯一的**高级解释入口，不要另做一套帮助文档页面。

---

## 6. 文案规范

- 中文，句号结尾的完整句子用于说明；按钮用动词短语，2–6 个字。
- 按钮说的词，结果消息要用同一个词（「连接」→「已连接」）。
- 不用「请」开头堆客气话，不用感叹号，不用「哦」「呢」。
- 错误文案三段式：**发生了什么 → 为什么 → 现在做什么**。缺一段就算没写完。
  - 好：`系统代理没能恢复，为避免断网已保持连接。请重试，或重启应用。`
  - 坏：`操作失败` / `Error: proxy_restore_failed`
- 空态不写"暂无数据"，写用户能做的动作。
- 界面不出现英文术语裸奔：`TUN`、`mixed`、`selector` 这类词出现时必须带一句中文解释，或放进「详情」折叠区。

---

## 7. 实现约束

- 样式仍然集中在 `src/styles/app.css`，按区块注释分组；新增组件不要引入 CSS-in-JS 或 UI 框架。
- 所有状态文案、状态色映射集中在一处（`src/ui/status.ts`），不要在每个组件里各写一遍 `switch`。
- 删除组件时同时删除其 CSS 段，不留死代码。
- 离线优先：不加任何外部请求、字体、图片 CDN。
