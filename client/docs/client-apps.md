## 0. 结论先行

`client/` 下新增三个**纯使用端** APP，共用一套 Tauri 2 + React 代码：

| 目录 | 产物 | 形态 |
|---|---|---|
| `client/pc` | Windows（msi / nsis）+ macOS（.app / .dmg） | 一份代码，两个安装包 |
| `client/Android` | APK / AAB | Tauri 2 Android 目标 + 原生隧道层 |
| `client/iOS` | IPA | Tauri 2 iOS 目标 + Network Extension |

它们只做一件事：**把 Veyl 控制面已经生成的节点配置导进来，连上就能用。** APP 内没有登录、没有支付、没有创建节点，也没有 AI。

不做 AI 对话、不做创建/购买服务器、不做节点组与编排。桌面端仍是主控台与购买入口。

**不新增后端能力**：配置来源直接复用现有 `GET /v1/mobile/profile`（sing-box JSON，含最小 TUN 入站、DNS 分流、国内直连规则），认证沿用 HTTP Basic + 账户级导出令牌。客户端只是这条 URL 的另一个消费者。

## 1. 与现有「手机端导出」的关系

| 维度 | 现状（已上线） | 本次新增 |
|---|---|---|
| 谁在用配置 | sing-box 官方客户端（SFI / SFA）、Hiddify、CMFA、Shadowrocket | 我们自己的三个 APP |
| 配置来源 | `GET /v1/mobile/profile` 等六个端点 | **不变**，直接复用 |
| 令牌 | 账户级、长期、可轮换 | **不变** |
| 分发 | 指向官方商店 / GitHub Releases | 自家安装包与商店 |
| 桌面入口 | 设置 › 账户 › `在其它设备上使用` | 增加 `veyl-cli` 行（仅复制链接，无下载入口） |

**两者互不影响，不需要二选一。** 现有导出链路服务的是第三方官方客户端，继续保留、行为不变；自建客户端只是同一条 URL 与同一枚令牌的另一个消费者，不依赖也不改动前者。用户想用哪个客户端就用哪个。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 |
|---|---|
| G1 | 用户从桌面拿到一条订阅链接（或在桌面导出配置文件），在目标设备上导入后 1 分钟内连上 |
| G2 | 三端行为一致：同一份配置、同一套节点、同一套分流，不因平台出现「桌面能连、客户端没有」 |
| G3 | 节点重建、换 IP、换密码后，客户端自动跟上，不需要用户重新导入 |
| G4 | 免费 / 试用节点永远不进入客户端（与控制面现有筛选口径一致） |
| G5 | 三端都不出现 AI、建节点、购买入口 |

### 2.2 非目标（本期明确不做）

| 不做 | 理由 |
|---|---|
| AI 对话 / Claurst | 纯使用端，AI 留在桌面端 |
| 创建、购买、续费服务器 | 与 `client/` 定位冲突；付费在桌面端或网页 |
| 节点组、编排、布局个性化 | 同上 |
| APP 内登录 Veyl 账号 | 2026-11-25 产品拍板：导入只走订阅链接与本地配置文件 |
| 扫码导入 | 同上；二维码留给桌面端与官方客户端之间的路径 |
| 多协议客户端格式（Clash / ss / Shadowrocket） | 自家客户端只吃 sing-box JSON，不做多格式解析 |
| 测速 / 流量统计 / 到期提醒 | 未拍板，见 §10 #3；不默认实现 |
| 设备数限制 | 不限制设备数与并发登录；卖服务器而非卖席位 |

## 3. 用户与流程

### 3.1 用户获取配置

| 渠道 | 流程 |
|---|---|
| **订阅链接** | 桌面端 设置 › 账户 › `在其它设备上使用` 生成链接（现有）→ 复制 → 在 APP 内粘贴 → 导入 |
| **本地配置文件** | 桌面端导出 sing-box JSON 文件 → 传到目标设备 → APP 内「从文件导入」 |

两条渠道**导入后等价**：都变成客户端里的一条配置，后续都按同一套规则运行与更新。本地文件在客户端内**不自动更新**（它没有源）；订阅链接按固定间隔拉取。

### 3.2 门禁

| 对象 | 规则 |
|---|---|
| 订阅链接 | 只能从桌面端生成，需要已登录 + 至少一台可用的付费服务器（现有门禁，客户端不重复判断） |
| 客户端内 | 不登录、不校验账户；链接里的令牌是唯一凭据 |
| 令牌失效（401） | 客户端显示「链接已失效，请在桌面端重新生成」，**保留已有配置但标记为不可更新**，不清空 |
| 零节点（配置里没有代理节点） | 客户端显示「没有可用节点」，**不建立假 VPN**（沿用 `mobile-export-technical.md` §1.7 / §3.4 的口径） |

## 4. 功能需求

### 4.1 配置管理

| # | 需求 | 说明 |
|---|---|---|
| FR-1 | 添加订阅链接 | 粘贴 URL（含 `userinfo` 中的令牌）→ 拉取一次校验 → 成功才落库 |
| FR-2 | 从文件导入 | 系统文件选择器读取 `*.json`；必须是合法 sing-box 配置；校验失败给出可读原因 |
| FR-3 | 配置列表 | 多条配置并存，显示名称与节点数；可重命名、删除、设为当前 |
| FR-4 | 手动刷新 | 按需重新拉取订阅；显示上次更新时间 |
| FR-5 | 自动更新 | 订阅配置按固定间隔拉取，默认 60 分钟，与 `mobile-export-technical.md` §5 的口径一致；更新失败保留旧配置并标记 |
| FR-6 | 配置重名 | 同名配置允许并存，用时间戳区分展示 |

### 4.2 连接

| # | 需求 | 说明 |
|---|---|---|
| FR-7 | 一键连接 / 断开 | 主界面一个主按钮；连接中、已连接、连接失败三态可见 |
| FR-8 | 节点选择 | 配置内节点列表；切换节点不断链（若平台内核支持热切换），否则自动重连 |
| FR-9 | 启动时恢复 | 默认不自动连接；用户可在设置里开启 |
| FR-10 | 连接失败可见 | 不静默失败；给出「重试 / 换节点 / 查看日志」三个动作 |
| FR-11 | 分流 | **沿用服务端下发的规则**（国内直连、境外走节点）；客户端不提供改规则入口 |

### 4.3 系统集成

| # | 需求 | 说明 |
|---|---|---|
| FR-12 | 系统代理 / TUN | pc 默认 TUN；是否提供系统代理模式见 §10 #4 |
| FR-13 | 开机自启 | 可选，默认关 |
| FR-14 | 菜单栏常驻 | 菜单栏显示连接状态，提供显示主界面、连接 / 断开、退出；**关闭主界面不退出**，进程与隧道继续运行，可从菜单栏重新打开 |
| FR-15 | 后台运行 | 主界面关闭后应用继续在后台运行，保证 VPN 不断开；显式「退出」才结束进程，且必须先断开隧道 |
| FR-16 | 主界面可选 | 允许没有主界面的形态（只有菜单栏）。此时导入、刷新、连接 / 断开、退出必须在菜单栏可达；具体交互留给设计 |

### 4.4 明确不做

AI 对话、创建节点、购买 / 续费、节点组、测速、流量统计、到期提醒、扫码、账号登录、多语言之外的品牌定制。

## 5. 三端差异与平台约束

### 5.1 一句话：共用的是壳，隧道层各写各的

Tauri 2 覆盖 UI、状态管理、订阅拉取、配置解析、本地存储。**系统隧道不在其中**：

| 平台 | 隧道实现 | 主要工作量 |
|---|---|---|
| Windows | 沿用桌面端已定形态（`windows-tun.md` §3.2）：per-user 安装不弹 UAC，首次需要 TUN 时才提权安装常驻 LocalSystem 服务；sing-box 以服务侧进程运行 | 服务安装与 ACL、驱动、防火墙与 DNS 还原、代码签名 |
| macOS | 沿用桌面端形态（`tun-architecture-decision.md`）：spawn 随包的 sing-box 二进制，由它建 utun 与路由 | 签名、公证、授权、DNS 还原与验证 |
| Android | VpnService（Kotlin）+ libbox AAR | VPN 授权弹窗、前台服务、通知、电量 |
| iOS | Network Extension（Swift）+ libbox xcframework | NE entitlement、主 App 与扩展通信、签名与审核 |

### 5.2 已登记的平台风险

| 平台 | 风险 | 状态 |
|---|---|---|
| iOS | App Store 上架：VPN 类应用需要 Network Extension 权限与相应资质；中国大陆区上架另有监管要求 | **待核实**（`mobile-export.md` §2.1 与 §1.2 已登记「iOS 需 NE 权限与中国区上架资质」，但资质细节与当前政策需按官方渠道核实后再排期） |
| iOS | 若无法上架，只剩 TestFlight（需审核、有期限）或自签（免费 Apple 账号签名 7 天需重签；付费开发者证书有效期更长） | 结论取决于上架可行性 |
| Android | Google Play 对 VPN 类应用有专门政策；国内应用商店需要资质 | **待核实** |
| Windows | 提权与 TUN 驱动的安装/卸载体验 | 桌面端已走通同路线，可复用结论 |
| macOS | 签名、公证、Helper 的发布流程 | 桌面端已有流程，可复用 |
| 三端 | 安装包分发渠道（大陆网络可达性） | 与 `mobile-export-technical.md` §3.9 同一问题，暂不做补偿 |

> **排期建议**：iOS 的上架可行性是唯一可能推翻整个 iOS 目录的前置条件，应在写任何 iOS 代码之前查清；`client/iOS` 目录先占位。

### 5.3 内核与配置

| 项 | 约定 |
|---|---|
| 内核 | 随包 sing-box（与桌面端同一版本策略：只用随包版本；客户端不单独升级内核，随 APP 版本发布） |
| 配置来源 | 订阅：`GET /v1/mobile/profile` 返回的 sing-box JSON；文件：同形状 JSON，或用户提供的合法 sing-box 配置 |
| TUN 入站 | 订阅配置**已包含**最小 TUN 入站（`mobile-export-technical.md` §3.2）。**已定**（技术设计 §6.0）：移动端原样使用；PC 由客户端重写为自身网段并覆盖平台字段 |
| 分流 | 服务端下发（`geosite-cn` / `geoip-cn` 规则集 + DNS 分流）；客户端不改写 |
| 规则集 | 与 profile 同 origin，客户端只负责让内核去拉 |

## 6. 与现有接口的关系（只登记，不定契约）

### 6.1 直接复用的端点（现状）

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/v1/mobile/profile` | sing-box JSON（客户端唯一必需的端点） |
| `GET` | `/rules/geosite-cn.srs`、`/rules/geoip-cn.srs` | 内核按配置自行拉取，无需客户端代码 |
| `POST` | `/v1/mobile/token` / `/token/rotate` | 桌面生成 / 轮换链接，客户端不调用 |

### 6.2 新增项（导出配置文件已实现）

| 项 | 说明 | 是否必需 |
|---|---|---|
| 桌面「导出配置文件」 | **已实现**：`mobile_export_save_file`（`docs/contracts/commands.md` §7.34，2.71.0）；把当前账户的 sing-box 配置写成文件，供离线导入 | 是 |
| 客户端专用 profile 变体（如 `?client=veyl`） | **不需要**：PC 的参数差异由客户端重写 `inbounds` 解决（技术设计 §3.2），服务端保持一份配置 | 否 |
| 客户端版本上报 | 不需要；本期不做遥测 | 否 |

### 6.3 桌面端需要新增的入口

| 位置 | 变化 |
|---|---|
| 设置 › 账户 › `在其它设备上使用` 弹层 | 增加 `veyl-cli` 行（复制链接，无下载入口）；现有 iPhone / Android 行保留 |
| `veyl-cli` 行增加「导出配置文件」按钮 | **已实现**：拿到链接后出现，调系统保存对话框；文件含节点密码，界面提示导入后删除 |

## 7. 安全

| 项 | 规则 |
|---|---|
| 令牌 | 订阅 URL 含导出令牌，等价于「这份配置的读取权」；客户端**不得**把完整 URL 写入日志、崩溃报告或界面文本 |
| 存储 | 链接与配置存在应用私有目录；令牌不进入系统剪贴板历史以外的任何共享位置 |
| 截图 | 配置详情页默认隐藏 URL（与桌面端「界面不展示 IP / 端口」一致） |
| 日志 | 客户端日志只记事件与状态，不记 URL、节点地址、密码 |
| 撤销 | 只认桌面端「重新生成」；客户端收到 401 即停止更新并提示 |
| 本地文件 | 文件含节点密码，导入后提示用户删除源文件；客户端不主动清理外部文件 |

## 8. 验收条目（产品级，真机执行）

| 编号 | 场景 | 期望 |
|---|---|---|
| CA-1 | 粘贴订阅链接导入 | 拉取成功、节点数与桌面一致、免费 / 试用节点不出现 |
| CA-2 | 本地配置文件导入 | 导入成功、可连接；无网络时也能导入 |
| CA-3 | 连接 | 系统隧道建立（VPN 标志出现且流量计数非 0），能打开网页 |
| CA-4 | 分流 | 国内站点直连、境外站点走节点（探针沿用 `mobile-export-technical.md` 的 `api.ipify.org` + 国内站点组合） |
| CA-5 | 节点切换 | 切换后出口 IP 变化，无需重新导入 |
| CA-6 | 自动更新 | 桌面端重建节点后，客户端在一个更新周期内跟上 |
| CA-7 | 令牌轮换 | 桌面点「重新生成」后，客户端下一次拉取 401，显示失效提示，**不清空已有节点、当前连接保持到用户断开** |
| CA-8 | 零节点 | 账户无可用服务器时，不建立假 VPN，显示「没有可用节点」 |
| CA-9 | 退出 | 退出应用后隧道关闭、无残留进程；macOS / Windows 的 DNS 与路由还原后必须验证可用，超时也算未还原 |
| CA-10 | 断网恢复 | 断网再恢复后，连接可自动恢复或一键重连成功 |
| CA-11 | 日志 | 客户端日志中搜不到完整 URL、令牌、节点密码 |
| CA-12 | 冷启动规则集 | 首次连接时规则集拉取成功；规则源不可达时行为与官方客户端一致（可见失败，不静默全局） |
| CA-13 | 关窗与唤回 | 关闭主界面后进程与隧道保持；从菜单栏可重新打开主界面；显式退出后隧道关闭、无残留进程 |

三端各自执行；iOS 另需在商店版本与 TestFlight / 开发签名版本各做一次（签名差异可能影响 NE）。
