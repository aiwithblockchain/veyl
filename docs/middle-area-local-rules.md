# 中间区域本地兜底渲染规则

> 版本：1（2026-11-05）
> 适用：`ConfigDetail.layout === null`（还没被 AI 编排过）的有配置状态
> 上游依据：`docs/center-panel.md` §2.2–§2.5、`docs/data-model.md` §3.4、`docs/user-segments.md` §2
> 性质：纯本地规则。不调用 AI、不联网、不新增后端能力；同样输入必须得到同样输出。

---

## 1. 适用范围

### 1.1 只在这些条件下生效

同时满足：

1. 已经选中一套配置（`config !== null`）
2. 这套配置的 `layout === null`——从来没有被编排过
3. 当前不处于过渡态（见 §2.1）

### 1.2 这些情况不适用

| 情况 | 行为 |
|---|---|
| `layout.blocks = []` | AI 明确选择「中间什么都不放」，**合法，保留空白**。不要用本地规则覆盖 |
| `layout.blocks` 非空 | 按 AI 的块渲染，本文件不参与 |
| 没有任何配置（`hasConfigs = false`） | 走现有的零配置入口，不适用本文件 |
| `RuntimeState` 为 `starting` / `restarting` / `stopping` | 过渡态，**不渲染任何块**。顶部已经在说「正在连接 / 正在断开」，中间再说一句只会打架 |
| 跨配置切换的瞬间 | 等新配置的 `config_detail` 到达后再算；不要拿旧配置的字段渲染新状态 |

故障卡是**叠加渲染**，不写进 `layout`（`docs/data-model.md` §3.4）。本文件只定义 `layout === null` 时它长什么样；`layout` 非 null 时故障卡与 AI 块的先后顺序不在这里定。

## 2. 前置判定

### 2.1 三态归并

以 `runtime.state` 为准，不要用顶部的按钮文案反推。

| `runtime.state` | 本文件的状态 | 说明 |
|---|---|---|
| `failed` | **失败** | 即使 `connected_since` 有值也按失败处理 |
| `running` | **已连接** | |
| `degraded` | **已连接（降级）** | 仍算连上，但要多一张提示卡（§4.3.3） |
| `idle` | **未连接** | |
| `starting` / `restarting` / `stopping` | **过渡态** | 不渲染 |

### 2.2 「代理用户」判定

> 这是我们唯一能证明「用户要手动把参数填进别的软件」的配置形态。

```
proxyUser = config.connect_mode === "system_proxy"
         && config.routing_mode === "proxy_selected"
```

- `system_proxy`：本机有一个 mixed 入站端口。
- `proxy_selected`：只有指定服务走节点，其它直连——说明用户在逐个软件里做选择，最可能需要代理地址。

**已知缺口，必须写进实现注释：**

- 三级用户如果选了「全部走 VPN」（`proxy_all`），配置与一级用户完全相同，本地无法区分。这类人在本规则里按一级处理，看不到代理卡；他们仍可在底部「技术详情」里找到本机代理地址。
- 修复它需要配置里有一个显式的「这个人是否要手动填代理」标记，属于 Phase 2 的数据变更，本文件不假设它存在。
- **不要**用「有没有装 AI」「是不是手动建的配置」去猜等级，这些都不是等级。

### 2.3 可用数据白名单

中间区只准读这些字段。表外的字段一律不读，尤其不要读节点地址、端口、加密方式——那是底部节点卡的内容。

| 字段 | 来源 | 用途 |
|---|---|---|
| `runtime.state` | runtime 快照 | 三态归并 |
| `runtime.mixed_port` | runtime 快照 | 已连接时的代理卡地址；**唯一真值** |
| `runtime.health.exit_ip` | runtime 快照 | 只用于顶部出口；中间**不重复** |
| `runtime.health.process` | runtime 快照 | 失败/降级原因（本地组件是否起来） |
| `runtime.health.clash_api` | runtime 快照 | 失败/降级原因（控制接口是否响应） |
| `runtime.health.data_plane` | runtime 快照 | 失败/降级原因（流量是否真的出去） |
| `runtime.health.consecutive_failures` | runtime 快照 | 降级卡是否出现（> 0） |
| `runtime.last_error` | runtime 快照（可能为 null） | 失败原因的第一优先来源；只读 `code`，**不展示 `message`** |
| `config.connect_mode` | 配置 | 代理用户判定；「浏览器 / 所有软件」措辞 |
| `config.routing_mode` | 配置 | 代理用户判定；「全部走节点 / 指定服务走节点 / 直连」措辞 |
| `config.listen_port` | 配置（可空） | 未连接时的**预计**代理端口；不能当实际端口 |
| `config.nodes.length` | 配置 | 失败卡下一步是否提「换节点」 |
| `aiReady` | 现有 UI 状态 | 失败卡下一步措辞的二选一；不读 AI 会话内容 |
| `runtime-state-changed` 的 `from` | 状态迁移事件 | 失败卡标题区分「没连上」与「连接断了」 |

明确**不用**：

| 数据 | 为什么不用 |
|---|---|
| `runtime.connected_since` | 进入失败终态时后端已把它清空，失败快照里永远是 null，判不出「之前连上过」 |
| `runtime.traffic`、`runtime.latency_ms` | 顶部摘要已经展示，中间重复即噪音 |
| `runtime.direct_ip` | 底部技术详情已有 |
| `config.name`、节点名 / 地址 / 端口 / 加密方式 | 顶部状态与底部节点卡已有 |
| `routing targets`（分流目标清单） | 不在配置详情里，本地拿不到 |
| 出口国家 | **没有这个字段**。禁止从 `exit_ip` 反查或猜测国家 |

## 3. 状态 × 块矩阵

块只能从这里挑：`empty_hint` / `proxy_card` / `source_choice` / `reachability` / `issue_card` / `update_hint`。

| 状态 | 一级 / 二级（非代理用户） | 三级（`proxyUser`） |
|---|---|---|
| **未连接** | 1. `empty_hint` | 1. `proxy_card` |
| **已连接** | 1. `empty_hint` | 1. `proxy_card` |
| **已连接（降级）** | 1. `issue_card`（降级） | 1. `issue_card`（降级）<br>2. `proxy_card` |
| **失败** | 1. `issue_card`（失败） | 1. `issue_card`（失败） |
| **过渡态** | 无 | 无 |

规则：

- **一次最多两块。** 超过两块说明有内容放错了地方。
- `issue_card` 永远排第一。
- 出现失败卡时，不再渲染 `empty_hint` / `proxy_card`——失败时用户只有一件事要做。
- 代理用户已连接时，`proxy_card` 本身就是确认（标题「代理已经开好」），不再补一行「浏览器现在能用了」。
- 配置里一个节点都没有时，`empty_hint` 换成 §4.1.3 的无节点文案，其余规则不变。

## 4. 块规格

### 4.1 `empty_hint`

**形态：** 一段纯文本。没有标题、没有图标、没有按钮、没有卡片边框。整块就是一句话（最多两句）。

#### 4.1.1 未连接

| 条件 | 文案（原文） |
|---|---|
| `connect_mode === "tun"` | `点上面的「启动 VPN」，所有软件都会自动走节点。` |
| `connect_mode === "system_proxy"` 且 `routing_mode === "proxy_all"` | `点上面的「启动 VPN」，浏览器就能用了。所有流量都会从节点出去。` |
| `connect_mode === "system_proxy"` 且 `routing_mode === "direct"` | `点上面的「启动 VPN」，浏览器就能用了。` |

> `routing_mode === "proxy_selected"` 的人不会走到这里，他们有代理卡。
>
> **为什么不说具体哪些网站直连**：配置里没有分流目标清单，也没有「国家」字段。硬写「国内网站直连」在 `proxy_all` 上就是假话。宁可少说，不说错。

#### 4.1.2 已连接

| 条件 | 文案（原文） |
|---|---|
| `connect_mode === "tun"` | `所有软件现在都能用了。` |
| `connect_mode === "system_proxy"` | `浏览器现在能用了。` |

> 不再写「出口：某国」或重复 IP。出口地址在顶部摘要里，已经是可复制的一等公民；没有国家字段就不猜国家。

#### 4.1.3 无节点（覆盖 4.1.1 / 4.1.2）

`config.nodes.length === 0` 时：

```
让右侧的助手帮你加一个节点，或者新建一套配置。
```

- 不重复底部已有的「这套配置还没有节点」。
- 顶部按钮此时本来就是禁用态，不需要在中间再解释为什么点不了。

**数据来源：** `config.connect_mode`、`config.routing_mode`、`config.nodes.length`。

**消失条件：** 状态变化、节点数变化、或 AI 生成了布局（`layout` 变为非 null）。

### 4.2 `proxy_card`

卡片。只在 `proxyUser` 为真时出现，**常驻**，不提供关闭按钮。

#### 4.2.1 未连接

| 元素 | 内容 | 数据来源 |
|---|---|---|
| 标题 | `连上后，这里会给你一个代理地址` | — |
| 字段名 | `预计地址` | — |
| 字段值 | `127.0.0.1:<config.listen_port>` | `config.listen_port` |
| 字段值（`listen_port` 为 null） | `连上后显示` | — |
| 说明 | `HTTP 和 SOCKS5 都支持，同一个地址。` | 固定文案 |
| 脚注 | `实际端口连上后确认；被占用会自动换。` | 固定文案 |
| 复制按钮 | **没有** | — |

**为什么未连接不给复制**：契约要求卡片写的就是实际跑的那个端口。连接前只有「期望端口」，复制出去可能是个错的值，比不给更糟。

#### 4.2.2 已连接

| 元素 | 内容 | 数据来源 |
|---|---|---|
| 标题 | `代理已经开好` | — |
| 字段名 | `本机代理地址` | — |
| 字段值 | `127.0.0.1:<runtime.mixed_port>` | `runtime.mixed_port`，**唯一真值** |
| 复制按钮 | 复制上面的完整地址（`127.0.0.1:7890` 这一串），不复制说明文字 | — |
| 复制反馈 | `已复制` / `复制失败`，2 秒后回到 `复制` | 现有模式 |
| 说明 | `HTTP 和 SOCKS5 都支持，填同一个地址。` | 固定文案 |
| 脚注 | `只在本机可用，别的设备连不上。` | 固定文案 |

补充规则：

- `runtime.mixed_port === null` 但状态已经是 running：显示 `正在确认代理地址…`，**不回退**到 `config.listen_port`，不显示复制按钮。等 runtime 更新。
- `runtime.system_proxy_enabled === true` 时，可在标题下加一行 `浏览器已经设好了，其它软件按上面的地址填。`；为 false 时不加。
- **不放入分流清单**：配置详情里没有 targets，本地画不出来。等 Phase 2 有了数据再加，不要用「指定服务」这种空话占位。

**可复制字段：只有地址这一项。** 协议、说明、端口数字本身都不单独提供复制。

### 4.3 `issue_card`

#### 4.3.1 失败卡（三态里的「失败」）

结构固定为三段，但**不显示「发生了什么 / 为什么 / 现在做什么」这些小标题**。视觉上就是：标题 → 一句原因 → 一行下一步。

| 段 | 内容 |
|---|---|
| 发生了什么（标题） | 这次失败来自 `running` / `degraded`（`runtime-state-changed` 的 `from`）→ `连接断了。`<br>否则 → `这次没有连上。` |
| 为什么（正文，一句） | 按 §4.3.2 的顺序取第一条命中的 |
| 现在做什么（脚注，一句） | 按 §4.3.4 的规则取 |

**为什么不用 `runtime.connected_since` 判断标题：** 后端在进入失败终态时会执行
`health.exit_ip = None` 并清空 `connected_since`，UI 拿到的失败快照里它永远是 null，
这一支永远走不到——用户连了十分钟后断开，会被说成「这次没有连上」。
所以标题只看这次状态迁移是从哪来的，并由普通状态迁移（例如 stop 到 `idle`）复位，
避免上一次的「连接断了」残留到下一次失败。

**数据来源：** `runtime.state`、`runtime-state-changed` 的 `from`、`runtime.last_error.code`、`runtime.health.*`、`config.nodes.length`、`aiReady`。

#### 4.3.2 「为什么」的判定顺序

按顺序匹配，命中即停。`last_error.code` 优先于健康字段；健康字段优先于兜底。

| 顺序 | 条件 | 文案（原文） |
|---|---|---|
| 1 | `last_error.code === "PERMISSION_DENIED"` | `系统没有允许 Veyl 接管网络。` |
| 2 | `last_error.code === "RUNTIME_PORT_UNAVAILABLE"` | `本机用来做代理的端口被别的软件占用了。` |
| 3 | `last_error.code` ∈ `RUNTIME_START_TIMEOUT` / `RUNTIME_HEALTH_FAILED` / `RUNTIME_CRASH_LOOP` / `RUNTIME_EXITED` / `TIMEOUT` | `节点一直没有响应。` |
| 4 | `last_error.code` ∈ `RUNTIME_CONFIG_INVALID` / `INVALID_ARGUMENT` / `PRECONDITION_FAILED` / `UNSUPPORTED` | `这套配置没法用，启动被拒绝了。` |
| 5 | `last_error.code` ∈ `UPSTREAM_ERROR` / `RATE_LIMITED` | `节点服务暂时不可用。` |
| 6 | `health.process === false` | `Veyl 的网络组件没有启动起来。` |
| 7 | `health.clash_api === false` | `网络组件在，但控制接口没有响应。` |
| 8 | `health.data_plane === false` | `已经连上节点，但流量没有真正出去。` |
| 9 | 其它 | `具体原因还没确认。` |

禁止：

- 不展示 `last_error.message` 原文（多为英文技术句，普通用户读不懂）。
- 不展示错误码、配置哈希、端口号、堆栈。
- 不在同一张卡里列多个原因。

#### 4.3.3 降级卡（`degraded`）

已连接但健康检查没通过时，`issue_card` 排在 `proxy_card` 前面。

| 段 | 内容 |
|---|---|
| 标题 | `连接不太稳定。` |
| 为什么 | `health.data_plane === false` → `流量没有真正出去。`<br>`health.consecutive_failures > 0` → `最近的网络检查没有通过。`<br>否则 → `网络检查没有通过。` |
| 现在做什么 | `能继续用就先不动；网页打不开时，点上面的「断开 VPN」再重新连接。` |

#### 4.3.4 「现在做什么」的判定

失败卡：

| 条件 | 文案（原文） |
|---|---|
| `config.nodes.length >= 2` | `先点上面的「重新连接」。还是不行，就换下面的节点再试。` |
| `config.nodes.length <= 1` 且 `aiReady` | `先点上面的「重新连接」。还是不行，就在右侧对话里说「帮我看看为什么连不上」。` |
| `config.nodes.length <= 1` 且 `!aiReady` | `先点上面的「重新连接」。还是不行，就新建一套配置再试。` |

硬规则：

- 卡里**不放按钮**。「重新连接」在顶部，「换节点」在底部，再放一遍就是三个入口做同一件事。
- 不渲染「重置网络」（E3 尚未实现）和「让 AI 定位」（J3 尚未实现）。等能力就绪再加按钮，现在用一句话指路即可。
- 不说「请检查网络连接」这类用户无法执行的空话。

### 4.4 本阶段不渲染的块

| 块 | 判断 | 理由 |
|---|---|---|
| `reachability` | **Phase 2，不渲染，也不留占位** | 需要用户提过的目标清单与逐项探测结果，两类数据都没有。留一个「正在检查…」会永久停在那里，比没有更糟 |
| `update_hint` | 不在本地规则里渲染 | 数据源是默认配置包状态，不属于 runtime / 配置两类；且与「这一件事」无关。由默认配置模块决定是否插入 |
| `source_choice` | 不渲染 | 需要 C1 / B4 的节点来源选择能力，本地规则没有可执行动作；无节点情况改用 §4.1.3 的一句话指路 |
| 问题管理模块的 `issue_card` | Phase 2 | 目前 UI 只拿到 `issue_id` / `title` / `type`，没有可读的「为什么」；先用 runtime 推导的失败卡兜底 |

> 占位一律不加。中间区宁可空着，也不显示一个永远不结束的「加载中」。

## 6. 边界：中间不准重复的东西

| 信息 | 已经在哪里 | 中间的处理 |
|---|---|---|
| 连接状态（未连接 / 连接中 / 已连接 / 失败） | 顶部按钮 + 状态胶囊 | 不写「已连接」三个字 |
| 节点名 | 底部节点卡 | 不写 |
| 服务器地址 / 端口 / 加密方式 | 底部节点卡（技术详情） | 不写 |
| 延迟 | 顶部摘要 + 底部节点卡 | 不写 |
| 流量（已用） | 顶部摘要 + 底部节点卡 | 不写 |
| 连接时长 | 顶部摘要 | 不写 |
| 出口 IP | 顶部出口胶囊（可复制） | 不写；国家也不猜 |
| 切换节点 / 检查连接 | 底部节点卡 | 不放同类按钮 |
| 启动 / 断开 / 重新连接 | 顶部唯一主按钮 | 不放同类按钮 |
| TUN 授权 | 系统级弹窗 | 不进中间 |
| AI 服务商、端口、日志、版本 | 设置页 | 不进中间 |

中间区只回答一个问题：**「现在这一件事，用户必须自己知道或自己完成，而我们替不了他的是什么？」**

- 一级 / 二级：没有。给一句话就够。
- 三级（代理用户）：地址。给一张卡。
- 所有人失败时：发生了什么、为什么、下一步。给一张卡。

## 7. 留白与位置

### 7.1 只有一句话时

- 水平居中、垂直居中（在中间区可用高度内居中）。
- 最大宽度 `42em`，单行不折行优先；窄窗口允许折成两行。
- 不加上下分割线、不加图标、不加按钮。
- **为什么居中**：顶部有按钮、底部有节点卡，中间一句话居中读起来是「这个界面在告诉我一件事」；靠上会像一条没加载完的提示。

### 7.2 有卡片或两块时

- 靠上排，`padding-top: 24px`，块间距 `12px`。
- 卡片最大宽度 `520px`，水平居中。
- 不把卡片拉满整个中间区宽度。
- 中间区自身保留滚动（现有 `.console-mid` 已经是 `overflow-y: auto`），窗口很矮时卡片可以滚，不要压缩底部节点卡。

### 7.3 没有块时

- `layout.blocks = []`：什么都不画，也不显示「暂无内容」。
- 过渡态：什么都不画，避免和顶部抢话。
- 失败卡出现时不留其他块的位置，也不画占位骨架。

### 7.4 窄窗口

中间区宽度小于 `420px` 时：

- 一句话允许折行，左右内边距降到 `16px`。
- 代理卡地址允许换行，但复制按钮不换行到地址上面。
- 失败卡三段保持顺序，不折叠、不省略「为什么」。

---

## 8. 确定性约束

实现必须满足：

1. 不调用 AI、不读会话内容、不联网。
2. 不解析 `exit_ip` 推断国家，不做 GeoIP。
3. 不读时间做「刚刚 / 几分钟前」——中间区不展示时长。
4. 块的数量与顺序只由 §2、§3、§4 的表格决定，没有随机、没有「最近一次」记忆。
5. 复制反馈的 2 秒计时器只影响反馈文字，不影响块的去留。
6. 同样的 `runtime` + `config` + `aiReady` +「最近一次失败是否来自已连接态」输入，必须渲染出同样的块与文案。

## 10. 前端实现清单

1. 在 `Console` 里判断 `config?.layout === null`；非 null 时交给既有/将来的布局渲染，不进入本规则。
2. 由 `runtime.state` 归并三态 + 过渡态；不要用 `connection` 字符串另算一套。
3. 实现 `isProxyUser(config)`，只有 `system_proxy` + `proxy_selected` 为真。
4. 按 §3 的矩阵生成有序块数组，最多两块。
5. 新增三个块的渲染：
   - `empty_hint`：单个 `<p>`，居中；样式复用现有空态文字，不建新卡片。
   - `proxy_card`：卡片 + 地址 + 复制；已连接时 `runtime.mixed_port` 为空显示确认中，不回退。
   - `issue_card`：标题 / 一句原因 / 一行下一步；无按钮。
6. 失败原因与下一步各写成一个纯函数（输入 runtime/config/aiReady，输出字符串），便于单测覆盖 §4.3.2 与 §4.3.4 的全部分支。
7. 补 §9 的 12 条用例测试；测试不依赖真实网络与 AI。

**不做：** 不新增后端字段、不新增块类型、不改 `BlockType` 词表、不写布局回数据库。布局表的写入仍然只发生在 AI 编排之后。
