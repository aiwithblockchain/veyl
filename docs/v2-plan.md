# V2 开发计划

> 状态：草案，随 V1 收尾持续补充
> 日期：2026-11-20

V1 的目标是「能用、能卖」：自建服务器、按天计费、AI 能判断和解释。V2 的目标是**让用户少动手**——把需要人工执行的操作交给 AI，把需要人工完成的升级交给程序。

本文件只记录 V1 明确不做、且已决定推迟到 V2 的功能。V1 范围内的缺陷不进这里，走 issue。

---

## 1. AI 代操作全部界面

**现状（V1）**：AI 只读 + 只能加节点、连接、诊断。新建服务器、销毁、充值必须用户自己在界面点。

**V2 目标**：AI 能执行界面上的全部操作——新建节点、销毁节点、刷新余额、展示建机进展、发起充值、定位问题并给出处置建议。

**约束（做的时候不能松）**

- 每个动作仍是**独立工具 + 确认卡 + 审计日志**，不给 AI 一个万能执行器。
- 销毁与充值的二次确认不能被 AI 绕过，确认卡必须由用户点。
- 失败要有回滚或明确的「已扣费但未建成」状态，不能只报一句失败。

---

## 2. 导入后立即生效

**现状（V1）**：连着的时候通过「导入订阅 URL」或「粘贴 ss:// 文本」新增的节点会进池，但不会重建运行中的配置，需要重新连接一次才能切过去。

**V2 目标**：导入成功后直接触发重建，新节点立即可切。

**注意事项**：复用 `node_attach` 已有的 `rebuild_running_config` 路径，不要另写一份；一次导入可能带几十个节点，重建耗时与失败回滚要单独评估。

---

## 3. 应用内自动更新

**现状（V1）**：升级靠用户自己去 GitHub Releases 下载新包手动安装。设置页的「运行时升级」只管 sing-box 运行时，不是应用本身。

**V2 目标**：应用启动后自行检查新版本，下载完成后提示重启即生效；更新失败不影响当前正在运行的版本。

### 参考实现

`/Users/wesley/ai/TweetPilot/` 已经跑通同一套：

- `src-tauri/tauri.conf.json` 的 `plugins.updater`：`endpoints` 指向自建接口 `https://license.tweetpilot.dessage.xyz/v1/update/latest`，`dialog: false`（弹窗自己做），`pubkey` 为 minisign 公钥。
- 升级包由 Tauri 的 `createUpdaterArtifacts` 产出（macOS 为 `.app.tar.gz` + `.sig`，Windows 为安装包 + `.sig`）。

### 我们需要做的

1. **接入 `tauri-plugin-updater`**：`tauri.conf.json` 增加 `plugins.updater`，`endpoints` 指向控制面的新路由（建议 `https://veyl.dessage.xyz/v1/update/latest`），`pubkey` 写入公钥。
2. **控制面新增 `/v1/update/latest`**：按 Tauri updater 约定的 JSON 返回当前版本、发布日期、各平台的下载地址与 `.sig`；数据来源可以是 GitHub Releases API 的缓存，也可以是部署时写入的常量。
3. **签名密钥**：私钥只放本机 keychain 与 CI secret（见 `docs/build-and-release.md`），**永不入库**；公钥写进配置。
4. **客户端行为**：启动后静默检查一次；设置页提供「检查更新」；下载完成不强制重启，正在连接或正在建机时只提示、不打断。
5. **失败可见**：检查失败、下载失败、签名校验失败分别有明确文案，签名校验失败必须拒绝安装。

### 验收

- 从 `1.0.0` 自动升级到 `1.0.1`，全程不打开浏览器。
- 篡改过的安装包（签名不匹配）被拒绝，且当前版本仍可正常使用。
- 断网启动不报错、不阻塞主流程。

### 4.1 节点端口 / 密码轮换（补充）

- **什么时候才做**：只是偶尔出现端口的封锁或误伤；节点**开始能用、过一段时间不通、但 ping 通**时才值得轮换。一开始就 ping 不通的节点归类为 IP 被封，直接让用户重建，不要轮换。
- **为什么现在不做**：V1 有销毁重建这条通路，轮换的收益只在「机器本身还能用、只是端口被针对」这一种情况下体现；为它引入远程改配置、防火墙同步、客户端重新取凭据三套链路，成本远高于直接重建。
- **做的时候要验什么**：改完端口/密码后必须由客户端拿到新凭据并**实际连上一次**才算成功；只改服务端不验证，等于把「不通」变成「静默不通」。
- **人工验证路径**：用户可用 DigitalOcean 后台的 Web Console 登入机器，手动改配置与防火墙，确认可用后再决定是否工程化。

## 5. 暂缓项（未决定是否进 V2）
