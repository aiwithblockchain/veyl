## 0. 开始之前

### 0.1 执行纪律

- 应用**只由你本人启动**。其他人（包括 AI 会话）不代跑启动、不代改系统设置。
- 验收对象是 **Tauri 桌面窗口**（`/Applications/Veyl.app`）。浏览器里的 `localhost` 页面走 mock，不算数。
- 每条用例都按 **步骤 → 预期 → 失败特征 → 需要记录什么** 执行；不通过时只记录事实，不猜原因。
- 一次只跑一条；改设置、连断网、销毁服务器都会改变现场，跑下一条前先回到用例写明的前置状态。

### 0.2 前置条件

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 系统 | macOS（启动脚本只支持 Darwin） | `uname -s` |
| 工具链 | node/npm、cargo、Xcode Command Line Tools | `node -v`、`cargo -V`、`xcode-select -p` |
| 运行时资源 | `src-tauri/resources/runtime/sing-box`、`src-tauri/resources/rules/veyl-rules-*.tar.zst` 存在 | `ls` 两个路径 |
| 签名身份 | 自动挑 Developer ID 或 Apple Development（Team 与 `VEYL_TEAM_ID` 一致，默认 `2XYK8RBB6M`）；必要时设 `VEYL_DEV_ID_APP` | 脚本输出里能看到签名身份 |
| helper | 首次连接 TUN 时注册并请求系统授权；此前应为 `not_found` | 见 S2 |
| AI Key | DeepSeek Key（或「其他 AI 服务」端点）。没有 Key 时跳过标 **[需要 AI]** 的条目 | 首启页 |
| 网络 | 「新建节点」「我的服务器」「充值」要能访问控制面 | 对应条目里会看到 |

### 0.3 启动方式（唯一）

```bash
bash scripts/dev/tun-dev.sh --kill-existing
```

- 脚本会：构建 → 签名 → 装进 `/Applications` → 前台启动；`Ctrl-C` 结束。
- 日志：应用结构化日志在 `logs/app-<日期>.log`；本次运行的 stdout 在 `build/logs/tun-dev-<时间戳>.log`。
- 退出 App **不会**停 TUN（产品设计）。若 TUN 还在跑，回到 App 里断开，或在下一次启动后断开。

### 0.4 想从头复现首启

1. 退出 App（已连接时先在应用内断开）。
2. 删除 `~/.veyl`（本地库、密钥文件、试用状态都在这）。
3. 删掉钥匙串里 Veyl 的条目（DeepSeek Key / 设备令牌）。
4. 重新执行 0.3。

> 删除前先备份 `~/.veyl`，里面有本地配置与账本镜像。

### 0.5 每条怎么记

统一写成四行，失败时把**界面原文**抄下来，不要转述：

- **步骤**：你点了什么、输入了什么。
- **预期**：界面上应出现什么（包含关键文案）。
- **失败特征**：出现这些就判不通过。
- **需要记录什么**：失败时的文案原文、发生时间、`logs/app-<日期>.log` 里同一时刻的 `ERROR` / `WARN` 行；必要时截图。

## 1. 启动与前置

### S1 启动成功

- **步骤**：执行 0.3 的命令；等待脚本打印安装与启动完成。
- **预期**：`/Applications/Veyl.app` 被启动，窗口标题 `Veyl`；没有崩溃、没有空白窗；主界面出现（已有数据）或首启页出现（全新状态）。
- **失败特征**：脚本非 0 退出；窗口不出现或立刻消失；窗口一直空白；日志出现 `panicked`。
- **需要记录什么**：脚本最后 20 行输出、窗口是否出现、日志里 `ERROR` 与 `panicked` 行。

### S2 首次连 TUN 的授权

- **前提前置（2026-11-17 起）**：默认接管方式是 `Proxy 模式`，**默认状态下连接不应出现任何系统授权 / 密码弹窗**——这一步先验证这一点。
- **步骤**：在已有免费节点或自建节点的情况下，点主按钮 `连接`（应无授权弹窗、直接连上）→ 设置 → 连接段把接管方式切到 `Tun 模式`（就地确认）→ 再点 `连接`；如出现系统授权/密码弹窗，按提示完成。
- **预期**：Proxy 连接全程无授权；切到 Tun 后授权只出现一次；完成后状态带变为 `已连接`，主按钮变 `断开`；再次断开、重新连接不再要求授权。
- **失败特征**：每次连接都要求授权；授权后仍停在 `未连接` 或 `连接失败`；helper 报 `not_found`。
- **需要记录什么**：授权弹窗出现次数、连接后的状态带文案、日志里 helper 相关行。

## 2. 首启（DeepSeek Key）**[需要 AI]**

> 前置：按 0.4 清空本地状态，启动后停在首启页。

### O1 正确 Key

- **步骤**：在 `DeepSeek API Key` 输入框粘贴一个可用的 `sk-` 开头的 Key，点保存/继续。
- **预期**：保存成功，首启页淡出，进入主界面（无节点时是二选一）；没有任何错误提示。
- **失败特征**：报「Key 无效 / 连接失败」但 Key 实际可用；保存后仍停在首启页；重复弹回首启。
- **需要记录什么**：错误文案原文、Key 前 6 位（不要记完整 Key）、日志里 provider/key 相关行。

### O2 错误 Key

- **步骤**：输入一个格式正确但不可用的 Key（如 `sk-000…`），点保存。
- **预期**：错误**就地显示**（不跳页、不清空输入框）；把 Key 改成正确值再次保存可以成功。
- **失败特征**：输入框被清空；错误以弹窗/跳页出现；改对后仍报错且无法恢复。
- **需要记录什么**：错误文案原文、输入框是否保留内容、第二次保存的结果。

### O3 自定义端点（含本机端点免 Key）

- **步骤**：
  1. 点「使用其他 AI 服务」，接口类型选 OpenAI 或 Anthropic 兼容。
  2. 填一个 `https` 远程端点 + Key → 保存。
  3. 再换成 `http://127.0.0.1:<port>` 的本机端点，不填 Key → 保存。
  4. 再试 `http://` 的非本机地址 → 保存。
- **预期**：2 成功；3 成功（本机端点允许免 Key）；4 被拒，提示只允许本机地址用 http。
- **失败特征**：本机端点在没 Key 时被拒；非本机 http 被接受；保存后仍回退到 DeepSeek。
- **需要记录什么**：每种组合的结果与提示原文；端点只记 host，不记 Key。

## 3. 无节点：二选一与免费节点试用

> 前置：本地没有任何节点（可用 0.4 重置，或删除全部节点）。

### T1 二选一出现且不触发 AI

- **步骤**：进入主界面；观察中区。
- **预期**：只有两个选择：`先试用免费节点`（次）与 `新建节点`（主）；下方有「免费节点不保证稳定，试用 7 天」一类说明；右栏 AI **没有**自动发起对话。
- **失败特征**：AI 自动说话或自动开始拉取；出现第三、第四个入口；两个选择顺序/主次颠倒。
- **需要记录什么**：截图或抄下两个按钮的文案与顺序、AI 面板是否自动发消息。

### T2 试用步骤流与收敛句

- **步骤**：点 `先试用免费节点`，观察中区步骤流直到结束。
- **预期**：依次出现三步 `拉取预置配置` → `加入免费节点` → `逐个测速`，每步完成显示**真实耗时**（`N.N 秒`）；结束后收敛为一句 `已加入 2 个免费节点，最快 XXms`；状态 `未连接`，节点卡显示 2 个节点与延迟，主按钮 `连接`；**收敛句后面不出现 `报告问题`**（正常态不显示诊断入口）。
  - **不自动连接**：**主判据看界面**——状态带仍是 `未连接`、托盘未显示已连接、系统代理 / 隧道未启动；日志只作补充证据，不单独判失败（「日志里没有连接开始」可能只是没打日志）。
  - **不自动把某个节点设为当前**：`configs.current_node_id` 在这一刻仍为空；节点池里两台都在。**可观察的等价检查**：在步骤流结束后、点「连接」之前退出并重启 App，回到连接屏应**仍未选中任何节点**（预选不持久化）；**再等到启动后的自动测速跑完，仍应没有选中**——这一条专门用来抓「从测速结果推导预选」的实现。字段检查留给开发看日志时用，两条并列，不互相替代。
  - **最快预选**：界面本地把延迟最低的那台显示为选中，并带「最快」标记；连接前不写库。**预选只在试用步骤流完成时发生一次**——之后启动自动测速（如果有）不得把最快节点重新显示为选中，也不得从测速结果反推预选。**「最快」标记**：试用步骤流完成时标一次；之后**后台 / 自动测速只清除标记、不移动、不改变选中**；**用户主动点「测速」后跟随本次结果移动**（但不动选中）。规则见 `connection-stage-probe.md` §4。
  - **用户点连接才生效**：点之前状态带与托盘都保持 `未连接`，系统代理/隧道未启动；点之后才进入 `连接中` → `已连接`，且实际连的是预选的那台。
  - **重启后无预选时点连接**（边界，不是失败）：重启后既没有「最快」标记也没有选中，点「连接」落到配置的当前节点（为空则节点池第一个）。
- **依赖未落地时**：本用例假定「seed 配置留空 `current_node_id` + 界面本地预选 + 点连接前先 `node_switch`」三项前端改动已完成。**未完成前 T2 应预期失败，不要记为通过，也不要据此判实现有缺陷**——先确认改动是否已合入。
- **失败特征**：没有耗时或耗时全是 0；收敛句数字与节点卡不一致；步骤卡住不动；结束后仍停在步骤流；**结束后自动连接或自动把某台设为当前**；点 `连接` 之前系统代理已被打开；节点卡没有任何预选，或预选不是最快那台，或**试用刚完成时**「最快」标记落在非最低延迟的节点上；或**用户主动点「测速」后**标记没有跟到本次最快的那台（后台 / 自动测速把标记清掉、不移动，**不是**失败）；**不点连接直接重启后，连接屏已经选中了某台**；**重启后的自动测速完成时冒出了选中（无论标没标「最快」）**；**正常态收敛句后面出现 `报告问题`**。
- **需要记录什么**：三步各自耗时、收敛句原文、节点卡上的延迟、「最快」标记落在哪台、结束后的连接状态、**重启后连接屏是否仍无选中**、**自动测速完成后是否出现选中**、点连接后实际使用的节点名、收敛句后是否出现 `报告问题`。

### T3 拉取失败可重试

- **步骤**：断网（或让控制面不可达）后点 `先试用免费节点`。
- **预期**：`拉取预置配置` 一步标记 `没完成`，下方给出错误说明与 `重试`；恢复网络后点 `重试` 能继续，不必重启 App。
- **失败特征**：整页卡死；没有重试入口；重试后重复叠加节点；错误显示成「加入失败」而实际是拉取失败。
- **需要记录什么**：失败步骤名称、错误原文、重试后的结果。

### T4 测速全失败仍可先连接

- **步骤**：构造两个节点都测不通（例如连接到一个不可达网络后重跑试用，或让节点不可用）。
- **预期**：`逐个测速` 一步 `没完成`，给 `重试` 与 `先连接，不测速`；点后者进入连接屏，节点卡仍显示 2 个节点，主按钮 `连接`。
- **失败特征**：没有「先连接」入口；按钮点了没反应；节点被清空。
- **需要记录什么**：错误原文、点「先连接」后节点数量与主按钮文案。

### T5 到期屏只有「新建节点」

> 这条只适用于**池里没有自建节点**的情况；池里已有自建节点时到期不显示到期屏，走 T5b。

- **步骤**：构造「试用已到期」（把本地试用开始时间前移 8 天，或手改 `~/.veyl` 里的试用记录），然后启动 App；如果当时正连着免费节点，先连接再触发到期。
- **预期**：中区只有标题 `试用已到期`、一句「免费节点已从节点池移除」与唯一按钮 `新建节点`；没有「继续试用」「重新试用」；正在连接的免费节点被断开，并给出提示。
- **失败特征**：出现第二个入口；旧节点仍在节点卡里；连接没有断开但节点已消失。
- **需要记录什么**：到期屏全部文案、节点池数量、连接状态（是否断开）。

### T5b 到期但池里已有自建节点：不显示到期屏

> 依据 `docs/design/global-config-merge.md` §8.1。

- **前置**：池里同时有 2 台试用节点与至少 1 台自建节点。
- **步骤**：把试用开始时间前移 8 天（或设 `veyl.mock.trial=expired`）后启动 App。三种状态各跑一次：① 正连着试用节点；② 选中试用节点但未连接；③ 正连着自建节点。
- **预期**：
  - **不出现到期屏**，直接停在连接舞台（池里还有节点）。
  - 只移除免费节点；自建节点保留、**顺序不变**（节点卡行序与到期前一致）。
  - ①：**硬断开**，状态变 `未连接`，不静默换到自建节点。
  - ②：选中项回落到池里剩下的第一个（通常是自建节点）。
  - ③：连接不受影响，仍是那台自建节点。
- **失败特征**：出现到期屏；自建节点被删或顺序变了；正连试用节点时悄悄切到自建节点；选中项悬空（显示已选中但节点卡里没有那台）。
- **需要记录什么**：节点卡行序（到期前后各一次）、连接状态、选中项、是否出现到期屏。

## 4. 连接舞台

> 前置：至少有一个节点（免费或自建），当前未连接。

### C1 连接 / 断开 / 重新连接

- **步骤**：点主按钮 `连接`；等到状态带变为 `已连接`；点 `断开`；再点 `连接`；连接后拔网/让节点不可达，观察失败态，再点 `重新连接`。
- **预期**：按钮文案按 `连接 → 连接中… → 断开 → 断开中… → 连接` 变化；失败后按钮为 `让 AI 检查`（有 AI 时）或 `重新连接`；状态带显示 `已连接` 与计时；断开后计时消失。
  - **`报告问题` 只在两种状态出现**：连接失败与「连上了但没流量」。正常已连接、未连接时底部**没有** `报告问题` 链接。
- **失败特征**：按钮文案与状态不一致；连接中可重复点击；断开后仍显示计时；失败态没有出口；**正常已连接 / 未连接时底部出现 `报告问题`**，或**失败态没有 `报告问题`**。
- **需要记录什么**：每次点击后的按钮文案与状态带文案、计时是否启动/停止、`报告问题` 在哪些状态出现过。

### C2 Tun ↔ Proxy 切换（二次确认 + 短暂断开）

- **步骤**：设置 → 连接段（默认是 `Proxy 模式`）；已连接状态下切到 `Tun 模式`，在就地确认里先取消一次，再确认一次；切回 `Proxy 模式` 同样操作。
- **预期**：已连接时切换会先在**就地**出现确认（不是新弹窗），取消后设置不变；确认后连接短暂断开并自动恢复（或明确提示需要重连）；未连接时切换不需要确认。
- **失败特征**：没有确认就直接切；取消后设置已变；切换后一直停在 `未连接` 且没有提示。
- **需要记录什么**：确认文案原文、取消/确认后的状态带、是否自动恢复。

### C3 智能 / 全局热切换

- **步骤**：设置 → 连接段，把流量范围在 `智能` 与 `全局` 之间来回切两次；观察连接是否中断。
- **预期**：热切换，不断线、不弹确认；主界面顶部结果文案随之变化（如 `本机代理 · 智能 · 东京` → `本机代理 · 全局 · 东京`）。
- **失败特征**：切换导致断线；顶部文案不更新；切换后需要重新连接。
- **需要记录什么**：切换前后顶部文案、连接状态是否保持。

### C4 退出确认（三条用例：已连接弹 / 未连接也弹 / 系统注销不弹）

**C4a 已连接时按 `Cmd+Q`**

- **步骤**：在已连接状态下按 `Cmd+Q`（或菜单「退出 Veyl」）；分别测试 `Esc`、点 `×`、点遮罩、点 `后台运行`、点 `退出`。
- **预期**：弹窗标题含 `退出 Veyl？`，正文两行分别是 `后台运行` / `保持连接` 与 `退出` / `断开连接并恢复网络设置`（不是「……会……」的整句）；`Esc` / `×` / 遮罩一律等于**取消**（选择后台运行，不退出）；`退出` 后 App 关闭、连接断开、系统代理/DNS 恢复。
- **失败特征**：`Esc`/`×`/遮罩把 App 退了；正文仍是「……会……」整句；已连接却显示未连接的文案（`留在菜单栏` / `关闭 Veyl`）；退出后 TUN 仍显示连接中或网络未恢复。
- **需要记录什么**：每个取消入口的结果、退出后系统网络是否可用（打开一个网页确认）。

**C4b 未连接时按 `Cmd+Q`**

- **步骤**：断开连接（状态带为 `未连接`）后按 `Cmd+Q`；先点 `后台运行`，再从托盘或 Dock 回到主界面；再次 `Cmd+Q` 点 `退出`。
- **预期**：**弹窗照样出现**，标题 `退出 Veyl？`；正文两行是 `后台运行` / `留在菜单栏` 与 `退出` / `关闭 Veyl`，不是「断开连接并恢复网络设置」；`后台运行` 后窗口消失、应用仍在菜单栏、再次打开回到原界面；`退出` 后进程结束（菜单栏图标消失）。
- **失败特征**：未连接时 `Cmd+Q` 直接把 App 退了、没有弹窗；弹窗出现但正文沿用已连接的「断开连接并恢复网络设置」；`后台运行` 后菜单栏图标也没了。
- **需要记录什么**：弹窗是否出现、两行正文原文、`后台运行` 后菜单栏图标是否还在、`退出` 后进程是否结束。

**C4c 系统注销时直接退出（不弹）**

- **前置**：先保存其它应用的工作——注销会结束所有程序。**建议放在全部用例最后跑**。
- **步骤**：连接一个节点（让退出流程有事可做）→ 苹果菜单 → `注销…` → 确认注销，观察 Veyl 的表现。
- **预期**：**不出现任何 Veyl 弹窗**，应用随注销直接结束；不存在「弹窗卡住注销」的情况。
- **失败特征**：注销过程中 Veyl 弹出「退出 Veyl？」并阻塞注销；或注销后 Veyl 进程 / 托盘图标仍在。
- **需要记录什么**：注销时是否出现弹窗、注销后是否残留进程与托盘图标、系统代理是否恢复。

### C5 舞台快速切换（两步）

- **前置**：至少一个节点；主按钮下方能看到两个 chip `Proxy 模式 ⌄` / `智能 ⌄`（无节点、试用到期、新建节点屏不出现这一行）。
- **步骤**：
  1. 未连接，点左侧 chip 展开选择层；不选任何项，按 `Esc`。再点开一次，点层外。
  2. 再点开，选 `Tun 模式`；在就地确认条点 `取消`。
  3. 再选 `Tun 模式` → `继续`；如出现系统授权，按提示完成。
  4. 点右侧 chip，选 `全局`。
  5. 连接后重复第 1 步与第 4 步（接管方式再切回 `Proxy 模式` 一次）。
- **预期**：
  - 点 chip **只展开选择层**：状态带、连接状态、库里的值都不变——**误点一下不会切换、不会断线**。
  - 选择层出现在行正下方，当前值那一行右侧有 `✓`；`Esc`、点层外、再点同一个 chip 都能关闭且不改值。
  - 选 `Tun 模式` 后**先**出就地确认条（不是直接切换），焦点在 `取消`；`取消` 后仍显示 `Proxy 模式`。
  - 确认后才进入切换；成功前 chip 不显示新值。
  - 流量范围选中即生效：不断线、计时不停、播报 `已切到全局`。
  - 已连接时切接管方式：断开重连，状态带走一遍连接过程，**计时从 0 开始**。
- **失败特征**：点 chip 直接切换；没选定就改了值；选择层里当前值没有 `✓`；`Esc` 关不掉选择层；流量范围切换导致断线或计时归零；选 `Tun 模式` 后跳过确认条直接切；确认条焦点不在 `取消`。
- **需要记录什么**：每次点击后 chip 文案与是否展开、选择层里 `✓` 落在哪一项、确认条原文、切换后的连接状态与计时、授权弹窗出现次数。

**S2 补充**：舞台也能触发 Tun——从舞台选 `Tun 模式` 并确认后，首次连接同样会请求一次系统授权；已授权过的机器不再弹。

**其余入口（按设计直接退出）**：托盘菜单的 `退出` 不弹窗直接退出。只记录实际行为，不作为 C4 的通过条件。

## 5. 设置

### G1 四段与高级

- **步骤**：打开设置，依次点 `AI` / `连接` / `账户` / `高级`。
- **预期**：四段都在，顺序正确；`高级` 排最后且默认不展开；关闭方式（`×`、遮罩、`Esc`）都能回到原界面。
- **失败特征**：缺段或顺序错；高级跑到主路径前面；关闭后界面状态丢失。
- **需要记录什么**：四段标题与顺序、关闭方式是否都有效。

### G2 咨询 AI 分栏

- **步骤**：设置里点 `咨询 AI`；再点一次收起。
- **预期**：设置缩到左侧、右侧出现 AI 面板，两边可同时操作；再点一次恢复居中；关闭设置后右栏回到原来的收起/展开状态。
- **失败特征**：点 `咨询 AI` 后设置被关闭；分栏后中区被挤压错位；收起后宽度不恢复。
- **需要记录什么**：分栏前后设置宽度与右栏宽度、关闭设置后右栏状态。

### G3 AI 指路高亮

- **步骤**：在对话里问「端口在哪里设置」一类问题，让 AI 打开设置并指向具体行（AI 会调用 `OpenSettings`）。
- **预期**：设置打开并切到对应段；目标行滚动到可见并高亮约 **2 秒**后自动取消；不改任何值。
- **失败特征**：设置没打开或停在别的段；高亮不出现或一直不消失；值被改动。
- **需要记录什么**：AI 回复原文、设置打开的段、高亮持续的大致秒数。

### G4 端口行只在 Proxy 出现

- **步骤**：默认 `Proxy 模式` 下看连接段（应出现端口行）；切到 `Tun 模式` 再看；切回。
- **预期**：Tun 模式下**没有**本地代理端口行；Proxy 模式下出现，并可编辑/复制；切回 Tun 后消失。
- **失败特征**：Tun 下仍显示端口；Proxy 下不显示；切换后端口值被重置。
- **需要记录什么**：两种模式下端口行是否存在、端口值是否保持。

## 6. 新建节点

> 前置：能从二选一/到期屏进入 `新建节点`。

### N1 地区按大洲分组、来自目录

- **步骤**：进入新建节点舞台；观察地区列表；断网后重新进入一次。
- **预期**：地区按大洲（亚洲 / 北美洲 / 欧洲 / 大洋洲等）分组，名称与目录一致；断网时如实报目录不可用，**不编地区**。
- **失败特征**：出现界面写死的地区；分组缺失；断网时仍显示一份旧目录且没有提示。
- **需要记录什么**：前 5 个地区名与所属大洲、断网时的提示原文。

### N2 三档价格只写「每天 $X」

- **步骤**：观察三张类型卡（入门 / 标准 / 进阶）。
- **预期**：价格只以 `每天 $X` 出现；同卡另有 `每月 X GB 流量`；**不出现月费金额**；卡上不写退款说明。
- **失败特征**：出现 `$X/月` 或月价金额；出现退款/计费长文；三档价格与目录不一致。
- **需要记录什么**：三张卡的名称、每天价格、流量额度。

### N2b 三档卡的排布不压窄

- **步骤**：把窗口从宽拉到窄（跨过约 560px），再拉回；观察三张类型卡。
- **预期**：宽时一行三列；窄于约 **560px** 时允许排成 2+1；**两种排布下卡片内容都不折行**（`每天 $X` 与 `每月 X GB 流量` 各在一行内）。
- **失败特征**：为了凑三列把卡片压到 176px 以下，副行折成两行或末尾只剩一个字；宽窗口下仍排成 2+1（空间足够却不铺开）。
- **需要记录什么**：两种宽度下各排成几列、副行是否折行、卡片实际宽度。

### N3 让 AI 帮我选 → 舞台跟着变并高亮

- **步骤**：点 `让 AI 帮我选`（或直接在对话里说「帮我选新加坡、标准档」）；等 AI 调用 `StageSelect`。
- **预期**：舞台自动选中对应地区与类型，滚动到可见并高亮约 1.5 秒；对话里工具卡写「已把…发给新建节点舞台」，不承诺屏幕变化；不建机、不扣费。
- **失败特征**：AI 说选好了但舞台没变（且不在下述允许场景：舞台未打开、创建中、UI 目录快照过期）；舞台变了但高亮不出现；出现扣费/建机。
- **需要记录什么**：AI 回复与工具卡原文、舞台最终选中的地区/类型、高亮是否出现、余额是否变化。

### N4 余额校验与失败定位

- **步骤**：把余额调到不足 1 天（或用一个余额为 0 的账户）；点 `创建`；再构造一次建机失败（如让控制面拒绝）。
- **预期**：余额不足时**不发起创建**，就地提示还差多少并给 `去充值`；创建失败时舞台显示失败的步骤与原因，并给 `AI 定位`；AI 只解释结构化失败，不声称读过日志、不要求上传日志。
- **失败特征**：余额不足仍扣费/建机；失败没有原因或没有 `AI 定位`；AI 编造具体原因。
- **需要记录什么**：提示原文与短差金额、失败阶段/原因、AI 回复中是否出现「日志」。

### N5 创建中锁返回

- **步骤**：点 `创建` 后立刻尝试返回/切换目的地；创建过程中再对 AI 说「换成东京」。
- **预期**：创建开始后返回被锁住（或明确提示创建中）；创建中收到 `stage-select` 被整条忽略，舞台选择不变。
- **失败特征**：创建中能退回并丢失进度；创建中舞台选择被改动。
- **需要记录什么**：返回按钮是否可点、创建中舞台选择是否变化。

## 7. 我的服务器

### M1 列表行价格与状态

- **步骤**：进入「我的服务器」；观察列表行。
- **预期**：每行有名称、`每天 $X`、状态灯与状态词（如 `使用中` / `建机器中` / `已销毁`）；没有余额时不显示价格。
- **失败特征**：价格缺失或与详情不一致；状态词与实际状态矛盾。
- **需要记录什么**：行的价格与状态词。

### M2 详情行（含 IP 复制）

- **步骤**：选中一台可用服务器，看详情；点 IP 旁的 `复制`。
- **预期**：详情显示地区、规格、IP、节点、费用、流量；IP 可复制，按钮短暂变 `已复制`；凭据/密码不出现。
- **失败特征**：缺行；复制无反馈；出现密码或令牌。
- **需要记录什么**：六行是否齐全、复制结果、是否出现敏感字段。

### M3 销毁二次确认含退款两句

- **步骤**：点 `销毁`，**不要**立即确认；阅读确认文案；点取消。
- **预期**：确认文案包含「销毁后不再产生新费用」「未用完的整天退回余额，当天已扣不退」以及「配置里会少一个节点」一类影响说明；取消后服务器不变。
- **失败特征**：确认文案没有退款两句；取消后状态已变；文案承诺现金退款。
- **需要记录什么**：确认文案原文、取消后的状态。

### M4 重建入口不出现

- **步骤**：让一台服务器处于创建失败（`error`）状态，看详情。
- **预期**：**没有**「重建 / 重新建一台」入口（控制面端点未接入）；有 `AI 定位`。
- **失败特征**：出现重建按钮，点击后报「服务器状态异常」一类含糊错误。
- **需要记录什么**：详情里出现了哪些动作按钮。

### M5 未登录 / `auth_required` 拉起登录

- **步骤**：退出账号（或在全新设备上）点 `创建` / 进入我的服务器。
- **预期**：就地拉起邮箱验证码登录；发码、校验、登录后回到原来的动作，不丢上下文；登录错误按原因提示（邮箱格式、太频繁、验证码错误/过期、设备冲突）。
- **失败特征**：只在本地有账号时才弹登录，`auth_required` 时不弹；登录后回到首页而不是原动作。
- **需要记录什么**：触发时是否弹登录、登录后的落点、错误提示原文。

### M6 充值失败给「重新打开」与可复制链接

- **步骤**：进入充值；让系统浏览器打不开收银台（例如断网或把默认浏览器换成一个会失败的），发起一次充值。
- **预期**：明确提示打开失败，给 `重新打开支付页面` 与 `复制链接`，不谎报「已打开支付页面」。
- **失败特征**：仍提示「已打开」；没有重新打开/复制入口；链接不可复制。
- **需要记录什么**：提示原文、两个入口是否出现、复制的内容（只记前缀）。

## 8. AI ↔ UI

- **步骤**：让 AI 给出带按钮的卡片（如换地区、重试），点其中一个按钮；观察是否发生实际动作。

- **失败特征**：没有该按钮；AI 猜原因或让用户上传日志；给了多个并列动作。
- **需要记录什么**：按钮是否存在、AI 回复是否逐项、最终动作是什么。

## 10. 已知不覆盖

以下项目本轮**不作为验收项**，失败也不算回归：

| 项 | 原因 |
|---|---|
| 「重建」按钮 | 控制面 `/v1/servers/{id}/rebuild` 未接入，恒返回 `rebuild_not_supported`，界面已隐藏入口 |
| 目录快照过期的极端情况 | 控制面与 UI 各自取目录，极端时序下 `stage-select` 可能被 UI 丢弃；属已知口径，不构造 |
| Windows | 本轮只在 macOS 验收；Windows TUN 另有机型与验收命令 |
| 真实支付扣款 | 充值走 Dodo 沙箱/余额，不做真实扣款验证 |
| 7 天真实到期 | 不等待 7 天，只按 T5 构造到期 |
| 服务端容量/稳定性 | 免费节点只有 2 台，不承诺；换配置属预期 |

## 11. 15 分钟最小冒烟路径

先跑这 6 步，确认没坏再展开全量：

1. **启动**：`bash scripts/dev/tun-dev.sh --kill-existing`，窗口出现、无崩溃（S1）。
2. **试用与连接**：无节点 → `先试用免费节点` → 三步跑完 → 收敛句出现 → 点 `连接` → 状态 `已连接` → 点 `断开`（T2 + C1）。
3. **设置**：默认 `Proxy 模式` 下端口行已出现 → 切到 `Tun 模式`（就地确认）→ 端口行消失 → 切回 `Proxy 模式` → 端口行出现（G4 + C2）。
4. **新建节点**：进入舞台看地区分组与三档 `每天 $X` → 对 AI 说「帮我选新加坡、标准档」→ 舞台变化并高亮（N1 + N2 + N3）。
5. **我的服务器**：列表行有价格与状态 → 详情 IP 可复制 → 点 `销毁` 读确认文案后取消（M1 + M2 + M3）。
6. **退出确认**：已连接时 `Cmd+Q` → `Esc` 取消 → 再次 `Cmd+Q` → `后台运行`；断开后再 `Cmd+Q` → 出现弹窗（未连接也弹）→ `退出`（C4a + C4b）。

全部通过：本批可以进入提交流程。
任一步失败：停在失败处，按 0.5 记录，不要在失败状态下继续后面的步骤。

| 证据 | 位置 |
|---|---|
| 应用结构化日志 | `logs/app-<日期>.log` |
