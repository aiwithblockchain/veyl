## 1. 阶段目标

**让一个普通用户从安装到连上，全程只用对话完成。**

具体要验证三件事：

1. 用户愿不愿意用聊天来操作 VPN，而不是点按钮。
2. AI 能不能可靠地下载、启动 sing-box 并生成可用的客户端配置。
3. 我们提供的节点目录服务能不能让用户「打开就能用」。

如果这三件事有一件不成立，后面的自建节点、支付、链上都不必做。

## 4. 功能需求

### 4.1 应用外壳

- **FR-1.1** 单实例运行；重复启动时聚焦已有窗口。
- **FR-1.2** 主窗口左侧对话、右侧状态面板；窗口最小 900×600。
- **FR-1.3** 托盘图标：显示连接状态，提供「连接/断开/退出」。
- **FR-1.4** 退出前恢复系统代理；异常退出后下次启动检测并恢复。
- **FR-1.5** 应用版本与运行时版本在设置页可见。

### 4.2 AI 对话

- **FR-2.1** 消息流式渲染，支持 Markdown 与代码块。
- **FR-2.2** 工具调用卡片：显示工具名、参数摘要、状态（运行中/成功/失败）、耗时。
- **FR-2.3** 卡片可展开查看结果摘要；敏感字段脱敏。
- **FR-2.4** 高风险工具弹确认卡（P1 主要为安装运行时、修改系统代理）。
- **FR-2.5** 对话上下文按会话保存，重启可恢复。
- **FR-2.6** 支持「停止生成」与「重试上一条」。
- **FR-2.7** 无 Key 或 Key 无效时，降级为「无 AI 模式」：保留手动节点列表与连接按钮。

### 4.3 运行时管理

- **FR-3.1** 支持列出可用版本（P1 内置一份经过校验的官方版本清单）。
- **FR-3.2** 下载对应平台/架构的官方归档（macOS arm64/x86_64、Windows x64）。
- **FR-3.3** 下载后必须校验 SHA256 与文件大小，不匹配则删除并报错。
- **FR-3.4** 安全解压：拒绝路径穿越、绝对路径、指向目录外的符号链接。
- **FR-3.5** 安装到应用数据目录，保留版本号；P1 只保留一个活动版本。
- **FR-3.6** 安装后执行 `sing-box version`，确认可运行。
- **FR-3.7** 启动/停止/重启/状态查询；同一时刻只允许一个进程。
- **FR-3.8** 进程崩溃自动重启，最多 3 次（退避 1s/2s/4s），失败后提示。
- **FR-3.9** 启动超时 10 秒，超时视为失败。
- **FR-3.10** 显示进程 PID、版本、uptime、最近错误。

### 4.4 客户端配置生成

- **FR-4.1** 根据节点描述生成 sing-box JSON：
  - `mixed` 入站，监听 `127.0.0.1:<可配置端口>`，默认 2080。
  - 出站按节点协议生成（P1 支持 `VLESS + Reality`、`Hysteria2`）。
  - `route.final` 指向代理出站。
  - `experimental.clash_api` 监听 `127.0.0.1:<随机端口>`，`secret` 随机生成。
- **FR-4.2** 生成后先写临时文件（0600），执行 `sing-box check -c`。
- **FR-4.3** 校验失败不启动，返回具体错误字段。
- **FR-4.4** 配置与节点绑定，切换节点即切换配置。
- **FR-4.5** 配置中不写入我们的任何标识或遥测。

### 4.5 节点目录服务

- **FR-5.1** 客户端首次启动时匿名注册设备，获得 `device_id` 与访问 token。
- **FR-5.2** 提供节点列表查询，支持按地区、协议过滤。
- **FR-5.3** 节点字段：ID、名称、地区、城市、协议、服务器地址、端口、凭据、TLS 参数、健康分、延迟、更新时间、标签。
- **FR-5.4** 服务端对种子节点做定期连通性探测，健康分低于阈值时从列表隐藏或降权。
- **FR-5.5** 客户端缓存最近一次成功结果，离线时可用（标注「可能过期」）。
- **FR-5.6** 服务不可用时给出明确提示，不阻塞手动导入。
- **FR-5.7** 免费种子节点设速率与并发限制，防止被白嫖。

### 4.6 系统代理

- **FR-6.1** macOS：读取当前网络服务的 HTTP/HTTPS/SOCKS 代理设置并备份。
- **FR-6.2** macOS：连接时设置 HTTP/HTTPS 代理到 `127.0.0.1:<端口>`；断开时恢复备份。
- **FR-6.3** Windows：写入 Internet Settings 注册表并通知系统刷新；断开时恢复。
- **FR-6.4** 应用异常退出后，下次启动检测残留代理并恢复。
- **FR-6.5** 设置失败时给出系统版本相关的操作指引，不静默失败。

### 4.7 连接与验证

- **FR-7.1** 连接流程：确保运行时可用 → 生成配置 → 校验 → 启动 → 设置系统代理。
- **FR-7.2** 连接后通过代理请求出口 IP 服务，展示出口 IP 与地区。
- **FR-7.3** 延迟测试：对节点做一次 TCP/TLS 握手或 Clash API 延迟测试。
- **FR-7.4** 连接失败分类：节点不可达、认证失败、配置不合法、端口占用、运行时未启动。
- **FR-7.5** 切换节点时先停旧连接，失败则恢复旧配置（P1 至少恢复系统代理）。

### 4.8 设置

- **FR-8.1** DeepSeek API Key：保存到系统钥匙串，界面只显示掩码。
- **FR-8.2** 本地代理端口可配置（默认 2080）。
- **FR-8.3** 日志级别：info / debug；debug 仅本地。
- **FR-8.4** 「恢复系统代理」手动按钮。
- **FR-8.5** 清除本地数据（配置、日志、缓存），不删除 Key 时需二次确认。

### 4.9 最小诊断

- **FR-9.1** 展示运行时进程状态、监听端口、配置哈希。
- **FR-9.2** 展示最近 50 行脱敏日志。
- **FR-9.3** 一键复制诊断信息（不含 Key、UUID、密码）。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 启动时间 | 冷启动 < 3 秒（不含下载运行时） |
| 连接时间 | 运行时就绪后 < 15 秒 |

| 可观测 | 本地结构化日志，按天轮转，最多 7 天 |

## 8. 已知限制

### 8.1 系统代理的覆盖面

P1 只设置 HTTP/HTTPS/SOCKS 系统代理。以下场景不会被代理：

- 不读取系统代理的应用（部分命令行工具、游戏、UDP 流量）。
- 使用自己的网络栈的应用。

这是 P1 的明确取舍：先用零提权的方式验证核心体验。TUN 模式不在四阶段计划内，建议作为 P2 的补充项单独评估。

### 8.2 种子节点的容量

P1 的节点由我们自营，数量有限。目录服务需要限流，避免被当作免费公共代理刷爆。

### 8.3 运行时版本

P1 只支持一个内置版本（当前为 sing-box 1.14.x）。多版本安装、远程签名清单、自动升级在 P2 落地。

### 8.4 分发签名

P1 只面向内部与早期测试，Windows 安装包默认不签名。**Windows 代码签名与分发是最终收尾任务（P5），不阻塞 P1–P4**；macOS 公证在对外发布前完成。证书选型与申请清单见技术设计 10.1。

## 9. 验收标准

### 9.1 主流程

- [ ] 全新安装 → 打开应用 → 完成 DeepSeek Key 配置 → 说「连到日本」→ 60 秒内连上 → 浏览器能打开网页。
- [ ] 状态区显示：进程运行中、节点名、延迟、出口 IP、sing-box 版本。
- [ ] 说「断开」→ 系统代理恢复 → 浏览器恢复直连。

### 9.2 异常路径

- [ ] DeepSeek Key 无效：提示明确，仍可用手动模式选节点连接。
- [ ] 节点不可达：提示「节点不可达」并推荐同地区其他节点。
- [ ] sing-box 下载失败：显示 HTTP 状态或网络原因，可重试。
- [ ] SHA256 不匹配：拒绝安装并删除文件。
- [ ] 本地端口被占用：提示换端口，不崩溃。
- [ ] 应用被强杀：下次启动恢复系统代理。
- [ ] sing-box 崩溃：应用不退出，自动重启并提示。

### 9.3 安全检查

- [ ] 日志中搜索不到 Key、UUID、密码。
- [ ] Clash API 只监听 `127.0.0.1`，`secret` 非空且随机。
- [ ] 外发请求只包含匿名健康数据与目录查询。

### 9.4 分发检查

- [ ] macOS：`codesign --verify --deep --strict` 通过；`spctl -a -vv` 通过；双击安装包不出现「无法验证开发者」。
- [ ] macOS：DMG 已完成公证并 staple，离线首次打开也能通过 Gatekeeper。
- [ ] Windows：安装包可正常安装；未签名时，安装文档明确写出「更多信息 → 仍要运行」的步骤。
- [ ] Windows（可选，仅在启用签名时）：`signtool verify /pa /v` 通过；安装时显示发布者名称。
- [ ] 两个平台：安装包版本号与应用内版本一致；卸载后残留目录可清理。

### 9.5 体验指标

| 指标 | 目标 |
|---|---|
| 首次连接成功率（内部试用） | ≥ 90% |
| 从说「连接」到状态变为 running | ≤ 15 秒 |
| 工具调用失败后的可恢复率 | ≥ 80%（给出下一步） |
| 崩溃导致应用退出 | 0 次 |

## 10. 时间表（5 周，macOS + Windows 并行）

| 周 | 内容 | 产出 |
|---|---|---|
| W1 | 跨平台骨架、CI 矩阵（macOS arm64/x86_64、Windows x64）、运行时下载/校验/安装、配置生成 | 两个平台都能用命令行驱动 sing-box |
| W2 | Claurst crate 接入（会话、工具、权限、事件）、对话 UI；Windows 代理控制器并行开发 | 聊天能触发工具；Windows 代理能设能恢复 |
| W3 | 目录服务、种子节点、连接流程、macOS 系统代理 | 两个平台端到端都能连上 |
| W4 | 引导流程、错误处理、持久化、崩溃恢复、代理残留恢复 | 双平台可日常使用的内部版 |
| W5 | 双平台安装包 + macOS 公证；Windows 默认不签名（可配置开启）、测试、内部 dogfood | P1 发布候选 |

**macOS 证书必须 W1 确认**：Apple Developer 账号通常 1–3 天。签名与公证可直接复用 `TweetPilot/scripts/packaging/build-dmg.sh` 的流程：Developer ID → 嵌套 Mach-O 签名 → App 深度签名 → notarytool 公证 → staple → 制作 DMG → DMG 再签名再公证 → Gatekeeper 验证。

**Windows 签名不是必需品**：不签名也能安装运行，只是会触发 SmartScreen「未知发布者」提示。P1 默认不签，与 TweetPilot 的 `build-msi.ps1` 一致；等对外大规模分发或企业客户要求时再启用。

**人员约束**：双平台并行要求至少 2–3 人，且从 W1 起就要有人负责 Windows 的路径、归档格式（`.zip` vs `.tar.gz`）和系统代理。如果只有 2 人，建议把周期放宽到 6 周，而不是把 Windows 压到 W5。

## 12. 开放问题

1. Windows 安装包格式：MSI 还是 NSIS？P1 默认 MSI（与 TweetPilot 一致）。
2. 种子节点的地区选择与合规主体。
3. 免费额度如何限制：按设备、按 IP，还是按连接时长？
4. 是否在 P1 就加入「手动导入订阅」，还是只支持目录节点？
5. Claurst submodule 的版本锁定与升级节奏（建议季度升级 + 安全补丁例外）。
6. Apple Developer 账号由谁持有；Windows 签名何时启用（P1 默认不启用）。
