# 已连接但没有流量：状态词与行动句

> 适用状态：`docs/contracts/runtime.md` §4.3 `dataPlaneDown`。
> 本轮只出文案与位置判断，不改 `src/`。
> 依据优先级：`veyl-ui` 硬规则 > `ui-ux-pro-max` > 一般审美。

---

## 1. 这是什么状态

- 隧道与握手正常，`state` 仍是 `running`，托盘仍是「已连接」；但从当前连接路径发出去的请求出不去。
- 不是 `degraded`：`degraded` 会触发 30s 自动重启，断掉用户正在用的连接，而重启修不好一个坏节点或断掉的上游（`runtime.md` §4.3）。
- 也不是 `failed`：控制面没坏，连接没断。
- 判定函数只认契约里那一个：

```ts
dataPlaneDown(snapshot) =
  (snapshot.state === "running" || snapshot.state === "degraded") &&
  snapshot.health.data_plane === false;
```

- **界面只在 `state === "running"` 时进入本状态。** `state === "degraded"` 继续显示「连接不稳定」——已有更严重的词和自动重启，两个词不叠加。

---

## 2. 结论（四条）

| 项 | 结论 |
|---|---|
| 状态词 | `已连接，不通` |
| 行动句 | `网页打不开时，点上面的「重新连接」；还是不行，就换下面的节点再试。` |
| 状态色 | 状态点用 `--amber`（琥珀），**不用 `--green`**；44px 词保持 `--ink`，不做填充 |
| 中间区卡片 | **不加** |

---

## 3. 状态词

**定为 `已连接，不通`**（5 个字，不含标点）。

- 44px / 1.1 / 600 / `-0.02em`，前面 8×8 `--amber` 状态点（`aria-hidden`）。
- 保留「已连接」三个字，先回答用户第一个问题「断没断」；「不通」是他自己能看到的结果，不是实现词。
- 禁用词核对：不含 `数据面 / 探测 / 节点失败`，也不含 `proxy / TUN / 分流 / 规则集`。
- 为什么不用「连接不稳定」：那是 `degraded` 的词，含义是「检查没过、可能自己恢复、后台会重启试试」。本状态是「连着，但流量出不去，也不会自动恢复」。两个词必须分开，否则用户和客服分不清，测试也分不清该看哪条。
- 为什么不能只给「已连接」+ 琥珀点：颜色不能单独承载信息（`ui-ux-pro-max` · Color Only），而且这正是本次要修的抱怨——绿色说「已经连上」，实际什么也打不开。

---

## 4. 版式与位置

**进入本状态后，hero 换成「未连接 / 失败」那套版式：44px 状态词，不显示 64px 计时器。**

- 计时器是「一切正常」的签名元素；边跑秒边不通，等于换一种方式继续说谎。计时器消失本身就是最强的信号变化。
- 版式只在连续两次探测失败（约 20s）后切换，不会因为一次抖动跳来跳去。

```
● 已连接，不通                              [重新连接]

网页打不开时，点上面的「重新连接」；
还是不行，就换下面的节点再试。

流量 0 B/s        延迟 32 ms        出口 1.2.3.4
```

- 行动句在状态词下方 12px，**15px / 1.55 / `--ink-2`**，最大宽度 46ch。不复用 13px `--ink-3` 的 `hero__caption`——那是「本次连接」这类说明文字，压不住一句行动。
- **主按钮在同一个位置换成「重新连接」**（`btn--primary`），点击 = 先停再连。顶部仍然只有一个按钮（`veyl-ui` §2.1）。
  - 契约 §4.3 要求本状态能直达两个动作：**重新连接**、**更换节点**。前者放 hero，后者已由底部节点卡承担（「换下面的节点」指的就是它），不另加入口。
  - **不采用「断开 VPN」**：状态本身是「还连着」，按钮叫断开自相矛盾，也多一次点击。产品已定稿（2026-11-12），实现按本版，不要照着旧降级文案写成「断开」。
- 读数行保留（流量 / 延迟 / 出口）。流量会自然归零，正好印证状态词，不隐藏、不改口径。

---

## 5. 状态色

- **状态点用 `--amber`，不用 `--green`。** 绿色代表「正在正常接管流量」，这里是「接管了但出不去」，继续用绿点就是用户看到的那句「明明显示已连接」。
- 不用 `--red`：红色留给出错断开（`failed`）。这里进程在、连接在、可能自己恢复，红色会把用户推向「已经断了」的判断。
- **44px 词保持 `--ink`，不染琥珀。** 本屏「连接失败」也是墨色词 + 红色点；若把「已连接，不通」染成琥珀文字，它会比「连接失败」更响，严重程度倒挂。词的文字已经写清事实，颜色由点承担。
- 对比度：琥珀点对纸面 `#FAF8F2` 约 4.9:1，深色 `#1C1F23` 上约 7.3:1，均达到 4.5:1（`ui-ux-pro-max` · Color Contrast）。
- 状态色只做点/文字/描边，不做按钮或大面积填充（`veyl-ui` §3.1）。

---

## 6. 为什么中间区不加卡片

1. **状态词已经说了问题。** 用户此刻的疑问不是「发生了什么」，而是「我点哪里」；卡片只会把同一句再写一遍。
2. **两个动作各有住处。** 重连在 hero 主按钮，换节点在底部节点卡。再放一张卡就是第三个入口做同一件事，也违反 `docs/middle-area-local-rules.md` §4.3.4「卡里不放按钮」。
3. **原因不可执行。** 探测失败分不清「节点坏了」「本地上游断了」「探测目标临时不可达」（`runtime.md` §2.3.1 的误报面）。写进卡片要么是术语，要么是「网络检查没有通过」这类空话。
4. 只有将来有「自动诊断」或「一键换到最优节点」时，卡片才成立；那属于 `issue_card` 的演进，不属于本状态。

---

## 7. 生命周期与边界

- **进入**：连续两次探测失败（约 20s，契约 §2.3.1 已定），且 `health.checked_at` 在 30s 内。
- **退出**：`data_plane` 回到 `true` → 立即回普通「已连接」+ 计时器；`state` 变 `degraded` → 「连接不稳定」；断开 / 失败 → 对应状态。
- **新鲜度**：超过 30s 没有新的健康快照即视为未知，退出本状态回到普通「已连接」版式，不停留一个过期结论；不另加常驻的「几秒前检查」文字。
- **不自动切换节点、不自动重连**（契约 §4.3）：界面只指路，动作由用户触发。
- **读屏**：状态变化时播报一次「已连接，不通。网页打不开时，点上面的『重新连接』；还是不行，就换下面的节点再试。」探测事件每 10s 重发但文本不变，不重复播报（`ui-ux-pro-max` · Contextual Live Badge Updates）。

## 8. 实现要点（下一轮）

- 判定集中一处：`dataPlaneDown(runtime)`，组件里不各写 `!health.data_plane`（契约 §4.3 明确要求）。
- `Console.tsx` 的 hero 增加第三分支（`running && dataPlaneDown`）：44px 状态词 + 行动句 + 「重新连接」；`middleArea.ts` **不新增块**，本状态不产生中间内容。
- 状态点复用 `.led.is-warn`（已是 `--amber`），文案进 `srStatus`。
- 规范增补：`veyl-ui` §3.4 / §4.4 增加一条「已连接但没有流量」——44px 状态词、无计时器、琥珀点。

## 9. 验收

| 检查 | 期望 |
|---|---|
| 连续两次探测失败 | 20–30s 内状态词从「已连接」变为「已连接，不通」，计时器消失，琥珀点出现 |
| 恢复探测 | ≤10s 回到「已连接」+ 计时器，行动句消失 |
| 点「重新连接」 | 进入「正在连接」→ 成功后回「已连接」+ 计时器 |
| 同时进入 `degraded` | 只显示「连接不稳定」，不同时出现两个状态词 |
| 读屏 | 每种状态切换只播报一次，不随 10s 一次的健康事件重复 |
| 键盘 / 对比度 | 主按钮可 Tab 到、焦点可见；琥珀点 ≥4.5:1 |

## 10. 依据

- **`veyl-ui`**：§2.1 一屏一个主按钮；§2.2 连接状态只由 hero 说一次；§3.1 状态色只用于点 / 文字 / 描边；§3.4 44px 状态词用于非健康态；§6 错误三段式与禁用词。

- **`docs/contracts/runtime.md`**：§2.3.1 `data_plane` 判定与误报面；§4.3 判定函数、两个动作、不自动执行、30s 新鲜度、托盘不新增第四态。
