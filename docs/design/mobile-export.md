## 0. 结论先行

桌面端做两件事，**不做移动端 App**（2026-11-25 起已立项自研三端客户端，见 `client/docs/`；本节保留为当时的结论）：

1. 在 App 内给出 **iPhone / Android 的 sing-box 官方客户端下载入口**；
2. 给「已登录 + 拥有至少一台可用付费服务器」的用户生成一条 **远程配置（Remote Profile）URL**。用户在手机上的官方客户端里导入一次，之后由客户端**按自己的节奏定时拉取更新**，节点重建、换 IP、换密码都不需要重新扫码。

一句话：**我们不生产手机端软件，只生产它认的配置。**

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 |
|---|---|
| G1 | 用户不必在我们的界面里反复操作，手机装上官方客户端就能用上自己的付费节点 |
| G2 | 节点变化（重建、换 IP、换密码）后，手机端在客户端的一个更新周期内自动跟上 |
| G3 | 导出内容只包含用户自己的付费节点，免费 / 试用节点一个都不给 |
| G4 | 生成入口有明确门禁：未登录、没有可用付费服务器时不出现 |

### 1.2 非目标（本期明确不做）

| 不做 | 理由 |
|---|---|
| 自研 iOS / Android App | iOS 需 NetworkExtension 权限与中国区上架资质；官方客户端已经免费提供完整能力 |
| 免费 / 试用节点导出 | 产品决策：手机端只服务付费用户；且免费种子本就是公开 JSON，我们只承诺「不提供入口」，不承诺技术拦截 |
| 第三方客户端格式适配（Shadowrocket / Clash / v2rayN 等） | M1 只认 sing-box 官方客户端；多格式等于多套解析与验收面 |
| 推送式更新、服务端主动连设备 | 客户端已有定时拉取机制，我们只保证 URL 可用 |
| 设备数量限制、设备管理 | 设计非目标（`my-servers.md` §16）；转发风险记录在案，M1 不做技术对抗 |
| 转售 / 多人共用 | 同上，非目标 |

## 2. 外部事实与下载入口（已核对）

### 2.1 官方客户端

| 平台 | 客户端 | 系统要求 | 下载渠道 |
|---|---|---|---|
| iOS / macOS / tvOS | **SFI / SFM / SFT**（sing-box for Apple platforms） | iOS 15.0+ / macOS 13.0+ / tvOS 17.0+ | App Store；TestFlight beta **仅对赞助者开放**；iOS 另有越狱版（GitHub Releases） |
| Android | **SFA**（sing-box for Android） | 官方页面写 Android 5.0+；**1.13 起已停止支持 5.0**（以安装包实际要求为准，待验证） | Google Play / Play Store Beta / F-Droid / GitHub Releases |

**iOS 的关键限制（官方原文）**：`An Apple account outside of mainland China`——必须有大陆以外的 Apple 账号才能下载。这不是我们能绕开的，也没有替代方案能让普通大陆 Apple 账号装上。

### 2.2 放进 App 的链接

| 用途 | 链接 | 核实状态 |
|---|---|---|
| iPhone 下载（App Store） | `https://apps.apple.com/app/sing-box-mt/id6785326793` | 2026-11-19 本机直连返回 200 |
| Android 下载（Google Play） | `https://play.google.com/store/apps/details?id=io.nekohasekai.sfa` | 官方文档给出；**本机网络不可达（超时），未验证** |
| Android 备用（F-Droid） | `https://f-droid.org/packages/io.nekohasekai.sfa/` | 同上，未验证 |
| Android 备用（GitHub Releases） | `https://github.com/SagerNet/sing-box-for-android/releases` | 同上，未验证 |
| 兜底页（全平台渠道） | `https://sing-box.sagernet.org/clients/` | 本机直连返回 200 |

- 链接**一律指向官方商店 / 官方发布页**，不自行托管安装包、不做镜像（供应链与责任边界）。
- 大陆网络对 Google Play / F-Droid / GitHub 的可达性未知，且本机验证失败。**「点开可能打不开」是已知风险**，需要产品确认口径（见 §10 第 4 条）。

### 2.3 官方客户端的远程配置机制（我们方案的地基）

官方文档 `clients/general/` 对图形客户端的统一要求：

- **Remote Profile = 以 URL 为更新源的 sing-box 配置**；
- 客户端**必须**实现自动更新（**默认间隔 60 分钟**）与 **HTTP Basic 认证**；
- 客户端**必须**支持通过 URL Scheme 导入：

```
sing-box://import-remote-profile?url=<urlEncodedURL>#<urlEncodedName>
```

含义：**我们只要提供一个 HTTPS URL，返回 sing-box JSON，就等于提供了订阅能力**。桌面端本来就在生成 sing-box 配置（`src-tauri/src/config/`），不需要引入第二种格式。

补充：1.13 起客户端支持用 QRS 二维码互传配置（客户端 ↔ 客户端）。**我们的桌面端不在这个格式里，不作为主路径**。

### 2.4 域名：只用自有域名，且随构建环境切换

| 构建 | 控制面 origin | 生成的远程配置 URL origin |
|---|---|---|
| debug（`tauri dev` / `tauri build --debug`） | `https://dev.veyl.dessage.xyz` | 同左 |
| release / 安装包 | `https://veyl.dessage.xyz` | 同左 |

- **一律使用自有域名，不使用 `*.workers.dev`**。Cloudflare 默认域名会暴露供应商与 Worker 名，且大陆实测 TLS 中断（`environments.md` §1）。
- **不为导出功能另写域名常量**：URL 的 origin 必须取自控制面环境解析结果（`src-tauri/src/control_plane/env.rs` 的 `DEV_URL` / `PROD_URL`）。写第二处常量，就会在两个构建里指向不同环境。
- 环境是构建属性：release 包忽略 `VEYL_CONTROL_PLANE_ENV` / `VEYL_CONTROL_PLANE_URL`（`environments.md` §2.3）。因此 **release 生成的二维码永远是 `veyl.dessage.xyz`，debug 包生成的是 `dev.veyl.dessage.xyz`**，这条不需要用户理解，也不出现在界面文案里。
- 二维码 / 链接内容里**不出现** `workers.dev`、账户邮箱、设备号；只出现自有域名 + 路径 + 令牌。
- 2026-11-19 实测：两个域名均返回 200。

## 3. 用户与门禁

| 对象 | 规则 |
|---|---|
| 下载链接 | **所有用户可见**。它只是官方商店入口，不涉及账号、不涉及节点 |
| 生成远程配置 | 必须满足：**已邮箱登录** 且 **至少一台 `ready` 的付费服务器** |
| 免费节点 / 试用节点 | **永不进入导出内容**，配置生成时一次性排除 |
| 已销毁 / 到期服务器 | 其节点不进入导出内容；已有配置里的对应节点在下次拉取时消失 |
| 未满足条件时 | 不显示二维码 / 链接，只显示说明句与「去我的服务器」入口 |

门禁放在**桌面端 Host**（生成前判断），不放在手机端：手机端是别人的客户端，我们没有地方做判断。

## 4. 导出内容

### 4.1 形态

- 交付物是一条 **HTTPS URL**，`GET` 返回 **sing-box 配置 JSON**（Remote Profile 的更新源）。
- 用户侧可见的形式：**二维码**（内容为 `sing-box://import-remote-profile?url=…`）+ **复制链接**。
- 节点地址、端口、密码**出现在配置内容里**，但**不在界面文本中展示**——沿用 `my-servers.md` §17「界面不显示 IP / 端口 / 协议」的口径。

### 4.2 包含什么

| 包含 | 不包含 |
|---|---|
| 该账户当前可用的**自建付费服务器**节点（`source = owned`） | 免费种子节点、试用节点 |
| 节点选择与故障切换所需的最小组件（selector / urltest，具体形态由架构设计定） | 已销毁、到期、安装失败的服务器节点 |
| 移动端需要的**最小 TUN 入站**、路由与 DNS 基础配置 | 桌面端 TUN 的具体接入参数、系统代理设置、本地端口、Clash API 等**由客户端自己管理**的部分 |

> **2026-11-19 真机修正**：iOS / Android 官方客户端**不会**自动注入 TUN——它们只在配置声明了 TUN 入站时才创建系统隧道（已核对 sing-box-for-apple 与 sing-box-for-android 源码）。因此导出的配置**必须包含一个最小 TUN 入站**：`address`、`mtu`、`dns_mode: "hijack"`、`dns_address`、`auto_route: true`，其余桌面专有项仍不导出。没有它，VPN 会显示已连接但流量为 0。

### 4.3 一个还是多个

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 账户级一条配置（含全部可用付费节点） | 一次导入，之后节点增减自动同步 | **采用** |
| B. 每台服务器一条配置（二维码只含这一台） | 只把某一台给手机用 | **不做** |

**2026-11-19 产品负责人确认：既然已有账户级配置，就不做单台二维码。** 账户级配置本身包含全部可用付费节点，手机客户端里用 selector / urltest 选节点即可，比「先回桌面生成单台二维码、再扫一次」少一步且更好用。只有将来出现「账户里有节点、但只想把其中一台给某台手机」的真实需求时，再单独设计；在那之前不预留入口、不留半成品。

## 5. 定时更新

| 项 | 口径 |
|---|---|
| 谁在更新 | **客户端**按自己的周期拉取；官方默认 60 分钟。我们**不推送、不主动连接设备** |
| 我们保证 | URL 长期稳定；内容按请求生成或短时缓存，节点变化在客户端下一个周期可被拉到 |
| URL 域名 | 取自控制面环境解析结果：debug → `dev.veyl.dessage.xyz`，release → `veyl.dessage.xyz`；**任何情况下不出现 `workers.dev`**（§2.4） |
| 令牌 | 随 URL 下发；具体放在 query 还是 HTTP Basic credentials 由架构设计定（客户端原生支持 Basic 认证） |
| 吊销 | 桌面端提供「重新生成」，旧 URL 立即失效；M1 不做设备数与频率限制 |
| 没有可用节点时 | 不允许继续返回旧节点。返回空配置或错误状态由架构设计定，但**必须让客户端感知到失效**（见 §11） |
| 到期 / 销毁 | 服务器销毁或扣费失败销毁后，该节点从配置中移除；账户若已无付费服务器，整条配置进入「无可用节点」状态 |

**「定时」的边界**：我们不对「几分钟内一定更新」做承诺；对外只说「客户端会自动更新（默认约 60 分钟一次）」。

## 6. 界面需求（版式已由 `mobile-export-ui.md` v2 定稿）

**2026-11-19 PM 定稿：主入口只有一个——设置 › 账户 › `在手机上使用` 一行 + 480 弹层。** 弹层是**两个编号步骤**：`1 安装客户端`（iPhone / Android 两行 + 下载码）→ `2 导入节点`（导入码 + 复制 / 重新生成），底部 `不会操作？问 AI`。完整版式、尺寸、token、状态与文案见 [`mobile-export-ui.md`](mobile-export-ui.md)。

| 位置 | 结论 |
|---|---|
| 设置 › 账户 | **常驻住处**，余额下方独立一行，右侧 ghost `查看` |
| 「我的服务器」左栏底部 | **快捷入口（2026-11-19 产品负责人确认）**：紧挨 `新建节点` 下方一行 `在手机上使用`，只在「已登录 + 至少一台节点已就绪」时出现；点开同一个弹层 |
| 服务器详情页 / 中间区域 | **不做**（单台二维码方案不采用，见 §4.3） |

- **两步结构**：步骤 1 `安装客户端` 恒显示，与账号无关；步骤 2 `导入节点` 保留五态（未登录 / 无可用服务器 / 就绪 / 读取中 / 失败）。两个二维码不并列：靠步骤号、步骤标题、各 4 字图注（`扫码下载` / `扫码导入`）与左右位置区分。
- 下载链接：iPhone / Android **都指向官方客户端页**（渠道在页面里自选），不直接链 App Store——2026-11-19 实测：大陆 IP 访问任何地区路径都会 302 到 `apps.apple.com/cn/iphone/today`，`/cn/app/...` 为 404。
- **下载区提供官方下载页二维码**（2026-11-19 产品负责人要求）：104×104，`aria-hidden`，与导入码分开标注。
- 导入二维码：160×160、永远白底；内容为 `sing-box://import-remote-profile?…`；alt 不含 URL 与令牌。
- **删字**：v1 的首句「Veyl 不提供手机客户端…」、Android 渠道图注、导入码内标题全部删除；这些解释交给 AI 帮助。
- **AI 帮助**：底部 `不会操作？问 AI`，点击关闭弹层（若从设置打开则一起关闭），右栏发送**逐字固定**提示词 `mobileExportPrompt`（见 `mobile-export-ui.md` §5.2）；不新增命令。
- 未登录 / 无可用付费服务器：步骤 2 保留二维码空位，给登录或「去我的服务器」入口，不显示复制与重新生成。
- 术语沿用现有词汇：`服务器`、`节点`；用户可见文案不出现 `订阅`。**文案以 `mobile-export-ui.md` §6 为准。**

## 7. 验收条目（产品级）

| 编号 | 场景 | 期望 |
|---|---|---|
| ME-1 | 未登录打开设置 | 不出现二维码 / 链接生成入口，只有登录说明 |
| ME-2 | 已登录、无 `ready` 付费服务器 | 不出现生成入口，显示「先创建服务器」说明 |
| ME-3 | 已登录、有 1 台可用服务器 | 出现二维码与复制链接；iOS 官方客户端扫码导入成功；连接可用 |
| ME-4 | 服务器重建（新 IP / 新密码） | 客户端下次更新（默认 60 分钟）后使用新节点，无需重新扫码 |
| ME-5 | 账户同时有免费 / 试用节点 | 导出内容中**不出现**任何免费 / 试用节点 |
| ME-6 | 点「重新生成」 | 旧二维码 / 旧链接在客户端下一次拉取时失败；新链接可正常导入 |
| ME-7 | 服务器销毁 / 到期 | 该节点从配置移除；全部销毁后客户端触发「无可用节点」表现 |
| ME-8 | 桌面端点击两个下载链接 | 外链在系统浏览器打开；不接受应用内嵌网页 |
| ME-9 | 导出链接的域名 | 与该构建的控制面环境一致：release 包生成 `veyl.dessage.xyz`，debug 包生成 `dev.veyl.dessage.xyz`；任何情况下不出现 `workers.dev` |

验收由产品负责人 / 同事在真机执行；AI 只负责取证与核对。

## 12. 后续需求：局域网安装包分发（未实现，待排期）

> 2026-11-20 产品负责人提出，**只登记，不实现**。与第 1–11 节分开：下面 1–11 节都是已落地或已验收的内容。

### 12.1 要解决的问题

手机在装好客户端之前**没有可用网络**（节点还没导入），所以「从 Google Play / GitHub 下载安装包」这条路对大陆用户是死循环：下载要网络，网络要客户端，客户端要下载。

### 12.2 方案

桌面端替手机取包，再在局域网内交给手机：

1. 桌面端从**官方源**（sing-box 官方页 / CMFA GitHub Releases）下载安装包到本地；
2. 桌面端在本机启动一个**仅监听局域网**的临时 HTTP 服务；
3. 手机上扫码（或输入地址）从桌面下载安装包。

关键点：桌面端此时**可能已经连着 VPN**，能取到手机取不到的文件；整条链不需要手机事先具备任何网络能力。

### 12.3 边界（必须先定，否则不做）

| 项 | 要求 |
|---|---|
| 适用范围 | **仅 Android**。iOS 的 ipa 无法通过局域网侧载，必须走 App Store，本方案不解决 |
| 不是分发 | 我们**不对外托管镜像、不做 CDN**。桌面只是把用户自己电脑上、来自官方源的文件，转发给同一局域网内他自己的手机 |
| 访问控制 | 一次性令牌；只服务白名单内的文件；**不得实现成通用文件服务器**。笔记本接入公共 Wi-Fi 时不能成为对外开放的洞 |
| 完整性 | 下载后校验 sha256，并把校验和一并交给手机侧展示；校验失败必须拒绝提供 |
| 生命周期 | 服务随弹层打开、关闭即停；不常驻、不开机自启 |

### 12.4 待设计问题（实现前必须逐条回答）

1. 端口怎么给手机：二维码里带 `http://<局域网IP>:<端口>/<一次性令牌>`，多网卡 / IPv6 / 无局域网时怎么退化？
2. 文件缓存：是否长期保留安装包、存在哪个目录、删除策略、版本更新后旧包怎么处理。
3. 下载中断：是否支持 Range 续传（Android 安装器对断点续传的兼容性需验证）。
4. **桌面也取不到时**：桌面未连 VPN 且官方源不可达，是提示「先连 VPN 再试」、还是走本地代理端口重试？
5. 防火墙：macOS / Windows 首次监听会弹授权，用户拒绝时的文案与退路。
6. 是否需要展示文件大小与版本，让用户确认拿到的是哪个版本。

### 12.5 已定的不做项

| 不做 | 理由 |
|---|---|
| 我们托管 APK / 做镜像 / 上 CDN | 变成对外分发二进制，供应链与责任边界完全不同（产品负责人 2026-11-20） |
| iOS 侧载 | 需要签名体系，且与应用商店条款冲突 |
| 界面提示「可能需要网络工具」 | 见 §10 第 4 条：保持中性 |
