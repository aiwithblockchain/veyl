# 中英文切换（任务）

> 日期：2026-11-21
> 状态：**已定稿，进入实现**。2026-11-21 拍板 Q1 / Q3 / Q4，Q2 定稿于 §3.1（设置 › 高级第一行，三档分段控件）。
> 来源：产品负责人口述。相关：`docs/design/ai-docs-management.md` §7、`docs/notes/pending-topics.md` #2。

---

## 1. 目标

系统设置里增加语言选项（中文 / English）。切换后：

1. **界面文案**按所选语言展示；
2. **AI 对话**的回复按所选语言；
3. **AI 的思考过程**也按所选语言展示。

## 2. 范围

**做**

- 前端所有用户可见文案：引导页、主控制台、左栏、我的服务器、设置、账户菜单、弹层、按钮、空态、错误与提示、确认文案。
- AI 的系统提示词与用户提示词：按语言选择 `resources/prompts/zh/` 或 `resources/prompts/en/`（两套目录与文件已建立）。
- AI 回复与思考过程的语言约束：在系统提示词里明确「始终使用 {语言} 回答，思考过程也用该语言」。

**不做（本期）**

- 官网、文档站、GitHub 仓库的英文版。
- 邮件正文的双语（验证码邮件本期不做）。
- 第三语言；只支持中文、English 两档。

## 3. 交互

| 项 | 方案 |
|---|---|
| 入口 | 设置 › **高级**，第一行。分段控件三档：`跟随系统` / `中文` / `English`（§3.1） |
| 默认值 | `跟随系统`：启动时取系统语言（`zh*` → 中文，其它 → English）；用户选过之后以所选值为准，选回 `跟随系统` 即恢复跟随（Q3 拍板） |
| 生效时机 | 界面：切换成功后立即重绘，不需要重启或重新登录。AI 会话：只对新会话生效，老会话保持原语言（Q1 拍板）。**「跟随系统」时，系统显示语言在应用启动时读取一次**；改了系统语言要重启 Veyl 才生效 |
| 持久化 | SQLite `settings` 表，key `app_language`，值 `system` / `zh` / `en`；缺省或非法值一律按 `system` 处理。前端在打开设置时读取；Rust 在新建 AI 会话时读取同一值 |
| 反馈 | 不用 toast、不重启、不重连：控件选中态就是反馈。写库失败时界面不变，行下显示错误（§3.1） |
| 切换影响 | 不重连、不登出、不清配置 |

### 3.1 语言行（Q2 结论）

- **位置**：`高级` 第一行，在「修复网络」之前。现有段首说明「这里的东西平时不用改…」下移到 `修复网络` 小标题下，只约束修复类内容；语言是常规偏好，不受这句话约束。
- **为什么不是 `关于`**：产品没有独立的「关于」屏，`版本` 就在 `高级` 底部；放底部是全设置最深的角落，而需要一个语言开关的人往往正是看不懂界面语言的人。第一行在打开设置后一步可达，且不新增第五个 tab。
- **为什么三档而不是两档**：只存 `zh` / `en` 时，「跟随系统」只是一次性猜测——用户改过之后再没法回到跟随，系统语言后来变了应用也不会跟，界面上还没有入口解释这件事。三档让默认状态可见、可回退。
- **样式**：复用 `settings-row settings-row--stack` + `.settings-seg`（高 32、13/500、按钮不换行），只给语言档位加一条 `min-width: 72px`，不新增其它样式；三档横排，按钮宽度随文案。
- **文案**：

  | 位置 | 中文 | English |
  |---|---|---|
  | 行标签 | 语言 | Language |
  | 档位 | 跟随系统 · 中文 · English | Follow system · 中文 · English |
  | 行下说明 | 已开始的对话保持原语言。 | Conversations already started keep their current language. |
  | 分组 `aria-label` | 语言 | Language |
  | 写库失败 | 语言没有切换。本地设置写入失败。再试一次。 | Language wasn't changed. The local settings write failed. Try again. |

- **语言名不翻译**：`中文` 与 `English` 在两种界面里都按本语言书写，只有 `跟随系统` 随界面语言翻译。不要把 `中文` 译成 `Chinese`。
- **取值链路**：新增一对命令 `app_language_get` / `app_language_set`。`get` 返回 `{ selected, resolved }`，`selected` 是存库值，`resolved` 是 `zh` / `en`；系统语言的解析只在 Rust 一处做（`zh*` → `zh`，其它 → `en`，与提示词侧同一规则），前端不自己读 OS locale。`set` 先写库，成功后才返回新值，前端拿返回的 `resolved` 立即重绘；失败返回错误码、不带中文句（与 Q4 一致），界面保持原语言并在行下显示映射文案。
- **不做**：不加切换 toast；不在行下显示「当前 English」这类第二处状态（选中档位已经说了）；不在首启页加语言入口（默认跟随系统已覆盖）。
- **已开始的对话**：切换时正在流式输出的回复不中断，按原语言继续；界面文案立即换。

## 4. 实现要点

### 4.1 前端

- 现在文案直接写在组件里（中文）。建议自建轻量字典 `src/i18n/`：`zh.ts` / `en.ts` + `t(key)`，不引入外部 i18n 依赖（离线约束、体积可控）。
- 需要先把现有中文文案抽成 key——量最大的一步，建议按屏幕分批：引导页 → 主控制台 → 我的服务器 → 设置 → 账户菜单 → 错误与提示。
- 日期、金额、数字：金额固定 USD（`$8.30`），不做 locale 化；时间显示统一用 `YYYY-MM-DD HH:mm` 或相对时间（现有写法即可）。
- 缺失 key 的回退：**不显示 key 本身**，回退中文并在日志里记一行 `i18n missing key=… lang=en`，便于补齐。

### 4.2 后端与提示词

- 提示词文件按语言二选一，参考 TweetPilot 的 `prompt_lang_dir()`：语言前缀归一（`en-GB`、`en-AU` 都算 `en`），只认 zh / en 两档。
- 语言值从设置读取，在新建 AI 会话时决定用哪套系统提示词；系统提示词末尾追加一行语言约束。
- **错误文案**（Q4 拍板）：后端只返回稳定的错误码，不返回中文句；「登录后才能创建服务器」这类现有文句逐条换成错误码，前端建 `code → zh/en` 映射表。改动面比后端按语言返回大，但文案集中、可测试。

### 4.3 AI 思考过程

- 思考过程的语言由模型决定，我们能做的是在系统提示词里明确要求。若模型仍用英文思考，界面如实展示，不做二次翻译（不额外调用模型）。

## 5. 验收

1. 在设置里切到 English：所有界面文案变英文，无需重启；重启后仍是 English。
2. 新建 AI 会话：回复是英文，思考过程也是英文；后端加载的是 `resources/prompts/en/` 的提示词。
3. 切回中文：同上，行为对称。
4. 切换语言不影响：登录状态、正在进行的连接、已创建的服务器、节点池。
5. 不存在「中英混杂」的界面（专有名词如 Veyl、DeepSeek、sing-box 除外）。
6. 缺失翻译时界面回退中文且不裂开，日志有 `i18n missing key` 记录。
7. 首启是 `跟随系统`；系统语言不是 zh/en 时界面用 English；选 `跟随系统` 后改系统语言并重启，界面跟着变。
8. 切换前后已开始的对话语言不变；新开对话用新语言。

## 6. 四件事的决定

| # | 问题 | 决定 |
|---|---|---|
| Q1 | 切换语言后，**已经存在的 AI 会话**跟着换，还是新会话才生效？ | **老会话不管**：只有新会话生效；老会话保持原语言，不切换、不标注、不提示 |
| Q2 | 语言开关放哪里、怎么呈现？ | **设置 › 高级第一行**，三档分段控件 `跟随系统` / `中文` / `English`，默认跟随系统；详情见 §3.1 |
| Q3 | 首次启动默认跟随系统，还是固定中文？ | **跟随系统**；系统语言不是 zh/en 时用 English；用户改过之后以用户选择为准 |
| Q4 | 后端错误文案走「错误码 + 前端映射」还是「后端按语言返回」？ | **错误码 + 前端映射** |

批次 1 的边界（2026-11-21）：

- **已双语**：`system.md` / `kickoff.md` 正文；代码里的环境段（`# 环境` / `# Environment`，地区名走 `Region::label` / `label_en`）；安全底线（`SAFETY_RULES_ZH` / `SAFETY_RULES_EN`）；末尾语言约束。英文会话的系统提示词不再混中文。
- **仍中文，留批次 2–3**：
  - 工具描述与能力清单（`capability_catalog` 渲染的是各工具的 `description()`）——随界面文案一起翻；
  - 提示词里引用的界面固定按钮字串：中文 `解释这个设置的含义` / `开始` / `取消`，英文 `Explain what this setting means` / `Start` / `Cancel`。**前端翻译界面时必须同步这两组字串**，否则 AI 认不出用户点的是哪一个。
- **批次 2 必须补**：前端启动时读取 `app_language` 的 `resolved` 并据此选字典；批次 1 只在打开设置时读取，界面尚未翻译，所以暂无消费方。
- **批次 2–3 复查**：`claurst_session/mod.rs` 的「英文系统提示词无 CJK」断言目前用空 tool catalog；工具描述与能力清单翻译后要改用真实 catalog，否则是假通过。
- 批次 1 期间界面仍是中文：选 English 后 AI 用英文，但用户点的按钮回传的仍是中文字串；这属于批次 2–3 的过渡状态，不单独做兼容。

每批都要有对应的界面走查清单；构建与真机验收由用户执行。
