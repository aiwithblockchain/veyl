# 连接页：测不通时的两个动作（问 AI / 智能修复）

> 日期：2026-11-22
> 状态：**方案待评审**，与 Lena 对齐版面后由 PM 决策。只出规格与文案，不改代码、不改契约、不 commit。
> 依据：`connection-stage-probe.md`（节点卡动作的既有规格）、`veyl-ui` §2.1（一屏一个主按钮）/ §2.2（一个事实一个住处）、`MyServerDetail.tsx` 的智能修复实现与七类失败原因、`ConnectionStage.tsx` 的 `console.node.askAi`。
> 一句话：**两个动作都留在节点行内、都用文字链，`智能修复` 在前且字重更高；hero 的启动/重连仍是唯一实心主按钮；危险动作由确认弹窗承担分量，不靠版面放大。**

---

## 0. 结论

| 项 | 结论 |
|---|---|
| 位置 | 都放在坏行的右侧，状态词 `测不通` 之后：`测不通　智能修复 · 问 AI` |
| 层级 | 两个都是文字链（13px）；`智能修复` 600 字重 + `--link`，`问 AI` 500 字重 + `--link`；**不加实心按钮、不加图标** |
| 顺序 | `智能修复` 在前，`问 AI` 在后。修复是「把事办成」的短路，AI 是解释与诊断；用户已经看到失败，先给动作 |
| 主按钮冲突 | hero 的 `启动 VPN / 重连` 仍是唯一 `.btn--primary`；这里两个是次级文字链，不抢焦点、不改变底部主按钮 |
| 确认 | 点 `智能修复` 必须弹确认（复用详情页文案），默认焦点在「取消」；确认框里的「确认修复」是弹窗内的主按钮，不影响页面主按钮口径 |
| 进行中 | 两个动作都禁用，行右侧只留 `正在修复…`；修复期间节点行不可切换 |
| 成功 | 行内短暂显示 `已修复`；卡片底部一行 `已修复，端口 {port}，正在重新测速…`，随后自动重测，结果回到行内 |
| 失败 | 行恢复两个动作；卡片底部一行按七类 reason 分组的文案，`auth` / `agentFailed` 两类附 `去我的服务器` 导航链接 |
| 与 AI | 空闲时两个都可点；修复进行中 `问 AI` 禁用；AI 正在回答不阻塞修复。修复成功后，若 AI 面板已打开且本轮在聊这台节点，追加一条**不含凭据**的系统提示 |

## 1. 位置与版面

```
┌ 节点卡 ─────────────────────────────────────────────┐
│ 你的服务器                                           │
│ ─────────────────────────────────────────────────── │
│ 东京 01                        测不通  智能修复 · 问 AI │
│ 新加坡 01                          42 ms              │
└─────────────────────────────────────────────────────┘
                [        启动 VPN        ]
```

- 右侧顺序固定：**状态词 → 智能修复 → 分隔符 → 问 AI**。状态词不是动作，保持现有的 `--ink-3` / 12px，不加粗。
- 两个动作是同一行内的两个 `<button>`，`flex: 0 0 auto`；节点名先截断（`text-overflow: ellipsis`），动作永远完整显示。
- 命中区 ≥44：两个链接都用伪元素扩点击区（与 `测速` 相同：`inset: -14px -8px`）；两个链接之间的间距 ≥12px，避免误触。
- 分隔符 `·` 用 `--ink-3`，不可点、`aria-hidden`。
- 窄容器（卡片内容宽 < 320）：允许动作整体换到行内第二行（行高 +20），只发生在「坏 + 自有」的行；不隐藏任何一个动作，不改文案。

### 1.1 为什么不把「智能修复」单独放一行

- **动作属于节点，不属于卡片**。多台自有节点同时测不通时，单独一行会变成多条重复区块，用户要来回对应是哪台；行内动作天然绑定节点。
- **危险动作不该靠版面放大**。换端口会短暂断线、当前连接可能中断；把它做成整行按钮或更大字，会增加误触，也会和 hero 的主按钮争夺视觉层级。分量应放在确认弹窗，而不是入口尺寸。
- **失败行本来就是「一行事实 + 一个出口」**。现有 `测不通问 AI` 已经把出口放在行内，新增第二个出口继续放在同一位置，用户的扫视路径不变（名称 → 状态 → 动作）。
- **不新增区块就不新增状态**。单独一行需要额外的空态、隐藏规则、多节点排序；行内方案不需要。

### 1.2 字号与颜色

| 元素 | 规格 |
|---|---|
| `测不通` | 12 / `--ink-3`，与现有 `is-muted` 一致 |
| `智能修复` | 13 / 600 / `--link`；hover 与 focus-visible 加下划线 |
| `·` | 13 / `--ink-3` |
| `问 AI` | 13 / 500 / `--link`；hover 与 focus-visible 加下划线 |
| 禁用态 | 两者 `--ink-3`、`cursor: default`，`aria-disabled="true"`，不改变行高 |

不用 `--warn-text` 给动作：这一屏的 `--warn-text` 只属于失败事实与提示句，动作色统一走 `--link`。

## 2. 与「一个屏幕一个主按钮」的冲突

- 页面主按钮仍是 `.stage-primary`（启动 / 重连 / 断开 / 诊断），固定在 Hero 顶部、不随节点列表滚动。行内两个动作**不改变它的文案、位置、实心样式与禁用条件**。
- 两个动作都不是 `.btn--primary`：没有底色、没有边框、没有阴影；焦点环用统一的 `--focus`，不额外放大。
- 确认弹窗里的 `确认修复` 是**弹窗自己的主按钮**，与页面主按钮不在一层；弹窗关闭后焦点回到行内的 `智能修复`（不是页面主按钮）。
- 键盘顺序：节点行 → `智能修复` → `问 AI` → 下一行。行本身仍是可选中项，`Enter/Space` 在行上仍是切换节点；内部按钮自己处理按键，不冒泡（现有实现已如此）。

## 3. 状态与反馈

| 状态 | 行右侧 | 可点 | 其它 |
|---|---|---|---|
| 坏、自有、空闲 | `测不通　智能修复 · 问 AI` | 两个都可点；行可切换 | — |
| 确认中 | 同上 | 行与两个动作都不可点（弹窗持焦点） | 弹窗文案复用详情页：`智能修复会重启节点并更换端口；节点会短暂断线，当前连接可能中断。` |
| 修复中 | `测不通　正在修复…`（三点动画，`--ink-3`） | 都不可点；**节点行不可切换** | 其它行的 `智能修复` 也禁用（同一时间只跑一台） |
| 成功（3 秒内） | `已修复`（`--link`，不带端口） | 不可点 | 卡片底部一行：`已修复，端口 {port}，正在重新测速…`；同时自动对这台节点跑一次真实测速 |
| 成功（重测后） | 新延迟（如 `42 ms`） | 行可切换 | 底部那行在测速出结果后消失；若测速仍失败，回到「坏」并给新的失败状态，不谎报成功 |
| 失败 | 恢复 `测不通　智能修复 · 问 AI` | 两个都可点 | 卡片底部按 §4 给一行原因；不弹 toast、不自动开 AI |

- 端口只在底部那行出现一次，不写进行内、不进 AI 上下文；行内保持「名称 + 状态 + 动作」三列。
- 修复期间连接若仍在这台节点上，确认弹窗已经预告会断线；修复成功后不自动重连（沿用现有连接策略），只重测。
- 修复成功后的自动重测用**现有手动测速通道**（`useNodeProbes`），只更新该节点延迟，不移动「最快」标记（与 `connection-stage-probe.md` §4 一致：后台/自动测速只清标记，不移动）。

### 3.1 多台同时坏

- 一次只允许一台在修复（agent 侧本来也只允许一个 apply）。
- 正在修复时，**所有行**的 `智能修复` 都禁用，`问 AI` 也禁用；避免用户在等待期点另一台。
- 不做队列、不做「批量修复」：端口轮换会重启节点，批量失败时无法向用户解释是哪一台的哪一步。

## 4. 失败文案与去向（七类 reason）

| reason（后端） | 用户看到的（卡片底部一行） | 去向 |
|---|---|---|
| `agent_token_unavailable` | `控制面暂时不可达，智能修复暂不可用。稍后再试。` | 只留文字；保留行内 `智能修复`，稍后可重试 |
| `agent_tls_untrusted` / `agent_token_rejected` | `无法与这台服务器建立可信连接，智能修复暂不可用。` | 文字后附 `去我的服务器` 导航链接（不是危险按钮）；下一步是销毁重建 |
| `agent_timeout` / `agent_unreachable` | `服务器暂时连不上，智能修复没完成。稍后再试。` | 只留文字；保留行内 `智能修复` |
| `agent_tool_failed` / `agent_bad_response` | `服务器上的节点 agent 没完成修复。` | 文字后附 `去我的服务器`；还是不行就销毁重建 |
| （兜底） | `智能修复没完成。稍后再试。` | 只留文字 |

- **所有失败都落在卡片底部同一行**（复用 `.stage-card__probe-note`），不放在行内：行内只有 3 个位置，塞原因会把名称挤没。
- 底部行必须带节点名（多台时才知道是哪台）：`东京 01：服务器暂时连不上…`。同一时刻只显示最近一次的失败，新的失败替换旧的。
- `去我的服务器` 只做导航，不直接给销毁按钮：连接页不提供服务器操作入口（`connection-stage-probe.md` §2.1 的既有边界）。
- 失败原因只用于 UI 文案，不进 AI 上下文；`问 AI` 被点击时只传「这台节点测不通」，不传错误原文。

## 5. 与「问 AI」的先后关系

- 空闲时**不是互斥的**：两个动作都在，用户自己选。`问 AI` 是安全动作，`智能修复` 是危险动作（有确认）。
- **执行期互斥**：修复进行中禁用 `问 AI`，避免 AI 在节点正在换端口时给出过时的诊断。AI 正在回答则**不阻塞**修复：AI 面板在右栏，修复在左栏，二者没有共享写操作。
- **AI 发起的修复**：AI 通过 `NodeRotateCredentials` 工具走同一执行入口（`agent/commands.rs` 的 `node_rotate_credentials` → `rotate_from_ui`），确认卡就是它的确认步骤；从此开始，行内状态与手动修复完全一致（`正在修复…`、两个动作禁用）。
- **成功后的 AI 提示**：仅当 AI 面板已打开、且本轮对话最近一次涉及这台节点时，追加一条系统行：
  `已对「东京 01」执行智能修复，已重新测速：42 ms。`
  - 不含端口、不含密码、不含端点；端口只在卡片底部出现一次。
  - 面板没打开时**不自动打开**，也不写进历史里等下次；用户下次问起时 AI 从节点数据里读当前延迟。
- **失败后**：不自动把错误发给 AI。用户点 `问 AI` 时，AI 从「测不通」开始诊断即可；错误原因属于 UI 文案，不进入模型上下文（与令牌/凭据同一条边界）。

## 6. 边界与验收

- **入口条件**：只在 `node.source === "owned"` 且 `probeBad`（确实测不通）时出现；`untested`、免费节点、停机删除的墓碑都不出现（与现有 `console.node.askAi` 完全一致）。
- **未测过不算**：`未测` 行没有这两个动作，避免被当成「多点几次就通」。
- **已连接也能修复**：确认文案已说明会断线；修复成功后不自动恢复连接，用户自己决定何时重连。
- **虚拟列表/长列表**：动作是行内元素，不改变行高（窄容器换行是例外）；不做悬浮层、不做右键菜单。
- **可访问性**：两个动作都有 `aria-label`（`对东京 01 执行智能修复` / `就东京 01 测不通咨询 AI`）；`正在修复…` 用 `role="status"` 播报一次；底部失败行不自动播报（避免打断读屏），由用户移动到该行时读出。
- **验收**：坏的自有节点行出现两个动作；点修复弹确认、确认后行内变「正在修复…」、成功后自动重测并回到延迟；断网/控制面不可达时给对应文案且不改变连接；免费节点与 `未测` 行不出现动作。
