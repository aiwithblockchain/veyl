> 日期：2026-11-17
> 状态：设计定稿，待实现。只定文案与展示条件，不改代码。
> 依据：`docs/design/ai-first-product.md`（AI 自动执行、用户只需开口）、`veyl-ui` §6（禁词与固定用词）、`docs/contracts/tools.md` §4.13 `DiagRun`、§4.27 `NodeSwitch`、§4.28 `NodeProbe`、§4.37 `RouteSetMode`、§4.38 `ConfigSetMode`、§4.50 `OpenSettings`。

## 1. 硬约束

- 最多 5 条，一次全部展示；不做「换一批」。
- 只在**对话为空**且**本次会话没有用户发言**时出现；用户一开口立即消失。
- 不占舞台、不做浮层、不写 `localStorage`。
- 语气平实：不用「立即」「一键」「极速」「解锁」这类营销词，不用感叹号，不写「请」。
- 每条都必须能被现有工具回答：`DiagRun` / `NodeProbe` / `NodeSwitch` / `RouteSetMode` / `ConfigSetMode` / `NetConfigGet` / `OpenSettings`。答案里不出现产品没有的能力（不做测速历史、不做自动换节点、不承诺解锁某个网站）。
- 句末不加问号：它们是按钮文案，不是正文问句。

## 2. 五条原文与触发意图

| # | 原文 | 意图 | 允许用到的工具 |
|---|---|---|---|
| 1 | 连上了，但网页打不开 | 跑诊断，定位是数据面、DNS 还是节点 | `DiagRun`、`NodeProbe` |
| 2 | 怎么换成更快的节点 | 逐个测速、排序、换到最快的一个 | `NodeProbe`、`NodeSwitch` |
| 3 | 为什么有的软件没走 VPN | 解释两种接管方式，并指到设置 | `OpenSettings`、`ConfigSetMode` |
| 4 | 为什么个别网站还是打不开 | 查直连范围是否命中了这个网站 | `RouteGet`、`RouteSetMode` |
| 5 | 终端里的命令也想走 VPN | 按当前接管方式给终端设置代理的办法 | `NetConfigGet`、`OpenSettings`、`ConfigSetMode` |

### 2.1 「连上了，但网页打不开」

- 先 `DiagRun`，按检查项逐条说人话；只给**一个**可点的动作（重新连接 / 换节点 / 修 DNS）。
- 数据面没起来时，不要说「网络是好的」；也不要把责任推给用户。
- 不猜具体网站，不读日志（控制面不保留原始日志）。

### 2.2 「怎么换成更快的节点」

- 用 `NodeProbe` 逐个测，按延迟从低到高列出来，指出最快的一个。
- 换节点必须由用户点（`NodeSwitch`）；不自动换出口、不静默切换。
- 节点少于 2 个时直接说「现在只有一个节点，没法比较」，不要编造另一个。

### 2.3 「为什么有的软件没走 VPN」

- 解释两种接管方式时先点名再解释：`Tun 模式（接管全部软件）` / `Proxy 模式（只给填了地址的软件）`。名字与界面一致，解释用用户的话。
- 指出当前是哪一种，并给 `OpenSettings { section: "connection" }`。
- 切换接管方式会断开重连（`ConfigSetMode`），必须用户明确同意后才执行。
- 正文可以用 `Proxy 模式` / `Tun 模式`（`veyl-ui` §6：2026-11-17 起是常规用词，不是例外）；仍不出现 `分流`、`规则集`。

### 2.4 「为什么个别网站还是打不开」

- 用 `RouteGet` 看当前流量范围：**智能**（中国大陆的网站直连）还是**全局**（全部走节点）。
- 说明这个网站可能被直连了；建议切到全局试一次。流量范围可热切换（`RouteSetMode`），不需要重连。
- 不解释、不猜测网站为什么被限制，也不承诺「一定能打开」。

### 2.5 「终端里的命令也想走 VPN」

- 先说明：**全部软件**模式下终端本来就走 VPN，不需要额外设置。
- **只给要填地址的软件**模式下，用 `NetConfigGet` 读本机地址与端口，给出在终端里设置代理环境变量的办法（`http_proxy` / `https_proxy`），并说明只对当前这个终端窗口有效。
- 想一劳永逸就切到**全部软件**模式，但要先说明会断开重连，由用户决定。
- 不写具体命令以外的系统级改动，不改 shell 配置文件。

## 3. 展示、消失与点击

| 项 | 规则 |
|---|---|
| 出现条件 | 已配置 AI（`aiReady`）、当前会话 `messages.length === 0`、且没有任何 `role === "user"` 的消息 |
| 不出现 | 无 AI Key；AI 正在提问（有 `question` 卡）；会话里已有任何消息（含 AI 的自动开场） |
| 位置 | 右栏空态文案下方 16px；竖排，每条高 44（命中区 ≥44），13 / `--ink-2`，左对齐 |
| 点击 | 把该条原文作为用户消息发送，走现有 `onEmptySend` 同一条路径；发送后整块消失 |
| 消失 | 用户发出第一条消息即永久消失（本次会话内不再出现）；切换会话不影响其他会话自己的判断 |
| 新会话 | 新会话重新出现；不做「已读过」的记忆 |
| 无障碍 | 容器 `role="group"` + `aria-label="可以这样问"`；每条是普通按钮，**Tab 顺序与视觉一致：五条在输入框之前**（空态文案 → 五条 → 输入框 → 发送）；点击后焦点进入消息流 |
| 状态 | 不写 `localStorage`，不计数，不记录点过哪条 |

**与现有实现的关系**：现有 `SUGGESTIONS`（`src/components/AiPanel.tsx:63`）只在 `!hasEverConnected` 时显示两条；实现时用本文件的五条替换它，并把显示条件改为上表（不再依赖 `hasEverConnected`）。无 Key 的首启态仍沿用输入框自己的引导，不显示这套。
