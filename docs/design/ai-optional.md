# AI 可选与统一入口

> 2026-11-22 · 产品负责人拍板
> 结论：**AI 可跳过；没配 AI 时右栏不空转，输入区换成「配置 AI」。**
> 覆盖本文列出的旧口径；旧文档不删，就地标注作废点。

---

## 1. 为什么

AI 服务由用户自带 Key（BYOK）。强制配置 AI，等于强制每个用户先去注册服务商、拿 Key；只想用网络功能的人会被挡在首启页之外。

因此：**AI 是加速器，不是门票。** 不配 AI 也能完整使用连接、节点、服务器、导出；配了 AI 才多出对话与自动操作。

---

## 2. 首次启动：AI 可跳过

首启页保持一屏，三个动作：

| 顺序 | 动作 | 结果 |
|---|---|---|
| 1 | 填 Key + `保存并验证` | 校验通过 → 进主界面，右栏展开，AI 开场（现有行为） |
| 2 | `使用其他 AI 服务` | 同屏展开自定义表单（现有行为） |
| 3 | `我懂网络，不用 AI` | 不写任何 Key，写跳过标记 → 进主界面 |

- 跳过标记沿用已设计的键名 `veyl.onboarding.skipped`（localStorage）。
- 标记只决定**下次启动还要不要弹首启**，不影响其它任何逻辑。
- 跳过后的主界面：左栏、中间控制台、右栏按钮全部正常；右栏默认关闭。
- 右栏入口**永远可见可点**，不因没配 AI 而隐藏——否则以后想接 AI 就找不到门。

---

## 3. 没配 AI 时

### 3.1 右栏：可以点开，但换内容

右栏永远可以打开。未配置 AI 时，**输入区整块换成配置引导**：

```
┌─────────────────────────────┐
│                             │
│   还没有配置 AI 服务        │
│   配置后才能对话和自动操作   │
│                             │
│        [  配置 AI  ]        │
│                             │
└─────────────────────────────┘
```

- 不显示输入框、发送按钮、会话列表入口——没有 AI 就没有会话，空输入框只会让用户白打一段字。
- `配置 AI` → 打开设置页并定位到 `AI` 分区。
- 不做常驻提示条 + 仍可输入的组合（旧设计），也不在点开面板时弹告警。
- 配置成功后，右栏恢复成正常对话界面；首次配置成功仍自动展开一次（用户手动关过则不再自动开）。

### 3.2 动作入口：全局告警

凡是"点一下就要 AI 干活"的入口，未配置时弹同一个全局模态：

| 入口 | 触发 |
|---|---|
| 连接页 chips `问 AI`（接管方式 / 流量范围旁） | 点击 |
| 节点行 `问 AI`（托管节点、服务器不可诊断时） | 点击 |
| 创建失败 `AI 定位` | 点击 |
| 设置页 `咨询 AI` | 点击 |
| 诊断面板 `去问 AI` / `问 AI` | 点击 |
| 手机导出弹层 `不会操作？问 AI` | 点击 |
| 报告问题里的 AI 辅助 | 点击 |

`智能诊断` 本身是本地诊断面板，未配置 AI 时照常可用、**不弹告警**；面板最后的「去问 AI」才需要 AI。非托管（订阅 / 手动导入）节点没有行内 AI 入口。

告警内容：

- 标题：`还没有配置 AI 服务`
- 正文：一句——配置后才能使用对话与智能操作。
- 主按钮：`去配置` → 关闭告警，打开设置 › AI。
- 次按钮：`取消` → 关闭，什么都不发生。Esc / 点遮罩同取消。

**不自动重放**：从告警去配置成功后，原来那次点击不补发，用户回来再点一次。理由：隔了几分钟再补发一条"测不通问 AI"，上下文来源不可预期。

**按钮不隐藏、不置灰、不改文案**：用户点了就知道这件事需要 AI，并且一步能去配。

### 3.3 不需要 AI 的动作

不过闸门，未配置时照常可用：连接、断开、切节点、测速、建机、销毁、导出、打开设置、看日志、跑诊断。诊断本身不是 AI 动作——未配置时照常输出结构化结果，只是没有 AI 解释。

## 5. 实现要点

- **一处实现**：前端只留一个 `requireAi()`（命名待定），动作入口统一调用；`sendToSession` 里现有的 `!aiConfiguredRef.current` 分支并入它，不再单独 `openSettings("ai")`。
- **判定来源**：已配置 = 有当前服务 + Key 非空（本机端点免 Key）；**Key 是否有效不判**，无效 Key 由发送时的服务商错误反馈。沿用 `isAiReady({ providers })`，不新增第二套判断。但它必须与后端 `has_credentials()` 同一语义——当前服务可用。现有实现里"只要存过一份 DeepSeek Key 就返回 true"的分支要去掉，否则界面放行、后端拒绝。
- **右栏状态**：由同一个 `aiReady` 决定渲染输入区还是配置引导；不要另存一份"要不要显示配置页"的标志。
- **后端兜底**：绕过界面的直接命令调用，`ai_session_*` 在未配置时返回结构化错误（如 `ai_not_configured`），不返回空回复。界面仍以前端判断为准。
- **文案中英各一份**：标题、正文、`配置 AI`、`去配置`、`取消` 进 `src/i18n` 字典。
- **跳转**：复用现有 `openSettings("ai")`。

## 6. 验收

1. 全新安装 → 点「我懂网络，不用 AI」→ 进主界面；重启后不再弹首启。
2. 未配置 AI 时点右栏按钮 → 面板打开，显示「配置 AI」，没有输入框；不弹告警。
3. 点「配置 AI」→ 落在设置 › AI；配好后右栏恢复输入框并自动展开一次。
4. 未配置 AI 时，连接、切节点、测速、建机、导出全部可用。
5. 未配置 AI 时点会真的发给模型的入口（连接页 chips `问 AI` / 节点行 `问 AI` / `AI 定位` / `咨询 AI` / 诊断面板 `去问 AI` / 手机导出 `不会操作？问 AI` / 报告问题的 AI 辅助）→ 弹同一个全局告警；取消后无残留。`智能诊断` 本身是本地诊断，未配置 AI 时照常可用，不弹告警（面板里的 `去问 AI` 会）。
6. 关闭右栏后再启动，保持关闭。
