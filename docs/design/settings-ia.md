## 0. 结论（一页）

1. **四个 tab 保留，骨架不动。** 改的是：第一个 tab 改名、每屏的行序、删除一处重复事实、把危险项和高级项各归其位。**不新增 tab，不新增页面，不新增中间区域的块。**
2. **三个会直接影响验收的问题必须先修**（都不是措辞问题）：
   - 「导入节点文件」实际调用 `import_seed_file`，只收 Veyl 种子 JSON，**不是**用户理解的节点列表（`services.rs:4431`）。用户拿一份普通节点文件进来会报「文件不是合法的种子 JSON」。→ 改名「添加节点」，换到 `node_import_text`，文件读取新增一条 UI-only 命令。
   - 端口顺延说明取错了数据源：现在用 `mixed_port !== proxyPort` 推断（`Settings.tsx:1054-1055`），把「本次连接被占用而顺延」说成「保存的是 X，下次连接生效」，还会和「已保存，下次连接生效」叠成两句。`runtime.port_fallback` 已经带 `requested / actual / reason`（`protocol.ts:748-753`），应当直接用它。
   - 「用哪个节点」与主界面底部重复，违反 `veyl-ui` §2.2「当前节点唯一住处 = 中间底部」。建议删除该行及其 `openNodeSheetSignal` 专线。
3. **频率分层落在 tab 内，不落在 tab 数量上。** 常看的（AI 当前服务、Veyl 免费节点、本机地址）在每屏最上面；偶尔的（添加服务、添加节点、改端口）紧随其后；维护类（连接程序、后台服务、日志、诊断）收进「更新与诊断」。重置网络虽然也是低频，但它是「救命」动作，保持可见，不折叠。
4. **A 批次契约零改动；B 批次新增一条命令。** `node_import_file` 的契约在 `commands.md` §4.1.2 定稿（2.16.14）；**命令与设置页文件入口已实现（未提交），随本批次验证**。另有三份文档、五处条目需要同步，见 §4.5。

## 2. 分组方案

### 2.1 判据

**按「用户什么时候会来找它」分，不按「技术上属于哪个模块」分。** 每一行必须能回答三问中的两个：它是什么、什么时候需要动它、动了会怎样。答不出来的行不出现；只读的状态不做成设置行的样子。

### 2.2 频率分层

| 层 | 什么时候来 | 内容 | 落点 |
|---|---|---|---|
| **常看** | 换场景 / 每天 | AI 当前服务是否可用、Veyl 免费节点有没有更新、本机地址是多少（三级） | 各 tab 第一屏 |
| **偶尔** | 新建或调整配置时 | 添加 / 切换 AI 服务、添加节点、改端口、清除残留代理 | 各 tab 第一屏靠下 |
| **维护** | 升级或出问题时 | 连接程序、后台服务、日志、诊断、重置网络 | 「更新与诊断」折叠；重置网络例外，保持可见 |

**为什么端口不折叠**：对一级 / 二级（全部软件配置）它整行不出现；对三级（代理配置）它是每天要复制的地址，折叠会把一个高频动作变成两次点击。它的一次性部分是「换端口」，仍然只在编辑态出现。

### 2.3 目标结构

```

├─ 连接           节点从哪来、本机地址是多少；连接方式只读
├─ 遇到问题       连不上网时修；升级、日志、诊断收在折叠里
└─ 关于           版本；开源入口（待 URL）；一句数据去向

├─ 用哪个 AI 服务
│   服务列表（当前项排第一）

├─ [ 添加 AI 服务 ]（表单在列表下方展开）

### 2.4 每区边界

| 区 | 放什么 | 不放什么 | 为什么 |
|---|---|---|---|
| **AI 服务** | AI 用哪个服务、模型、Key；添加与测试 | 对话历史、AI 人格 / 提示词、模型参数教程 | 用户来这里只解决「AI 用谁」；对话在右栏 |
| **连接** | 当前连接方式（只读）、节点来源、本机地址 | 连接 / 断开按钮、节点切换、分流规则 | 连接按钮在主界面顶部；节点切换在主界面底部；规则属于新建配置 |
| **遇到问题** | 修复网络、重置网络、升级、日志、诊断 | 日常设置、端口、AI | 这屏的预期是「平时不用来」；日常项混进来会让人不敢排除障 |
| **关于** | 版本、开源入口、一句数据去向 | 日志、诊断、连接程序升级 | 那些是排障，不是「关于」 |

### 2.5 为什么不是别的分法

| 备选 | 不采用的理由 |
|---|---|
| 加第五个 tab（节点 / 网络分开） | 「节点」和「连接」在用户嘴里是同一件事；拆开后每个 tab 只有一两行，且与左栏配置列表的角色重叠 |
| 按模块分（AI / 网络 / 高级 / 关于） | 这正是 `settings-advanced.md` 在 2026-11-06 已经推翻的旧结构；「高级」会重新变成杂物箱 |
| 把「关于」并进「遇到问题」 | 版本与反馈不是排障；合并后标题会变成更大的杂物箱 |
| 把所有低频项放进一个「高级」tab | 端口是三级用户的日常复制对象，折叠或移走会让「填地址」多一层；「重置网络」更不能藏 |
| 设置里做搜索 | 四个 tab、不足二十行，搜索的维护成本高于收益 |

```
重置网络？

会立刻断开当前连接，并撤销 Veyl 对网络的改动。

## 4. 契约影响

### 4.1 契约已定（2.16.14），已实现待验证：`node_import_file`

> **2026-11-11：已实现（未提交）。** 接口见 `commands.md` §4.1.2；后端命令 `node_import_file` 与设置页「添加节点」文件入口均已落地，随本批次用验收手册验证。下面是设计摘要，供对照实现。

```
node_import_file { path, configId? } → NodeImportResult
```

- **仅 UI**，不注册为 AI 工具。AI 侧继续走 `NodeImportText`（粘贴文本），不给模型读本地文件的能力。
- 读文件（≤1 MiB，按 UTF-8 解码、非法字节替换，不做编码猜测），把文本交给与 `node_import_text` **同一个解析实现**；行为、返回形状、错误码、事件与 `commands.md` §4.1.1 一致。
- `path` 只用于读取，**不返回、不落日志**；回显的只有节点摘要，不含密码与文件内容。
- 错误：`invalid_path`（空 / 非绝对）、`file_unreadable`、`file_too_large`、`not_node_text`；其余沿用 `NOT_FOUND` / `SECRET_STORE` / `INTERNAL`。
- **不按扩展名过滤**；本轮不解析 Clash YAML，YAML 会落到 `not_node_text`。
- 命令编号 #69，`commands.md` 版本 `2.16.14`，完整条目见 §4.1.2。
- 前端行为：系统对话框选文件 → 显示文件名并确认 → 调命令。**不把文件内容填进文本框**（需要前端读文件或命令回显全文，两者都不做）。
- **窗口拖放不接这条命令**（2026-11-11 决议）：拖入的只可能是种子文件，格式与逐行 `ss://` 不同，继续走 `import_seed_file`。拖入非 `.json` 时的提示要指向本页的「添加节点」，不能只说「请换一个文件」。

**备选（不推荐）**：给 `node_import_text` 加可选 `path`，二选一。这样会让「不发网络请求、也不读文件系统」的文本命令多一种能力，边界变模糊，也更容易被调用方误用。

### 4.2 需要保留但从设置页退出：`import_seed_file`

- 继续注册（离线兜底、开发测试仍可能用），但目标状态是设置页不再调用。
- **当前状态**：只剩**窗口级拖放**在调用它（`App.tsx:341-375` 的 `onDragDropEvent` → `importPath` → `importSeedFile`，只收 `.json` 种子文件）。设置页的粘贴 / 订阅 / 文件入口在 A、B 批次分别接 `node_import_text` / `node_import_url` / `node_import_file`，不再调它。窗口拖放**不迁**（见 §4.1），种子分发退场后再定去向——那时才可能把 UI 调用方降到零。
