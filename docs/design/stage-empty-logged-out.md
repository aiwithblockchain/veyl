# 未登录 · 无节点：两个 destination 各显示什么

> 日期：2026-11-17
> 状态：设计定稿，待实现（本轮只有两处文案改动）。只出结论与规格，不改代码。
> 依据：`veyl-ui` §2.1（一屏一个主动作）/ §6、`ui-ux-pro-max` §9 `empty-nav-state` / `nav-hierarchy` / `avoid-mixed-patterns` / `state-preservation`、`ai-first-product.md` §第一次进入主界面 / §登录、`acceptance-ui-refactor.md` R1（日常操作全程不弹登录）、`servers-list-detail.md` §1.2–§1.4。
> 问题：未登录且没有节点时，「连接」与「我的服务器」两屏各自该显示什么？是否只留一个登录按钮？

---

## 0. 结论

**两个 destination 都保持现状，不改结构；只改两处文案。**

| destination | 显示 | 主按钮 | 结果 |
|---|---|---|---|
| 连接（无节点） | `从哪里开始？` + `新建节点`（主）/ `先试用免费节点`（次） | `新建节点` | **结构不改**；未登录时说明行补一句「建自己的服务器要先登录」 |
| 我的服务器（未登录） | `先登录` + 说明 + `登录` | `登录` | **结构与按钮都不改**；说明句改成与零台一致的说法 |

一句话：**登录在「连接」屏是新建节点这条路的第 0 步，在「我的服务器」屏是唯一的答案——两边都不是「目的地」。**

---

## 1. 判定依据

1. **登录只在购买服务器与查看账单时需要**（`ai-first-product.md`；`account-menu.md` 头部援引同一条）。免费试用不需要账号，日常连接不需要账号。所以登录不能成为首屏的主动作。
2. **`ui-ux-pro-max` `empty-nav-state`**：空态必须给出用户能做的下一步动作，而不是描述缺失。两屏现在都有动作；要检查的是这个动作是不是**这一屏真正的下一步**。
3. **`ui-ux-pro-max` `nav-hierarchy`**：两个一级模块的空态**不应该**长得一样。「连接」是无资产用户的主战场；「我的服务器」是资产列表，没登录时它本来就没有内容可列。
4. **`ui-ux-pro-max` `avoid-mixed-patterns`**：同一类空态不能一处是「二选一」、一处是「门禁」。现在正好是这种差异，而它是对的——因为两屏问的问题不同。

---

## 2. 连接 destination（无节点）

### 2.1 结构：不改

```
从哪里开始？
免费节点不保证稳定，试用 7 天。          ← 未登录时改为下一行
┌──────────────────────────────┐
│ 新建节点                       │  ← 主（整卡）
│ 用自己的服务器，更稳定           │
├──────────────────────────────┤
│ 先试用免费节点                  │  ← 次（整卡）
│ 2 个节点，7 天试用              │
└──────────────────────────────┘
```

- 这是首次用户的默认屏，也是 `ai-first-product.md` §第一次进入主界面 定稿的形态，**上轮刚确认，不推翻**。
- 两个选项是同一个决定的两种做法，不是「两个并列功能」；`veyl-ui` §2.1 的一屏一个主动作在这里的读法是「一个主、一个次」，主次已经分明（`start-choice__pick--primary` / `--secondary`）。

### 2.2 唯一改动：把「登录」写进说明行

| 账户状态 | 说明行 |
|---|---|
| 未登录 | `免费节点不保证稳定，试用 7 天；建自己的服务器要先登录。` |
| 已登录 | `免费节点不保证稳定，试用 7 天。`（原样） |

理由：现在未登录用户点 `新建节点`，一路填完地区与档位、按「创建」时才被要求登录。**顺序本身是对的**（先表达意图，再补身份），但用户事先不知道，会觉得被拦了一道。在这行 13px 灰字里说一句，成本极低，且不改变任何动作。

- 不把这句话放到 `新建节点` 的副行（`用自己的服务器，更稳定`）里：那行是这一屏唯一还在「卖」的东西，加一句要求会把选择变成条件。
- 不在按钮上写 `新建节点（需登录）`：括号补丁会让主按钮读起来像劝阻。

## 3. 我的服务器 destination（未登录）

### 3.1 结构：不改

```
先登录
登录后可以买服务器；装好后节点会出现在这里，也能直接用来连接。
[ 登录 ]
```

- 主按钮仍是 `登录`，**不加** `新建节点`、**不加** `先试用免费节点`。
- 理由：这一屏的问题是「我有哪些服务器」，没登录时唯一的诚实答案是「先证明你是谁」。多给一个按钮，就是在资产列表里卖东西。

### 3.2 标题为什么不能用 `还没有服务器`

未登录时我们**读不到**账户里有几台服务器。`servers-list-detail.md` §1.4 已经把这条写成规则：**「读不到」与「没有」是两件事。** 说 `还没有服务器`，会让一个已经买过三台的用户以为资产丢了——这是这一屏最不能犯的错。

所以 `先登录` 保留。它不是把登录当成目的地，而是在说：**这一栏的内容需要你登录才能看**。

### 3.3 说明句对齐

`登录后可以买服务器；服务器装好后，节点会出现在节点池里。` → **`登录后可以买服务器；装好后节点会出现在这里，也能直接用来连接。`**

对齐零台空态的原句（`买一台装好后，节点会出现在这里，也能直接用来连接。`），让「登录后」与「买了之后」两屏说的是同一件事。同时去掉了 `节点池` 这个内部词——界面上没有别处这么叫。

---

## 4. 直接回答两个备选

### 4.1 「是不是只留一个登录按钮？」

**不是。** 三个理由：

1. **会误导。** 试用免费节点不需要账号。首屏只放 `登录`，等于告诉用户「想用这个产品先注册」，而实际上他两秒钟就能连上。
2. **会把登录变成目的地。** 产品负责人的约束就是这条：登录是步骤，不是目的地。一整屏只有 `登录` 时，用户确实不知道登录之后能得到什么——现在这屏的说明句还写着「能买服务器」，但如果首屏也这样，产品就变成了「注册即入口」。
3. **与既有验收冲突。** `acceptance-ui-refactor.md` R1 要求「连续做连接 → 断开 → 换节点 → 试用 → 让 AI 检查，全程不弹登录」。首屏放登录按钮，是在第一次见面就把这条破了。

### 4.2 「还是直接摆出『可以创建服务器，但要先登录』？」

这个方向是对的，但**不该新增一个按钮来做**。

- 现在的路径已经是「新建节点 → 走完表单 → 点创建时登录」。要补的不是动作，是**预期**。
- 新增一个 `创建服务器（需登录）` 按钮，会让主按钮的语义变成「登录」的委婉说法：用户点下去发现是登录表单，比现在更意外。
- 所以按 §2.2 把它写进说明行——同一个事实，说在用户做选择之前，而不是替用户做一个更绕的选择。

---

## 5. 免费节点试用：未登录时保持可用

**保持可用，不加登录门槛。** 理由：

1. 试用是 7 天、2 个免费节点，是产品唯一的「先体验再决定」路径；加登录等于关掉这条路径。
2. `ai-first-product.md` 与 `acceptance-ui-refactor.md` R1 都把「日常使用不需要账号」当作承诺。
3. 试用不需要控制面身份：预置配置随包、节点由种子池直出（`/v1/seed`），没有账户参与。
4. 转化顺序应该是「先连上 → 觉得有用 → 建自己的服务器时登录」，而不是「先交邮箱」。

- 试用到期后（`trial_expired` 屏）：那一屏只有 `新建节点` 一个按钮，用户会在建机流程里遇到登录——这是对的顺序，**不改**。

## 6. 文案原文

| 位置 | 文案 |
|---|---|
| 连接 · 标题 | `从哪里开始？` |
| 连接 · 说明（未登录） | `免费节点不保证稳定，试用 7 天；建自己的服务器要先登录。` |
| 连接 · 说明（已登录） | `免费节点不保证稳定，试用 7 天。` |
| 连接 · 主选项 | `新建节点` / `用自己的服务器，更稳定` |
| 连接 · 次选项 | `先试用免费节点` / `2 个节点，7 天试用` |
| 服务器 · 标题（未登录） | `先登录` |
| 服务器 · 说明（未登录） | `登录后可以买服务器；装好后节点会出现在这里，也能直接用来连接。` |
| 服务器 · 按钮 | `登录` |

- 不用「注册」：产品里没有独立的注册动作，登录即注册。
- 不用「账号」：说 `登录`，不说 `账号`。
- `节点池` 不出现在界面（只在契约文档里）。

## 7. 必须改 / 建议改 / 不改

### 建议改（P2）

1. 连接屏说明行按 §2.2 分登录 / 未登录两种写法。
2. 服务器屏说明句改成 §3.3 的版本（去掉 `节点池`，与零台对齐）。
3. 服务器屏空态按钮当前是 `.btn` 32 高 —— 按 `stage-pages-review.md` §6.2，空态主按钮应为 **44 高、内边距 0 20**。这一条已经在那份文档里记过，本轮不重复列，实现时一起改。

### 不改

| 项 | 理由 |
|---|---|
| 连接屏两个选项的结构与主次 | 上轮刚定稿；无节点的核心选择就是「自建 / 试用」，与登录无关。 |
| 服务器屏只放 `登录` | 未登录时读不到资产；`还没有服务器` 会说谎（`servers-list-detail.md` §1.4）。 |
| 未登录也能试用免费节点 | 试用不需要账号，是产品承诺（§5）。 |
| 服务器屏不放 `新建节点` | 资产列表里卖东西；建机入口在连接屏，且只在那一处。 |
| `trial_expired` 屏只有 `新建节点` | 到期后唯一出路就是建机，登录发生在建机流程里，顺序正确。 |
