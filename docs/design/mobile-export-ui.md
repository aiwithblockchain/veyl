# 在手机上使用：入口、两个下载链接与二维码

> 日期：2026-11-19
> 状态：**设计定稿，待评审**。只出设计与文案，不改代码、不改契约、不发截图。
> 上游：`mobile-export.md` §2.2 / §2.4 / §6（需求草案）、`settings-ia.md`（设置四段）、`account-menu.md` §11（账户 tab 现状）、`servers-list-detail.md` §1.5（左栏底部常驻行）/ §2.3（详情不提供连接入口）、`veyl-ui` §2.1 / §2.2 / §3 / §6。
> 依据：`ui-ux-pro-max` 检索结果见 §7（图标库无匹配，已如实标注）。
> 问题：iPhone / Android 下载链接放在哪里、用什么形态、怎么排列；它和「生成二维码」是什么关系。

---

## 0. 结论

**主住处只有一个：设置 › 账户 › 新增一行 `在手机上使用`，点开一个二级弹层。** 弹层里放两行下载入口 + 二维码 + 复制链接 + 重新生成。「我的服务器」左栏底部另有一个**快捷入口**，打开同一个弹层（§1.4）。

| # | 决策 | 结论 |
|---|---|---|
| 1 | 主入口位置 | **设置 › 账户**，余额下方，独立一行 |
| 1b | 快捷入口 | **「我的服务器」左栏底部**，紧挨 `新建节点` 下方，打开同一个弹层；只在一台服务器节点就绪后出现（§1.4） |
| 2 | 形态 | 一行设置项 + **480 弹层**（不内联展开、不做大卡片） |
| 3 | 下载入口形态 | **文字链接**（`App Store ↗` / `官方下载页 ↗`），不用品牌图标 |
| 4 | 排列 | **iPhone 在上，Android 在下**；二维码区在下载区之下，用一条分隔线隔开 |
| 5 | 「我的服务器」空态 | **不放**（理由见 §1.2） |
| 6 | 服务器详情页 | **本期不放**；单台二维码已定不做（2026-11-19 PM，见 `mobile-export.md` §4.3） |
| 7 | 主操作 | 二维码是主角；弹层里**没有实心主按钮**，复制与重新生成都是次级 |

一句话：**下载是「先装客户端」，二维码是「装上之后做什么」——先下载、后扫码，顺序就是弹层从上到下的顺序。**

## 1. 位置

### 1.1 为什么是「设置 › 账户」

| 候选 | 判断 |
|---|---|
| **设置 › 账户** | **采用。** 导出物是账户级的：要登录、要求有付费服务器、令牌可吊销。账户 tab 本来就负责「这个人」和「他的钱」，加一段「他的设备」是同一层语义。现状这一屏只有邮箱和余额，是全设置最空的一屏，有位置。 |
| 设置 › 连接 | 否。这一屏每一行都在改**这台电脑**怎么连（接管方式、流量范围、端口、节点来源）。手机不是这台电脑的连接参数，放进去会让人以为它影响本机连接。 |
| 设置 › 高级 | 否。高级是排障与维护；这是主路径功能。 |
| 新增第五个 tab | 否。`settings-ia.md` 明令四段固定、不新增 tab。 |
| 左栏底部 / 导航菜单 | 主住处否；**左栏底部只放快捷入口**（§1.4，与 `新建节点` 并列，就绪后出现）。账号菜单只有余额、充值、退出登录（`account-menu.md` §9），不放。 |

### 1.2 为什么「我的服务器」空态不放

需求草案（`mobile-export.md` §6）留了一个「空态推荐位」的口子，**建议不做**：

- 空态出现的条件是「**还没有服务器**」。此刻用户没有可导出的节点，下载客户端对他没有下一步；
- 空态已经有两行内容 + 一个主按钮（`新建节点` / `登录`），再加一组下载链接会变成第二个动作；
- 一个事实一个住处（`veyl-ui` §2.2）：下载入口只住在设置 › 账户，别处不重复。

这不妨碍 §1.4 的左栏底部行：那一行**只在至少一台服务器就绪之后出现**，与空态互斥——空态时它不在，有内容时它才在。

**例外只在以后**：单台二维码已定不做；若将来重启，入口应落在服务器详情，而不是空态。

### 1.3 为什么服务器详情本期不放

- `servers-list-detail.md` §2.3 刚拍板「**详情不提供任何连接入口**」，详情只剩事实 + `销毁`。在对象页再挂一个全局动作，会破坏这条刚立下的规矩；
- 单台二维码（`mobile-export.md` §4.3 方案 B）**已定不做**（2026-11-19 PM）：账户级配置已包含全部可用付费节点。详情页不预留位置。

### 1.4 「我的服务器」左栏底部：快捷入口（2026-11-19 产品负责人确认）

**入口不藏在设置里。** 「我的服务器」左栏底部加一行常驻入口，紧挨现有的 `新建节点`，点开的是**同一个** 480 弹层。

```
我的服务器          2   ＋
● 东京 1 号
  可用 · 东京 · $0.20/天
● 洛杉矶 1 号
  可用 · 洛杉矶 · $0.30/天
─────────────────────────
[＋]  新建节点
[手机] 在手机上使用
```

| 项 | 规格 |
|---|---|
| 位置 | 左栏（非紧凑模式）底部，`新建节点` 之后；DOM 顺序与视觉顺序一致 |
| 出现条件 | **已登录 且 至少一台服务器的节点已就绪**（与详情「节点 已就绪」同一判定源）。注意不是「服务器台数 > 0」：安装中、出错、墓碑都不算 |
| 形态 | 与 `.rail__new-row` 同构：flex、gap 8、高 40、`margin: 8px 8px 0`、`padding: 0 10px`、`border-top: 1px --hair`、`border-radius: 0 0 8px 8px`、13 / 500 / `--ink-2`。建议把公共盒模型抽成 `.rail__action-row`，两行共用，避免复制一份样式 |
| 图标列 | 14×14 槽（`.rail__new-row__icon` 同款）；文字起点与上一行对齐（14 + 8 gap）。**图标库里没有现成的手机图标**（`src/components/icons.tsx` 只有 close / plus / chevron / list / sliders / pencil / trash / key / console / server / groups）。**决定（2026-11-19 PM）：按同一族新增 `IconPhone`**——16 viewBox、stroke 1.4、圆角矩形 + 底部横线，**不用 Apple / Android 品牌标志**（§3.2）。保留 14px 空槽只作为实现被砍时的兜底，不是并列选项 |
| 分隔线 | 每行各自保留 `border-top`；**不要把两条线并成一条**——合并后两行 hover 底连成一片，看起来像一个动作 |
| 间距 | 两行之间只有第二行的 `margin-top: 8`，不额外加 gap |
| hover / focus | 与 `.rail__new-row` 完全一致：hover `--bg-hover` + 文字转 `--ink`；`:focus-visible` 内侧 2px `--focus` |
| 滚动 | **不随列表滚动**：放在 `.rail__body` 之外、`flex: none`，与 `新建节点` 同一套规则；列表再长也固定在底部 |
| 权重 | 次级：不加实心底、不用品牌粉；与 `新建节点` 视觉权重相同 |

**出现 / 消失时机**

| 事件 | 这一行 |
|---|---|
| 建机完成、节点刚就绪 | **出现**。跟随服务器列表的同一份状态更新；建机完成本来就会刷新一次列表（现有行为），**不新增轮询、不新增定时器** |
| 最后一台就绪服务器被销毁 / 变为不可用 | **消失** |
| 账户登出 | **立即消失**（账户状态变化驱动） |
| 账户读取中 / 失败 | **不出现**：门禁判不了，不摆一个可能点不动的入口 |
| 有就绪服务器，同时有安装中 / 出错的 | **保持出现**：条件是「至少一台就绪」，不是「全部就绪」 |
| 列表加载中 / 读取失败 | **不出现**（与 `新建节点` 行相同的 `loading / error` 门控） |
| 向导打开（`.rail--locked`） | **保留但禁用**：与 `新建节点` 一样 `disabled` + 45% 透明 + `pointer-events: none` |
| 抽屉模式（`rail--compact`） | **不出现**：抽屉里已有 `新建节点`，不在抽屉内重复第二行；设置 › 账户 仍是常驻入口 |

**交互与无障碍**

| 项 | 规则 |
|---|---|
| 点击 | 打开同一个 480 弹层（与设置行共用组件与状态，不写第二套） |
| 关闭 | 焦点回到触发它的这一行；若关闭前该行已消失（登出、最后一台销毁），回到左栏标题行的 `＋` |
| 键盘 | `<button>`，DOM 顺序在 `新建节点` 之后；Tab 顺序与视觉一致 |
| 无障碍名称 | 可见文字 `在手机上使用` 已足够，**不加 `aria-label` 覆盖**；加 `aria-haspopup="dialog"` 说明会打开弹层 |
| 副行说明 | **不做**。加一行会把它撑到 56+ 高，与 `新建节点` 的 40 不齐；「做什么」由弹层回答，行文字不重复解释 |
| 文案 | 只有 `在手机上使用`；不加「扫码」「导入」「客户端」等词——那些在弹层里说一次就够 |

## 2. 形态：一行 + 二级弹层

### 2.1 设置行

放在「设置 › 账户」余额行之后，加一条 `1px --hair` 分隔（与 `account-menu.md` §11 的邮箱 / 余额分隔同一套）。

```
邮箱
ribencong@gmail.com
────────────────────────────
余额                                [充值]
$9.20
余额按天扣费，每台服务器单独计费。
────────────────────────────
在手机上使用                                    [查看]
下载 sing-box 官方客户端，扫码导入你的节点。
```

| 元素 | 规格 |
|---|---|
| 行 | 复用 `.settings-row`：min-height 40、gap 16、padding-bottom 12、底部 1px `--hair` |
| 标签 | 14 / `--ink`（`.settings-row__label`），文案 `在手机上使用` |
| 说明 | 12 / 1.6 / `--ink-3`（`.settings-note`），最多一行，宽度按 360 预留 |
| 右侧动作 | `btn btn--ghost`，高 32、内边距 0 14、文案 `查看` |
| 出现条件 | **恒定出现**，与登录无关。未登录时也显示——下载链接对所有人开放（`mobile-export.md` §3） |
| 账户读取中 | 行照常出现（它不依赖账户数据）；点开弹层里二维码区显示 `读取中` |

**为什么右侧是 `查看` 而不是直接铺两个链接**：两个外链 + 二维码 + 复制 + 重新生成是四五个控件，铺在设置行里会把账户 tab 撑成一屏工具面板；设置行的职责是「告诉你有这件事」，弹层负责做。`查看` 与账户 tab 现有 `[充值]` 同为 ghost，权重一致。

### 2.2 弹层

复用 `.modal`（`width: min(480px, calc(100vw - 48px))`），不新建尺寸。头部沿用 `.modal__head` / `.modal__title` / `.modal__close`。

```
┌ 在手机上使用                                        × ┐
│                                                      │
│  Veyl 不提供手机客户端，用 sing-box 官方客户端。       │
│                                                      │
│  iPhone                              App Store ↗      │
│    需要大陆以外的 Apple 账号。                         │
│  Android                            官方下载页 ↗       │
│    Google Play、F-Droid 或 GitHub 任选。               │
│  ────────────────────────────────────────────────    │
│  ┌──────────┐   你的节点                               │
│  │  二维码   │   用手机扫码导入。节点变化会自动更新，    │
│  │  160×160  │   不用重扫。                             │
│  └──────────┘   [复制链接]  重新生成                    │
│                 链接相当于密码，别转发。                 │
└──────────────────────────────────────────────────────┘
```

| 区块 | 规格 |
|---|---|
| 弹层内边距 | 20（与 `.modal__head` 的左右 20 对齐） |
| 首句 | 13 / 1.6 / `--ink-2`，距头部 16 |
| 下载组 → 分隔线 | 24 |
| 分隔线 → 二维码区 | 20 |
| 二维码区布局 | 左 160 二维码 + 间距 24 + 右列（自适应，最小 220） |

**为什么用弹层而不是行内展开**：

- 二维码需要 160×160 的干净面积，行内展开会把设置页撑长、并和下方的余额说明抢视觉；
- 弹层可以只滚动自己（`max-height: min(86vh, 780px)`），不改变账户 tab 的高度；
- 以后若从别处（服务器详情）打开同一个弹层，不用再写一套版式。

**同一个弹层，两个入口**：设置 › 账户 的行与「我的服务器」左栏底部的行（§1.4）打开的是同一个组件、同一份状态；两处的关闭焦点分别回到各自的触发行。

**为什么不做成大卡片 / 带插图的引导页**：这是一次工具性操作，用户来是为了「拿到二维码」或「先装客户端」。卡片和图会拉长路径、增加滚动，且与本产品「边界靠留白不靠线框」的视觉不一致。

## 3. 两个下载链接

### 3.1 排列

| 顺序 | 平台 | 链接文字 | 跳转 |
|---|---|---|---|
| 1 | `iPhone` | `App Store ↗` | `https://apps.apple.com/app/sing-box-mt/id6785326793` |
| 2 | `Android` | `官方下载页 ↗` | `https://sing-box.sagernet.org/clients/` |

- **iPhone 在上**：它是唯一有额外前置条件（大陆以外 Apple 账号）的一个，先出现能让 iPhone 用户在第一时间看到限制，而不是装到一半才发现。项目文档与常见下载页也都是 iPhone 在前，保持一致。
- **Android 只给一个链接**：需求草案列了 Google Play / F-Droid / GitHub 三条。界面上给三条会让一行变成三行、且在哪个都打不开时是一排死路。改为指向**官方客户端页**（它把三个渠道列全），行下图注说明可以换一个。这样无论用户用哪种网络，都有一个能走的入口。
- 两个链接都是**外链**：用现有 `open_external`，系统浏览器打开，不内嵌网页（`mobile-export.md` §2.2）。

### 3.2 样式

| 元素 | 规格 |
|---|---|
| 平台名 | 14 / `--ink`，与设置行标签一致 |
| 链接 | 13 / 500 / `--link`；hover `--link-hover` + 下划线；`:focus-visible` 2px `--focus`、offset 2 |
| 外链符号 | `↗` 跟在文字后 4，`aria-hidden="true"`，13 / 同色 |
| 命中区 | 文字外扩 `::after { inset: -10px -8px }`，高度约 32（与 ghost 按钮同高），不改行高 |
| 图注 | 12 / 1.5 / `--ink-3`，距平台名 2；两行以内 |
| 行间距 | 下载行之间 16 |

**为什么不用品牌图标**：

1. 设置页所有行都没有前置图标，只有文字与右侧动作；给这两行加 Apple / Android 标志会成为页面里唯一的装饰，破坏一致性;
2. 品牌标志必须使用官方素材并遵守留白与配色规范，自绘或改色都有商标风险（`ui-ux-pro-max` pro-rules「Correct Brand Logos」）；
3. 平台名已经是文字，图标不提供额外信息。

**为什么不用实心按钮**：两个商店入口是并列的次级动作，不是这一步的主操作；主操作是下方的二维码。两个实心按钮会与本产品「一屏一个实心按钮」冲突。

## 4. 二维码区

### 4.1 三种状态

| 状态 | 二维码位 | 右列 |
|---|---|---|
| 未登录 | 不显示，留 160×160 空位（保持弹层高度稳定） | `先登录。` + `登录后可以把自己的节点导入手机。` + ghost `登录` |
| 已登录 · 没有 `ready` 付费服务器 | 不显示，同上 | `还没有可用的服务器。` + `先在「我的服务器」里创建一台，再回来扫码。` + ghost `去我的服务器` |
| 已登录 · ≥1 台 `ready` | 160×160 二维码 | `你的节点` + `用手机扫码导入。节点变化会自动更新，不用重扫。` + `[复制链接]` + `重新生成` + 安全说明 |
| 正在生成 | 160×160 骨架（`--hair` 填充、圆角 8、`aria-busy`） | `正在读取节点…` |
| 生成失败 | 不显示 | `二维码暂时生成不了。` + ghost `重试` |

- `登录` / `去我的服务器` 都**先关闭弹层**再执行（登录弹窗或切 destination），避免两层弹窗叠在一起。
- `去我的服务器` 关闭设置并切到 servers destination；若该动作还没有现成回调，实现时复用设置关闭 + 切 destination 的现有路径。

### 4.2 二维码本身

| 项 | 规格 |
|---|---|
| 尺寸 | 160×160 CSS px |
| 内容 | `sing-box://import-remote-profile?url=…`（URL 编码后，见 `mobile-export.md` §2.3） |
| 底与模块 | **永远是白底黑码**，浅色 / 深色主题都一样；不加透明度、不反色、不加品牌粉 |
| 留白 | 静区 12（白），与 1px `--hair` 描边之间 |
| 圆角 | 8（不裁切二维码本身，白底容器圆角） |
| 清晰度 | 用矢量或至少 2× 位图；不缩放浏览器截图 |
| 无障碍 | `<img alt="sing-box 导入二维码">`；不把 URL 写进 alt、title 或界面文本 |

**深色主题必须单独检查**：二维码区块在深色下仍是一块白色，不能跟随 `--card` 变黑。

### 4.3 复制与重新生成

| 动作 | 规格 |
|---|---|
| `复制链接` | `btn btn--ghost`，高 32、内边距 0 12；点击复制的是二维码里的**同一个 URL**（不是二维码图片）。成功原位变 `已复制` 1.5 秒，`role="status"`；失败 `复制失败`，同样原位 |
| `重新生成` | 文字链接 13 / `--ink-2` + 下划线，与 `account-menu.md` §11 `查看账单` 同款，**不用粉色**；距 `复制链接` 12 |
| 重新生成的确认 | 就地展开，不弹第二层：`重新生成后，手机上的旧配置下次更新时失效。` + `[取消]` + `[重新生成]`（最终按钮 `btn--danger-ghost`，初始焦点在 `取消`） |
| 成功反馈 | `已重新生成；手机上的旧配置下次更新时失效。` 12 / `--ink-3`，`role="status"` |
| 无服务器 / 未登录 | 不显示 `重新生成` |

- 确认文案不写「删除」「作废」——真正发生的是「旧链接失效」，且新链接立刻可用，这是可恢复动作，但会打断手机上的使用，所以仍需确认。
- 安全说明固定在右列底部：`链接相当于密码，别转发。` 12 / `--ink-3`。**不写「订阅链接」**，界面不出现「订阅」（`settings-ia.md` §3.8）。

## 5. 文案

### 5.1 设置行与左栏行

| 位置 | 文案 |

## 6. 键盘与无障碍

| 项 | 规则 |
|---|---|
| 设置行 | 右侧是 `<button>`（`查看`），Tab 可达；Enter / Space 打开弹层 |
| 左栏行 | `<button aria-haspopup="dialog">`，Tab 顺序在 `新建节点` 之后；视觉顺序与 DOM 顺序一致 |
| 弹层打开 | 焦点进入弹层（沿用现有 modal 的 focus trap）；`Esc` 关闭 |
| 弹层关闭 | 焦点回到触发它的那一行；若该行已消失（登出 / 最后一台销毁），回到左栏标题行的 `＋` |
| 外链 | `<a>` 或带 `role="link"` 的按钮，`aria-label` 补全目的地：`在 App Store 打开 sing-box` / `打开 sing-box 官方下载页`；`↗` `aria-hidden` |
| 二维码 | `alt="sing-box 导入二维码"`；不含 URL 与令牌 |
| 复制反馈 | `role="status"`，同一位置替换文字，不弹 toast |
| 重新生成确认 | 初始焦点 `取消`；`Esc` 等同取消；确认中焦点不离开弹层 |
| 颜色 | 不只靠颜色传达状态：生成失败有文字、复制成功有文字 |
| 深色 | 二维码白底、行分隔线 `--hair`、链接 `--link` 均需在深色下复核对比度 |
