## 0. 结论

**一个 480 弹层，两个编号步骤：`1 安装客户端` → `2 导入节点`；底部一个 `不会操作？问 AI`。** 步骤号承担顺序，步骤标题承担分组，说明句只留真正需要读的那几句。

| # | 决策 | 结论 |
|---|---|---|
| 1 | 主住处 / 快捷入口 | 设置 › 账户 一行；「我的服务器」左栏底部一行；两处打开同一个弹层（§1，不变） |
| 2 | 弹层结构 | **两个编号步骤**，同屏显示，不做 tab、不做折叠 |
| 3 | 步骤 1 | `1 安装客户端`：iPhone / Android 两行 + 右侧下载码（104）+ 图注 `扫码下载` |
| 4 | 步骤 2 | `2 导入节点`：导入码（160）+ 说明 + 复制 / 重新生成 + 安全说明 |
| 5 | 两个码怎么区分 | **编号 + 步骤标题 + 两个 4 字图注（`扫码下载` / `扫码导入`）+ 尺寸差**；下载码在步骤 1 右侧，导入码在步骤 2 左侧，位置也不同 |
| 6 | 已知信息去哪 | 首句、Android 渠道图注、导入码内标题全部删除；「Veyl 不提供手机客户端」「三个 Android 渠道」进 AI 帮助 |
| 7 | AI 帮助 | 弹层底部 `不会操作？问 AI`，点击关闭弹层并在右栏发送**逐字固定**的提示词（§5） |
| 8 | 视觉层级 | 标题 17/600 → 步骤标题 15/600 → 平台名 14 → 说明/链接 13 → 图注 12；只用现有字号与 token |

一句话：**先装、再导，两步各一个标题、各一个码、各一句话；剩下的解释交给 AI。**

**文字量（不含平台名、按钮、安全句）**：v1 约 118 字 → v2 约 65 字；删掉的不是信息，是重复和可由页面/AI 承担的解释。

## 1. 位置（v1 不变）

### 1.1 为什么是「设置 › 账户」

| 候选 | 判断 |
|---|---|
| **设置 › 账户** | **采用。** 导出物是账户级的：要登录、要求有付费服务器、令牌可吊销。账户 tab 本来就负责「这个人」和「他的钱」，加一段「他的设备」是同一层语义。 |
| 设置 › 连接 | 否。这一屏每一行都在改**这台电脑**怎么连，手机不是本机连接参数。 |
| 设置 › 高级 | 否。高级是排障与维护。 |
| 新增第五个 tab | 否。`settings-ia.md` 明令四段固定。 |
| 左栏底部 / 导航菜单 | 主住处否；左栏底部只放快捷入口（§1.4）。账号菜单不放。 |

### 1.2 为什么「我的服务器」空态不放

- 空态时用户还没有服务器，没有可导出的节点，下载客户端对他没有下一步；
- 空态已有一个主按钮，再加一组下载入口会变成第二个动作；
- 一个事实一个住处（`veyl-ui` §2.2）。

§1.4 的左栏底部行只在「至少一台服务器就绪」后出现，与空态互斥。

### 1.3 为什么服务器详情本期不放

- `servers-list-detail.md` §2.3 已拍板「详情不提供任何连接入口」；
- 单台二维码（方案 B）已定不做（2026-11-19 PM）：账户级配置已包含全部可用付费节点。

### 2.1 草图

```
│                                     │ 下载码  │        │
│                                     │  104   │        │
│                                     └────────┘        │
│                                                      │
│  2   导入节点                                         │
│                                                      │
```

- 步骤号 `1` / `2` 是 12px mono `--ink-3`，标题 15/600 `--ink`；号与标题间距 8。

- 没有分隔线：步骤号 + 32 的留白已经分组，v1 那条线只是「堆元素」时的补救。

### 2.2 版式与层级

| 元素 | 规格 |
|---|---|
| 弹层 | `.modal`，`min(480px, 100vw - 48px)`；内边距 20 |
| 标题 | **17 / 600 / `--ink`**（比默认 `modal__title` 15 大一档；17 是现有字号阶梯里的「复杂弹窗标题」） |
| 步骤头 | 12 mono `--ink-3` + 8 + 15 / 600 `--ink`；步骤 1 距头部 20，步骤 2 距上一段 32 |
| 步骤头 → 内容 | 16 |
| 平台行 | 名 14 / `--ink`；链接 13 / 500 / `--link`；图注 12 / 1.5 / `--ink-3` |
| 平台行间距 | 12 |
| 步骤 1 码列 | 桌面宽度下与左侧两行**垂直居中**（2026-11-19 实机评审：`align-items: center`）；窄屏改成单列时不受影响 |
| 二维码图注 | 12 / 1.5 / `--ink-3`；图注 → 码 8 |
| 步骤 2 说明 | 13 / 1.6 / `--ink-2` |
| 按钮行 | 距说明 12；按钮间距 12 |
| 安全说明 | 12 / `--ink-3`；**紧贴按钮下方 16**（2026-11-19 实机评审修正：右列底部对齐会让它离按钮 60–75px） |
| AI 帮助 | 距步骤 2 内容 32；13 / 500 / `--ink-2` + 下划线 |
| 窄屏断点 | ≤560px：两个步骤的内容都改为单列（下载码落在平台行下方、导入码在上文字在下） |

**层级靠什么做出来（对照 v1 的「堆元素」）**：

| v1 的问题 | v2 的处理 |
|---|---|
| 首句、两行图注、码图注、导入说明、安全说明是五句同级小字，没有组标题 | 两句小字被删；剩下的说明各自挂在编号步骤下，先读标题再读内容 |
| 两个二维码只差尺寸，处理方式相同 | 编号 + 不同位置（右 / 左）+ 4 字图注各说各的动作 |
| 唯一的分组手段是一条分隔线 | 编号 + 32 留白分组；线删掉 |
| 标题与正文同重（15/600 vs 14） | 标题提到 17/600，步骤标题 15/600，形成三级 |
| 下载码与导入码权重接近 | 下载码 104 靠右、导入码 160 靠左做主视觉；步骤 2 才是主产物 |

### 2.3 为什么两个步骤同屏

| 方案 | 取舍 |
|---|---|
| **同屏 + 编号** | **采用。** 用户可能在装之前、装之后或装到一半打开这个弹层；两步都不是「必须完成上一步才能看」的状态。编号给出顺序，不拦人。 |
| Tab / 分段切换 | 否。主目标是导入，把导入码藏在第二个 tab 后面等于多加一次点击；两个步骤也不是互斥视图。 |
| 步骤 2 折叠到「我装好了」之后 | 否。这是假门禁：用户可能早装好了，也可能先在旧手机上装过；折叠只会让回来的人多点一次。 |
| 分两个弹层 | 否。入口只有一个，多一层容器没有收益。 |

### 2.4 为什么下载码在步骤 1 的右侧

- v1 把它放在两行之下，是因为当时 iPhone 图注有 25 字，右侧切不出空间。v2 把图注压到 13 字、删掉 Android 图注后，右侧 104 + 24 的列放得下，两行仍保持单行。
- 这样步骤 1 变成「两行 + 一个码」的紧凑块（高约 120），步骤 2 的 160 码成为整屏最大的视觉块——**先装是小动作，导入是主产物**。
- 位置差（右 / 左）让两个码不用读文字也能分辨。

### 2.5 窄屏（≤560px）

- 两个步骤的内容都改成单列：步骤 1 的平台行在上、下载码在下（左对齐）；步骤 2 的导入码在上、说明与按钮在下（沿用现有断点）。
- 弹层宽度仍 `min(480px, 100vw - 48px)`，不出现横向滚动；iPhone 图注最多两行。
- 下载码在窄屏不缩小（104），保证可扫。

## 3. 步骤 1：安装客户端

### 3.1 两个平台行

| 顺序 | 平台 | 链接 | 图注 |
|---|---|---|---|
| 1 | `iPhone` | `官方下载页 ↗` | `需要大陆以外的 Apple 账号。` |
| 2 | `Android` | `官方下载页 ↗` | **无** |

- 链接外链：`open_external`，系统浏览器打开，不内嵌。

### 3.2 下载码

| 项 | 规格 |
|---|---|
| 位置 | 步骤 1 右侧列，与两个平台行并排；列宽 104、列间距 24 |
| 尺寸 | **104×104** 外框；码区 80，静区 12 |
| 底 / 边 / 圆角 | 永远白底黑码；1px `--hair` 描边；圆角 8 |

## 4. 步骤 2：导入节点

### 4.1 五态

| 状态 | 二维码位 | 右列 |
|---|---|---|
| 未登录 | 不显示，留 160×160 空位 | `先登录。` + `登录后可以把自己的节点导入手机。` + ghost `登录` |
| 已登录 · 没有 `ready` 服务器 | 不显示，同上 | `还没有可用的服务器。` + `先在「我的服务器」里创建一台，再回来扫码。` + ghost `去我的服务器` |
| 已登录 · ≥1 台 `ready` | 160×160 导入码 | `节点变化会自动更新，不用重扫。` + `[复制链接]` + `重新生成` + 安全说明 |
| 读取中 | 160×160 骨架，`aria-busy` | `正在读取节点…` |
| 生成失败 | 不显示 | `二维码暂时生成不了。` + ghost `重试` |

- 步骤 1 与 AI 帮助**不参与这五态**，任何时候都在。
- `登录` / `去我的服务器` 先关闭弹层再执行，避免两层弹窗叠在一起。
- 保留 160 空位是为了切换状态时不跳高度。

### 4.2 导入码

| 项 | 规格 |
|---|---|
| 尺寸 | 160×160 CSS px |
| 内容 | `sing-box://import-remote-profile?url=…`（URL 编码） |
| 底 / 边 / 圆角 | 白底黑码；1px `--hair`；圆角 8 |
| 静区 | 12（白） |
| 图注 | `扫码导入`，12 / 1.5 / `--ink-3`，在码**上方** 8 |
| 清晰度 | SVG 或 ≥2× |
| 无障碍 | `<img alt="sing-box 导入二维码">`；URL 与令牌不进 alt / title / 界面文本 |

- **令牌不出现在任何可见文本**：二维码内容只存在于图片里；`复制链接` 复制的是 URL，不显示。

### 4.3 复制与重新生成

| 动作 | 规格 |
|---|---|
| `复制链接` | ghost，高 32；复制导入码里的同一个 URL；成功原位变 `已复制` 1.5 秒，失败 `复制失败`；`role="status"` |
| `重新生成` | 文字按钮 13 / `--ink-2` + 下划线（`btn--link`），不用粉色；距复制 12 |
| 确认 | 就地展开，不弹第二层：`重新生成后，手机上的旧配置下次更新时失效。` + `[取消]` + `[重新生成]`（最终按钮 `btn--danger-ghost`，初始焦点 `取消`） |
| 成功 / 失败 | 成功 `已重新生成；手机上的旧配置下次更新时失效。` 12 / `--ink-3`；失败 `没能重新生成。旧链接还在，稍后再试。` 12 / `--err-text` |
| 不可见时 | 未登录 / 无服务器 / 读取中 / 失败时不显示 |

### 4.4 安全说明

`链接相当于密码，别转发。` 12 / `--ink-3`，**紧贴按钮下方 16**（2026-11-19 实机评审修正：原「右列底部对齐」会把它推离按钮 60–75px，读起来像与操作无关的脚注）。**唯一保留的额外说明句**：它防的是转发泄露，不能交给 AI 在事后解释。

### 13.2 为什么导入在前、编号取消

- 产品负责人的口径：**导入是主视觉，客户端在旁边/下方成列表**；并且**客户端不是必做步骤**——用户手机里可能已经有 Shadowrocket、Clash、Karing，有就直接扫，不用再装一个。
- 所以客户端区写成条件句 `还没有客户端？`，不编号、不排在导入之前：它是「没有才往下挑」的退路，不是流程的第一步。
- 主次用三件事表达：标题字号（15/600 vs 13/500）、二维码尺寸（160 vs 104）、位置（上 vs 下）。
- v2 的「一个下载码对应所有客户端」在这个模型下自然消失：**一个码对一个客户端**，不会错。

**全新用户会不会找不到第一步？** 这个风险是真的，取舍如下：

- 客户端区就在导入码下方，480 弹层里**首屏可见**（区块标题约在 330px 处），不需要滚动才发现；
- 标题 `还没有客户端？` 本身就是条件句：有客户端的人读到「可以跳过」，没有的人读到「往下看」；
- 如果反过来先列 6 个客户端，**已有客户端的人**（常见）要先滚过整张列表才看到码，主动作被挡在后面——这比新用户多看一眼更常见、代价更大；
- 再不确定的新用户还有底部的 `不会操作？问 AI`。

因此：**导入在前、客户端在后，且客户端区不折叠、不加编号。**

### 13.5 二级：就地展开

| 项 | 规则 |
|---|---|
| 形式 | **就地展开**（accordion），不用浮层、不用侧滑。理由见下 |
| 内容 | 左 104 下载码（白底、静区 12、圆角 8、1px `--hair`）+ 20 + 右列：`打开下载页 ↗`（13 / 500 / `--link`）。客户端的外部约束（如 iPhone 外区账号）只放行副行，面板里不重复 |
| 高度 | 展开块上下留 12 / 16；弹层自身滚动，不撑破 `max-height` |
| 同时展开 | **只允许一行**：打开另一行时自动收起上一行 |
| 收起 | 点同一行、或在展开时按 `Esc`（只收起，不关弹层）；再按一次 `Esc` 才关弹层 |
| 焦点 | 展开 / 收起后焦点留在该行按钮上；面板内只有 `打开下载页` 是 Tab 停点 |
| 下载码无障碍 | `alt=""` + `aria-hidden="true"`——`打开下载页` 是等价入口，读屏只读链接 |

**为什么是就地展开**：

- 浮层要在 480 弹层里再定位一个锚点，容易溢出弹层边界，还要额外处理 Esc 与焦点；
- 侧滑需要一个二级容器，480 宽里再切一刀太挤；
- 就地展开不需要新容器，同一时刻只开一个用 `aria-expanded` 就能表达，Esc 的优先级也简单：先收二级、再关弹层。

### 14.2 格式切换控件

| 项 | 规格 |
|---|---|
| 位置 | `导入节点` 标题下 12；切换器下 16 是二维码区 |
| 形态 | 三段分段控件：高 32、1px `--hair-strong`、圆角 6、13 / 500；选中段 `--card` 底 + `--ink`，未选 `--ink-2`；hover `--bg-hover`；`:focus-visible` 内侧 2px `--focus` |
| 宽度 | 按内容，三段等宽（每段约 72），**不撑满整行**；≤560px 仍单行，标签不折行 |
| 文案 | `sing-box` / `Clash` / `ss://`（与产品负责人口径一致；`Clash` 覆盖 Mihomo） |
| 语义 | `role="group" aria-label="导入格式"`；每段 `<button aria-pressed>`；Tab 依次可达 |
| 层级 | **不是主按钮**：描边分段、无实心底、不用 `--ink` 实心、不用品牌粉 |
| 默认值 | 每次打开弹层回到 `sing-box`；**不持久化**（切错了下次重开就回来） |
| 切换 | 二维码与 `复制链接` 的目标同时换成该格式；`复制链接` 在未加载时禁用 |
| 高度稳定 | 切换器固定 32、二维码区固定 160（骨架同尺寸）；右侧列 `min-height: 160`，不因文案长短跳 |
| 缓存 | 三个格式各自缓存结果；切回已加载格式立即显示，不重复请求 |
| 重新生成 | 作用域随令牌范围：账户级 → 清空三格式缓存；每格式一份 → 只清当前格式。确认文案随之变（§14.9） |

**为什么放二维码上方**：格式是二维码的属性，必须先读后扫；放在码下方等于扫完才看到选错了。

### 14.3 每格式的状态与内容

| 状态 | 切换器 | 码位 | 右列 |
|---|---|---|---|
| 未登录 | 可用（切了也没码） | 160 空位 | `先登录。` / `登录后可以把自己的节点导入手机。` / ghost `登录` |
| 已登录 · 没有 `ready` 服务器 | 可用 | 160 空位 | `还没有可用的服务器。` / `先在「我的服务器」里创建一台，再回来扫码。` / ghost `去我的服务器` |
| 就绪 | 可用 | 选中格式的 160 码 | `[复制链接]` `重新生成` + `链接相当于密码，别转发。` |
| 读取中（选中格式未加载） | 可用 | 160 骨架，`aria-busy` | `正在读取节点…` |
| 失败（选中格式） | 可用 | 不显示 | `这个格式暂时生成不了。` / ghost `重试` |

- 登录 / 服务器状态是**账户级**，三格式共享；只有「就绪」态的码与链接随格式变。
- 每个格式的内容由架构师定：sing-box 是 `sing-box://import-remote-profile?…`；Clash 大概率是订阅 URL（YAML）；`ss://` 是单条 URI 还是列表 URL **待架构师确认**。界面只负责随格式切换，不假设内容形状。
- `复制链接` 复制的是**选中格式**的 URL；未就绪时禁用。
- 切换时若上一个格式的请求还在飞，只显示当前选中格式的状态（结果按格式归属，不串台）。

### 14.4 客户端行：标注格式与点了就切

| 项 | 规则 |
|---|---|
| 副行 | `平台 · 格式`，一行。**当前只有 sing-box 官方上线**：`iOS / Android · sing-box`。Karing / Hiddify **行与副行一起等矩阵**——矩阵确认能吃 sing-box JSON 后才上线；在此之前列表只有 sing-box 官方一行 |
| 点击 | **展开二级 + 把导入格式切到该客户端的首选格式**；不弹确认。首选格式 = 副行里第一个 |
| 已选中同一格式 | 只展开，不重复切换、不播报 |
| 格式未核实 | **只展开，不切**——不猜 |
| 反馈 | 切换时 `aria-live="polite"` 播报 `已切到 sing-box 格式。`（视觉隐藏）；可见反馈是切换器选中段与二维码变化 |
| 二级面板 | 左 104 下载码（白底、静区 12、圆角 8、1px `--hair`）+ 20 + `打开下载页 ↗`（13 / 500 / `--link`）；**不放「用这个导入」**：行点击已经切过，切换器是手动覆盖，再放一个就是同一动作两个入口 |
| 同时展开 | 仍只允许一行；展开另一行会收起上一行 |
| 收起 | 点同一行或 `Esc`；`Esc` 先收二级、再关弹层 |

**为什么不做确认**：切换格式可逆、结果立刻可见（切换器与码都变了），为一个加分动作加确认只会打断。

### 16.1 为什么默认一行都不展开

产品负责人的前提变了：**用户不认识 `sing-box` / `Clash` 这类格式名，只认识自己在用的 App。** 一旦按 App 分类，弹层的第一屏就是「选哪个 App」，而不是「扫这个码」。

| 用户 | 默认不展开的代价 | 默认展开 sing-box 的代价 |
|---|---|---|
| 手机上已有 App 的人 | 多点一下自己那一行 | 少点一下，但先看到的是别的 App 的码，要先收起来 |
| 全新用户（还没装 App） | 看到完整列表，先装再导入 | **先看到一个能扫的码，扫了不会发生任何事**——他没有接收方 |

四条理由：

1. **默认展开会制造一个假的可执行动作。** 全新用户极可能需要先装客户端；默认亮出的码对他没有用处，而「扫了没反应」会被读成我们的 bug。
2. **默认展开会把弹层变成「sing-box 的页面」。** 这个弹层的产品定义是「选 App」；第一屏就给某一个 App 的码，等于我们替用户做了那次选择，而第 3 条说明我们没有依据做这个选择。（展开态约 730–760 高，在 768 高的窗口里还要滚动才看得到底部的归属句与 `问 AI`；不展开约 420，整张列表一屏可见。）
3. **没有哪一行配当默认。** sing-box 覆盖两个平台，但它在 iPhone 上要求大陆以外 Apple 账号；Shadowrocket 只在 iOS；CMFA 与 Hiddify 覆盖 Android / 双平台，却都不是唯一选择。把任何一行预先展开，都是替一类用户做了选择、对另一类用户是错的。
4. **成本极低。** 已装 App 的人只多一次点击，而这次点击本身就是选择；默认展开则是替所有人先选错一次。

因此：**默认一行不展开，第一屏是一张完整的选择列表。** 展开后的高度见 §16.4，滚动与焦点规则见 §16.9。

### 16.2 为什么按 App：机制

- 格式是**我们的**中间层：同一份节点，我们按矩阵生成三份 URL。用户要做的事只有一件——把它导入自己在用的 App，格式是派生的。
- 按格式分类会让用户做**只有我们知道答案的判断**：切错段，码在 App 里导入失败，看起来像是我们的 bug。按 App 选，映射写在代码里，选不错。
- 界面因此**少一个维度**：没有切换器、没有「已切到 X 格式」的播报、没有格式级的失败态。切换器原本是这三个控件里唯一需要解释的东西，现在整个消失。

### 16.4 展开面板：导入块

| 元素 | 规格 |
|---|---|
| 位置 | 行标题下 12；面板上下留 12 / 16；展开后整行约 360 高 |
| 布局 | 左 160 导入码 + 24 + 右列（`flex: 1`，`min-width: 230`） |
| 导入码 | 160×160，白底容器、静区 12、圆角 8、1px `--hair`；`alt="导入二维码"` |
| 图注 | **无**。行标题已经说明这是哪个 App |
| 右列 | `[复制链接]` `[重新生成]` 同一行，高 32，间距 12 |
| 安全说明 | `链接相当于密码，别转发。` 12 / 1.6 / `--ink-3`，**按钮下 16**；不底对齐、不设 `min-height` |
| 加载 | 展开时按行懒加载；每行独立缓存；收起再展开立即显示 |
| 重新生成 | **账户级**：在任何一行的面板里点，清空**所有行**的缓存与码；确认文案必须写明作用域（`重新生成后，手机上所有 App 的旧配置下次更新时失效。`） |
| 复制 | 复制**当前行**的 URL；未就绪时 `disabled` |
| 失败 | 只影响该行：`暂时生成不了。` + ghost `重试`；其他行不受影响 |
| 行级备注 | 只有 **Shadowrocket** 行有：导入块下 12，**整行宽**（不塞进 160 的码列），一句 `用它只能全部走节点，国内网站也会绕道。` 12 / `--ink-3`，与其他说明同规格，不加粗、不加图标、不拆两句；下载块在它下面 16 处。与码的状态无关，五态下都显示 |

**为什么导入在前、下载在后**：面板第一屏应该是用户来这里的目的——码。下载块是「还没装 App」时向下的一个分支，和处理方式和登录表单下面的「还没有账号？」一样；已经装好的人直接在上面扫，不用读它。

**为什么只有 Shadowrocket 有一句备注**：这一行与另外三行行为不同——它只能全局，另外三行会国内直连。不说的话用户以为都一样，等发现银行 App 打不开时已经踩坑。只加这一句：不解释原因、不出现「分流」、不写「节点会自动更新」之类的复述——这一行的唯一额外信息就是这句。

### 16.5 展开面板：下载块

| 元素 | 规格 |
|---|---|
| 位置 | 导入块下 16 |
| 布局 | 左 104 下载码 + 16 + 右列 |
| 下载码 | 104×104，同一白底规格；`alt=""` + `aria-hidden="true"`（`打开下载页` 是等价入口） |
| 右列 | `还没装这个 App？` 12 / `--ink-3`；下行 `打开下载页 ↗` 13 / 500 / `--link`（`↗` `aria-hidden`） |
| 可用性 | **与账号状态无关**，五态下都显示（下载不涉及节点，`mobile-export.md` §3） |
| 地址 | sing-box：`https://sing-box.sagernet.org/clients/`；Shadowrocket：`https://apps.apple.com/us/app/shadowrocket/id932747118`；CMFA：`https://github.com/MetaCubeX/ClashMetaForAndroid/releases`（不锁 tag）；Hiddify：`https://github.com/hiddify/hiddify-app` |

- **保持 104，不缩。** 内容是 38 个字符的 URL，104 是此前定的下限；白底码区再小时，手机在 25–30cm 处就有识别不稳的风险。布局放不下时**先减间距、不减码**——真机扫码失败一次的代价，远高于省下的十几像素。四条 App 行 + 兜底行让列表更长，也不能拿码的尺寸换空间。
- Shadowrocket 的下载页是**美区路径**，大陆 IP 访问可能被重定向到自家地区的商店首页（与 sing-box 的 App Store 链接同类风险，2026-11-19 实测 302 到 `/cn/iphone/today`）。界面按 PM 口径**不提示**，副行只写 `iOS`。

### 16.6 兜底行

| 项 | 规则 |
|---|---|
| 位置 | 列表最后一行，永远存在；没有副行、没有下载入口 |
| 文案 | `我的 App 不在列表里` |
| 展开 | 与其它行同一套手风琴规则（`aria-expanded`、只开一行、Esc 先收） |
| 内容 | `换一个上面列出的 App 就行，节点是同一份。不确定用什么，就问 AI。` 12 / 1.6 / `--ink-3`；**面板里不放按钮** |
| 出口 | 底部的 `不会操作？问 AI` 就在这行面板下方 20 内——展开后说明与 AI 入口上下相邻，不需要再放第三个入口 |
| 不写死的承诺 | 不说「以后会加」「暂不支持」，也不列未核实的 App 名 |

**为什么它必须在列表里，而不是靠底部那行 AI 链接兜住**：底部链接说的是「不会操作」，而这批用户的问题是「我的 App 不在你们的清单里」——不说清这一句，他们只会觉得自己的情况被无视了。兜底行是列表对它覆盖不到的人的正式出口。

### 16.7 五态

登录 / 服务器状态是**账户级**；「读取中」「失败」是**逐行**的（每行一个 URL）。下载块始终正常。

| 状态 | 导入块 | 右列 |
|---|---|---|
| 未登录 | 不显示，留 160 空位 | `先登录。` / `登录后可以把自己的节点导入手机。` / ghost `登录` |
| 已登录 · 没有 `ready` 服务器 | 不显示，同上 | `还没有可用的服务器。` / `先在「我的服务器」里创建一台，再回来扫码。` / ghost `去我的服务器` |
| 该行读取中 | 160 骨架，`aria-busy` | `正在读取节点…` |
| 该行失败 | 不显示 | `暂时生成不了。` / ghost `重试` |
| 就绪 | 该行 160 导入码 | `[复制链接]` `重新生成` + `链接相当于密码，别转发。` |

- **账户级提示只出现在展开面板里**，弹层顶部不写：第一层是选 App，账号状态与选哪个 App 无关；提到顶部会让「只想下载客户端」的人先读一段与他无关的账户说明。
- 面板里点 `登录` 关闭弹层并进入登录；登录成功后由用户重新打开弹层。**本期不做就地刷新**（2026-11-20 PM 决定）：它只影响「弹层打开时恰好未登录」这条低频路径，而就地刷新要重建弹层与已展开行的状态，属于新的状态机，不值得在本期引入。
- 任何状态下**行都可展开**，下载块始终可用——下载与账号无关。
- 四行共享账户级状态，但各自独立请求、独立缓存；一行的失败不波及另一行。

### 16.9 交互、键盘与无障碍

| 项 | 规则 |
|---|---|
| 行 | `<button aria-expanded aria-controls>`；名称与副行是可见文本；`›` `aria-hidden` |
| 面板 | `role="region"`，`aria-labelledby` 指向该行按钮；同一时刻只有一个 |
| 展开 / 收起 | 点同一行收起；展开另一行自动收起上一行；焦点始终留在被点的行按钮上 |
| 滚进可视区 | 展开后若行标题被遮住，滚到可见（`scroll-margin-top: 12`）；不跳到底、不居中 |
| Esc | 有展开行 → 收起该行，不关弹层；再按一次才关弹层 |
| Tab 顺序 | 关闭 → 行 1 →（展开时）复制链接 → 重新生成 → 打开下载页 → 行 2 → … → 兜底行 → 问 AI |
| 复制反馈 | `role="status"`，原位改字，不弹 toast |
| 重新生成 | 确认中初始焦点 `取消`；`Esc` 先取消确认、不关弹层 |
| 导入码 | `alt="导入二维码"`；**不含 App 名以外的内容**，不含 URL 与令牌 |
| 下载码 | `alt=""` + `aria-hidden="true"`；不可聚焦 |
| 令牌 | 不出现在任何可见文本、`alt`、`title`、`aria-label` 里；只在码的内容中 |
| 颜色 | 不只靠颜色：展开有箭头转向与面板出现，失败有文字，复制成功有文字 |
| 深色 | 两个码的白底容器不跟随主题；`--link` 深色 #F48FB1；副行与归属句在卡片上 ≥4.5:1 |
| 减少动效 | `prefers-reduced-motion` 下箭头不转、面板不淡入 |
| 窄屏（≤560） | 面板：码居中、右列在下（复制 / 重新生成 / 安全说明），下载块 104 + 16 + 文字仍可并排（392 − 104 − 16 = 272）；行与副行不重排，副行超长时省略并给 `title` |

**格式词禁用清单（落地自查项）**：界面上不得出现 `sing-box 格式`、`Clash 格式`、`Clash`（单独出现时）、`ss://`、`Clash YAML`、`Mihomo`、`订阅`、`分流`；只允许 App 产品名本身（`sing-box`、`Clash Meta for Android`）。检查范围包括可见文本、`alt`、`title`、`aria-label`、播报文本。

### 16.10 内部映射（不出界面）

| 行 | 内部格式 | 界面表现 |
|---|---|---|

### 17.2 sing-box 的推荐标签

产品负责人在 iPhone 上用官方客户端（App Store 的 sing-box MT）实测通过，界面要有倾向。

```
│  sing-box  推荐                                    ›  │
│    iPhone（需大陆以外 Apple 账号）/ Android            │
```

| 项 | 规格 |
|---|---|
| 形态 | 名称右侧一个 18 高的弱标签：文字 `推荐`，11 / 500 / `--ink-2` |
| 尺寸 | 高 18、内边距 0 6、圆角 4、1px `--hair-strong` 描边、背景透明、`margin-left: 8` |
| 对齐 | 与名称同一行、垂直居中；`flex: none`，名称过长时先省略名称 |
| 不做 | 不用 `--link` / 品牌色、不填充、不可聚焦、不 hover、不加图标 |
| 无障碍 | 是纯文本，读屏把它并进行名：`sing-box 推荐，iPhone（…）/ Android`；不设 `role`、不当按钮 |
| 其余行 | 不加任何标记；「没有标签」本身就是默认 |

**为什么用标签，不用横幅或彩色按钮**

1. **推荐只属于一行**。横幅会重新排布整屏、把列表压下去，用一屏的空间表达一个属性；标签就在那一行上。
2. **副行已经满了**。`iPhone（需大陆以外 Apple 账号）/ Android` 是这一行唯一的判断依据；再塞「已实测可用」既挤，又是一句要对每个平台版本都保真的承诺。`推荐` 是我们的倾向，不是技术保证。
3. **不能看起来能点**。彩色/实心按钮会招来一次没有结果的点击；18 高的描边小字在这一行里与副行同层级，读起来是标签不是操作。
4. 它不改变默认不展开的决定：标签是静态的，不替用户展开任何一行。

### 17.4 弹层结构：标题 / 滚动区 / 固定页脚

```
┌ 在手机上使用                                        × ┐   ← 固定
│                                                      │
│  选你手机上用的 App，还没有就先装一个。                 │   ← 以下滚动
│  sing-box  推荐                                     › │
│    iPhone（需大陆以外 Apple 账号）/ Android            │
│  ────────────────────────────────────────────────    │
│  …                                                   │
├──────────────────────────────────────────────────────┤   ← 固定页脚
│ 这些 App 不是我们开发的，Veyl 只提供节点。  不会操作？问 AI │
└──────────────────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 弹层 | `display: flex; flex-direction: column; overflow: hidden`，`max-height: min(86vh, 780px)` 不变 |
| 标题区 | `modal__head` 不滚动 |
| 滚动区 | `.mobile-export__body` 接管滚动（`overflow-y: auto; flex: 1`），左右内边距 20，**去掉底部 20** |
| 页脚 | 常驻、不滚动：上一行 1px `--hair`，内边距 12 20，底色 `--bg-card` |
| 页脚内容 | **一行两件**：左 `这些 App 不是我们开发的，Veyl 只提供节点。` 12 / `--ink-3`；右 `不会操作？问 AI` 13 / 500 / `--link`，`flex: none`，间距 16 |
| 页脚高度 | 约 42（18 文字 + 上下 12），比原来两行分开时省约 30 |
| 窄屏（≤560） | 页脚仍是两件一行；放不下时左句省略为一句话中间截断 + `title` 全句，不换行、不把 AI 挤到第二行 |

**为什么把归属句和 AI 放进同一行**：它们是同一层——「这堆 App 不是我们的」+「不行就问 AI」，都是弹层的兜底说明；合成一行既省 30 高，也让常驻页脚不至于占掉太多滚动区。

**为什么必须是常驻页脚**：R1 的根因是内容超过弹层高度，而 AI 入口在最后。只要它跟着内容滚，任何一次展开都可能把它推出去；吸底之后，无论展开哪一行、滚到哪里，AI 都在。

## 18. v5：两个编号步骤 + 无服务器状态（2026-11-20）

> 依据：`ui-ux-pro-max` 检索（`ux` 域：Progress Indicators、Empty States、User Freedom；`web` 域：Modal Escape；检索结果见 §18.10）；产品负责人对 v4.1 实机截图的意见；`src/components/MobileExport.tsx` 的当前实现。只出设计与文案，不改代码、不发截图、不提交。

### 18.0 结论

| 问题 | 结论 |
|---|---|
| 一、顺序不清楚、观感偏小气 | **采用 A**：保留弹层，展开面板重排为**两个编号步骤**——① 还没有 App？先下载 → ② 用这个 App 扫码导入，下载在前、导入在后。**否决 B（中间详情页）与 C（弹层加宽到 640）**，理由见 §18.1 |
| 二、没有可用付费服务器 | 弹层照开、App 列表与下载照常；② 的内容换成说明句 + `去创建服务器`；**不显示空码位 / 骨架**，**不显示复制与重新生成**（§18.3） |

**为什么问题一不是「加个标题」这么简单**：现在用户看到的是「一张大码 + 一张小码 + 一句问句」，两张码在同一面板里没有先后；编号是把「先装再扫」这件事写进结构，而不是写进一句提示。

### 18.1 三种形态的比较

| 维度 | A 弹层 + 两个编号步骤 | B 中间详情页 | C 弹层加宽到 640 |
|---|---|---|---|
| **理解成本** | 编号直接给出顺序；① 的标题自带条件（「还没有 App？」），已有 App 的人一眼知道跳过；两张码靠数字分先后，不靠位置猜 | 空间大，但多一层「进入 / 返回」；从设置进来时先关设置弹层再开页面，用户丢了原地的位置；**顺序本身仍要靠编号解决**，页面只是把同样两块放大 | **不解决顺序**：不加编号就和现在一样；加了编号就等于 A，只是更宽。而 640 的两步也并排放不下（① 约 264 + ② 约 414 > 内容宽 600），布局与 480 完全一样 |
| **实现成本** | 低：重排现有面板 + 两个步骤标题 + 编号徽标；不动入口、不动状态机、不动两个开弹层的地方 | 高：新页面或新 destination、两个入口都要改、返回与焦点、设置弹层与页面叠加的返回路径、额外测试 | 低（改一个数字），但收益接近零 |
| **现状一致性** | 与 v2 起定下的「设置行 + 左栏快捷行，开同一个 480 弹层」一致 | 与现有设置体系（设置本身是弹层）不一致；「我的服务器」左栏的快捷行也会变成跳页，两处行为分叉 | 480 是本弹层定过的宽度；settings 用 640 是因为它有四段导航，本弹层没有 |
| **结论** | **采用** | 否决 | 否决 |

**B 被否决的具体理由**

1. 产品负责人的原话是「如果在中间详情页显示，可能会更大气」，但也说明仅供参考——这是观感判断，不是流程要求。
2. 「大气」的根因是**两块没有标题、重量接近**，不是容器太窄。把同样两块搬进 900 宽的页面，仍然是一张码接一张码；加宽能让 ① ② 并排的唯一尺寸是 ≥900，而那要多一层导航才能换来。
3. 入口有两个（设置 › 账户、左栏底部），都要改成「跳页 + 能回来」；设置本身是弹层，从弹层里跳页会打断当前上下文。
4. 这个任务是两次扫码、几十秒完成的一次性操作，不是需要来回查看的工作区。

**C 被否决的具体理由**

- 宽度不是顺序问题的解：600 的内容宽放不下 ① + ② 并排，最终仍是上下两块。
- 480 → 640 会让行列表与说明句的留白变大，但二维码不变大（码的尺寸由扫码距离决定，不由容器决定），观感改善有限。
- 若将来内容继续长（多服务器、分平台步骤），再考虑 B；现在不为此改造。

**A 的代价（写在这里，不藏）**

- 导入码从第一位移到第二位，已有 App 的用户每次展开都要先看到一小块下载区。抵消它的两点：① 的码只有 104，是面板里最小的一块；① 的标题是条件句（`还没有 App？`），一眼就知道可以跳过。
- 面板高度增加约 60（两个步骤标题），展开态约 770–780，正好顶到 `min(86vh, 780px)`；固定页脚（§17.4）保证归属句与 `问 AI` 始终可见。

```
│  sing-box  推荐                                    ⌄  │
│    iPhone（需大陆以外 Apple 账号）/ Android            │
│                                                       │
│  ①  还没有 App？先下载                                 │
│     ┌──────┐   打开下载页 ↗                            │
│     │ 104  │                                          │
│     └──────┘                                          │
│                                                       │
│  ②  用 sing-box 扫码导入                               │
│     ┌────────────┐  [复制链接]  [重新生成]              │

│     └────────────┘                                    │
```

| 元素 | 规格 |
|---|---|
| 步骤标题 | `<h3>`：编号徽标 + 文字；文字 13 / 500 / `--ink`；标题与块之间 8 |
| 编号徽标 | 20×20 圆、1px `--hair-strong`、数字 11 / 600 / `--ink-2`、居中；`aria-hidden="true"`（读屏只读标题；顺序由标题里的「先下载」与文档顺序表达） |
| 步骤间距 | ① 块底 → ② 标题 20；块内标题 → 码 8 |
| ① 标题 | `还没有 App？先下载`（所有行一致） |

| ① 块 | 104 码（白卡 128，描边 1px `--hair`，与导入码同一套）+ 16 + `打开下载页 ↗`（13 / 500 / `--link`） |
| ② 块 | 160 导入码 + 24 + 右列（复制 / 重新生成 + 安全句），沿用 §16.4 |
| 删除 | `还没装这个 App？` 这行小字——它的意思已经由 ① 的标题承担，不再重复 |
| Shadowrocket 行备注 | 仍在 ② 块之后，12 / `--ink-3` |
| Tab 顺序 | 行 →（展开）① 的 `打开下载页` → ② 的 `复制链接` → `重新生成` → … ——与视觉顺序一致 |
| 收起 / Esc | 不变（点同一行收起；Esc 先收面板、再关弹层） |

**为什么 ② 的标题要带 App 名**：这一步是在那个 App 里完成的动作；标题写成 `用 sing-box 扫码导入`，用户不会把 ① 的下载码和 ② 的导入码搞混。

### 18.3 没有可用付费服务器时

弹层照常打开，列表与 ① 照常可用；**只有 ② 的内容换掉**。

```
│  ②  用 sing-box 扫码导入                               │
│     手机端只能导出你自己创建的付费节点。免费和试用节点不包含。  │
│     [ 去创建服务器 ]                                    │
```

| 项 | 规则 |
|---|---|
| 触发 | 已登录但没有 `ready` 的付费服务器（`hasReadyServer` 为假） |
| ① 装 App | **照常可用**：码与 `打开下载页` 都保留。装 App 与有没有服务器无关，藏起来只会让用户多跑一趟 |
| ② 块 | 不显示二维码、**不显示 160 空位、不显示骨架**——空位会被读成加载失败 |
| 说明句 | `手机端只能导出你自己创建的付费节点。免费和试用节点不包含。` 12 / 1.6 / `--ink-3` |
| 动作 | ghost `去创建服务器`：关闭弹层并跳到「我的服务器」。按钮说的是「创建」——若该页 `＋` 能就地展开建机向导，落地时一并展开更贴合文案；不能就直接落列表，由用户点 `＋` |
| 不显示 | `复制链接`、`重新生成`、安全句（没有码，就没有可复制的链接） |
| 登录态 | 不变：② 显示 `先登录。` / `登录后可以把自己的节点导入手机。` / `登录`；登录成功后就地刷新，不关弹层 |
| 失败态 | 不变：`暂时生成不了。` + `重试` |

- **为什么说明句放在 ② 里而不是弹层顶部**：弹层顶部是「选哪个 App」，与账号状态无关；提示提到顶部会让只想装 App 的人先读一段与他无关的账户说明。② 正是「导出节点」这一步，说明它为什么暂时做不了，位置就是它该在的地方。
- **为什么用 `去创建服务器` 而不是 `去我的服务器`**：用户在这里的问题不是「看服务器」，是「还没有服务器」；动词直接给下一步。

### 19.1 三个决定与理由

**① 为什么下载码是 104，不按建议缩到 88–96**

- 生成端是 `qrcode 0.14`，`render()` 默认带 **4 模块静区**；SVG 边长 S 时单模块边长 = S / (模块数 + 8)。
- Shadowrocket 的下载页 URL 57 字符 → 版本 4（33 模块）：104 / 41 ≈ **2.5 px/模块**；88 / 41 ≈ 2.1；80 / 41 ≈ 1.95。
- 屏幕上 25–30cm 扫码的经验下限在 2.5 px/模块左右，所以 **104 是底线**；88 会退回到产品负责人上一轮明确否掉的位置。
- 顺带修一个真实问题：现在是「白卡 104 + 图 80 + 内边距 11」，码实际只有 80——这次改为**图铺满白卡**（静区已经在 SVG 里，不需要再留内边距），同一张 104 卡里的码从 80 涨到 104。
- 「轻」用布局来做（紧凑行、限宽、两行文字），不用缩码。

**② 为什么 ① 块限宽 380、不拉满**

- 拉满会让 ① 变成一条整宽带子，和 ② 的整宽并列，层级又平了——这正是「两块像平级的两步」的来源。
- 限宽后 ① 读作「② 的前提」，右边剩下的 200 属于面板边距，不属于这一行缺内容。
- 备选（实机看仍松时再上）：在 ① 与 ② 之间加一条 1px `--hair` 分隔线，不改变布局。先不加——面板内多一条线就多一个要解释的元素。

**③ 为什么安全句在码下方**

- 它说的是「这个码 / 这条链接相当于密码」，主语是码；放在码正下方、与码同宽，就是一组「码 + 图注」，而不是从右列掉出来的脚注。
- 右列因此只剩「步骤标题 + 两个按钮」，也不再出现空行。

## 20. v6.1：下载码 104 → 120（2026-11-20 真机反馈）

### 20.1 触发

产品负责人真机扫描 `Shadowrocket` 的下载码：第一次扫无反应，**再扫一次可以打开**；同一行「打开下载页」的链接始终正常。

### 20.2 定位

- 链接与二维码同源：两者都取 `CLIENTS_URLS`（`src-tauri/src/control_plane/mobile.rs` §35），`qr_data_url(url)` 编码的就是这个字符串。内容不存在第二种可能。
- 尺寸才是变量。Shadowrocket 的 URL 57 字符 → 版本 4（33 模块），104 / (33+8) = **2.54 px/模块**，正好压在 §19.1 写的「25–30cm 经验下限 2.5」上。间歇失败＝在阈值上飘。

### 20.3 改法

| 项 | v6 | v6.1 |
|---|---|---|
| 下载码（白卡 + 图） | 104 | **120**，模块 2.93 px |
| 导入码 | 200 | 200（不动） |
| ① 的块结构 | 码 + 20 + 文字、限宽 380 | 不动；块高随码到 120 |
| 面积比 ① : ② | 0.27 | 0.36（仍是「前提 → 主动作」） |

### 20.4 边界

- 120 仍是估计值，不是验证结论：真机需复扫确认「第一下就中」。若仍偶发失败，下一档是 128（3.12 px/模块），再往上就破坏 ① 的从属地位。
- 收起高度不变（① 只在展开态出现）；展开高度 +16，仍被 88vh 封顶，占用的是列表的滚动余量。
- 不做：把下载码提到与导入码同级、或在界面里加「请多扫几次」这类说明——链接已经是等价入口。

## 21. v7：Shadowrocket 导入入口提示（2026-11-24）

### 21.1 触发

真机把弹层里的 Shadowrocket 导入码拿到首页扫，Shadowrocket 提示「无法获取订阅节点」。

### 21.2 定位

- 那条 URL 返回的是 Surge 风格配置（`mobile-export-technical.md` §3.7.13），不是节点列表。Shadowrocket 的「订阅」入口只解析 `ss://` 等节点链接、Base64 列表或 Clash YAML，**不认 `[Proxy]` / `[Proxy Group]`**，所以首页扫码必然失败。
- 11-21 的真机通过走的是「配置 → 扫码」：同一份配置从「配置」页导入是合法的。§16.13 的备注 `用它只能全部走节点` 写于「只发 ss」时期，已被 §3.7.13 的带规则配置取代，不采用。

### 21.3 改法

| 项 | 内容 |
|---|---|
| 文案 | Shadowrocket 行导入块下方加一句：`先在 Shadowrocket 里打开「配置」页，再扫码导入。` |
| 位置 | 整行宽，导入块下 12；安全说明在它下面 |
| 规格 | 13 / 1.6 / `--ink-3`，与步骤说明同规格；只在该行有码时显示 |
| 其它行 | 不显示。sing-box / CMFA / Hiddify 的码本身就是订阅或深链，没有这个前置动作 |

### 21.4 边界

- 不改后端格式：产品口径仍是「国内直连、其余走节点」，Surge 配置是唯一同时带节点与规则的载体；退回 `ss://` 订阅会把全部流量送进节点。
- 不新增客户端深链：`shadowrocket://` 只覆盖「添加订阅」，没有可靠的「添加配置」scheme，不猜。
