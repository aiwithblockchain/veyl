## 1. 结构：状态在上，事实在中，动作在下

三段固定，任何状态都按这个顺序；状态区随状态换内容，事实区与操作区位置不动。

```
纽约                                 ● 安装服务端 · 已等待 2 分 38 秒
                                                      ← 24
[━━━━━━━━━ ━━━━━━━━━ ▓▓▓▓▓▓▓▓ ░░░░░░░░░]
第 3 步，共 4 步 · sing-box 1.10.0 · 通常 2–4 分钟
                                                      ← 32
地区        纽约
流量        每月 1000 GB 出站
                                                      ← 32 + 1px hair
[取消创建]                                            ← 危险操作在最左
```

- **阶段词只出现一次**：就是头部状态行里的那一个词；进度块不再有自己的标题，也不再有四个阶段词列表。
- **两个时间事实分开住**：已等待在头部状态行（12 mono `--ink-2`），典型时长在进度块说明行（12 `--ink-3`），不再并排。
- 状态区之后固定 32 的呼吸；操作区上方固定一条 `1px --hair`，销毁不再裸挂在页面最下方。

### 1.1 进度条语义（四段 = 四阶段）

| 段 | 颜色 | 含义 |
|---|---|---|
| 已完成 | `--ink` 实心 | 这四步里的第 1…N−1 步 |
| 当前 | `--accent` 实心 | 正在走的这一步 |
| 未到 | `--hair` | 还没开始 |

- 高度 6、段间距 4、圆角 3；去掉现在的流光动画——进度靠颜色和说明行表达，不靠动画。
- 说明行写 **「第 N 步，共 4 步」** + 次要事实：安装中带 `sing-box {version}`；未超时写「通常 2–4 分钟」，超时改写成「这一步已经 {m} 分钟，还在继续。」（两者只出现一个）。
- 无障碍：整组 `role="progressbar"`，`aria-valuemin=1`、`aria-valuemax=4`、`aria-valuenow=N`，`aria-label` 为「建机进度」。

## 5. 失败的可重试 / 不可重试

- 动作**不按 `failure.retryable` 分支**：两种情况都只有「重新建一台」这一条真实路径——`my_server_rebuild` 目前恒 `rebuild_not_supported`（`commands.md` 2.36.1），控制面也没有原地重试端点；造一个「重试」按钮就是兑现不了的按钮。
- 区别只在说明句：可重试加一句「可以再建一台试试。」；不可重试给 code 专属原因，不加这句。
- **现状提醒**：`servers.ts:176` 现在恒写 `retryable: false`，所以可重试分支今天是死代码；等后端真的会写 `true` 再放开这句文案。

## 7. 验收点

1. **无重复**：当前阶段词只在头部出现一次；`已等待` 只出现一次；`通常 2–4 分钟` 与超时句互斥；进度块不再有阶段标题或四个阶段词列表。
2. **进度可读**：四段与四阶段一一对应，`aria-valuenow` 等于当前步；填充只有 `--ink` / `--accent` / `--hair`，`--ok/--warn/--err` 只用于状态点与文字。
3. **字段按态显隐**：建机中只有地区 + 流量；失败只有地区 + 费用结论；就绪五行；墓碑零行；不出现 `未就绪`、`创建中，开通后开始计费` 这类占位句。
4. **动作可兑现**：每个失败 / 欠费都有主按钮（重新建一台 / 去充值）；不出现原地「重试安装」；销毁恒为 danger-ghost + 二次确认，建机中写「取消创建」。
5. **中英文**：两种语言下状态行与说明行都不折行溢出；`role="status"` / `role="alert"` / `progressbar` 语义齐全。
