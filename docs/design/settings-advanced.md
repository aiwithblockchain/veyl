# 设置页重做：按用户任务分区

> 日期：2026-11-06
> 状态：目标设计，待确认后实现
> 范围：设置页整体信息架构与文案；替换旧版 `settings-advanced.md`
> 依据：用户原话「把核心的功能和操作展示给用户，展示的时候要方便用户理解，大部分人都不理解这些设置的意思。」

---

## 0. 诊断：问题不在措辞，在结构

旧界面按「系统零件」分区：账号与 AI / 网络 / 高级 / 关于。
用户打开时面对的是四个模块名，而不是四个他能完成的任务：

- 「高级」里同时放着自动升级的程序、Veyl 提供的节点、后台服务、诊断和强制修复——没人知道该不该看。
- 「测试节点」「运行时」「后台组件」都是实现名词，标题不说明点下去会发生什么。
- 同一个 Key 有「基础 / 高级」两套界面；同一个节点更新有两个入口。
- 维护类项目（升级、诊断）和日常设置混在一起，是「看不懂」的主要来源。

**重做原则**（本稿所有决定都按这四条检查）：

1. **按用户想做什么分 tab**，不按模块分。
2. **每行标题是「动作」或「问题」**，不是名词。
3. **每行至少回答三问中的两个**：它是什么（一句人话）、什么时候需要动它、动了会怎样。答不出来的行不出现。
4. **维护类默认收起**：连接程序升级、后台组件、诊断放进「遇到问题再看」的区域，区域内第一句写明「平时不用改」。

## 1. 目标信息架构

四个 tab，每个名字都是用户会说出口的短语：

```
设置
├─ AI 助手         AI 用哪个服务、哪个模型；怎么换、怎么加
├─ 连接            现在怎么连、用哪个节点、Veyl 免费节点、导入节点
├─ 遇到问题        平时不用改；出问题时修复、更新、看诊断
└─ 关于            版本与开源信息
```

逐 tab 内容：


## 2. 逐 tab 设计

每行后面的小表回答「它是什么 / 什么时候动它 / 动了会怎样」。

### 2.1 AI 助手

用户问的是「AI 用哪个服务、哪个模型，怎么换」。这个 tab 只做这一件事。

```
AI 助手

用哪个 AI 服务
AI 助手用这里的服务回答你；换服务或换模型都在这里。

┌──────────────────────────────────────────────┐
│ DeepSeek · deepseek-chat            当前     │
│ https://api.deepseek.com      [测试] [编辑]  │
├──────────────────────────────────────────────┤
│ OpenAI · gpt-4o-mini                         │
│ https://api.openai.com  [设为当前] [测试] [编辑] [删除] │
└──────────────────────────────────────────────┘

[ 添加 AI 服务 ]

请求会发往你填写的服务地址。切换服务会开始一个新会话，之前的对话不会带过去。
```

| 行 | 它是什么 | 什么时候动它 | 动了会怎样 |
|---|---|---|---|
| 用哪个 AI 服务 | AI 助手当前使用的服务与模型 | 想换服务商或换模型 | 切换后从头开始一个新会话 |
| 添加 AI 服务 | 新增一个可用的 AI 服务 | 现有服务不够用、想接自己的服务 | 保存后可设为当前；没 Key 的服务不能切换 |
| 说明 | 请求发送的目标与会话影响 | ——（说明） | —— |

**删除**：

- 「基础 / 高级」API 模式切换。同一个 Key 的两套界面（基础视图与内置 provider）合并成服务列表里的一项；
  引导页写入同一个服务存储，不再产生第三个入口。
- 基础视图里单独的 DeepSeek Key 表单。编辑「DeepSeek」这项即可，模型也能在这里改——解决「基础模式不能选模型」。
- 「刷新」按钮。列表在打开时自动读取。

**保留**：预设、表单校验、测试连接、删除确认、切换后重建会话的提示（现在放在列表上方，一句话）。

### 2.2 连接

> 2026-11-06 起，连接屏已被 `docs/design/settings-connection.md` 取代；本节仅作历史参考。
> 2026-11-11 起，**分区名与行序以 `docs/design/settings-ia.md` 为准**；本节与 `settings-connection.md` 里与它冲突的行（如「用哪个节点」）均已废止。

用户问的是「网络怎么连、用哪个节点、节点从哪来」。连接/断开按钮仍只在主界面，不在这里重复。

**全部流量配置：**

```
连接

现在怎么连
全部流量走 VPN
连接方式在新建配置时确定；想换需要新建一套配置。

用哪个节点
东京 01
在主界面点节点行可以切换。

更新 Veyl 免费节点
Veyl 提供的 12 个节点 · 3 小时前检查过      [ 检查更新 ]

导入节点文件
把别处的节点文件拖进来，或选择文件。        [ 选择文件 ]
```

**代理模式且已连接：**

```
现在怎么连
只有设置了代理的软件走 VPN
127.0.0.1:2080                              [ 复制 ]
浏览器已经设好了；其它软件按上面的地址填。
连接方式在新建配置时确定；想换需要新建一套配置。
```

**没有配置：**

```
现在怎么连
还没有配置
先在左侧新建一套配置，再回来这里看。
```

| 行 | 它是什么 | 什么时候动它 | 动了会怎样 |
|---|---|---|---|
| 现在怎么连 | 当前配置的连接方式 | 想换方式时（只能新建配置） | 新建配置时选择；已有配置不受影响 |
| 用哪个节点 | 当前使用的节点 | 想换节点 | 在主界面切换；这里只显示，不重复入口 |
| 更新 Veyl 免费节点 | Veyl 提供的节点池 | 想补节点、更新失效节点 | 拉取后节点数更新，下次连接生效 |
| 导入节点文件 | 从本地文件加入节点 | 有别的节点想用 | 只增不删；文件含共享凭据，不要外传 |

**沿用已定结论**：

- Veyl 免费节点一行只留：有多少个、上次什么时候检查过、检查更新；不显示版本号，不挂「问 AI」。
- 「3 小时前检查过」写成完整句子；从未检查时「从未检查过」。
- 节点切换入口不在这里重复；这里只显示当前节点，并说明去哪切。

### 2.3 遇到问题

用户问的是「出问题怎么办」。这个 tab 先把预期说清，再把维护项收起来。

```
遇到问题

这里的东西平时不用改。连不上网、打不开网页时再看。

修复网络

清除残留代理
已经断开 VPN，但仍上不了网时用。不会影响「全部流量」的接管。
                                        [ 清除残留代理 ]

┌ 强制重置网络 ────────────────────────────────────┐
│ 网络出问题时用。停掉 Veyl 的后台服务，把网络恢复   │
│ 到没有 VPN 的状态；不会删除配置和节点。            │
│ 先试上面的「清除残留代理」；还是不行，再用这个。   │
│ 能正常上网时不要用。只想断开连接，回主界面点       │
│ 「断开 VPN」。                                    │
│                                  [ 强制重置网络 ] │
└──────────────────────────────────────────────────┘

▸ 更新与诊断    平时不用管，升级或排查时再展开
```

展开后：

```
▾ 更新与诊断

连接程序
真正建立连接的程序。
已是最新 · 版本 1.14.4
暂时连不上更新服务器，继续用自带的版本。   [ 再试一次 ]
有新版本 1.15.0（约 12 MB）                [ 升级 ]
正在使用 1.15.0（自带 1.14.4）             [ 换回自带的版本 ]

更新后台组件
接管全部流量时要用的系统服务。
已是最新（2026.11.1）
需要更新：连接「全部流量」时会请求一次系统授权。   [ 更新 ]

打开日志
在文件管理器中定位最近的日志文件。          [ 打开日志目录 ]

复制诊断信息
复制当前状态，便于排查问题；不包含 Key。     [ 复制诊断信息 ]
```

| 行 | 它是什么 | 什么时候动它 | 动了会怎样 |
|---|---|---|---|
| 清除残留代理 | 清掉系统里指向 Veyl 的残留代理设置 | 已经断开但仍上不了网 | 撤代理、删临时配置；不停「全部流量」 |
| 强制重置网络 | 把网络恢复成没有 VPN 的状态 | 上面的方法都无效 | 断开连接、停后台服务、恢复代理/路由/DNS；不删配置 |
| 连接程序 | 真正建立连接的程序 | 有新版本时 | 升级后下次连接生效；失败保持现有版本 |
| 更新后台组件 | 接管全部流量用的系统服务 | 需要管理员授权时 | 请求一次授权并更新；成功/失败回到原行 |
| 打开日志 | 最近的日志文件 | 需要发给支持人员时 | 在文件管理器中定位文件 |
| 复制诊断信息 | 当前状态摘要 | 排查问题、发给助手时 | 复制到剪贴板，不含 Key |

**沿用已定结论**：

- 连接程序：正常态无操作；有新版本只有一个「升级」；检查失败一句「暂时连不上更新服务器，继续用自带的版本。」+「再试一次」；删除「用随包版本继续」与「取消」。
- 打开这个 tab 时自动检查一次连接程序更新（只取版本清单、不下载；断网按失败态显示，不额外请求别的网络）。
- 后台组件：自动更新；正常态无操作；**`needs_admin_restart` 时保留一个 ghost「更新」**，点击触发授权与更新；
  更新中禁用并显示「更新中…」，成功或失败都重新读取状态、回到原行（取消授权则仍显示需要授权的说明）；
  显示 `helper_version`。
- 强制重置网络：独立危险区域、危险描边 + 危险色标题、`danger-ghost` 按钮；确认弹层保持二次确认。
- 清除残留代理：由「恢复直连」改名；归入修复组；只在适用时出现（无残留且非代理配置时不显示；
  当前正连着代理时也不显示，断开后仍有残留再自动出现）。
- 首次引导：不在正式界面出现，只在 DEV 构建的「更新与诊断」里保留。

## 3. 10 秒自评

假设一个从没用过 Veyl 的人打开设置，逐 tab 自评：

| tab | 10 秒内能否说出 | 结论 |
|---|---|---|
| AI 助手 | 「这里管 AI 用哪个服务、哪个模型，能加新服务」 | 通过。服务列表第一屏就能看到当前项与模型 |
| 连接 | 「这里看现在怎么连、用哪个节点、怎么更新/导入节点」 | 通过。四行各答一件事，没有实现词 |
| 遇到问题 | 「平时不用动；连不上时先清残留代理、再强制重置；更新和诊断收在下面」 | 通过。首句设定期望，维护项默认收起 |
| 关于 | 「看版本、找源码和反馈」 | 通过，但内容最少；如果暂时没有开源入口，只保留版本也成立 |

**上一版过不了的地方与本版的改法**：

1. 旧「高级」首屏是「运行时 / 测试节点 / 后台组件」——10 秒内说不出这些是什么。→ 移入「遇到问题 → 更新与诊断」，默认收起。
2. 旧「网络」里「恢复直连」看起来像断开按钮。→ 改名「清除残留代理」，移入修复组。
3. 旧「账号与 AI」有基础/高级两套——10 秒内分不清该用哪个。→ 合并成一个服务列表。

## 8. 前置与协调

1. **自动检查连接程序更新**：打开「遇到问题」时自动调用一次 `core_check_updates`（只取版本清单，不下载安装包），
   在后台进行、不阻塞页面；先显示已知版本，检查返回后再更新状态。断网时后端会回退到本地缓存并标记 `cached`，
   界面统一按失败态显示「暂时连不上更新服务器，继续用自带的版本。」+「再试一次」，不拿缓存结果提供升级。
   不额外请求其它网络。
2. **后台组件版本号**：`tun/backend.rs` 已返回 `helper_version`，只是前端 bridge 没透传。
   在 `bridge.ts` / `tauriBridge.ts` 暴露即可，不新造字段。
3. **清除残留代理的可见条件**：前端目前读不到 `applied_endpoint`。
   先用现有信号：代理模式且未连接，或 `system_proxy_enabled` 为真且运行时不在一起；
   后端若暴露残留标记，再加「任何模式下有残留」。
4. **首次引导 DEV 门控**：沿用 `import.meta.env.DEV`；测试环境默认开启，需要时在用例里关闭。
5. **开源/反馈链接**：需要产品提供最终 URL；没有则「关于」只保留版本。
6. **当前节点名称**：设置页目前只拿到 `connectMode`。显示「用哪个节点」需要从 `App` 传入
   `vpn.activeConfig`（按 `current_node_id` 找名称），不新增命令。
7. **引导页与设置的关系**：引导页仍会保存 Key 或创建自定义服务，它写入同一个服务存储；
   设置的服务列表会显示同一项，因此设置里不再需要独立的 DeepSeek Key 表单。

## 附录：事实核对与状态矩阵

保留自上一版，供实现时对照；结构变了，事实与状态不变。

### A.1 清除残留代理的真实行为

- `repair_restore_direct`（`services.rs:5578`）只做三件事：撤销系统代理、删掉临时配置文件、探测直连 IP。
- 它调的 `manager.stop()` 只停止 App 自己起的运行时；**TUN 的进程由后台组件持有，这条路径停不掉**。
- 对「全部流量」用户，这个按钮除了清一下残留代理，基本什么也没做——所以文案不写「停止运行时」。
- 可见条件（命中即显示）：
  1. 系统里确实有 Veyl 写过的代理残留（后端 `applied_endpoint` 非空，且运行时不在一起）；
  2. 当前配置是代理模式，且当前未连接；
  3. 当前配置是代理模式，`system_proxy_enabled` 仍为真且运行时不在一起。
- **当前正连着代理时不显示**：一个叫「清除残留」的按钮把正在用的连接断掉，会让人不再信任这类按钮；
  断开后如果仍有残留，它会自动出现。
