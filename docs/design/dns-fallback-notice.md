# 连接降级提示：系统 DNS 没接管

> 后端字段：`RuntimeSnapshot.system_dns: "tunnel" | "unchanged" | null`（`docs/contracts/runtime.md` §2.5，2.6.0 新增）。
> 本文只定界面；不改代码，不提交。

## 1. 结论

**落点：中间控制台的 AI 编排区，新增一个系统叠加块 `dns_note`。** 不放进顶部状态区，也不做成底部节点详情的一部分。

- 顶部状态区只回答「连没连上」，状态词与主按钮已经在用；再挂一行会把它变成状态面板。
- 底部节点详情只讲节点，与系统 DNS 无关。
- 中间区本来就是「有话要说」的地方，`empty_hint` / `update_hint` 都在这里；一行常驻说明放在这里最自然，也不会动固定骨架。
- 现有六种块没有一个能直接用：`empty_hint` 只在未连接时出现；`update_hint` 可被「稍后提醒」关掉，而契约要求这条不能静默；`issue_card` 是 P0/P1 问题卡，会把「慢一点」说成「出故障」。所以按 `docs/center-panel.md` §2.5「新增一个块的完整清单」登记新块。

## 2. 块登记（写进 `docs/center-panel.md` §2.5）

| 块 | AI 可写 | 何时出现 | 内容 | 依赖 AI |
|---|---|---|---|---|
| `dns_note` | ❌（系统叠加） | 已连接（`running` / `degraded`）且 `system_dns = "unchanged"` | 一行：这次没能给国外网站提速，访问可能慢一些。连接不受影响。 | 否 |

§2.5.1 编排区块映射：

| 块 | 依赖能力 | 后端 | 出现条件 |
|---|---|---|---|
| `dns_note` | A4 连接状态（`RuntimeSnapshot.system_dns`） | `runtime_status` | 已连接且 `system_dns = "unchanged"` |

> 不需要新能力、不需要新命令：A4 已经在返回状态快照，这次只是新增了一个字段。

系统叠加规则与 `issue_card` 一致：**`dns_note` 永远不写进布局、不进系统提示词的块清单**。布局里出现它，按非法块整份丢弃，与出现 `issue_card` 时相同。

- 位置：读数行（流量 / 延迟 / 出口）之下、AI 编排块之上。
- 与 `issue_card` 同时存在时，`issue_card` 在前，`dns_note` 紧随其后。
- 没有 AI 布局、布局为空、布局非法回退到本地块时，这一行都在。
- 只有一行，不折成卡片，不加图标，不加按钮。

## 4. 文案

**正式文案**

> 这次没能给国外网站提速，访问可能慢一些。连接不受影响。

三件事一句话说完：

| 要求 | 落在哪 |
|---|---|
| 发生了什么 | 这次没能给国外网站提速 |
| 对他什么影响 | 访问可能慢一些 |
| 现在做什么 | 连接不受影响 —— 不需要处理 |

为什么这样写：

- 不出现「DNS」「解析」「接管」「降级」「污染」这些词。用户看到的现象是「国外网站慢了」，不是「解析器没切」。
- 不说「失败」「异常」，不用红色，不用感叹号。它是自动降级，不是错误。
- 「连接不受影响」放在最后，先给现象再给结论，避免用户以为 VPN 没连上。
- 不用「可能无法打开」这种更吓人的说法；契约里的实际影响是「可能解析到污染地址、国外网站变慢」，用「访问可能慢一些」覆盖，不夸大。
- 一条文案覆盖所有降级情形，不按原因分支——界面拿不到更细的原因，也不该编。

## 5. 生命周期

| 时刻 | `system_dns` | 这一行 |
|---|---|---|
| 未连接 / 连接中 / 正在断开 | `null`（或旧值滞留） | 不显示。以 `state` 为准：只有 `running` / `degraded` 才可能显示，`stopping` 时立即隐藏 |
| 已连接，接管成功 | `"tunnel"` | 不显示 |
| 已连接，接管失败 | `"unchanged"` | 显示，常驻 |
| 连接不稳定（`degraded`） | `"unchanged"` | 显示 |
| 断开 / 连接失败 | `null` | 立即消失 |
| 重连 | 新快照 | 重新判断：变 `"tunnel"` 就消失，仍 `"unchanged"` 就继续显示 |
| 切到代理模式的配置 | `null` | 消失（代理模式本来不需要这一步） |
| 应用重启、还没连接 | `null` | 不显示 |

- **不能关掉。** 没有「稍后提醒」「知道了」。契约要求降级可见，可关闭就等于回到静默。
- 不做延时出现或延时消失：状态一到就显示，状态一走就消失，避免用户看到过期结论。
- 首次使用：它不在未连接的空态与首次引导里，不干扰「点按钮就能用」；第一次连上且降级时照常出现——这条是事实说明，不因为是新用户就藏起来。

## 6. 出口

**不加按钮、不加链接、不加任何补救动作。** 用户看到之后不需要做什么。

理由：

1. 这是 fail-open 的优化项，连接已经可用；为了一个提速项让用户「重试」或「修复」，会把可用状态打断。
2. 加「让 AI 定位」会把一句说明升级成问题卡，夸大严重性；右栏助手一直都在，想深究的人自己会去问。
3. 加「知道了」等于允许把降级藏起来，和契约冲突。
4. 唯一的「出口」是连接本身：断开、重连、换配置都会让这行按新状态自然消失。

## 7. 实现说明（给前端）

**读哪个字段**

- 只读 `runtime.system_dns`，不要从 `mode`、`health` 或 `system_proxy_enabled` 推导。
- 判定：`state` 是 `running` 或 `degraded`，且 `system_dns === "unchanged"`。
- `"tunnel"` 与 `null` 都不显示。

**类型与归一**

- `src/agent/protocol.ts`：`RuntimeSnapshot` 与 `RuntimeView` 增加 `system_dns: "tunnel" | "unchanged" | null`。
- `src/agent/bridge.ts`：`emptyRuntimeView()` 默认 `null`；断开时随 `port_fallback` / `route_region` 一起复位为 `null`；`snapshotToView` 原样透传。
- `src/agent/tauriBridge.ts`：只接受 `"tunnel"` / `"unchanged"`，其余（未知值、缺省）归一为 `null`。
- `src/agent/mockAgent.ts`：mock 快照补上该字段，测试要能造出 `"unchanged"`。

**放在哪个组件**

- `src/ui/middleArea.ts`：`MiddleBlock` 增加 `{ kind: "dns_note" }`；`middleBlocks()` 命中条件时把它放进本地块，排在最前。**不依赖 `aiReady`**，也不依赖 `hasSeedUpdate`：AI 没配好、布局为空时同样出现。
- `src/components/MiddleArea.tsx`：新增 `DnsNote`，渲染 `<p className="note note--warn">`，内容固定，无 props。
- `src/components/Console.tsx`：这是**系统叠加块**，与 `issue_card` 同一套合并规则——有 AI 布局时前置（`issue_card` 之后、布局块之前），没有布局时不要重复插入。布局里出现 `dns_note` 按非法块处理，整份丢弃。

**字号与颜色**

- 复用 `.note`：`font-size: 15px`、`line-height: 1.6`、`color: var(--ink-2)`、最大宽度 `52ch`。
- 左侧 2px 竖线用 `.note--warn` 的 `var(--amber)`；不铺背景、不加边框。浅色 / 深色两套都走 token，不写死颜色。
- 不加图标；不加 `role="alert"`（不是错误，也不希望每次重渲染都打断朗读）。

**读屏**

- 不要为它再建一个 live region。沿用 Console 现有的 `sr-only` 状态播报：连接成功且降级时，把「这次没能给国外网站提速」并进那条已连接播报里，只播一次。
- 视觉上的整句仍是普通文本，用户用读屏浏览中间区时能读到。

**测试要点**

| 用例 | 期望 |
|---|---|
| `system_dns = "unchanged"` + `running` | 出现 |
| `system_dns = "unchanged"` + `degraded` | 出现 |
| `system_dns = "tunnel"` | 不出现 |
| `system_dns = null`（代理 / 未连接） | 不出现 |
| `stopping` 时旧值滞留 | 不出现 |
| 有 AI 布局且布局里没有它 | 仍出现，且排在布局块前、`issue_card` 后 |
| 布局里写了 `dns_note` | 整份布局丢弃，不渲染这个块 |
| 断开后 | 立即消失 |

## 8. 依据

**`veyl-ui`（硬规则，优先）**

- §1.1 中间永远是三段骨架，不能新造位置 → 只放进 AI 编排区。
- §2.1 同一屏幕只有一个主按钮 → 这一行没有任何按钮，不改变主按钮权重。
- §3.1 用色规则：`--amber` 只用于状态文字与描边，不做填充 → 只使用 2px 竖线。
- §3.2 字号阶梯：15px/400 正文 → 使用 `.note` 的正文档，不新造字号。
- §6 文案：完整句子；错误三段式是「发生了什么 → 为什么 → 现在做什么」→ 文案按「现象 → 影响 → 不用处理」组织；界面不出现 `proxy` / `TUN` / `分流` / `规则集`，也不出现 DNS / 解析 / 接管。

**`docs/center-panel.md`**

- §2.5 块词汇表：表外不能自造块；新增块按「新增一个块的完整清单」登记。
- §2.5 规则：系统叠加块永远不写进布局、不进提示词，布局里出现按非法块整份丢弃。
- §2.5.1：新增块必须补「能力 → 块 → 后端」映射。

**`ui-ux-pro-max`（低于 veyl-ui）**

- Feedback · Error Feedback：失败或降级要有明确、就近的说明，不能静默 → 常驻一行，放在读数下方。
- Feedback · Toast Notifications：短暂提示才用 toast；长期状态用常驻行 → 不用 toast、不自动消失。
- Accessibility · Contextual Live Badge Updates：异步状态用一条原子状态播报，不做互相竞争的 live region → 复用现有 `srStatus`。
- Feedback · Error Recovery：给用户明确的下一步 → 这里下一步是「不用处理」，写进文案的「连接不受影响」。

## 9. 不做

- 不做成 `issue_card`：这不是 P0/P1，也不该带「让 AI 定位 / 重置网络」。
- 不做成 `update_hint`：那条可以被「稍后提醒」关掉，这条不能。
- 不放进顶部状态区或底部节点详情：会改动固定骨架。
- 不用 toast、不自动消失、不加关闭按钮。
- 不加任何按钮或链接。
- 不改后端的接管逻辑与 `system_dns` 语义。
