# 余额刷新：让余额不会无声过期

> 日期：2026-11-21
> 状态：设计定稿，待实现。只出规格与文案，不改代码。
> 依据：`account-menu.md` §10、`veyl-ui` §2.2（一个事实一个住处）/ §6（文案）、`useMyServers.ts`、`AccountMenu.tsx`、`Settings.tsx`。
> 一句话：**打开即刷、看得见时每 15 分钟刷、失败就明说旧值；不做成实时行情。**

---

## 0. 结论

| 问题 | 结论 |
|---|---|
| 手动刷新 | 菜单不加按钮，打开即刷（距上次成功 >30 秒）；设置加 `刷新` 文字链接，强制刷 |
| 新鲜度 | 不显示「N 分钟前」；只在刷新失败且已有旧值时写 `显示的是上次的余额` |
| 自动刷新 | 余额界面打开且窗口可见时每 15 分钟；隐藏暂停；恢复可见立即补一次 |
| 后台扣费 | 只更新数字；不弹 toast、不发通知、不加角标 |
| 两处 | 同一份数据与格式；菜单是快照，设置是明细；差别只在手动入口 |

**核心不变量**：界面上任何一次显示的余额，要么是最近一次成功读到的值，要么在同一屏明确写着「显示的是上次的余额」。**不允许无提示地展示过期值。**

---

## 1. 现状

- 余额只在两处出现：账户菜单（280 浮层）、设置 › 账户。
- 现有刷新时机（`src/myservers/useMyServers.ts`）：
  - 进入「我的服务器」destination（`:781`）；
  - 窗口获得焦点（`:787-790`）；
  - 充值 / 销毁 / 建机 / 重建等操作之后（`:641`、`:713`、`:727`、`:738`）。
- 没有手动刷新；没有「数据是旧的」提示；**打开菜单或设置不触发刷新**。
- `account-menu.md` §10 已经写了「打开任一面时刷新一次钱包（距上次成功超过 30 秒才发请求）」，实现里没有。文档与实现不一致，这是本次缺口之一。

---

## 2. 问题

2026-11-20 真机：用户昨天看到 `$8.50`，09:17 后台续费扣了 `$0.20` 变成 `$8.30`；窗口自始至终没有失去焦点，界面一直停在 `$8.50`。用户以为扣费没发生。

根因三条：

1. 打开余额界面不刷新；
2. 窗口长期聚焦时没有定时刷新；
3. 没有「这是旧值」的提示。

余额是外部系统的快照，不是本地事实；快照可以旧，但不能**无声地**旧。

---

## 3. 方案

### 3.1 何时刷新

| 时机 | 行为 |
|---|---|
| 打开账户菜单 | 距上次成功 >30 秒就发一次；≤30 秒不发 |
| 打开 设置 › 账户 | 同上 |
| 点击设置里的 `刷新` | **强制发**，不受 30 秒限制；请求在途时按钮禁用 |
| 窗口从隐藏变可见 / 获得焦点 | 余额界面开着且距上次成功 >30 秒时发一次 |
| 余额界面开着、窗口可见 | 每 15 分钟发一次 |
| 充值 / 销毁 / 建机 / 重建成功 | 保持现有立即刷新 |
| 未登录 / 没有余额界面打开 / 窗口隐藏 | 不发 |

- **15 分钟的理由**：扣费每小时最多一次（Cron `:17`）。15 分钟把「扣完到看见」的上限压在一刻钟内；每用户每小时最多 4 次请求，对 Worker + D1 是噪声级。不做 1 分钟，也不做实时。
- **只在余额界面打开时轮询**：菜单与设置›账户之外，余额不可见。看不见的数字不值得轮询，这也是成本边界；用户打开界面的那一刻已经会刷一次。
- **失焦但可见**：继续每 15 分钟刷新（窗口可能被别的应用盖住，用户仍会回来看）；**隐藏**（最小化 / 切到别的桌面 / 页面不可见）才暂停，恢复可见时立即补一次。
- **不按「有没有机器在运行」加密频率**：余额由计费驱动，与隧道是否运行无关；连接着不会让余额变得更快。
- **进入「我的服务器」destination 的现有刷新保留**：建机向导要用 `wallet.balance_cents` 做「日价 × 7」的门槛判断，余额旧了会误判能不能建。这条与余额界面无关，不并入定时轮询。

### 3.2 节流与并发

- 打开菜单 / 设置账户页 → `refreshWallet()`，内部做 30 秒节流（`now - lastWalletOkAt < 30s` 直接返回）。
- 手动 `刷新` → `refreshWallet({ force: true })`，绕过 30 秒节流；**显式动作不能被节流吞掉**。
- 同一时刻只允许一个钱包请求；在途时忽略重复触发。
- 成功才更新 `lastWalletOkAt`；失败不更新，下一次打开 / 下一次定时自然重试。

### 3.3 刷新期间与失败时

| 状态 | 显示 |
|---|---|
| 从没有值，加载中 | `读取中`（不写 `—`） |
| 已有值，刷新中 | **保留旧值**，不闪 `读取中`；设置里的入口写 `刷新中`，菜单没有额外变化 |
| 从没有值，失败 | `余额暂时读不到。` + `重试` |
| 已有值，刷新失败 | **保留旧值** + `没刷新成功，显示的是上次的余额。` + `重试`（菜单）/ `刷新`（设置） |

- 成功不弹「已刷新 / 刚刚更新」：数字变了就是结果，没变就是没变；再加一句会制造第二个会过期的状态。
- 不用旋转或三点动画：请求通常几百毫秒，动效只会闪一下；文字 `刷新中` 足够。
- 失败时绝不把金额换成 `—` 或 `读取中`——那会把「已知的旧值」变成「没有值」，信息更少。

### 3.4 两处的关系

| 位置 | 手动入口 | 失败提示 |
|---|---|---|
| 账户菜单（浮层） | 无；打开即刷 | 旧值 + `没刷新成功，显示的是上次的余额。` + `重试` |
| 设置 › 账户 | `刷新` 文字链接（13 / `--link`） | 旧值 + 同一句 + `刷新` |

- 同一份 `wallet`、同一个 `formatUsdCents`、同一句失败文案；不各自缓存、不各自格式化。
- 菜单是随手看一眼的浮层，48 高的一行里再塞一个按钮会挤；**打开动作本身就是刷新**。设置是会长开的页面，才需要显式入口。
- 「一个动作一个入口」：刷新只在设置里有一个显式按钮；`重试` 只出现在失败态。

账户菜单（正常）：

```
```

余额按天扣费，每台服务器单独计费。

### 3.6 文案

- `刷新`
- `刷新中`
- `读取中`
- `余额暂时读不到。`
- `没刷新成功，显示的是上次的余额。`
- `重试`

不用「刚刚更新」「上次更新于」「同步中」「立即刷新」；不加感叹号；不用旋转图标。

## 5. 验收清单

| # | 检查 | 期望 |
|---|---|---|
| 1 | 打开账户菜单（距上次成功 >30s） | 发一次钱包请求；返回后数字更新 |
| 2 | 30 秒内反复开关菜单 | 不重复发请求 |
| 3 | 打开 设置 › 账户 | 同 1 |
| 4 | 点设置里的 `刷新` | 立即发请求（不受 30s 限制）；入口变 `刷新中`；旧值一直在 |
| 5 | 打开余额界面、前台停留 15 分钟 | 至少刷新一次；跨过 `:17` 扣费后 15 分钟内数字更新 |
| 6 | 余额界面开着，窗口隐藏 30 分钟再恢复 | 隐藏期间不发请求；恢复可见立即补一次 |
| 7 | 余额界面开着，失焦但可见 | 15 分钟定时照跑 |
| 8 | 刷新失败、已有旧值 | 金额保留；同屏出现 `没刷新成功，显示的是上次的余额。` + `重试` / `刷新` |
| 9 | 刷新失败、从未取到值 | `余额暂时读不到。` + `重试` |
| 10 | 未登录 | 不发钱包请求，不显示余额 |
| 11 | 后台自动刷新 | 金额不闪 `读取中`；无 toast、无通知、无角标 |
| 12 | 充值 / 销毁 / 建机成功 | 仍然立即刷新（现有行为不回退） |
| 13 | 停在连接页（没有余额界面）1 小时 | 不发钱包请求；进入「我的服务器」时的现有刷新不受此限 |

**判定**：1 / 3 / 4 / 5 / 6 任意一条的成功返回后，屏幕上的余额等于该次响应的 `balance_cents`；任何失败路径都必须在同屏写明「显示的是上次的余额」，**不允许静默显示旧值**。

## 6. 不做

- **不做「N 分钟前更新」时间戳**：唯一会过期的情况就是刷新失败，那时写「上次的余额」比写时间更直接；时间戳自己也会过期，还要多一个每分钟跳动的元素。
- **不做余额变化的 toast / 通知 / 角标**：扣费是预期内的低频事件；多台服务器会变成轰炸。数字更新就是告知。
- **不做秒级 / 分钟级轮询**：扣费每小时一次，15 分钟已经足够。
- **不按连接状态调整频率**：余额与隧道是否运行无关。
- **不在连接页、服务器详情、建机页加第三处余额**（沿用 `account-menu.md` §10）。
