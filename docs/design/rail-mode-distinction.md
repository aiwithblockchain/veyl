# 左栏配置行：按接管方式做视觉区分

> 只出设计，不改代码、不改文案。
> 依据优先级：`veyl-ui` 硬规则 > `ui-ux-pro-max` > 一般审美。
> 现状取证：`ConfigRail.tsx:192-283`（行结构）、`:304-314`（72px 只有抽屉入口）、`app.css:3343-3398`（行与第二行样式）、`configLabels.ts:4-8`（两词来源）。
>
> **口径更新（2026-11-13，用户原话）**：用户看到了「全部软件 / 本机代理」那行小字，仍要求「还是用样式区分一下比较好」。所以**只提重小字不成立**，必须有形态标记；也不再回头提「只改字重」的方案。

---

## 0. 结论

**在名称前加一个 6×6 的哑灰形状点：TUN 用实心方块，Proxy 用空心圆环。第二行小字给出模式名，作为这个标记的图例。**

```
▪ 配置 1                  ◇ 配置 2
  2 个节点 · TUN 模式        2 个节点 · Proxy 模式
```

（上图为示意：实际是实心方块 / 空心圆环，不是 emoji。）

为什么是这一版：

1. **形状差别是真差别，不靠颜色。** 全屏没有新增色相，标记只用 `--ink-3`，与「一屏彩色不超过两种」「状态色只做点/文字/描边」都不冲突。
2. **不和选中态撞车。** 选中是「行左边缘 2px 钴蓝竖条 + 卡片底 + 名称 600」；标记在 x≈12–18 的方/环，形状是块状而非竖条，颜色是灰不是强调色，位置也离边缘 10px 以上。
3. **标记当索引，文字当确认。** 方块 = 整台电脑被盖住；圆环 = 只框住一部分。这不是谜语——旁边那行小字就是它的释义。
   分工写死：**标记负责扫视时快速分组（形状差异），小字负责确认具体是哪种模式（`TUN 模式` / `Proxy 模式`）**。
   两者同时存在是冗余编码，不是重复：只见形状也能分两类，只见文字也不会误读。
4. **两种类型都标。** 不给一种类型「留空」——缺席即含义读起来弱，也让两种模式不再成对。

## 1. 规格

### 1.1 位置与尺寸（280px 列表）

```
┌ 行高 64，内边距 12 ──────────────────────────────┐
│ [▪]  配置 1                       ← 标记 6×6，名称 15/500 │
│      2 个节点 · TUN 模式           ← 12px，`--ink-3`      │
└──────────────────────────────────────────────────┘
```

| 元素 | 规格 |
|---|---|
| 标记尺寸 | 6×6，圆角：方块 1.5px；圆环 `50%` |
| 标记与名称 | 间距 8；垂直对齐名称的视觉中线（不是行中线） |
| 名称起点 | 由 12 变为 26（标记 6 + 间距 8）；两行都不动 |
| 描边 | 圆环 `1.5px solid var(--ink-3)`；方块 `background: var(--ink-3)`、`border-radius: 1.5px` |
| 颜色 | 只有一个：`--ink-3`（浅色 `#6E6A5F`，深色 `#90908A`）。**不用 `--cobalt`、不用 `--ok/--warn/--err`** |
| 对比度 | 形状属非文本图形，需 ≥3:1；`--ink-3` 在 `--canvas` 上约 4.5:1、在 `--card` 上约 5.4:1、面板上约 4.8:1，深色卡片上约 4.7:1，均满足 |

### 1.2 两种模式

| `connect_mode` | 标记 | 小字 | 读法 |
|---|---|---|---|
| `tun` | 实心方块 | `2 个节点 · TUN 模式` | 整台电脑被盖住 |
| `system_proxy` | 空心圆环 | `2 个节点 · Proxy 模式` | 只框住填了地址的软件 |

- 小字措辞与新建配置的选项标题统一为 `TUN 模式` / `Proxy 模式`，不再用「全部软件 / 本机代理」。
- 左栏标签仍只由 `connect_mode` 决定（`configLabels.ts:4-8`），不随流量范围变。
- 不引入第三种状态；`tun` 与 `system_proxy` 之外没有第三种标记。

### 1.3 各状态下的表现

| 状态 | 标记 | 说明 |
|---|---|---|
| 默认 | `--ink-3` | 与名称同处一行，但小、不抢主 |
| hover | 不变 | hover 只改行底 `--bg-hover`；不让悬停改变类型信息 |
| 选中（`is-active`） | **不变**，仍 `--ink-3` | 选中已由左竖条 + 卡底 + 名称 600 表达；标记若也变钴蓝或加粗，两种强调叠一起，反而看不出类型 |
| 编辑态（改名） | 保留 | 改名时名称换成输入框，标记是此时唯一的类型线索，必须留着 |
| 删除 / 改名按钮出现 | 不变 | 按钮在右侧 60px 区，标记在左侧，互不重叠 |
| 已连接 / 连接中 | 不变 | 行上不显示连接状态；连接状态只住 hero（`veyl-ui` §2.2） |
| 深色 | `--ink-3` 自动切换 | 不写死色值 |

### 1.4 无障碍

- 标记 `aria-hidden`：类型已由行文本里的 `TUN 模式` / `Proxy 模式` 承载，不需要第二份可访问名，也不新增 Tab 停靠点。
- 不用颜色单独承载信息（`ui-ux-pro-max` · Compact Label Semantics / Color Only）——这里用形状 + 文字，颜色只是哑灰。
- 名称可用宽度减少 14px，会更早出现省略；`title` 已经存在，不改。

## 2. 72px 图标栏与抽屉

**先纠事实：72px 下今天没有配置行。** `<1024` 时 `ConfigRail.tsx:304-314` 只渲染一个抽屉入口（列表图标 + 配置套数），配置行全部收进 280px 抽屉；抽屉复用桌面那套 `.config` 行（`app.css:3574-3600`）。

| 形态 | 宽度 | 本次怎么做 |
|---|---|---|
| 宽屏列表 | 280 / 260 / 240 | 名称前 6×6 形状标记（§1） |
| 抽屉 | 280 | 同一套行样式，标记原样生效，无需降级 |
| 72px 图标栏 | 72 | **不加标记**。入口是「配置 N 套」的聚合按钮，可能同时含两种模式；放任意单个形状都会说谎，除非做「混合态」，那是新形态，不在本批 |

若将来 72px 要直接显示行（首字），标记可以沿用 6×6 放在首字上方 4px——但那是另一份 72px 行设计，本批不做，也不预留半成品。

## 3. 备选方案与取舍

### 备选 A：同一个形状，放到第二行行首（贴着方式词）

```
  配置 1
  ▪ 2 个节点 · TUN 模式
```

- **优点**：离图例最近，学习成本最低；离选中竖条最远（在第二行），几乎不可能混淆。
- **取舍**：扫视要先落到第二行，而用户先看的是名称；两种标记会跟着文字一起被长节点数推着走，对齐没有名称前那条稳定。
- **备选，不推荐。**

### 备选 B：只在 TUN 行加一个 4×4 小方点（Proxy 不加）

```
▪ 配置 1
  配置 2
```

- **优点**：元素最少，一眼只多一个小点。
- **取舍**：靠「有没有」表达类型，缺席不是含义，Proxy 行没有任何形态线索；两种模式不再成对，用户会以为 Proxy 是「默认/未设置」而不是另一种模式。也和 `.led` 状态点更容易混。
- **备选，不推荐。**

### 推荐：名称前的 6×6 形状（§0–§1）

- 形状可辨、颜色中性、位置固定，与选中态、hover、编辑态全不冲突。
- 文字仍是图例，标记不需要图例页。
- 唯一代价：名称可用宽度少 14px，更早省略；`title` 补足。

## 5. 依据

- **`veyl-ui`**：§1.3 左栏行结构；§2.2 每个事实一个住处（类型只在左栏行与未连接读数里）；§3.1 颜色 token、「状态色只用于点/文字/描边」「一屏彩色不超过两种」「`--ink-4` 只用于线条/点/focus」（本方案用 `--ink-3`，比它更稳）；§3.2 不新增字号（标记无文字）；§3.3 4px 网格（6 与 8 落在既有间距与尺寸惯例内，与 `.led` 6×6 同族）；§6 不改文案。
- **现状**：`ConfigRail.tsx:192-283`、`:304-314`；`app.css:3343-3398`（`.config.is-active::before` 的左竖条与 `box-shadow` 描边）；`app.css:3467-3497`（`.led` 6×6 的既有尺寸，标记沿用同族尺寸）。
- **`ui-ux-pro-max`**（本次检索）：
  - *Compact Label Semantics*（High）：属性用静态标记 + 文字表达，不用颜色单独编码，也不把每个标记做成可点。
  - *Compact Label Overflow*（High）：紧凑标记保持单行完整，不靠 hover 才显示含义。
  - *Color Only*（High）：信息不能只靠颜色——本方案靠形状差异。
  - *Focus States / Keyboard Navigation*（High）：不给行内增加新的可聚焦元素，Tab 顺序不变。
