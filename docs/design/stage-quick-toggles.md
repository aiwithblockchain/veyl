# 连接舞台的快速切换：接管方式 / 流量范围

> 日期：2026-11-17
> 状态：可行性结论 + 设计规格，待产品负责人拍板、`docs/design/` 定稿后交实现。只出文档，不改代码。
> 依据：`veyl-ui` §2.1 / §2.2 / §6、`ui-ux-pro-max` §5 Layout / §9 Navigation、`ai-first-product.md` §设置（2026-11-16 用词例外）、`acceptance-ui-refactor.md` S2 / C2 / C3、`account-menu.md` §10（同一份状态两处展示的先例）。
> 前置事实：舞台现在**不显示**这两个值（`ConnectionStage.tsx` 的状态带只有状态词与计时），所以这不是「把已有读数改成可点」，而是**在主按钮下面新增一行**。

---

## 0. 结论

**有条件能做。** 两个值放在主按钮下方一行纯文字上，成立；但不能做成两个「按钮」，接管方式也不能一键切完。

三条硬条件，缺一条就不做：

1. **视觉上不能是控件**：12 / 500 / `--ink-2` 的纯文字，无描边、无底色、无容器。屏幕上唯一的实心块仍然是主按钮。
2. **接管方式必须先确认再切**：它要么断线，要么进入一个需要系统授权的模式。必须插一行就地确认，且默认焦点在「取消」。
3. **设置页两行保留**，不删除——舞台是快照 + 快捷改，设置是完整说明 + 端口 + 排查上下文，两处读同一份状态、写同一个命令。

不满足这三条而做成「两个小分段控件」的话，会同时踩到 `veyl-ui` §2.1（一屏一个主按钮）和 §2.2（一个事实一个住处），那时结论就变成**不做**。

## 1. 与两条规则逐条核对

| 规则 | 判断 | 理由 |
|---|---|---|
| `veyl-ui` §2.1 一屏一个主按钮 | **不冲突** | 这一行是两个**值**的显示器，不是动作按钮：无填充、无描边、12px、与说明行同色。用户扫一眼读到的是「Proxy 模式 · 智能」，像一个读数。真正的按钮仍然只有 `断开` / `连接`。 |
| `veyl-ui` §2.2 一个事实一个住处 | **不冲突，但要写死纪律** | 与 `account-menu.md` §10 的余额两处同构：同一份状态、同一套标签、同一组命令；一处改了另一处立刻是同一个值。区别只在上下文——舞台给「现在就改」，设置给「看清它、连带看端口」。**不允许**舞台自己缓存一份值。 |
| `ui-ux-pro-max` `nav-hierarchy` / `avoid-mixed-patterns` | **有条件** | 同一屏出现「主操作 + 两个配置快捷方式」是允许的层级，只要三者的视觉重量依次递减（48 实心 → 无 → 12px 文字）。若把快捷方式做成 32 高的分段控件，重量就变成「两个次级按钮」，层级塌陷。 |
| `ai-first-product.md:115`「主界面顶部只显示结果，点它进设置对应段」 | **这一条会被改掉** | 现在舞台根本没有这行读数，等于「进设置」是唯一入口。加行之后，点击从「跳设置」变成「就地改」。这是对既定分工的修改，**需要产品负责人确认**（见 §9 第 1 项）。 |

## 2. 设置页怎么处理：保留

**两行都保留，不删除、不降权。** 理由：

1. 接管方式的完整信息在设置里才齐：它旁边就是「本地代理端口」——**切到 Tun 之后那一行会整行消失**（`veyl-ui` §128）。在舞台切到 Tun，用户不知道端口为什么没了；在设置里切，因果在同一屏。
2. 设置里有解释：「Proxy 模式只给设了代理的软件用；Tun 模式接管全部流量。切换会短暂断开当前连接。」舞台那一行只有两个字，放不下后果。
3. 排查场景要走设置：连不上网时用户进「高级 → 重置网络」的路径上会路过这两行，那里必须能看到当前值。

**分工写死：**

| 位置 | 角色 | 必须做到 |
|---|---|---|
| 连接舞台 | 快照 + 快捷改 | 只显示当前值；改完立刻反映；失败时回退到真实值 |
| 设置 › 连接 | 完整说明 + 端口 + 排查 | 与舞台同一份状态、同一套标签；切换失败两处同时回退 |

## 3. 标签：不建议改成「仅代理 / 全部软件」

产品负责人提议的中文标签（`仅代理` / `全部软件`）**不建议采用**，理由按重要性排：

1. **同一个值已经有一个名字，而且到处在用。** `Proxy 模式` / `Tun 模式` 出现在：设置 › 连接的分段控件、左栏每一行的接管方式小字、新建配置的两张卡标题、AI 对话里的选项。舞台若改叫「全部软件」，用户会在左栏看到 `Tun 模式`、在舞台看到 `全部软件`，指同一件事的两个词——这比出现一个英文词更糟。
2. **`Tun 模式` / `Proxy 模式` 是产品负责人 2026-11-16 明确指定的例外**（`ai-first-product.md:114`：接管方式一律写这两个词）。`veyl-ui` §6 的例外清单里也已经包含「中间区未连接读数『方式』的值」。新增这一行属于同一类位置，扩展例外即可，不需要换词。
3. **`智能分流` 直接违反禁用词。** `veyl-ui` §6 禁 `分流`。流量范围本来就叫 `智能` / `全局`，两个词都干净，没有改的必要。

**采用：`Proxy 模式` · `Tun 模式`，`智能` · `全局`。**

用户视角靠**解释**补，不靠换词：确认条和设置行里都有一句人话——`Tun 模式接管全部软件，Proxy 模式只给设了代理的软件用。`

> 如果产品负责人坚持要中文标签，那必须是一次全局改名：左栏小字、设置分段控件、新建卡标题、AI 选项同批改，并同步修订 `veyl-ui` §6 与 `ai-first-product.md:114`。**不能只改舞台这一处。**

## 4. 形态与规格（唯一方案）

### 4.1 位置与形状

主按钮下方一行，与说明行左对齐：

```
        ┌───────────────────────────┐
        │           断开            │   48，实心
        └───────────────────────────┘
        Proxy 模式 · 智能                  ← 新增，12px 纯文字
        已加入 2 个免费节点，最快 238ms      ← 现有说明 / 摘要
```

- 一行放两个值，中间 `·` 分隔；**不是**两行、不是 chip、不是分段控件。
- 每个值是一个独立的 `<button>`，点它 = 切到另一个值（二元开关）。
- 只在有节点时出现；`config === null`、节点数为 0、试用到期屏、`new_node` 舞台都不显示。

### 4.2 尺寸与颜色

| 项 | 值 |
|---|---|
| 文字 | **12 / 500 / `--ink-2`**（#5B5850，与说明行的 `--ink-3` 拉开一档，保证看得出可点） |
| 分隔符 | `·`，`--ink-3`，左右各 8 |
| 行高 | 20；与主按钮间距 **12**；与下方说明间距 **12** |
| 悬停 | 文字变 `--ink` + 下划线（`text-underline-offset: 2px`） |
| 焦点 | `:focus-visible` 2px `--focus`，offset 3 |
| 命中区 | `padding: 12px 6px; margin: -12px -6px` → 约 44 高，不改行高、不推动布局 |
| 禁用 | `opacity: .45`；文字不变 |
| 无障碍 | `aria-label="切换接管方式，当前 Proxy 模式"`；切完用 `role="status"` 播报新值 |

### 4.3 为什么不是另外三种

| 方案 | 为什么不选 |
|---|---|
| 两个 chip / 描边小按钮 | 立刻变成两个次级按钮，与 48 的主按钮抢重量；`veyl-ui` §2.1 的直接冲突。 |
| 32 高的分段控件（照搬设置页 `.settings-seg`） | 白底 + 阴影的选中块在 400 宽的舞台里非常抢眼，等于把设置页的一个卡片搬到最安静的屏幕上。 |
| 一行 `接管方式 · 智能` 点开小浮层 | 多一层且要解释「接管方式」这个抽象词；用户认的是「Proxy 模式」「智能」这两个值本身。 |

## 5. 状态与交互

### 5.1 两种切换的后果不同，所以确认不同

| 切换 | 未连接 | 已连接 | 有节点、连接中/断开中 |
|---|---|---|---|
| `Proxy 模式` → `Tun 模式` | **就地确认**（说明下次连接要授权） | **就地确认**（说明会短暂断开） | 禁用 |
| `Tun 模式` → `Proxy 模式` | 直接切 | **就地确认**（会短暂断开） | 禁用 |
| `智能` → `全局` | 直接切 | 直接切（热切换，不断线） | 直接切 |
| `全局` → `智能` | 直接切 | 直接切 | 直接切 |

规则一句话：**只有「会动到当前这条连接的接管方式」才确认；流量范围是热切换，永远直接生效。**

- 视觉不变、行为按后果加重——和「删除要二次确认、改名不要」是同一个道理。
- 流量范围切完播报 `已切到全局`，不弹任何东西。

### 5.2 就地确认条

```
Proxy 模式 · 智能
┌──────────────────────────────────────┐
│ 切到 Tun 模式？接管全部软件，会短暂断开当前连接。│
│                        取消    继续   │
└──────────────────────────────────────┘
```

| 项 | 值 |
|---|---|
| 容器 | 与舞台列同宽；padding 10 12；1px `--hair-strong`；圆角 10（`--r-md`）；底 `--card`；上 12、下 12 |
| 说明 | 13 / 1.6 / `--ink-2` |
| `取消` | 文字按钮，13 / `--ink-3`；命中区 `padding: 10px 8px; margin: -10px -8px` |
| `继续` | 文字按钮，13 / 600 / `--ink`；**不用填充按钮**——屏幕上唯一的实心块仍是主按钮 |
| 入门焦点 | 落在 **`取消`** 上 |
| 关闭 | `Esc` = 取消；点条外 = 取消（没有遮罩，舞台仍可操作，但主按钮在确认期间保持可用） |

> `Esc` 的优先级：若 AI 助手面板打开且焦点在内，先归助手；不在时 `Esc` 关确认条。与设置页端口编辑态的既有规则一致。

### 5.3 切换过程与失败

以下过程对两种结局（免中断 / 断开重连）都成立；**是否断线由架构师定，这里只写用户看到的**。

| 阶段 | 模式行 | 说明行 | 其它 |
|---|---|---|---|
| 点「继续」 | `正在切换到 Tun 模式…`（12 / `--ink-3`，不可点） | 保留原内容 | 行加 `aria-busy="true"`；主按钮不禁用（切换由自己收口） |
| 需要系统授权 | 同上 | `正在请求系统授权…` | 沿用现有 `helperPreparing` 的语义与主按钮 `准备中…` 文案 |
| 成功 | `Tun 模式 · 智能` | 回到原说明 / 摘要 | 播报 `已切到 Tun 模式` |
| 失败（授权被拒 / 后端报错） | **先显示 `正在恢复…`**，恢复完成后才写回 `Proxy 模式 · 智能` | `没能切换到 Tun 模式，已回到 Proxy 模式。`（13 / `--err-text`） | 给 `报告问题` 链接（若 AI 可用）；不弹 toast |

**不留半接管状态**：模式行只在确认「后端已回到 Proxy」之后才写 `Proxy 模式`。恢复期间写 `正在恢复…`，绝不提前把标签改成成功态。同理，成功前不把标签改成 `Tun 模式`。

### 5.4 已连接时切换

- 用户看到的过程：状态带保持 `已连接`（或按架构师结论变成 `正在切换…`），计时按架构师的结论暂停或继续；**界面不承诺「不断线」也不承诺「会断线」**，只在确认条里说「会短暂断开」——这句是 `ai-first-product.md:119` 的既有口径，若架构师定为免中断热切换，这句要一并改。
- 切换失败且原连接已断：状态带变成失败态，主按钮 `重新连接`（现有失败分支），模式行回退到切换前的值。

### 5.5 试用期（7 天免费节点）

**两个切换都可用。** 理由：接管方式和流量范围都是**本机行为**，与节点是买来的还是试用的无关；试用期用户同样会遇到「某个软件没走代理」，正是最需要切到 Tun 的人。不因为试用而降级功能。

### 5.6 无节点 / 到期

不显示这一行。没有连接对象时，改接管方式没有可见结果，只会让用户改完发现「什么都没变」。

## 6. 文案原文

| 场景 | 文案 |
|---|---|
| 行（当前值） | `Proxy 模式 · 智能`（值随状态变） |
| 切到 Tun · 未连接 | `切到 Tun 模式？接管全部软件；下次连接时会请求一次系统授权。` |
| 切到 Tun · 已连接 | `切到 Tun 模式？接管全部软件，会短暂断开当前连接。` |
| 切回 Proxy · 已连接 | `切回 Proxy 模式？会短暂断开当前连接。` |
| 确认按钮 | `取消` / `继续` |
| 进行中 | `正在切换到 Tun 模式…` |
| 授权中 | `正在请求系统授权…` |
| 恢复中 | `正在恢复…` |
| 失败 | `没能切换到 Tun 模式，已回到 Proxy 模式。` |
| 流量范围切换后播报 | `已切到全局` / `已切到智能` |

- 不加感叹号；不用「系统代理」（`veyl-ui` §358：说「网络设置」）；不用「分流」。

## 7. 待架构师确认（不要替它拍板）

1. **已连接时切换接管方式**：免中断热切换，还是断开重连？两种情况界面都已支持，但确认条的「会短暂断开当前连接」这句要按结论改。
2. **切换期间计时**：清零、暂停、还是继续走？
3. **免授权路径**：如果本机已经授权过 helper，切到 Tun 是否还弹系统授权？（`acceptance-ui-refactor.md` S2 的口径是「授权只出现一次」，需要确认切模式时也算在那一次之内。）
4. **流量范围切换的生效时机**：现有设置页是热切换；舞台入口是否走同一条命令、同一个返回码。
5. **失败回退的判据**：什么情况下可以判定「已回到 Proxy」，界面才能把标签写回。

## 9. 必须改 / 建议改 / 不改

### 必须改（P1，实现前先定）

1. **产品负责人确认**：舞台从「只显示结果」变成「就地可改」，等于取消「进设置改这两项」的唯一路径（§1 第 4 行）。这是分工变化，不是纯视觉。
2. 两个值做成 12 / 500 / `--ink-2` 纯文字，无描边无底色；不做 chip、不做分段控件（§4.2 / §4.3）。
3. 接管方式一律就地确认，入门焦点在 `取消`，`Esc` 取消（§5.2）。
4. 失败时先 `正在恢复…` 再写回旧值，不留半接管（§5.3）。
5. 设置页两行**保留**，与舞台共用同一份状态与标签（§2）。

### 建议改（P2）

6. 切完用 `role="status"` 播报新值，屏幕阅读器用户不会漏掉。
7. 主按钮在确认条打开期间保持可用（避免「确认条卡住整屏」）。
8. 流量范围切换给一条 1.5s 的轻微播报（`已切到全局`），不弹 toast、不改状态带。

### 不做

| 项 | 理由 |
|---|---|
| 把两个值做成 chip / 分段控件 | 与一屏一个主按钮冲突；舞台会变得比设置页还重。 |
| 只保留舞台、删掉设置里的两行 | 端口行与解释都在设置；删了以后切到 Tun 的「端口为什么消失」无处可查。 |
| 把标签改成「仅代理 / 全部软件」 | 与左栏、设置、新建卡的既有用词分裂（§3）。 |
| 在无节点 / 到期屏显示 | 改了没有可见结果，是噪声。 |
| 试用期禁用 | 接管方式与流量范围与本机有关，与节点来源无关（§5.5）。 |
| 一键切到 Tun 不确认 | 会断线，且可能弹系统授权；在主按钮下面手滑的代价太高。 |
