# 连接舞台的快速切换：接管方式 / 流量范围

> 日期：2026-11-17
> 状态：可行性结论 + 设计规格，待产品负责人拍板、`docs/design/` 定稿后交实现。只出文档，不改代码。
> 依据：`veyl-ui` §2.1 / §2.2 / §6（2026-11-17 改写后的用词规则）、`ui-ux-pro-max` §5 Layout / §9 Navigation、`ai-first-product.md` §设置、`acceptance-ui-refactor.md` S2 / C2 / C3、`account-menu.md` §10（同一份状态两处展示的先例）。
> 前置事实：舞台现在**不显示**这两个值（`ConnectionStage.tsx` 的状态带只有状态词与计时），所以这不是「把已有读数改成可点」，而是**在主按钮下面新增一行**。

---

## 0. 结论

**有条件能做。** 两个值放在主按钮下方一行两个弱底 chip 上，点开是选择层、选定才执行，成立；但不能做成两个「按钮」，接管方式也不能选完就切。

三条硬条件，缺一条就不做：

1. **视觉上不能变成按钮**：20 高弱底 chip + 10px 箭头、无描边、无阴影、4% 墨（§4.2 / §4.3）。屏幕上唯一的实心块仍然是主按钮。
2. **两步，不是一键**：点 chip 只展开选择层，选定后才执行（§5.1）；接管方式还要在执行前插一道就地确认，默认焦点在「取消」（§5.3）。
3. **设置页两行保留**，不删除——舞台是快照 + 快捷改，设置是完整说明 + 端口 + 排查上下文，两处读同一份状态、写同一个命令。

不满足这三条而做成「两个小分段控件」的话，会同时踩到 `veyl-ui` §2.1（一屏一个主按钮）和 §2.2（一个事实一个住处），那时结论就变成**不做**。

## 1. 与两条规则逐条核对

| 规则 | 判断 | 理由 |
|---|---|---|
| `veyl-ui` §2.1 一屏一个主按钮 | **不冲突** | 这一行是两个**值**的入口，不是动作按钮：20 高、4% 墨、无描边、无阴影，与 48 的主按钮差一个数量级。用户扫一眼读到的是两个「可改的当前值」，点开还多一步才生效。真正的按钮仍然只有 `断开` / `连接`。 |
| `veyl-ui` §2.2 一个事实一个住处 | **不冲突，但要写死纪律** | 与 `account-menu.md` §10 的余额两处同构：同一份状态、同一套标签、同一组命令；一处改了另一处立刻是同一个值。区别只在上下文——舞台给「现在就改」，设置给「看清它、连带看端口」。**不允许**舞台自己缓存一份值。 |
| `ui-ux-pro-max` `nav-hierarchy` / `avoid-mixed-patterns` | **有条件** | 同一屏出现「主操作 + 两个配置入口」是允许的层级，只要三者的视觉重量依次递减（48 实心 → 20 高弱底 chip）。若把快捷方式做成 32 高的分段控件，重量就变成「两个次级按钮」，层级塌陷。 |
| `ai-first-product.md:115`「主界面顶部只显示结果，点它进设置对应段」 | **已改（2026-11-17）** | 舞台原本根本没有这行读数，「进设置」是唯一入口。加行之后点击从「跳设置」变成「就地改」——产品负责人已确认这是主动要的分工变化，115 行同步改为「就地可改，设置仍是完整入口」。 |

## 2. 设置页怎么处理：保留

**两行都保留，不删除、不降权。** 理由：

1. 接管方式的完整信息在设置里才齐：它旁边就是「本地代理端口」——**切到 Tun 之后那一行会整行消失**（`veyl-ui` §128）。在舞台切到 Tun，用户不知道端口为什么没了；在设置里切，因果在同一屏。
2. 设置里有解释：「Proxy 模式只给设了代理的软件用；Tun 模式接管全部流量。切换会短暂断开当前连接。」舞台那一行只有两个字，放不下后果。
3. 排查场景要走设置：连不上网时用户进「高级 → 重置网络」的路径上会路过这两行，那里必须能看到当前值。

**分工写死：**

| 位置 | 角色 | 必须做到 |
|---|---|---|
| 连接舞台 | 快照 + 快捷改 | 只显示当前值；改完立刻反映；失败时回退到真实值 |
| 设置 › 连接 | 完整说明 + 端口 + 排查 | 与舞台同一份状态、同一套标签；切换失败两处同时回退 |

## 3. 用词与解释

### 3.1 结论（2026-11-17 产品负责人拍板）

界面**直说** `Proxy 模式` / `Tun 模式`，`智能` / `全局`；不另造中文别名。概念解释交给 AI，界面不写长篇说明。

- `Proxy` / `Tun` 已从 `veyl-ui` §6 的禁用清单里拿掉（同日修订）；仍禁 `分流`、`规则集`。
- 统一写 `Proxy 模式` / `Tun 模式`，与设置 › 连接的分段控件、左栏每行小字、建机卡标题、AI 选项同一套；不写小写 `proxy` / `tun`，不写裸 `Proxy` / `Tun`。**大小写也要统一**：现在左栏（`src/ui/configLabels.ts`）写 `TUN 模式`、设置里写 `Tun 模式`，实现时统一到 `Tun 模式`。
- `仅代理`、`全部软件` 这类说法只出现在**解释句**里，不作选项名——同一件事两个名字，比一个英文词更糟。
- 其它实现词（`selector`、`mixed`、`geosite`、`tun2socks`）仍只在高级设置与日志。

### 3.2 解释的入口：交给助手（选 A），2026-11-19 控制台 chip 行增加一个入口

| 候选 | 判断 |
|---|---|
| **A 界面不加入口，用户直接问助手** | **采用** |
| B 设置 › 接管方式行加 `问 AI` | 否。`settings-review.md` §2.5 刚把「问 AI」收敛成**一页最多一个**，端口行已经占了；同页第二个 `问 AI` 会把它变成装饰。 |
| C 确认条里写「不明白？问 AI」 | 否。确认条出现在用户**已经决定要切**之后，此时解释已经晚了；而且会在最需要两个明确动作（取消 / 继续）的位置塞进第三个动作。 |

选 A 的两个前提，缺一个就退回 B：

1. **确认条本身已经说清后果**（`接管全部软件，会短暂断开当前连接。`），用户不必为了知道会发生什么而去提问。
2. **助手必须答得出**，且知道当前值与当前屏幕（§3.3 / §3.4）。

A 的代价是发现性——用户得先想到问。接受这个代价：这一行本来就是低频设置，而助手常驻右栏，是本产品和别的 VPN 最不一样的地方。

**2026-11-19 改口（用户裁定；覆盖上面「接受这个代价」一句）**

在控制台主按钮下面那一行、两个 chip（接管方式 / 流量范围）之后，加一个 `问 AI`：点击即打开右栏助手并自动发问。用户不接受 A 的发现性代价——「得先想到问」这一步在实际使用里没人走，低频的「低频」抵不过「根本没人问」。

- **样式：常态就带下划线，不依赖 `hover` / `focus`。** 用户原话是「加一个带下划线的『问 AI』这样的按钮」——要的就是一眼看出可点，而不是悬停才显形。这与 `settings-review.md` §2.3 的「`问 AI` 只在 hover / focus 加下划线」不冲突：那条是设置页的规则，控制台这一处是**明确的例外**（该条已注明）。
- **为什么这里可以不收着**：它旁边是两个弱底 chip，不是一段说明文字。chip 有底、链接有下划线，两种「可点」信号各管一个对象，常驻下划线不会干扰阅读，也不会把主按钮的重量分走。

- **例外只到控制台这一行。** 设置页仍然不加：`settings-review.md` §2.5「一页最多一个 `问 AI`」的规则不变，端口行已经占了那一个（候选 B 依旧否）。
- **A 的两个前提仍然保留**，其中第二条现在升级为**入口的前置条件**：
  1. 确认条本身已经说清后果——不变，不因为多了入口就省掉后果句。
  2. **助手必须答得出**——把入口点开却只回一句空话，比没有入口更伤：用户此后不再点它。所以系统提示词里的两组定义、§3.3 四句边界、`screen = client` 的当前值上下文（§3.4 第 1、2 条）必须与入口同批落地；**助手侧没接好就不发这个入口**，不再有「缺一条就退回 B」的退路。
- **入口要自带上下文**：自动发出的那一问带上当前屏幕与两个当前值（`Proxy 模式` / `Tun 模式`、`智能` / `全局`），否则助手只能泛泛讲概念，答的不是眼前这一行。
- **同屏不再加第二个** `问 AI`；这一行是控制台上唯一的解释入口。

### 3.3 助手侧的回答边界（两轴四句，不是教程）

**前置条件（没满足就别发入口）**：助手侧系统提示词目前还没有 `Proxy 模式` / `Tun 模式` 的定义，也没有流量范围（`智能` / `全局`）的定义。**入口点了却答不出来等于白加**，甚至更糟——用户此后不再点它。补齐这两组定义 + 本节四句边界，是控制台 `问 AI` 入口能用的前提；后端已派单。

控制台那一个入口发出的是**两根轴**的问题：接管方式，和流量范围。回答按轴各两句，合计**不超过四句**：

**接管方式（最多两句）**

1. **改了什么**：`Proxy 模式只让设了代理的软件走节点；Tun 模式接管全部流量。`
2. **什么时候该改**：`某个软件不认代理，或者你在终端里跑的命令没走节点时，才需要切到 Tun。`

**流量范围（最多两句）**

3. **智能是什么**：`智能只让需要的网站走节点，其余的直连。`
4. **全局是什么**：`全局就是所有网站都走节点。`

只被问一根轴时就只答那两句，不把另一根轴顺带讲一遍。切换要系统授权、会短暂断线这类后果**不占固定句**：确认条本身已经写了后果（§3.2 前提 1），助手只在用户直接问到「会不会断线 / 要不要授权」时补一句。

不许出现：安装步骤、`selector` / `mixed` / `geosite` / 路由表 / `规则集` / `分流`、第三方工具推荐。用户问的是「我的软件为什么没走节点」时，**先跑 `DiagRun` 再回答**，不直接讲概念。

`screen = client` 下被问到，末尾补一句：`要改的话，主按钮下面那行点一下。`

### 3.4 待办（给实现方 / 助手侧）

1. 系统提示词里加两组定义（接管方式 `Proxy 模式` / `Tun 模式`，流量范围 `智能` / `全局`）+ §3.3 的四句边界（两轴各两句）。这是控制台 `问 AI` 入口的前置：**入口点了却答不出来等于白加**，定义没进提示词就先别发入口。
2. `screen = client` 的 UI 上下文带上当前值与「可切换」这一事实，否则助手只能说「你去设置里改」。
3. **设置页不再加界面入口；控制台 chip 行已有入口（§3.2，2026-11-19 改口），不要在同一屏加第二个。**——这条写在这里，避免下一个人顺手补一个「问 AI」链接。

## 4. 形态与规格（唯一方案）

> 2026-11-17 二次改口径：从「点值即切」改为**两步**——点值先展开选择层，选定后才执行。本节按两步写。

### 4.1 位置与形状

主按钮下方一行，与说明行左对齐：

```
        ┌───────────────────────────┐
        │           断开            │   48，实心
        └───────────────────────────┘
         (Proxy 模式 ⌄) (智能 ⌄)        ← 两个 20 高弱底 chip，各带 10px 箭头
        已加入 2 个免费节点，最快 238ms   ← 说明 / 摘要，纯文字
```

- 一行两个入口，各管一个设置；**两个值都是入口**，不是整行一个入口。
- 只在有节点时出现；`config === null`、节点数为 0、试用到期屏、`new_node` 舞台都不显示。

**为什么是两个入口而不是一个**：接管方式与流量范围是两个互相独立的设置，后果也不同——一个断线要确认、一个热切换。合成一个入口就要在一个面板里塞两组选项，面板变大、选择变慢，而且说不清「这次改的是哪个」。

### 4.2 入口形态：候选逐条对比

| 候选 | 判断 |
|---|---|
| 1 常驻下划线 | **否。** 两个常驻下划线就是两个网页链接，而链接的语义是「去别处」。这一屏已经有 `.stage-probe`（测速，13/`--link`）和失败态的 `报告问题` 用下划线表示「触发 / 跳转」，同一种样式再表示「打开选择」，一屏里就混进两类语义。 |
| 2 纯文字 + `⌄` | **否（单独用不够）。** 箭头说明了「点开还有东西」，但文字本身仍然像读数；静止时 12px 字加 10px 箭头，第一次看还是容易滑过去。 |
| 3 弱底 chip（无箭头） | **否（单独用不够）。** 形状说明「这是控件」，但说明不了「点开会有选项」——用户会以为点一下就变。 |
| **2 + 3：弱底 chip + `⌄`** | **采用。** 形状和箭头各回答一个问题：「这是控件」与「点开有得选」。 |
| 4 一次性提示「点这里切换」 | **否。** 要多存一个「已提示过」的状态；用户忽略了就没有第二次；而且是在用文字解释一件本该由形状说明的事。 |
| 5 换成「标签 + 值」（`接管方式 Proxy 模式 · 流量范围 智能`） | **否。** 400 宽里要折行，而且把两个短值变成一句话，更不像能点。 |

**为什么是 chip + 箭头：**

1. **形状先于文字。** 「有边界、有底」是判断「这是控件」的第一信号，不读字、不 hover 也成立——截图冻结在静止态时依然有效。
2. **箭头现在说的是真话。** 上一版否掉箭头，是因为当时点一下就翻转；改成两步后，点开确实会出现选项，`⌄` 不再误导。
3. **它让下一行变成信息。** 摘要行保持纯文字、没有底。这个「有底能点 / 没底不能点」的对比本身就是可点性的来源。
4. **重量够低。** 20 高 / 4% 墨 / 无描边，与 48 的主按钮差一个数量级；眯眼看仍只有一个实心块（`veyl-ui` §2.1）。

**验收标准（写死在这里）**：没用过的人第一次看到这一行，要能发现它能点；点开之后能看懂有哪些选项、当前是哪个；**不会因为误点一下就直接切换甚至断线**——这最后一条由两步流程本身保证。

### 4.3 行内规格

| 项 | 值 |
|---|---|
| chip | 高 **20**、`padding: 0 8`、圆角 **6**、底色 `--bg-hover`（≈4% 墨）、**无描边、无阴影** |
| 文字 | **12 / 500 / `--ink-2`** |
| 箭头 | **10×10**、1.4 描边、`--ink-3`、与文字间距 4；展开时换成 `⌃`（**瞬时替换，不做旋转动画**） |
| 间隔 | 两个 chip 间距 **8** |
| 悬停 | 底 `rgba(20,22,28,.09)`；文字 `--ink`；箭头 `--ink-2` |
| 展开中 | 底 `rgba(20,22,28,.12)`；文字 `--ink` |
| 焦点 | `:focus-visible` 2px `--focus`，offset 2（描边落在 chip 外，不改尺寸） |
| 命中区 | chip 本体 20 高；`::after { inset: -12px -4px }` → 约 44 ×（宽+8），与相邻 chip 不重叠（间距 8 ≥ 4+4） |
| 禁用 | `opacity: .45`；底与文字不变 |
| 无障碍 | `aria-haspopup="listbox"` + `aria-expanded`；`aria-label="接管方式，当前 Proxy 模式"` |
| 行距 | 与主按钮 **12**；与下方说明 **12** |

- **命中区不小于 chip 本身，两个 chip 的命中区不重叠。** 窄窗口下宁可让这一行折成两段，也不要把命中区压进文字里。
- 深色主题下 `--bg-hover` 自动变成白色 5%（token 已有），不需要单独给值。

### 4.4 选择层

**内联展开在行正下方，不做浮层。**

```
 (Proxy 模式 ⌃) (智能 ⌄)
 ┌──────────────────────────────┐
 │ Proxy 模式                 ✓ │   ← 当前值，✓ 右对齐
 │ Tun 模式                     │
 └──────────────────────────────┘
 已加入 2 个免费节点，最快 238ms
```

| 项 | 值 |
|---|---|
| 形式 | 内联展开；不加遮罩、不遮挡内容，只把下面几行推下去 |
| 宽度 | 与内容列同宽（400 的舞台列），左右与主按钮对齐 |
| 容器 | `margin-top: 8`；`padding: 4`；1px `--hair-strong`；圆角 **10**；底 `--card`；`0 8px 24px rgba(23,22,20,.10)` |
| 选项行 | 高 **32**、`padding: 0 10`、圆角 6、13 / `--ink`、单行不折行 |
| 悬停 | 底 `--bg-hover` |
| 键盘焦点 | 2px `--focus`，offset −2（画在选项行内侧，不撑开容器） |
| 当前值 | 右侧 `✓` 14 / `--link`，`margin-left: auto` |
| 无标题 | 不写「接管方式」这样的分组标题——chip 上已经写着当前值，两个选项自身就说明了这是什么 |

- 选项行 32 高是桌面菜单的常规尺寸；命中区是**整行宽**（约 400×32），不需要再往上补到 44——高度换来的点击便利在这里已经足够。
- 选择层背景与主按钮同宽同边，打开时用户的视线不需要横向移动。

**为什么内联而不是浮层**：舞台只有一列，下面只有一行摘要，推下去没有代价；浮层要处理锚点、贴边翻转和遮挡，而收益只有省掉几十像素的高度。

### 4.5 为什么不是另外几种

| 方案 | 为什么不选 |
|---|---|
| 描边 chip / 描边小按钮 | 描边会把重量抬到「两个次级按钮」，与 48 的主按钮抢；`veyl-ui` §2.1 的直接冲突。弱底没有这条问题。 |
| 32 高的分段控件（照搬设置页 `.settings-seg`） | 白底 + 阴影的选中块在 400 宽的舞台里非常抢眼，等于把设置页的一个卡片搬到最安静的屏幕上；而且它是「常驻展开两个选项」，与两步流程冲突。 |
| 一行 `接管方式 · 智能` 点开一个合并面板 | 多一层且要解释「接管方式」这个抽象词；两组选项混在一个面板里，选择变慢。 |
| 点值直接切（上一版） | 弃用：误点一下就会断线或弹授权，代价与一次点击不匹配。 |

## 5. 状态与交互

### 5.1 两步：点开 → 选定 → 必要时确认

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | 点 `Proxy 模式 ⌄` | 展开接管方式的选择层（另一个 chip 自动收起，同时只有一个选择层） |
| 2 | 点 `Tun 模式` | 选择层关闭 → 出现就地确认条（§5.3） |
| 3 | 点 `继续` | 执行切换（§5.4） |

**选定之后做什么，取决于改的是哪一项、以及当前能不能断：**

| 选定的目标 | 未连接 | 已连接 | 连接中 / 断开中 |
|---|---|---|---|
| 接管方式 → 另一个值 | 确认条（说明首次使用需要系统授权） | 确认条（说明会短暂断开） | chip 禁用，无法展开 |
| 流量范围 → 另一个值 | **选中即生效**，选择层关闭，焦点回到 chip | 同左（热切换，不断线） | 同左 |
| 选中当前值（两项都一样） | 只关闭选择层，什么都不做 | 同左 | — |

规则一句话：**选定即执行；只有「会动到当前这条连接的接管方式」在执行前插一道确认。**

- 选中的是当前值时**不**弹确认——那不算一次切换。
- 流量范围生效后播报 `已切到全局`，不弹任何东西。

### 5.2 选择层的交互细节

| 场景 | 行为 |
|---|---|
| 打开 | 点任一 chip；再点同一个 chip = 收起 |
| 换层 | 打开时点另一个 chip，直接换成它的选择层（一次点击） |
| 关闭 | `Esc`、点层外、再点同一个 chip、选定任意一项 |
| 键盘 | 打开后焦点落在**当前值那一行**；`↑` / `↓` 在两项间移动（不循环）；`Enter` / `Space` 选定 |
| `Esc` | 关闭并把焦点还给打开它的 chip |
| `Tab` | 移出选择层并关闭（焦点继续往下走） |
| 打开时的另一项 | 可以点（换层）；主按钮保持可用；舞台其余部分不冻结——**不设遮罩** |

- 选择层不抢舞台：它展开时下面的摘要行只是被推下去，不消失。
- 打开选择层本身**不改变任何值**，也不发任何命令。

### 5.3 就地确认条

```
(Proxy 模式 ⌄) (智能 ⌄)
┌──────────────────────────────────────┐
│ 切到 Tun 模式？接管全部软件，会短暂断开当前连接。│
│                        取消    继续   │
└──────────────────────────────────────┘
```

- 确认条出现时，选择层已经关闭、两个 chip 回到常态但**不可点**（确认中重复点会把状态搅乱），确认结束后恢复。
- 确认条出现的位置就是选择层刚才的位置：用户在原地继续，视线不用移动。

| 项 | 值 |
|---|---|
| 容器 | 与舞台列同宽；padding 10 12；1px `--hair-strong`；圆角 10（`--r-md`）；底 `--card`；上 12、下 12 |
| 说明 | 13 / 1.6 / `--ink-2` |
| `取消` | 文字按钮，13 / `--ink-3`；命中区 `padding: 10px 8px; margin: -10px -8px` |
| `继续` | 文字按钮，13 / 600 / `--ink`；**不用填充按钮**——屏幕上唯一的实心块仍是主按钮 |
| 入门焦点 | 落在 **`取消`** 上 |
| 关闭 | `Esc` = 取消；点条外 = 取消（没有遮罩，舞台仍可操作，但主按钮在确认期间保持可用） |

> `Esc` 的优先级：若 AI 助手面板打开且焦点在内，先归助手；不在时 `Esc` 关确认条。与设置页端口编辑态的既有规则一致。

### 5.4 切换过程与失败

以下过程对两种结局（免中断 / 断开重连）都成立；**是否断线由架构师定，这里只写用户看到的**。

| 阶段 | 模式行 | 说明行 | 其它 |
|---|---|---|---|
| 点「继续」 | `正在切换到 Tun 模式…`（12 / `--ink-3`，不可点） | 保留原内容 | 行加 `aria-busy="true"`；主按钮不禁用（切换由自己收口） |
| 需要系统授权 | 同上 | `正在请求系统授权…` | 沿用现有 `helperPreparing` 的语义与主按钮 `准备中…` 文案 |
| 成功 | `[Tun 模式] [智能]` | 回到原说明 / 摘要 | 播报 `已切到 Tun 模式` |
| 失败（授权被拒 / 后端报错，且已回滚） | **先显示 `正在恢复…`**，恢复完成后才写回 `[Proxy 模式] [智能]` | `没能切换到 Tun 模式，已回到 Proxy 模式。`（13 / `--err-text`） | 给 `报告问题` 链接（若 AI 可用）；不弹 toast |
| 失败且**回滚也失败**（`restored: false`） | 写**库里真实的新值**（如 `[Tun 模式] [智能]`） | `没能切换到 Tun 模式，连接已断开。` | 状态带按失败分支，主按钮 `重新连接`；**不写「已回到 Proxy 模式」** |

**不留半接管状态**：模式行只在确认「后端已回到 Proxy」之后才写 `Proxy 模式`。恢复期间写 `正在恢复…`，绝不提前把标签改成成功态。同理，成功前不把标签改成 `Tun 模式`。

### 5.5 已连接时切换

- **接管方式：断开重连，不是热切换。** 走 `config_set_mode`，Host 的实际动作是「停旧 → 写库 → 用新模式启动」，连接状态按既有迁移 `stopping → idle → starting → running` 走一遍（`commands.md` §3.7）。**状态带不可能保持 `已连接`**，它会先变 `连接中…`，回来后是新的 `已连接`。
- **计时清零。** 计时器唯一来源是 `runtime.connected_since`（`ConnectionStage.tsx`），它只在进入 `running` 时刷新（`runtime.md` §5.1）——重连就是新一次连接，计时从 0 开始。不暂停、不继承，也不为它新增本地计时状态。
- **流量范围：真的热切换。** `route_set_mode` 对 `direct ↔ proxy_all` 走 Clash API selector，`hot_switched = true`、`effective = "current_connection"`，不断线、计时不间断（`commands.md` §10.2）。2026-11-22 修订：重启接手的 TUN 单配置下按全局配置认定（`tools.md` 3.25.1）；读不到 Clash 端点 → `config_not_running`，不热切、不改库，界面保留旧值并提示先重连；只有连全局配置也复原不出配置 id（防御分支）才是 `config_unknown`。
- 用户看到的过程：确认条 → 模式行 `正在切换到 Tun 模式…` → 状态带按迁移显示 → 成功写回新值；失败见本节下表与 §8 第 5 条。
- 切换失败且连接已断：状态带按既有失败分支显示，主按钮 `重新连接`，模式行按**库里真实值**写（见 §8 第 5 条），不一律写回切换前的值。

### 5.6 试用期（7 天免费节点）

**两个切换都可用。** 理由：接管方式和流量范围都是**本机行为**，与节点是买来的还是试用的无关；试用期用户同样会遇到「某个软件没走代理」，正是最需要切到 Tun 的人。不因为试用而降级功能。

### 5.7 无节点 / 到期

不显示这一行。没有连接对象时，改接管方式没有可见结果，只会让用户改完发现「什么都没变」。

## 7. 架构裁决（2026-11-17）

### 7.1 五条判断

1. **已连接时切换接管方式：断开重连，不是热切换。** `config_set_mode` 的实际动作是「停旧 → 写库 → 用新模式启动」（`commands.md` §3.7），运行时没有原地改接管方式的路径。确认条里「会短暂断开当前连接」**保留**，且 `Tun → Proxy` 同样成立。
2. **切换期间计时：清零。** 唯一来源 `runtime.connected_since` 只在进入 `running` 时刷新（`runtime.md` §5.1）；重连是新连接，计时从 0 起。不加「暂停」状态，状态带按 `stopping → idle → starting → running` 正常迁移。
3. **免授权路径：成立。** helper 的 `ensure_available` 是幂等的——已 `Enabled` 时直接返回，不重复触发系统授权（`tun-backend.md` §4）。所以**本机授权过之后，切到 Tun 不再弹授权**；切模式算在「授权只出现一次」之内。只有在 helper 未安装 / 未授权、或上次用户拒过（`tun_denied`，此后每次连接会再请求，`tun-mode.md` §8）时才会弹。
   - **界面不能预知会不会弹**：`tun_helper_info` 只有运行态五值，没有系统授权位。所以未连接时的文案只能写「首次使用需要系统授权」，不能断言「下次连接会请求」。
4. **命令复用，不新增。**
   - 接管方式：`config_set_mode { configId, mode }` → `ConfigSetModeData`（`commands.md` §3.7，2.34.0）。设置页现在走的就是它（`Settings.tsx:953`）。
   - 流量范围：`route_set_mode { configId?, mode }` → `RouteSetModeData`（`commands.md` §10.2，2.1）。设置页的 `TrafficScopeSwitch` 走的就是它。
   - **禁止**用 `config_update.routingMode`：它只写库、不打断连接，也不在线切换（`commands.md` §3.3），用它会让界面显示新值而实际没变。
   - 两处入口共用同一命令、同一套返回码与错误码，不新增命令、不新增错误分支。
5. **失败回退判据：以 `restored` 为准，不猜。** `restored` 的参照点是调用前（成功返回里也有这个字段）。
   - 成功（`changed: true`、`connected: true`、`restored: true`）→ 写新值。
   - 失败且 `details.restored = true` → 库已是旧值、已按旧模式恢复 → 写回旧值，文案「已回到 Proxy 模式」。
   - 失败且 `details.restored = false` → 库是新值、连接停在断开态 → **写库里的新值**、进入失败分支、主按钮 `重新连接`；**不得**写「已回到 Proxy 模式」。
   - `details` 没有 `restored`（旧版本 / 未知）→ 读一次 `config_detail` 按库值写，不按「应该回到了」推断。

> 实现事实：错误 `details` 已经带 `restored`（`src-tauri/src/tools/config_mode.rs:162`），契约只需补一句说明。

### 7.2 另外四条

- **这一行什么时候出现**：用配置层的 `hasNodes`（`activeConfig.nodes.length > 0`，`App.tsx:661`），**不要用运行时状态**——没连接时运行时是空的，而这一行恰恰要在连接之前就能改。无节点 / 到期 / 新建节点屏自然不满足。
- **流量范围是否真的不断线**：**是**。`direct ↔ proxy_all` 走 Clash selector，`hot_switched = true`、`effective = "current_connection"`。2026-11-22 修订：接手 TUN 单配置下按全局配置认定（`tools.md` 3.25.1）；读不到 Clash 端点 → `PRECONDITION_FAILED / config_not_running`，不热切、不改库；只有连全局配置也复原不出配置 id（防御分支）才是 `config_unknown`，界面保留旧值并提示先重连。设计里「热切换」那句成立。
- **契约影响：零语义改动。** 命令、载荷、错误码都不变；`runtime.md` / `events.md` 不需要改。只在 `commands.md` §3.7 补一句「失败时 `details` 含 `restored`」的说明（实现已如此），不改字段、不升版本。
- **当前值的来源**：`connect_mode` 来自 `activeConfig`（`config_detail`），流量范围来自 `activeRoutingMode`——即 `activeConfig.routing_mode` 叠加 `route_set_mode` / `routing-changed` 的覆盖层（`App.tsx:656`）。设置页收的也是这两个值（`App.tsx:2448/2473`）。**舞台直接复用，不新增状态、不本地缓存。**

### 7.3 给实现的提醒

- 设置页现有的失败路径只提示错误、不读 `restored`（`Settings.tsx:955`）。`restored = false` 时库已是新模式，界面却还显示旧值——两个入口要按 §7.1 第 5 条一起改，否则就是「舞台对了、设置页还错」。
- 切换期间不要让模式行在成功前变成新值；`正在切换到…` / `正在恢复…` 就够，失败按 `restored` 分叉。

## 9. 必须改 / 建议改 / 不改

### 必须改（P1，实现前先定）

1. **助手侧补知识**：系统提示词加入两组定义（`Proxy 模式` / `Tun 模式`、`智能` / `全局`）与 §3.3 的四句边界（两轴各两句）；`screen = client` 的上下文带上当前值与「可切换」。**这是控制台 `问 AI` 入口的前置**——入口点了却答不出来等于白加。**设置页不加界面入口**；控制台 chip 行的 `问 AI` 入口 2026-11-19 已开（§3.2），同屏不再加第二个。
2. **入口**：两个值做成 20 高弱底 chip + 10px `⌄`（`padding: 0 8`、圆角 6、`--bg-hover`、无描边无阴影、12/500/`--ink-2`、间距 8）；不做描边 chip、不做分段控件（§4.2 / §4.3）。
3. **两步流程**：点 chip 只展开内联选择层（不加遮罩、宽度与内容列对齐、选项行 32 高、当前值带 `✓`），**选定之后才执行**；不复用「点值即切」（§4.4 / §5.1）。
4. **确认时机**：接管方式选定后**再**出就地确认条（焦点在 `取消`）；流量范围选定即生效、不出确认（§5.1 / §5.3）。
5. 失败时先 `正在恢复…`，回滚成功后写回旧值；**回滚也失败时写库里的新值 + 失败分支**，两种都不留半接管（§5.4、§7.1 第 5 条）。
6. 设置页两行**保留**，与舞台共用同一份状态与标签（§2）。

### 建议改（P2）

7. 键盘：展开后焦点落在当前值那行，`↑` / `↓` 移动（不循环），`Enter` / `Space` 选定，`Esc` 关闭并把焦点还给 chip，`Tab` 移出并关闭（§5.2）。
8. 切完用 `role="status"` 播报新值，屏幕阅读器用户不会漏掉。
9. 主按钮在确认条 / 选择层打开期间保持可用（避免局部 UI 卡住整屏）。
10. 流量范围切换给一条 1.5s 的轻微播报（`已切到全局`），不弹 toast、不改状态带。

### 不做

| 项 | 理由 |
|---|---|
| 把两个值做成**描边** chip / 分段控件 | 描边会把重量抬到「两个次级按钮」，与一屏一个主按钮冲突；弱底 chip 没有这条问题（§4.4）。 |
| 只保留舞台、删掉设置里的两行 | 端口行与解释都在设置；删了以后切到 Tun 的「端口为什么消失」无处可查。 |
| 把标签改成「仅代理 / 全部软件」 | 与左栏、设置、新建卡的既有用词分裂（§3）。 |
| 在无节点 / 到期屏显示 | 改了没有可见结果，是噪声。 |
| 试用期禁用 | 接管方式与流量范围与本机有关，与节点来源无关（§5.6）。 |
| 一键切到 Tun 不确认 | 会断线，且可能弹系统授权；在主按钮下面手滑的代价太高。 |
