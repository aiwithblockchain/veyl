# Veyl 整体 UI 再优化方案

> 审查对象：实际组件与 `src/styles/app.css`，不是文档想象。
> 依据优先级：`veyl-ui` 硬规则 > `ui-ux-pro-max` > 一般审美。
> 本轮只出设计，不改代码。TUN 主链路已跑通，目标是「收一遍视觉 + 修真实缺陷」，不是重做界面。

---

## 0. 先决问题：两套设计同时存在

这是本轮所有「违反规范」判断的根源，必须先拍板，否则前端会照着两份互相打架的文档改。

| 项 | `veyl-ui` SKILL.md（旧） | 实际实现 / `ui-redesign-proposal.md`（新） |
|---|---|---|
| 列结构 | 四列：activity bar 56 + 配置 240 + 控制台 + 助手 400 | 三列：配置 280 + 控制台 + 助手 420（提案 §1.1） |
| 右栏默认 | 启动时隐藏，默认 `false` | 宽屏 ≥1200 默认展开；窄屏收成右边缘 56px tab（提案 §4.2） |
| 助手入口 | 中间顶部最右侧的对话图标按钮 | 右边缘 56px 竖排 tab（提案 §4.2） |
| 浅色色板 | `#FAFAF9 / #F5F5F3 / #FFFFFF` 中性灰 | `#EFEBE1 / #FAF8F2 / #F6F2E9` 暖石（提案 §3.1） |
| 字号 | 只有 6 档，最大 22 | 增加 64 计时器 / 44 状态词 / 20 读数 / 12 元信息 / 10.5 英文标签（提案 §3.2） |
| 签名元素 | 本机→出口的线路图 | 64px 计时器 + 44px 状态词；线路图明确删除（提案 §1.2） |
| 圆角 | `8 / 12` 两档 | `6 / 10 / 14` 三档 |
| 首启第二入口 | 「使用 Google 登录」 | 「使用其他 AI 服务」（无账号体系，`docs/real-device-walkthrough.md` 已记录） |

**结论**：实际实现完整遵循 `ui-redesign-proposal.md`，它不是漂移，是另一次已批准的设计。建议：

1. **更新 `veyl-ui/SKILL.md`**，把上述 6 项改成提案里的版本，保留三条不变量与文案规则。否则每做一次审查都会产出同几条假 P0。
2. 如果反过来以旧 SKILL 为准则需要回退三栏、暖色板、计时器和助手入口——那是重做外壳，不属于本轮打磨，本轮不做。
3. 「Google 登录」是账号体系缺失，不是视觉问题；本轮不补，也不能在首启里放一个点了没反应的入口。

> 本节是 **P0-1（决策项）**，不改样式。下文所有结论基于「保留已批准的新设计」。

## 1. 逐屏结论

### 1.1 三栏外壳与导航

**现状**

- 左栏 280 / 助手 420 / 控制台弹性，断点 1440 / 1200 / 1024（`src/ui/breakpoints.ts`），与提案一致。
- 助手收起为右边缘 56px tab（`AssistantTab.tsx`），带未读点；与提案一致，与旧 SKILL 不一致（见 §0）。
- 左栏顶部 `Veyl / 网络控制台`，底部「设置」；没有 activity bar——与提案一致。
- 三条栏之间是 1px `--hair`，没有阴影；符合「边界靠留白/细线」。

**问题**

1. **P0-1** 旧规范与新实现的冲突（见 §0）。
2. **P1-3 左栏空态没有就地动作**：`ConfigRail` 空态写「让助手配一条，或自己新建一套」，但空态里没有按钮，新建只能去点标题行右侧 28px 的 `+`（`ConfigRail.tsx:105-109`、`:183`）。违反 Empty States「给消息和动作」。
3. **P1-3 左栏错误态没有出路**：`rail__empty` 只显示「配置读取失败」+ 错误文本，没有重试（`ConfigRail.tsx:100-104`）。
4. **P2 零配置时强制展开助手**：`shouldOpenPanelForEmptyConfigs` 只尊重「本次运行关过」，不尊重上次运行存下的关闭选择（`config/onboarding.ts:56-68`）。控制台已有「让助手帮我配」按钮，不必强制。
5. **P2 左栏行高与元信息**：行实际高约 64（padding 11 + 两行），提案也是 64，OK；但元信息 `12px --ink-3` 在深色卡片上对比度不足（见 P0-2）。

### 1.2 中间控制台

**现状**

- 三段骨架正确：hero（主按钮 + 状态）、AI 编排区、底部节点卡。
- 已连接用 64px 计时器 + 20px 状态标签；未连接用 44px 状态词；与提案 §5.2 一致，且状态只由 H1 说一次。
- 读数行（流量 / 延迟 / 出口）20px mono、tabular-nums；标签/副值 12px。
- 空态：零配置有三步说明 + 主按钮；无激活配置有一句「在左侧选一套配置」；加载有 44px hero + 148px 读数 + 96px 卡片骨架；不会像「没加载」。
- 已连接且无 AI 布局时永远至少有一个本地块（`empty_hint` 或 `proxy_card`），不会出现无解释的空白。`blocks: []` 的空白是 AI 明确要求「中间别放东西」，按 `ai-layout.md:482` 是合法状态。

**问题**

1. **P1-1 顶部 64px「控制台」眉标是纯装饰**：`.console__head` 高 64px，只放一个 10.5px 大写、0.14em 字距的「控制台」（`Console.tsx:448-450`、`app.css:3559-3574`）。它不携带事实、重复产品名、把 hero 往下压 64px；也违反「信息密度低、边界靠留白」。删掉后 hero 直接成为首屏。
2. **P2 控制台左右内边距 40px**：提案允许 40，但与左栏 20、助手 24 的节奏不同；窄屏降到 28（`@media 1200`）又出现第二套值。建议宽屏 40 / 窄屏 28 保留，但把 hero 与读数行的上间距统一成 24/32/40 三档，不要 26、34 等散值。
3. **P2 中间区注释块 `.note` 上间距固定 30px**：与读数行 18px 行内边距、AI 块 22px 间距不统一；建议统一 24/32。

### 1.3 左栏配置列表

- 选中行：`--card` 底 + 左侧 2px `--cobalt` + 名称 600；符合提案 §5.3。
- 删除按钮只在 hover / 键盘 focus 时出现（`app.css:3390-3393`），键盘可达；对次要危险动作可接受。
- 加载骨架三行，宽度/高度与真实行不完全等高（骨架约 47px，真实 64px），加载完成会有一次跳动（**P3-6**）。
- 空态/错误态问题见 1.1。

### 1.4 右栏助手

**现状**

- 头部 64px：`助手` 15/600 + 服务名标签 + 三个 28px 图标；对话/历史一二级；输入框在底部。
- 空态按 `needsFirstConfig / hasEverConnected` 分三种，不重复引导；符合「引导只对没学会的用户」。
- 历史会话：标题 + 相对时间；hover/focus 时时间让位给重命名/删除；可用。

**问题**

1. **P0-4 服务名写死**：`AiPanel.tsx:191` 永远显示 `DeepSeek`。用户在设置里切换到 OpenAI / Anthropic 后，头部仍是 DeepSeek——事实错误。App 启动时已经读了 `llmProviderList()`（`App.tsx:287-292`），只是没把当前服务名传下来。
2. **P1-5 消息形态与已批准提案不一致**：用户消息是右对齐白底气泡（`.msg__bubble`，`app.css:228-236`），提案 §5.7 明确「无气泡；每条消息上方 11px 署名（Veyl / 你）；正文 14.5」。现在是气泡 + 14px，且没有「你」署名。
3. **P1-11 服务名标签**：`.ai-panel__model` 10px、大写、`--ink-4`（`app.css:4938-4945`）——低于提案的 11px 标签，且深色对比度 3.37:1。
4. **P2 技术信息外露**：每条助手消息右上角显示 `N tokens`（`MessageItem.tsx:46-48`）。对用户没有决策价值，增加噪音；建议删除或仅 DEV 显示。
5. **P2 状态文字脉冲**：`.msg__streaming` 1.6s pulse、`.composer__status` 1.8s pulse（`app.css:258-261`、`687-690`）超出「动效只有三类」；状态文字保持静态颜色即可。
6. **P2 输入框禁用文案**：`Composer.tsx:152-154` 写「去配置 Key」；现在也支持服务商，改成「去配置 AI」更准。
7. **P2 空态「先连上，再聊」**：有配置但未连接时成立；零配置时被 `needsFirstConfig` 分支覆盖，无矛盾。保留。

### 1.5 首次引导

**现状**：一屏、单列 400px；DeepSeek Key 为主入口，`使用其他 AI 服务`展开自定义表单，`我懂网络，不用 AI` 最轻；主按钮 44px；焦点态清晰；符合提案/规范。

**问题**

1. **P1-6 两个同名主按钮**：展开「其他 AI 服务」后，原来的 `保存并验证` 只降级为 ghost，仍然显示；自定义表单底部又有一个 `保存并验证`（`Onboarding.tsx:128`、`:166-172`、`:288-294`）。同一屏两个同名按钮，点错就保存了另一个表单。展开自定义表单时应隐藏/折叠 DeepSeek 表单，只留一个主按钮。
2. **P2 缺 Google 登录**：已确认是账号体系未接（`docs/real-device-walkthrough.md:141`），不在本轮补；但应在 SKILL 里标注「暂缓」，避免每次审查都报。
3. **P2 字段间距 7/9/10/12/26/28px**：不在 4px 网格上；统一 8/12/24/32 会更稳。

### 1.6 设置页

**现状**：四个 tab（AI 助手 / 连接 / 遇到问题 / 关于），连接页已按上一轮收成一屏；维护项默认收起；行、ghost 按钮、行内反馈；深色可用。

**问题**

1. **P1-2 三个 tab 仍有与 tab 同名的页内标题**：`AI 助手`（`Settings.tsx:1186`）、`遇到问题`（`:1800`）、`关于`（`:1926`）都重复了一遍 tab 名，而「连接」已经删掉。应统一删除，内容直接从第一行开始。
2. **P1-8 设置页整体比主界面小一档**：行标签 13、值 13、说明 11、tab 13/30px 高（`app.css:1176-1214`、`:1339-1372`），而控制台行是 15/12。设置是独立屏幕，但不能像另一个产品；建议：行标签/值 14，说明 12，tab 14、tab 高 36，区块标题（若保留）17/600。
3. **P2 设置行没有 hover 态**：可点行 `.settings-row--button` 有 hover，静态行没有；可以接受。
4. **P2 服务列表操作按钮**：4 个 ghost 按钮挤在一行（编辑/测试/使用/删除），在 760px 弹窗里可读；窄屏需要允许换行（当前 `.settings-actions` 有 wrap，OK）。
5. **P2 版本号写死**：`Settings.tsx:26` `APP_VERSION = "0.1.0"`，现在与 `package.json` / `tauri.conf.json` 一致，但发版会漂移。应从 Tauri `getVersion()` 或构建期注入读取（**P1-10**，列在这里因为主要在设置页露出）。

### 1.7 对话框与浮层

- 焦点陷阱、Esc、aria-modal 覆盖完整；未发现可复现的键盘陷阱。
- 新建配置、确认框、提问框、节点面板、连接遮罩、助手浮层各自可用。

**问题**

1. **P1-4 五套对话框壳子不统一**：标题 15/500（普通 modal、ask-question）、16/500（reset-result）、16/600（connection-overlay）、17/600（new-config）；头部内边距 14/20、16/24、20；关闭按钮 26/28/44。用户在不同弹窗之间会感到「换了套 UI」。
2. **P0-3 节点面板搜索框没有可见焦点**：`.node-sheet__input` 设了 `outline: none`，父级 `.node-sheet__search` 没有 `:focus-within`（`app.css:4503-4533`）。键盘用户 Tab 到搜索框时完全看不出焦点在哪。
3. **P2 对话框宽度档位**：400 / 420 / 480 / 560 / 760 五档；建议收敛为 400（确认）/ 480（表单）/ 760（设置），420 归 400，560 归 480。
4. **P2 连接遮罩**：无按钮、不可取消是对的；文案与节奏保持，不动。

### 1.8 空态、加载态、失败态

| 场景 | 现状 | 结论 |
|---|---|---|
| 左栏加载 | 三行骨架，`aria-busy` | 合格；高度与真实行差 ~17px，P2 |
| 左栏空 | 文案有、动作不在空态里 | P1-3 |
| 左栏错误 | 只有错误文本，无重试 | P1-3 |
| 控制台加载 | hero/读数/卡片骨架 | 合格 |
| 控制台无配置 | 三步 + 主按钮 | 合格 |
| 控制台无激活配置 | 一句「在左侧选一套配置」 | 合格 |
| 中间无内容 | 本地至少一条说明；`blocks: []` 是显式空白 | 合格（不需要加「暂无内容」） |
| 助手空 | 按三种处境给一句话 | 合格 |
| 助手历史空 | 一句话 | 合格 |
| 节点搜索无结果 | 「没有匹配的节点」+ 清空按钮 | 合格 |
| 设置服务读取中 | 「读取服务…」 | 合格 |

### 1.9 深色模式

**结论：结构完整，对比度不完整。**

- 颜色全部走 token，没有写死的浅色值；深色块把 `--canvas/--paper/--panel/--card/--ink*` 全部反相；阴影、遮罩、滚动条也有深色值；`prefers-reduced-motion` 全局兜底。不是临时反色。
- **P0-2 对比度**：
  - 深色 `--ink-3` `#8A8A82` 在卡片 `#22262B` 上是 **4.38:1**（低于 4.5），大量 11–12px 标签落在卡片上（节点事实、设置行、读数副值）。
  - 深色 `--ink-4` `#77776F` 在卡片上是 **3.37:1**、在面板 3.82:1；浅色 `--ink-4` 在面板 `#F6F2E9` 上是 **4.48:1**。`--ink-4` 被当作文字色用了 12 处（步骤序号、速率轴、模型标签、节点元信息等）。
- 修复：深色 `--ink-3` 提到 `#90908A`（卡片 4.74、面板 5.15）；所有 `color: var(--ink-4)` 改成 `--ink-3`；`--ink-4` 只保留给线条、点、focus 描边。

### 1.10 数字与标识符

- 计时器、读数、节点 IP/端口、加密方式、版本、诊断哈希都用 mono / `.num` / tabular-nums；符合。
- 例外：
  - `MessageItem` 的 `N tokens` 用 11px sans + tabular-nums（数值但无 mono）；若保留应改 mono，建议直接删（P2）。
  - `seedSummary` 整句套 `.num`（`Settings.tsx:434`），中文也被送进 mono 字体栈，数字与汉字字重不齐；只给数字包 `<span className="num">`（P2）。
  - 左栏 `N 个节点` 用 12px sans，是提案 §5.3 的规定，不改。
