# 设置界面审查

> 日期：2026-11-06
> 范围：仅设置界面（`src/components/Settings.tsx` 及其子组件），不含主界面与对话区
> 方法：逐项从代码读出控件、文案、状态与消费方；文案是否属实以 Rust 实现为准
> 结论先行：可操作项都已接线；三处只读项**没有任何消费方**（代理模式、测试节点地址、日志级别），
> 其中两处的值或说法与事实不符。另有一处**有条件不属实**（更换 Key 的会话警告），
> 以及一组结构性重复（DeepSeek Key 三个入口）。

---

## 0. 结论摘要

| 类别 | 数量 | 最严重的 |
|---|---|---|
| 重复 | 5 组 | DeepSeek Key 在引导、基础模式、内置 provider 三处 |
| 无效 / 存疑 | 5 项 | 「代理模式」永远是「系统代理」，与实际连接方式无关 |
| 解释不准 | 6 处 | 「恢复直连」在 TUN 连接时不会断开；「测试节点地址」显示的 URL 不存在 |
| 缺失 | 6 项 | 看不到当前配置是「全部流量」还是「只给代理地址」；基础模式不能选模型 |
| 风格不一致 | 5 组 | 危险操作三种形态；只读信息与设置项同形 |

最该先改的三件事见 §6。

## 2. 问题分类

### 2.1 重复

**R1. DeepSeek Key 有三个入口。**
引导页（`Onboarding.tsx:149`）、设置的基础模式（`Settings.tsx:1080-1170`）、高级 provider 列表里的内置 DeepSeek。
三者读写的是同一个 `provider:deepseek`（`llm.rs:15` 明确「内置 DeepSeek 复用已有的 `provider:deepseek`」）。
用户在基础模式改 Key，高级列表里的「内置 DeepSeek」随之变化；反之亦然。用户无从知道这是同一个东西。

**R2. 测试节点被拆成两行。**
「测试节点」（H2，可刷新）与「测试节点地址」（H4，只读 URL）在同一个 tab 相邻，讲的是同一件事。
地址行不提供任何操作，而且显示的还是错误的 URL。

**R3. 网络收尾动作分散在两个 tab。**
「恢复直连」在网络（N3），「强制重置网络」在高级 → 诊断（H8）。
重置确认弹层第 `1757` 行还要求用户「先到「网络」里点「恢复直连」」——同一类操作被拆开，弹层自己都要跨 tab 指路。
另外「恢复直连」与主界面的「断开 VPN」也重叠：一个在控制台，一个在设置。

**R4. 「复制诊断信息」三处。**
设置 → 诊断（H6）、运行时失败块（`RuntimeUpgrade.tsx:855`）、测试节点内容异常块（`Settings.tsx:453-461`）。
上下文不同可以接受，但三处按钮名称与反馈要统一（现在是「复制诊断信息」/「复制诊断」）。

**R5. 「高级」一词两用。**
顶部 tab 叫「高级」（`SECTIONS`，`485-490`），AI 里的 API 模式也叫「高级」（`1055-1077`）。
用户说「高级设置里改一下」时，无法确定指哪一个。

### 2.2 无效或存疑

**I1. 「代理模式 = 系统代理」不属实，且没有消费方。**
`Settings.tsx:1460-1474` 是写死的字符串。实际连接方式来自当前配置：`ConfigDetail.connect_mode`（`system_proxy` / `tun`），
新建配置时可以选「接管全部流量」（`NewConfigDialog.tsx:97-101`）。`RuntimeView` 里没有 `mode` 字段，所以即使想显示也读不到运行时真值。
结论：这一行既不是设置，也不反映现实。→ 见 §4 建议删除，另补真实信息。

**I2. 「日志级别 info（固定）」不属实。**
`logging.rs:31` 的 `FILE_LEVEL = Info` 只是默认值；`logging.rs:289-293` 明确从 `RUST_LOG` 读取覆盖。
界面既不能改，也不该断言「固定」。

**I3. 「测试节点地址」显示的是不存在的 URL。**
UI 常量 `DEFAULT_SOURCE_URL = ".../bootstrap.json"`（`Settings.tsx:26`）；
后端 `DEFAULT_SEED_URL = ".../veyl_seed.json"`（`seed.rs:21`）。两个地址都不是同一个文件，
而且用户没有任何办法修改，显示错误地址只会让排障走偏。

**I4. 强制重置网络在 Windows 上必然失败。**
`services.rs:4966-4970` 对非 macOS 直接报 `UNSUPPORTED`；
设置页没有平台判断，Windows 用户会看到一个永远失败的「最后手段」，错误文案还说「请重启 App」（重启也不会好）。

**I5. 版本号三处双写。**
`Settings.tsx:27` 的 `APP_VERSION` 与 `tauri.conf.json:4`、`package.json:4` 各写一份。
Tauri 提供 `@tauri-apps/api/app` 的 `getVersion()`；不接的话发版必然出现「设置里显示旧版本」。

### 2.3 解释不清或不准

**E1. 「更换 Key 会重建当前会话」只在特定条件下成立。**
基础模式无条件显示这句（`1092-1096`）。后端只在**当前服务是 DeepSeek** 时刷新凭据（`commands.rs:1023` → `agent/mod.rs:205`）。
如果用户当前用的是其它 provider，改 DeepSeek Key 既不重建会话，也不影响任何正在用的东西——
用户却被警告「对话上下文将清空」。

**E2. 反过来，高级模式切换 provider 会重建会话，却什么也不提示。**
`llm_provider_activate` → `refresh_credentials()`（`commands.rs:843`）→ `apply_provider` 让凭据代数 +1
（`agent/mod.rs:84-89`）→ 下一次 `session()` 丢弃旧会话重建（`agent/mod.rs:110-122`）。
界面上只有一句「已切换到「X」。」。同一个后果，一处过度警告、一处完全不警告。

**E3. 「恢复直连」这个名字承诺了它做不到的事。**
`repair_restore_direct`（`services.rs:5578-5614`）只撤代理、停运行时、删临时配置，**没有 stop TUN**。
而主界面的「断开 VPN」走 `runtime_stop`，会先 `self.tun.stop()`（`services.rs:2740-2745`）——设置里这个动作比主按钮还弱。
TUN 连接中点它，隧道还在，网络并没有「直连」。说明里的「不处理接管残留」是内部说法，用户读不出「不会断开全部流量」。

**E4. 「测试节点」这个名字容易被理解成「测试用的节点」。**
这一行实际是默认节点池（种子），来源是远端 JSON；界面上又只显示「v3 · 12 个节点」。
结合相邻的「测试节点地址」，用户很可能以为这两个是测速用的节点或测速服务器。

**E5. 「问 AI」的提示词与位置/只读性不符。**
`advancedPrompts.ts:5-9` 固定「我在 Veyl 的高级设置里调整「X」，当前值是 Y」。
但「代理模式」「本地端口」在**网络** tab，而且是只读信息；「日志级别」「诊断信息」也不是用户在调整的东西。
`ADVANCED_FIELDS.defaultSource` 仍叫「默认配置源」（`advancedPrompts.ts:14`），行名早已改成「测试节点地址」。

**E6. 只读行与可操作行同形。**
代理模式、本地端口、测试节点地址、日志级别、版本、事件源都是 `.settings-row`，
与真正能改的行（恢复直连、导入、复制诊断）长得一样，只有右侧有没有按钮能区分。
用户会点「日志级别」想改它。

### 2.4 缺失

**M1. 看不到当前配置用哪种连接方式。**
「全部流量」与「只给代理地址」是用户做的关键选择，设置里没有任何地方显示它；
反过来，设置里显示的是错误的「系统代理」。这是本次审查里最该补的一项。

**M2. 基础模式不能选模型。**
基础模式只存 Key，模型固定 `deepseek-chat`（`llm.rs:16`）。
想换 `deepseek-reasoner` 或其它模型，必须进「高级」编辑内置 provider——与「基础」这个命名矛盾。
用户如果是从引导页选了自定义 provider，回到设置默认落在基础模式，看到的是一个空的 DeepSeek Key 输入框，
完全看不出「其实已经在用另一个服务了」。

**M3. 刷新 DNS 没有入口。**
后端 `net_repair("flush_dns")` 已实现（`tools/net.rs`、`services.rs`），AI 可以用，设置里没有。
这是 VPN 断连后最常见的修复动作，却只能找助手或执行强制重置。

**M4. 关于页没有开源仓库、许可证、反馈入口。**
开源是产品的硬约束，关于页却只有版本、事件源、首次引导、日志。
用户找不到源码、许可证和反馈渠道。

**M5. provider 列表项上没有「测试连接」。**
必须先点「编辑」再点「测试连接」。测试一个已有服务是只读场景，不该先进编辑态。

**M6. 没有数据与隐私说明。**
只有一句「Key 加密保存在本机」。没有说明：请求会发往哪个域名、诊断信息包含什么、日志里有什么、如何彻底清除。

### 2.5 风格不一致

**S1. 刷新类动词三种。**「检查更新」（运行时、测试节点）、「检查并更新」（后台组件）、「刷新」（provider，且不联网）。

**S2. 危险操作三种形态。** 清除 DeepSeek Key 无确认（`1151-1157`）；删除 provider 行内确认（`1237-1256`）；强制重置模态确认（`1754-1797`）。三者都不可撤销或影响面大，应当统一。

**S3. 反馈通道三种。** 全局 notice（恢复直连、打开日志，且设置已关闭）、行内 feedback（Key、provider）、行内 status（运行时、测试节点、后台组件）。

**S4. 表单形态两套。** AI tab 是内联编辑表单 + `primary` 保存；其余设置全是「行 + 右侧 ghost 动作」。

**S5. 客套语堆积。** `describeKeyError` / `describeProviderError` / `describeResetError` 等处连续使用「请稍后再试」「请检查磁盘权限」「请重新输入」，
与 veyl-ui「说明用完整句子、不堆请」的要求不一致（`Settings.tsx:1992-2107`）。

## 3. 结构建议

### 3.1 现在的划分问题

1. 按「系统零件」分区（账号与 AI / 网络 / 高级 / 关于），用户面对的是模块名，不是能完成的任务。
2. 「高级」是杂物箱：自动升级的程序、Veyl 提供的节点、后台服务、诊断、强制重置混在一起，
   其中强制重置是网络修复，却和「恢复直连」分在两个 tab。
3. 维护类项目（升级、诊断）与日常设置平级混排，是「看不懂」的主要来源。
4. 「关于」里混了开发信息（事件源）与排障入口（日志）。
5. 同一个 Key 有「基础 / 高级」两套界面；同一个节点更新有两个入口。

### 3.2 目标信息架构：按用户想做什么分

```
设置
├─ AI 助手        AI 用哪个服务、哪个模型；怎么换、怎么加
├─ 连接           现在怎么连、用哪个节点、试用节点、导入节点
├─ 遇到问题       平时不用改；出问题时修复、更新、看诊断
└─ 关于           版本与开源信息
```

逐 tab：

- **AI 助手**：一个服务列表（内置 DeepSeek + 自定义），每项显示名称、模型、当前状态，
  动作是设为当前 / 测试 / 编辑 / 删除；下方是添加服务与一句「请求发往哪里、切换会开始新会话」。
  删除基础/高级双模式与独立 Key 表单。
- **连接**：四行——现在怎么连（行为描述 + 代理地址）、用哪个节点、更新试用节点、导入节点文件。
  连接/断开按钮不在这里重复。
- **遇到问题**：首句「这里的东西平时不用改」。修复组（清除残留代理、强制重置网络）可见；
  「更新与诊断」（连接程序、更新后台组件、打开日志、复制诊断信息）默认收起。
- **关于**：版本与开源/反馈；日志移到「遇到问题」。

### 3.3 变化要点

- 删除「高级」tab，内容按用户任务重新分配：试用节点 → 连接；连接程序/后台组件/日志/诊断 → 遇到问题。
- AI 取消基础/高级双模式，只保留一个服务列表；Key 与模型在服务项里编辑。
- 修复类动作集中到「遇到问题 → 修复网络」，按破坏力从低到高排；强制重置独立危险区域。
- 维护类默认收起，标题旁写明「平时不用管」。
- 每行标题是动作或问题（如「更新试用节点」「用哪个节点」），不是实现名词；
  只读信息不做成设置项的样子。

完整的逐 tab 线框、逐行三问检查和文案对照表见 `docs/design/settings-advanced.md`。

## 6. 最该先改的三件事

1. **删掉「代理模式」这一行，补上真实的「连接方式」。**
   这是唯一一处「显示的内容与事实相反、且用户无法从别处确认」的问题。
   改动小：删一行只读文本，在网络 tab 顶部显示当前配置的 `connect_mode`（数据已经在 `App.tsx` 的 `vpn.activeConfig` 里）。

   取消基础/高级双模式，或至少让基础模式显示「当前服务 + 模型」并能切模型。
   现在从引导页选了自定义服务的用户，打开设置会看到一个空的 DeepSeek Key 输入框，以为配置丢了。

   「恢复直连」改名并明确「不会断开全部流量」；强制重置移到「网络 → 修复」，Windows 上隐藏；
   顺带补「刷新 DNS」。这一步同时解决 E3、I4、M3 和重置弹层的跨 tab 指路。
