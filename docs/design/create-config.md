# 新建配置：入口选择与两条创建流程

> 日期：2026-11-07
> 状态：**已被 `docs/design/simplified-config-create.md` 取代**（2026-11-12）。旧内容保留作历史，不再作为实现依据；
> 「只有我指定的服务」与旧节点来源选项均已下线，以两问 / 两档的现行设计为准。
> 上游：`docs/contracts/commands.md` §3.2（`config_create`）、§4.1（`node_import_url`）、§4.2（`node_create`）、
> `docs/user-flows.md` §364、`docs/configs-and-nav.md` §4
> 涉及：`src/components/NewConfigDialog.tsx`、`src/App.tsx`、`src/agent/bridge.ts`、`src-tauri/src/nodes.rs`、
> `resources/prompts/zh/first-run.md`
>
> **这份文档解决什么**：现在点「新建」直接让人选「接管全部流量 / 只给代理地址」——
> 这是只有两选一的猜测题，不懂网络的人答不了，也没告诉他下一步会怎样。
> 改成**先问「谁来配」**，再分成 AI 全程带、或一次性填完两条路。

---

## 1. 现状（查过代码，不是印象）

| 事实 | 证据 |
|---|---|
| 弹窗只有两个字段：名字 + 接管方式，选完就直接建 | `NewConfigDialog.tsx:14-152` |
| 前端建配置固定带 `routingMode: "proxy_all"`、`source: "seed"` | `useVpnSession.ts:314-319` |
| `config_create` **不支持内联节点**，只能 `nodeIds` 或 `source: "seed"` | `commands.md` §3.2 |
| `node_create` / `node_import_url` 命令**都在**，AI 侧也分别有 `NodeCreate` / `NodeImportUrl` 工具（`tools/mod.rs:163-164`）；**只有前端 bridge 一条都没接** | `bridge.ts:441-449` 只有 `nodeSwitch` / `nodeProbe*` |
| 节点模型只有 5 个字段：`name` / `server` / `port` / `method` / `password` | `store/configs.rs:53`、`commands.md` §4.2 |
| **没有传输方式、SNI、伪装、插件字段**，只支持 Shadowsocks | `nodes.rs:19` 的 `SUPPORTED_METHODS` |
| 路由三档本来就存在，只是界面从没暴露 | `rules/plan.rs:184` |
| `category_list` 命令在，前端也没接 | `commands.md` #48，`grep category src/` 无命中 |
| 地区判定只读 `VEYL_REGION` / `LANG`，界面从不显示；**判错会直接走错分流与 DNS** | `rules/mod.rs:22-34`、`plan.rs:132-176` |

**第三条决定了手工流程的提交顺序；第六条决定了字段清单——用户要的「传输方式 / SNI / 伪装」
在当前数据模型里不存在，写出来就是骗人。**

## 2. 结论

| 问题 | 结论 |
|---|---|
| 入口 | 弹窗第一步只问「谁来配」，两张卡：**AI 协助** / **我自己配置** |
| AI 协助 | 新开一个对话，把意图交给现有的首启流程；**最多 3 问 + 1 次确认**，AI 在确认后一次性落库 |
| 我自己配置 | 一个完整表单，一次填完；节点来源四选一（Veyl 免费节点 / 粘贴分享链接 / 订阅地址 / 手动填） |
| 接管方式 | 不再是入口，降级为两条流程内部的**一个字段**，用「所有软件都走 VPN / 只让能填代理的软件走」表达 |
| Veyl 免费节点 | **两条流程都有**，不是 AI 专属 |
| 没有 AI | 卡片永远显示、永远可点；点了直接进 AI 配置模块，配完回到 AI 协助流程（§6） |
| 所在地区 | 从系统时区 / 区域推断，**真正决定分流规则与 DNS**；判不出时不回落 `cn`，改为不做本地直连（§7） |
| 组件 | `NewConfigDialog` 保留为「入口选择 + 载入手工表单」，手工表单独立成 `ManualConfigForm` |
| 新命令 | **两条**：`node_import_text`（粘贴的 `ss://`）、`system_region`（读地区）。其余全部复用已有命令 |

## 3. 第 0 步：谁来配

```
┌ 新建配置 ──────────────────────────── ✕ ┐
│                                          │
│  ┌────────────────┐  ┌────────────────┐  │
│  │ AI 协助          │  │ 我自己配置       │  │
│  │ 我一步步问你，    │  │ 一次填完。        │  │
│  │ 最后帮你建好。    │  │ 知道服务器信息     │  │
│  │                  │  │ 再用这个。        │  │
│  └────────────────┘  └────────────────┘  │
│                                          │
│                              取消         │
└──────────────────────────────────────────┘
```

- 两张卡等宽、可整卡点击，**没有主按钮**（`veyl-ui` §2.1：这一屏的动作就是选一张卡，再加一个实心按钮会出现两个主按钮）。
- 卡片标题 15px/500，说明 13px/400 `--ink-2`；整卡 ≥ 64px 高，命中区远大于 44px。
- 第一张卡默认获得焦点；`↑↓` 切换，`Enter` 进入；`Esc` 关闭。
- 不做「上次选过哪个就默认高亮」——这是每次都该想一下的选择，不是设置。

## 4. 流程 A：AI 协助

### 4.1 做什么

关掉弹窗 → 新建一个对话 → 打开右栏 → 发一条用户消息（AI 不可用时先走 §6，配好再回到这里）：

> 帮我新建一套配置。

用**可见的用户消息**而不是隐藏消息：用户按了按钮，就该看到自己说了什么；
隐藏消息会让 AI 突然自说自话，用户不知道是自己触发的。

### 4.2 AI 问什么（复用首启流程，只压缩轮数）

现有 `first-run.md` 的八步流程本来就是这件事，不重写。**只加一条分支**：
用户已经有配置、又要求「再建一套」时，跳过环境检测（已经知道地区），直接问：

| 轮次 | 问题 | 用户可选 |
|---|---|---|
| 1 | 这套配置主要用来做什么 | 浏览器上网页 / 浏览器，还有聊天、会议、游戏这类软件也要用 |
| 2 | 节点从哪来：用 Veyl 免费节点 / 粘贴分享链接 / 订阅地址 / 你手里有服务器信息 | 四选一 |

**最多 2 问**。接管方式由第 1 问直接推导（「浏览器上网页」→ `system_proxy`；「还有聊天、会议、游戏这类软件」→ `tun`），不再单独问。

为什么不保留原来那道「所有软件都走 VPN / 只让能填代理的软件走」：它和第 1 问是同一件事——用户答了「还要别的软件用」，就只能是全部接管，代理地址模式管不到 APP；而且「能填代理地址的软件」用户不知道自己哪个软件算，选项对他等于空的。2026-11-07 实机测试里两道题连着问出来，用户第一反应是「第二个选项我们没看到」。

第 2 问按用户给的来源走对应分支（粘贴的让用户直接贴，手填的逐项问）。最后用陈述句说结论，一句话确认，确认后落库。

**四个来源在 AI 流程里都能走完**，不存在「请你去手工表单填」这种降级：

| 用户给了什么 | AI 调什么 |
|---|---|
| 「用 Veyl 免费节点」 | `ConfigCreate { source: "seed" }` |
| 直接贴一条或多条 `ss://` | **`NodeImportText`**（新工具，与 UI 的 `node_import_text` 共用实现，走确认链路） |
| 一个 `https` 订阅地址 | `NodeImportUrl` |
| 口头报服务器信息 | `NodeCreate`（逐项问齐五个字段） |

粘贴那条尤其不能降级：用户已经把链接贴在对话里了，再让他去手工表单重贴一遍，
等于把我们收下的东西又扔回去。

### 4.3 什么时候落库

**确认之后一次性落库**，即 `ConfigCreate` 工具调用成功那一刻。在此之前的全部对话都不写库——
用户中途关掉对话、说「算了」，都不留半套配置。

唯一的例外是用户在第 3 问之前就贴了分享链接：节点会先被导入节点池（`NodeImportText`），
但**配置仍然要等确认才建**。只进池的节点是全局池里的孤儿，界面上看不到，不影响任何现有配置。

### 4.4 中途放弃的收尾

| 情况 | 行为 |
|---|---|
| 确认前关掉对话 / 说「算了」 | 什么都不留下（可能有一批孤儿节点，见上） |
| 确认前 AI 出错 | 同上；对话里一句「这次没建成，可以再说一次」 |
| 配置已建、用户不满意 | 配置已经在左栏；删掉它走现有的删除入口，不在这里另做撤销 |

**不做「创建向导」式的可回退步骤**：AI 的对话本身就是可回退的，再叠一层步骤条会出现两个进度概念。

## 5. 流程 B：我自己配置

### 5.1 线框

```
┌ 新建配置 ─────────────────────────────── ✕ ┐
│ ← 返回                                      │
│                                             │
│ 名字      [ 我的配置 2                    ] │
│                                             │
│ 怎么连                                      │
│  ◉ 所有软件都走 VPN                          │
│    装好就能用，不用逐个软件设置。              │
│  ○ 只让能填代理的软件走                        │
│    别的软件不受影响，需要你自己填地址。         │
│                                             │
│ 哪些走 VPN                                   │
│  ◉ 本地网站直连，其他都走 VPN                  │
│  ○ 全部走 VPN                                │
│  ○ 只有我指定的服务走 VPN，其他直连             │
│    └（选中后展开）[ 搜索服务…         ]        │
│                    [✓ ChatGPT] [✓ GitHub] … │
│                                             │
│ 节点                                        │
│  ○ Veyl 免费节点（仅供试用）           │
│  ○ 粘贴分享链接      [ ss://…              ] │
│  ○ 订阅地址          [ https://…           ] │
│  ◉ 自己填                                    │
│     名称 [东京 01        ]                   │
│     地址 [1.2.3.4        ]  端口 [ 443   ]  │
│     加密方式 [aes-256-gcm ▾]                │
│     密码   [••••••••      ] [显示]           │
│     + 再加一个节点                            │
│                                             │
│                         取消   [ 创建 ]      │
└─────────────────────────────────────────────┘
```

- 主按钮只有一个：`创建`（实心）。`取消` 与 `← 返回` 都是 ghost。
- **「只有我指定的服务」已下线**（`proxy_selected` 不可写，见 `simplified-config-create.md` §12）：上面第三项与「搜索服务」只作历史，现行只有两档。
- 单列纵向，分组之间 24px，组内 12px（`veyl-ui` §3.3 的 4px 网格）。
- 所有输入都有可见 label（不用 placeholder 当标签）。
- 校验失败：**字段旁**红字 + 该字段获得焦点；同时不弹 toast（`ui-ux-pro-max`：Error Messages / Form Labels，High）。

### 5.2 字段清单

#### 配置

| 字段 | 必填 | 用户从哪来 | 校验 | 控件 |
|---|---|---|---|---|
| 名字 | ✅ | 自动填「我的配置 N」，用户可改 | trim 非空、≤40、不重名 | 文本框，预填并全选 |
| 怎么连 | ✅ | 二选一 | — | 单选，默认「所有软件都走 VPN」 |
| 哪些走 VPN | ✅ | ~~三选一~~ 现行两选一 | — | 单选，默认「本地网站直连，其他都走 VPN」 |
| ~~指定的服务~~ | — | 已随第三项下线（`proxy_selected` 不可写）；现行两档没有这个字段 | — | — |

**「怎么连」与「哪些走 VPN」的组合关系**：

| 怎么连（`connect_mode`） | 哪些走 VPN（`routing_mode`） |
|---|---|
| 所有软件都走 VPN = `tun` | 本地直连 = `direct`；全部走 = `proxy_all`；指定服务 = `proxy_selected` |
| 只让能填代理的软件走 = `system_proxy` | 同上 |

> **命名陷阱**：枚举里的 `direct` 表示的是「**本地网站直连、其余走 VPN**」，不是「全部直连」。
> 依据 `rules/plan.rs:184-243` 与它的单元测试 `cn_direct_uses_cn_sets_and_route_local`。
> 实现时不要把用户选的「本地直连」映射成别的值。

#### 节点来源（四选一，默认「Veyl 免费节点」）

| 来源 | 走哪个命令 | 说明 |
|---|---|---|
| 用 Veyl 免费节点 | `config_create { source: "seed" }` | 不填任何节点字段；种子为空时按现有逻辑先刷新再重试 |
| 粘贴分享链接 | **`node_import_text`（新增）** | 支持一条或多条 `ss://`；不是 URL，不发网络请求 |
| 订阅地址 | `node_import_url { url }` | 必须 `https`；拉取失败整体失败，不建配置 |
| 自己填 | `node_create { … }` | 逐字段，可「再加一个」 |

#### 手动节点的五个字段

| 字段 | 必填 | 用户从哪来 | 校验 | 控件 |
|---|---|---|---|---|
| 名称 | ✅ | 自动填「节点 1」 | trim 非空、≤64 | 文本 |
| 地址 | ✅ | 服务商给的域名或 IP | 不带 `://`、不带端口、不含空白 | 文本（mono） |
| 端口 | ✅ | 服务商给的端口 | 整数 1–65535 | 数字输入（mono） |
| 加密方式 | ✅ | 服务商指定 | 必须在 `SUPPORTED_METHODS` 内（12 项） | 下拉，默认 `aes-256-gcm` |
| 密码 | ✅ | 服务商给的密码 | 非空、≤256 | 密码框，可切明文 |

**没有传输方式 / SNI / 伪装 / 插件字段**——这是本轮的能力边界，证据与理由见 §5.3。
表单底部一行小字：「目前只支持 Shadowsocks 服务器。」

#### 不放进表单的

`dns`（默认 `auto`）、`tun_excludes`（默认空）、`listen_port`（全局设置，不属于配置）。
三个都走默认值；要改是设置页或后续编辑，不是新建时该问的。

### 5.3 能力边界：只支持 Shadowsocks 的五个字段

**这是本轮的能力边界，不是设计漏了字段。** 实现时不要把它当成待补的 TODO，
也不要在表单里预留空位。

| 层 | 事实 | 证据 |
|---|---|---|
| 表结构 | `nodes` 只有 `id / name / server / port / method / password_ref` | `001_init.sql:52` |
| 领域模型 | `Node` 同样五个字段，没有传输层 / 插件字段 | `store/configs.rs:53` |
| 协议 | `SUPPORTED_METHODS` 全是 Shadowsocks 方法；没有 VMess / VLESS / Trojan / Hysteria | `nodes.rs:19` |
| 命令 | `node_create` 只接受五个参数，多传的字段无效 | `commands.md` §4.2 |

因此表单里**不出现**：传输方式（WS / gRPC / HTTP2）、SNI、伪装域名、REALITY、插件参数。
出现它们等于给用户一个填了也不生效的控件——比不提供更糟。

界面底部一行 13px `--ink-3`：**「目前只支持 Shadowsocks 服务器。」**

要支持别的协议，改动在数据模型与运行时配置生成两侧，不在这个表单里——那是一次独立的需求，
届时表结构、`node_create` 入参、`SUPPORTED_METHODS` 会一起变。

### 5.4 提交顺序（关键）

`config_create` 不能内联节点，所以是**先建节点、再建配置**：

```
1. 前端校验全部字段（不发命令）
2. 按来源建节点，收集 node_id：
     自己填 → node_create × N
     粘贴   → node_import_text
     订阅   → node_import_url
     测试   → 跳过（不建节点）
3. config_create { name, connectMode, routingMode, targets?, nodeIds | source: "seed" }
4. 成功 → 关闭弹窗；按 §3.2 的激活规则，未连接时它自动成为当前配置
```

**为什么不是先建配置**：先建配置会在左栏立刻出现一套**没有节点、连不上**的配置。
如果随后建节点失败，用户手里就多了一个需要自己删的空壳。先建节点，失败时配置根本不存在。

失败处理：

| 失败点 | 行为 |
|---|---|
| 节点校验失败（第 2 步） | 字段旁报错，停在表单；**不建配置** |
| 订阅拉取失败 | 同上，报「没拉到节点，检查地址或网络」 |
| 配置名重复（第 3 步） | 报在名字字段；**已建的节点留在池里，id 保留在表单状态里**，改名重试时复用，不会重复建节点 |
| 其他后端错误 | 顶部一条错误条 + 保留表单内容 |

## 6. 与 AI 配置模块的边界

**「新建配置」不负责配置 AI，它只调用 AI 配置模块。** 这条是本节的全部要点，
下面三小节分别是职责、接口、返回契约。

### 6.1 职责划分

| 模块 | 负责 | 不负责 |
|---|---|---|
| **新建配置**（本文） | 入口选择、两条流程、字段收集、落库 | 判断缺 Key 还是缺服务商、校验服务商、保存密钥、展示 AI 配置表单 |
| **AI 配置模块**（现有 `Onboarding`，`Onboarding.tsx:30`） | 密钥 / 服务商的选择、保存、校验、可用性判断 | 新建配置的任何字段与流程 |

两边只共用一个判断：**AI 现在可用吗**——`refreshAiStatus()` 返回的 `ready`
（`App.tsx:252-270`）。新建配置只读这个布尔值，**不问它为什么是 false**。

### 6.2 调用接口

```
createFlow.ensureAiReady():
  aiReady == true   → "ready"        继续「AI 协助」流程
  aiReady == false  → "needs_setup"  把控制权交给 AI 配置模块
```

不可用时**只做一件事**：把控制权交出去，并声明「结束后回到这里」。
**不在入口提示「先配置 AI」，不放禁用态，不隐藏卡片**——入口不替用户判断，
用户按了「AI 协助」就是要去配 AI，那就直接把他推到配置面前。

### 6.3 返回契约

AI 配置模块结束时回调——沿用 `Onboarding` 现有的 `onDone(skipped)` 形状，
但**由新建配置提供自己的处理器**（不是 `App.tsx` 里首启那个 `finishOnboarding`，见 §9）：

| 结果 | 新建配置这边做什么 |
|---|---|
| 配好了（`skipped = false`） | **回到「AI 协助」流程**，新开会话、发开场那句「帮我新建一套配置。」 |
| 放弃了（`skipped = true`） | **回到入口选择**（两张卡），不关弹窗、不丢上下文 |

三条硬约束：

1. **不跳到设置页，也不把用户丢在聊天页**——配完 AI 立刻接上刚才那条路。
2. **不静默关掉整个弹窗**——放弃时用户要看到那两张卡，知道自己在哪一步。
3. 回到入口时，**「我自己配置」仍然可用**——放弃配 AI 不等于放弃新建配置。

### 6.4 状态机

```
choose ──选 AI 协助──▶ aiReady? ─是─▶ ai_flow（新会话）
  │                       └─否─▶ ai_setup ──配好──▶ ai_flow
  │                                   └──放弃──▶ choose
  └──选 我自己配置──▶ manual ──创建成功──▶ 关闭
                        └──取消/返回──▶ choose
```

四条回头边都必须能走通。`ai_setup` 是唯一不属于本模块的状态——它归 AI 配置模块所有，
新建配置只在入口和出口各转发一次，不读它的内部状态。

### 6.5 为什么不在入口就提示

用户按「AI 协助」的意思是「我要 AI 帮我配」，不是「我要先看一段关于 AI 的说明」。
把配置引导直接推到面前更接近他要的结果；而入口一旦开始判断「缺 Key 还是缺服务商」，
就要维护第二套 AI 可用性逻辑——那正是把这件事交给独立模块的理由。

## 7. 当前所在地区

### 7.1 这是分流正确性问题，不是展示问题

地区决定两件事，都在 `rules/plan.rs` 里写死：

| 地区 | 本地直连用哪些规则 | DNS |
|---|---|---|
| `cn` | `geosite-cn` + `geoip-cn`（**域名 + IP 段**都直连） | 本地 `223.5.5.5` / `119.29.29.29`；国外域名走代理解析 |
| 其它 | 只有 `geoip-<cc>`（**仅 IP 段**） | `1.1.1.1` / `8.8.8.8` |

证据：`plan.rs:132-138 local_layer()`、`plan.rs:145-176 dns_servers()`。

判错的后果不是文案难看：

- 中国用户被判成 `us` → 国内网站**全部走代理**，DNS 走国外——又慢，还可能被污染；
- 非中国用户被判成 `cn` → 用上中国 DNS，解析自己的网站反而不正常。

所以这个值的用途是「**确认用户是不是中国用户**」，展示只是顺带——让人看明白为什么这样分流。

### 7.2 现状与真实 bug

| 事实 | 证据 |
|---|---|
| `detected_region()` 只读 `VEYL_REGION`，再读 `LANG`，取不到返回 `None` | `rules/mod.rs:22-34` |
| 三个调用点各自 `unwrap_or("cn")` | `services.rs:5317`（连接）、`probe_batch.rs:442`（测速）、`services.rs:2209`（`route_get` 回显） |
| 注释自己写着「UI 接上系统区域后改为传入」——一直没接 | `rules/mod.rs:19-21` |

GUI 应用里 `LANG` 常常是 `en_US.UTF-8`，甚至根本没有：结果中国用户被判成美国，
非中国用户在取不到时被回落成 `cn`。**两条都是真错，而且没人看得见。**

### 7.3 判定口径

优先级，离线、不联网、不测 IP：

| 顺序 | 来源 | 例 | 现在 |
|---|---|---|---|
| 1 | `VEYL_REGION` 环境变量 | `jp` | 有 |
| 2 | **系统时区**：macOS / Linux 读 `/etc/localtime` 符号链接；Windows 读注册表 `TimeZoneKeyName` | `Asia/Shanghai` → `cn` | 没有 |
| 3 | 系统区域：macOS `defaults read -g AppleLocale`；Windows `Control Panel\International\LocaleName`；Linux `LC_ALL` | `zh_CN` → `cn` | 没有 |
| 4 | `LANG`（今天的首选，降为最后） | `zh_CN.UTF-8` → `cn` | 有 |
| 5 | 都取不到 | `未知` | — |

**为什么时区优先于区域**：分流关心的是「哪些网站对这台机器算本地网站」，那是位置；
区域设置反映的是语言偏好，双语机器、旅行中的机器、公司统一装机都会与位置不符。
时区是位置最接近的代理指标。

时区 → cc 用一张小表（约 30 条），不引第三方库：

| 时区（节选） | cc |
|---|---|
| `Asia/Shanghai`、`Asia/Chongqing`、`Asia/Harbin`、`Asia/Urumqi` | `cn` |
| `Asia/Hong_Kong` | `hk` |
| `Asia/Taipei` | `tw` |
| `Asia/Tokyo` | `jp` |
| `America/*` 任意 | `us` |
| Windows 的 `China Standard Time`、`Tokyo Standard Time` 等 | 同名映射 |

表外的一律按区域/`LANG` 再判；仍判不出就是未知。

### 7.4 未知时不回落 `cn`

今天是 `None → "cn"`。**改成本轮之后：未知 → 不做本地直连层。**

- `local_layer` 返回空：没有 `geosite-*` / `geoip-*` 直连规则，除内网外全部走代理；
- DNS 用国际那组（`1.1.1.1` / `8.8.8.8`）。

理由：两种错法的代价不一样。给一个非中国用户套上中国 DNS 与 `geosite-cn`，他的网络会解析异常；
给一个中国用户少一层直连，只是国内网站慢一点。**宁可少优化，不要错优化。**

改动点：`RouteInput.region` 从「字符串」变成可表达「未知」的形态（见 §7.5），
`local_layer(None) -> vec![]`，`dns_servers(None, ..)` 走国际那组。

这一段改的是**自动路径**；用户手选「本地网站直连」时走的是同一段生成代码，见 §7.4.1。

### 7.4.1 未知地区 + 用户手选「本地网站直连」

`normalized_region`（`plan.rs:99-104`）今天把 `None` 折成 `"cn"`：

```rust
fn normalized_region(region: Option<&str>) -> String {
    region.unwrap_or("cn").trim().to_ascii_lowercase()
}
```

也就是说，**就算调用方传进来的是「未知」，`build` 里拿到的仍然是 `cn`**。
非中国用户只要在表单里点一下「本地网站直连」，就又套上了中国规则集与国内 DNS——
同一个 bug，只是从自动触发变成手动触发。这一条必须连同 §7.4 一起改。

三种做法，**选 1**：

| 做法 | 结果 |
|---|---|
| **1. 不给本地规则集** | `local_layer(未知) = []`，实际等价于「全部走 VPN」；界面如实说明 |
| 2. 回落 `cn` | 明确接受误判：非中国用户 DNS 被污染、国内规则误直连 |
| 3. 禁用这个选项 | 把我们的能力不足变成用户的限制 |

选 1 的理由：用户明确说了「我要让本地网站直连」，我们做不到（不知道哪些算本地），
就**如实说做不到**，而不是偷偷套一个国家的规则。方案 3 挡住了用户一个合理的意图，
而识别不出地区是**我们**的问题；方案 2 是把已知的错当成答案。

配套两处，缺一不可：

- **表单里**：未知地区时选中「本地网站直连」，该选项下方出现一句
  「认不出你所在的地区，选这个的话所有网站都会走 VPN」。**不阻止选择。**
- **连接后**：中间区那行（§7.6）写「没识别出你在哪个地区，所有网站都走 VPN」，与实际行为一致。

**改动点**：删掉 `plan.rs:101` 的 `unwrap_or("cn")`；`normalized_region` 返回 `Option<String>`；
`local_layer` / `dns_servers` 接受未知并走「无直连层 + 国际 DNS」。

### 7.5 接进分流：传递路径

```
detected_region()            ← 补时区 / 系统区域两级（§7.3）
      │
      ├─ services.rs:5317    连接：RouteInput.region
      ├─ probe_batch.rs:442  批量测速的临时运行时：同一个值
      ├─ services.rs:2209    route_get.detected_region（回显，给界面）
      └─ 新命令 system_region（给新建配置那一行）
```

**四个入口读同一个函数，回落只允许有一处。** 今天 `None → "cn"` 的折返点在
`plan.rs:99-104 normalized_region`，也就是**分流侧**；而界面侧如果显示「未知」，
同一台机器就会出现「界面说未知、实际按中国分流」。删掉那处 `unwrap_or` 之后，
四个入口拿到的是同一个 `Region`，「显示」与「实际使用」只剩一个来源。

回归断言：同一进程内，四处取到的 `Region` 必须相等（写成一个单元测试，别靠人工核对）。

实现建议：在 `rules` 里定义

```rust
pub enum Region { Cn, Cc(String), Unknown }
```

让四个调用点拿同一个类型，不要在每处各写一次 `unwrap_or("cn")`——今天这个 bug 就是这么来的。
`RouteInput` 的字段随之改成 `region: &Region`。

### 7.6 展示（解释性，不是目的）

**新建配置**（手工表单）：放在「哪些走 VPN」组标题下，紧贴它建议的那组选项：

```
哪些走 VPN
  你的电脑在中国大陆，下面默认选了「本地网站直连」——中国网站不会变慢。
  ◉ 本地网站直连，其他都走 VPN
  ○ 全部走 VPN
  ○ 只有我指定的服务走 VPN，其他直连        ← 已下线，只作历史
```

**「只有我指定的服务」已下线**：现行只有前两项；用户要按服务挑选时如实说明暂不支持（`simplified-config-create.md` §12）。

**AI 协助**：由 AI 在对话里说（「你在中国大陆，我建议让国内网站直连」），界面不另起一行。

**已连接时的中间区**：在本地规则渲染的那张卡里加一行 13px `--ink-2`，说明当前直连口径：

| 地区 | 文案 |
|---|---|
| `cn` | 国内网站直连，其他走 VPN |
| 其它 cc | 这个地区的网站直连，其他走 VPN |
| 未知 | 没识别出你在哪个地区，所有网站都走 VPN |

- 只在**路由模式是「本地网站直连」**时出现。「全部走 VPN」没有直连层（本地规则虽被引用，
  但同样路由到代理），「只指定服务」也不经过本地层——这两种都不显示，避免说一句做不到的话。
- 这一行同时是 §7.7 的迁移说明——用户升级后第一次连接就能看到现在按什么规则走。

### 7.7 迁移影响

改判定之后，一部分老用户的规则集会变：

| 用户 | 以前 | 以后 | 后果 |
|---|---|---|---|
| `LANG=en_US` 的中国用户 | `geoip-us` | `geosite-cn` + `geoip-cn` | 国内网站变直连、DNS 变国内——更快 |
| 取不到地区但不在中国 | 回落 `cn` | 未知（无直连层） | 不再被套中国 DNS |
| 其余 | — | — | 不变 |

- **改的是下一次连接**，当前连接不动（与 `config_update` 的「下次连接生效」同一条原则）。
- **不弹窗、不登记问题**：这不是故障，是修好了一个错。
- 用户能看见的只有 §7.6 那行说明——它本来就在，不需要为此新增一次性提示。
- 如果真有用户觉得「以前是直连，现在不是了」，他在对话里说一句就能改；分流本身也有选项。

### 7.8 AI 侧怎么拿到

**注入系统提示词，不加工具。** 这是每轮都要用、几乎不变的上下文，做成工具等于让模型多花一轮
去拿一句它每句话都可能用到的常识。

注入点：`claurst_session/mod.rs:67 system_prompt()`，追加：

```
# 环境
用户所在地区：中国大陆（由系统时区与区域设置推断，不是 IP 定位）。
给分流建议时按这个地区说。用户说不对，就以用户为准，照着他的说法继续。
```

- 每次请求组装一次，离线。
- 未知时写「未知」，让 AI **不要猜**，直接问「你现在在哪个国家或地区？」——
  `first-run.md:56-66` 已有这个分支，不需要新逻辑。
- 顺带修一个现存的空头承诺：`first-run.md:56-66` 写着「环境信息每轮由系统提供，
  不需要调用工具」，但**没有任何地方提供过**。这段注入就是那份信息。

### 7.9 契约

- **新增一条命令**（编号顺延，排在 `node_import_text` 之后）：

  ```ts
  system_region {} → { region: string | null }   // 小写 cc，如 "cn"；未知为 null
  ```

  只有 UI 调用，AI 不调用（它拿的是提示词里那句话）。
- 为什么不复用 `route_get.detected_region`：`route_get` 要一套配置才返回
  （`services.rs:2209`），而新建配置时**可能一套都没有**（全新安装）。`route_get` 里那个字段保留，
  两处读同一个函数。
- `commands.md` 补这条命令；`route_get` 的说明补一句「与 `system_region` 同源」。
- **`runtime.md` / `rules` 的分流说明要补**：未知地区不再回落 `cn`，改为无本地直连层（§7.4）。
- 不落库、不加事件：地区随系统变，缓存它只会制造「设置改了但没生效」。

## 8. Veyl 免费节点放在哪

**两条流程都能一键用**，不是 AI 专属：

## 10. 契约与实现影响

### 10.1 新增两条命令

```ts
// 命令表 #67（#65/#66 已被本地代理端口占用）
node_import_text { text: string, configId?: string } → NodeImportResult
// 命令表 #68
system_region    {} → { region: string | null }     // 小写 cc；取不到为 null
```

- `node_import_text` 复用 `nodes.rs:159 parse_subscription`（它本来就接受已展开的 `ss://` 列表），
  **不发网络请求**。`node_import_url` 保持 URL-only：它的 SSRF / https-only 规则是为「我们替用户去拉」
  设计的，不能拿来接收用户粘贴的文本。
- `system_region` 读同一个 `detected_region()`，只给 UI 用（AI 拿的是提示词里那句话，§7.8）。
  新建配置时可能一套配置都没有，`route_get` 那条路拿不到值，所以单独一条。
- 其余全部复用：`node_create`、`node_import_url`、`config_create`、`category_list`。
- **同一条能力在 AI 侧还有一层工具**：`NodeImportText`，与 `node_import_text` 共用实现，
  只是注册成模型可调用的工具（走现有确认链路）。**命令数不变，工具 +1。**

### 10.2 前端 bridge

`bridge.ts` 目前一条节点写命令都没有，要补五个：`nodeCreate`、`nodeImportUrl`、`nodeImportText`、
`categoryList`（只读，用于「指定服务」）、`systemRegion`（只读，用于 §7 那一行）。

### 10.3 提示词

- `first-run.md` 增加一段「再建一套配置」：跳过环境检测，按 §4.2 的两问走，确认后 `ConfigCreate`。
  不改现有的首启八步。
- `system_prompt()` 注入「用户所在地区」一段（§7.8）。**这同时补上了 `first-run.md:56-66`
  「环境信息每轮由系统提供」这个从来没兑现过的承诺。**
- 节点来源段补一条：**用户在对话里直接贴 `ss://` 链接时，调用 `NodeImportText`，
  不要自己解析、不要编造节点**。模型自己读链接里的密码/加密方式去拼节点，
  既容易错（SIP002 有两种编码），也会把不该进正文的东西念出来。贴了几条就传几条。

## 12. 不做的事

- 不做多步向导/步骤条（AI 那条路的进度就是对话）。
- 不做「传输方式 / SNI / 伪装」字段——这是本轮的能力边界，理由与证据见 §5.3。
- 不做 IP → 国家的映射，也不联网查 IP 归属——地区只看系统区域与时区（§7.1）。
- 不做「地区设置」的独立开关：识别错了，用户在对话里说一句，AI 就以用户为准；分流选项本身也能改。
- 不在新建时问 DNS 与内网排除。
- 不把「Veyl 免费节点」做成 AI 专属。
- 不在没有 AI 时隐藏或禁用「AI 协助」，也不在入口提示「先配置 AI」——直接进配置引导（§6）。
- 不做配置模板/预设组合。
- 不改左栏与四个 tab 的信息架构。

## 13. 设计依据

- **`ui-ux-pro-max`**（本次查询）：
  - *Error Messages*（High）：错误用 `role="alert"` 播报，不能只靠红色边框 → §5.1 字段旁错误。
  - *Form Labels*（High）：每个输入都要有可关联的 label，不用 placeholder 当标签 → §5.2 全部字段带 label。
  - *Focusable Error Summary*（High）：多处错误时汇总要能被键盘找到 → 本表单错误就近显示，不另做汇总。
  - *Submit Feedback*（High）：提交后必须有加载/成功/失败反馈 → §5.4 第 4 步与失败表。
  - *Focus States*（High）：浮层内所有控件都有可见焦点环 → §3 键盘操作。
  - *User Freedom*（Medium）：任何流程都能退出 → §3 的 `Esc`、§5.1 的 `取消`/`← 返回`。
- **`veyl-ui`**：
  - §2.1 同一屏只有一个主按钮 → §3 入口弹窗不放实心按钮，§5.1 只有「创建」是实心。
  - §3.2 字号阶梯（22/17/15/14/13/11）→ 卡片标题 15、说明 13、字段标签 13。
  - §3.3 4px 网格、`--r-sm 8px` / `--r-lg 12px`。
  - §5 界面禁词：**proxy、TUN、分流、规则集**——全文案用「所有软件都走 VPN」「能填代理的软件」「本地网站直连」表达。
