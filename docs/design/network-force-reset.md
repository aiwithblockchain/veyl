# 强制重置网络（E3）设计与交互规格

> 日期：2026-11-05
> 状态：方案定稿，前端与评审用；本文只写规格，不改代码。
> 关联：`docs/capabilities.md` §3、`docs/issue-management.md` §8、`docs/middle-area-local-rules.md` §4.3.4、`.claude/skills/veyl-ui/SKILL.md`

---

## 1. 入口

**选择 B：保留轻量「恢复直连」，在「设置 → 高级 → 诊断」新增「强制重置网络」。**

- A（升级现有「恢复网络」并加确认）否决：日常修复会突然变成高破坏操作，用户容易误触。
- C（问题卡二级入口）本轮不做：与 `middle-area-local-rules.md` §4.3.4「失败卡里不放按钮」冲突，且主界面不该出现危险按钮；托盘的本地入口已能覆盖自救场景。

### 1.1 设置 → 网络：保留轻量入口「恢复直连」

原来的「恢复网络」只做「撤销系统代理 + 停止运行时」，不处理接管残留。它是常用修复，不是最后手段。

| 元素 | 文案 |
|---|---|
| 标签 | `恢复直连` |
| 说明 | `撤销系统代理并停止运行时；不处理接管残留。` |
| 按钮 | `恢复直连`，`btn btn--ghost` |
| 确认 | 无；一键执行 |

改名是为了和下面那个高破坏性入口区分。不要让用户以为两个按钮是同一件事。

### 1.2 设置 → 高级 → 诊断：新增「强制重置网络」

在「高级」分区里加一个 `settings-subhead`：`诊断`。保留「诊断信息」行，在它下面新增：

| 元素 | 文案 / 类名 |
|---|---|
| 标签 | `强制重置网络` |
| 说明 | `停掉接管并恢复系统网络设置；保留配置和助手授权。` |
| 按钮 | `强制重置网络`，`btn btn--danger-ghost` |
| 行下提示 | `只在「恢复直连」无效时使用。`，`settings-note` |

规则：

- **只在 `reset_network` 能力可用时渲染整行。** 能力未就绪就整行不出现，不要放一个点了报错的死按钮。
- 执行中按钮变为 `正在重置…`，`disabled`。
- 这是唯一常驻入口；主界面固定骨架里不出现强制重置按钮。

### 1.3 托盘菜单

- 菜单顺序：`显示 Veyl` / 分隔线 / `强制重置网络…` / 分隔线 / `退出`。
- 带省略号：点击**不直接执行**，只把主窗口带到 `设置 → 高级 → 诊断`，把「强制重置网络」行滚到可见位置，再打开同一个确认弹层。
- 运行中再次点击：只聚焦正在运行的弹层，不发起第二次重置。
- 能力未就绪时不注册这个菜单项。
- 不加入应用菜单栏；不设全局快捷键。最后手段不该有一个容易误触的快捷键。

### 1.4 问题卡（本轮不做）

问题卡里加二级入口与 `docs/middle-area-local-rules.md` §4.3.4「失败卡里不放按钮」冲突，且会让主界面多一个危险按钮。本轮不做。

将来如果产品确认要做，只在 P0/P1 网络问题卡 footer 加一个 `btn btn--danger-ghost btn--sm`：`强制重置网络…`，复用同一个全局弹层，不改文案。

## 2. 文案

界面文案统一用「接管」「系统代理」「路由」「DNS」；不出现内部术语。

### 2.1 确认弹层

- 容器：`modal-backdrop` + `modal modal--confirm reset-dialog`
- 标题：`强制重置网络？`（`modal__title`）
- 右上角：`modal__close`，`aria-label="关闭"`
- 顶部警告：`这是最后手段。先到「网络」里点「恢复直连」；只有它无效时再继续。`（`reset-confirm__warning`，12px，`--warn-text`）

三段式：

| 段 | 文案 |
|---|---|
| **会发生什么** | `当前连接会立即断开。Veyl 会停止接管、清理残留组件和临时文件、恢复路由和 DNS，并撤销系统代理。` |
| **不会发生什么** | `不会删除配置和节点，不会撤销助手的授权，也不会改动其它设置。` |
| **现在做什么** | `先退出其它 VPN、代理或网络加速软件；如果正在开会或下载，等结束再做。确认后网络会短暂中断，通常几秒内恢复；需要时再点「启动 VPN」。` |

按钮：

| 按钮 | 文案 | 类名 |
|---|---|---|
| 取消 | `取消` | `btn btn--ghost` |
| 最终 | `强制重置` | `btn btn--danger-ghost` |

交互：

- 初始焦点落在「取消」，不落在危险按钮。
- 确认前：Esc、背景点击、右上角关闭都可用；焦点陷阱。
- 运行中：禁用关闭、Esc、背景点击和「取消」，避免半途中断。

### 2.2 执行中

- 标题：`正在重置网络`
- 正文：`不要关闭 Veyl。网络会短暂中断。`
- 进度：
  - 后端有逐步事件：显示八步，当前步 `进行中`，其余 `等待中`。
  - 后端只有一次性结果：显示一条 1px 不确定进度线 `reset-progress` + `正在重置…`。**不要伪造八步完成。**
- 按钮：`正在重置…`，`disabled`。
- `prefers-reduced-motion` 下进度线改为静态。

### 2.3 成功与失败的标题

| 情况 | 标题 | 颜色 |
|---|---|---|
| 八步全过 | `网络已重置` | `--ink` |
| 仅「恢复 DNS」/「删除临时配置」/「复查网络状态」失败 | `网络已重置，但有 {n} 项没完成`（n ≥ 1） | `--warn-text` |
| 「关闭接管」/「停止运行时」/「撤销系统代理」/「清理残留进程」/「恢复系统路由」任一步失败 | `重置没有完成` | `--err-text` |
| 命令没有开始 | `重置没有开始` | `--err-text` |

成功后副标题：`八项检查都通过。需要时再点「启动 VPN」。`

## 3. 八步与结果展示

> 执行顺序固定，前端按后端返回的 `steps` 顺序渲染。能力文档 §3 的 5 步是粗粒度版本；本文的 8 步是界面与结果展示的最终粒度。

### 3.1 步骤 id 与中文名

| # | id | 界面中文名 | 成功后说明 |
|---|---|---|---|
| 1 | `stop_tun` | `关闭接管` | `接管已关闭。` |
| 2 | `stop_runtime` | `停止运行时` | `运行时进程已停止。` |
| 3 | `restore_proxy` | `撤销系统代理` | `系统代理已恢复到连接前的设置。` |
| 4 | `sweep_processes` | `清理残留进程` | `没有遗留的 Veyl 网络进程。` |
| 5 | `clear_routes` | `恢复系统路由` | `系统路由已恢复。` |
| 6 | `flush_dns` | `恢复 DNS` | `DNS 已恢复为系统默认。` |
| 7 | `clear_plaintext` | `删除临时配置` | `临时配置文件已删除。` |
| 8 | `verify` | `复查网络状态` | `代理、路由、DNS 和组件都符合预期。` |

说明：

- id 只用于代码与契约，不展示给用户；`stop_tun` 的中文名固定为「关闭接管」。
- 每一步结果只有 `ok: true / false`；没有第三种状态。没有执行的步骤也返回 `ok: false`，并在 `detail` 说明原因。

### 3.2 结果弹层结构

复用确认弹层，切换为结果视图：

- `reset-result` 容器
- 标题：`reset-result__title`
- 副标题：`reset-result__sub`
- 步骤列表：`reset-steps`
- 单行：`reset-step`
  - `reset-step__icon`：14px SVG；`ok=true` 用对勾、`ok=false` 用叉；颜色 `--ok` / `--err`
  - `reset-step__body`
  - `reset-step__label`：14 / 500
  - `reset-step__detail`：12 / `--ink-3`
  - `reset-step__status`：11px，右侧；`已完成` / `未完成`
- 失败行的下一步：`reset-step__next`，12 / `--ink-2`
- 列表栅格：`grid-template-columns: 18px 1fr auto`，行高约 52px，行间 `1px solid var(--hair)`；8 行时列表 `max-height: 56vh; overflow-y: auto`。

状态不能只靠颜色：每行同时有图标和文字状态。

### 3.3 成功

- 标题：`网络已重置`
- 副标题：`八项检查都通过。需要时再点「启动 VPN」。`
- 八行全部 `已完成`，说明用 §3.1 的「成功后说明」。
- `exit_ip` 有值时，在步骤列表下追加一行 `直连出口 <ip>`（mono 12px，可复制）；为 null 时不显示。
- 底部：`关闭`，`btn btn--ghost`。
- 关闭后设置页显示：`上次重置：刚刚 · 8 项全部完成`，`settings-note`。

### 3.4 失败与下一步

| 失败步骤 | 说明 | 下一步 |
|---|---|---|
| `关闭接管` | `接管没有关闭。` | `点「再试一次」；仍失败就重启电脑。` |
| `停止运行时` | `还有运行时没停下来。` | `退出其它 VPN 后点「再试一次」；仍失败就重启电脑。` |
| `撤销系统代理` | `系统代理没有恢复。` | `点「再试一次」；仍失败就重启电脑后再试。` |
| `清理残留进程` | `还有残留进程。` | `退出其它 VPN 或安全软件后点「再试一次」。` |
| `恢复系统路由` | `系统路由还有残留。` | `重启电脑后再试一次；仍然不行，展开「手动清理路由」。` |
| `恢复 DNS` | `DNS 没有恢复。` | `点「再试一次」；仍失败就在系统设置里把 DNS 改回自动。` |
| `删除临时配置` | `临时配置没有删掉。` | `点「再试一次」；这不影响上网。` |
| `复查网络状态` | `复查没有通过。` | `点「再试一次」；仍失败就复制诊断信息发给助手。` |

- 失败行显示 `未完成`；没有执行的步骤也是 `ok=false`，`detail` 写 `没有执行：前面一步失败。`，界面仍显示 `未完成`，不新增第三种状态。
- 底部：`再试一次`（`btn btn--ghost`）+ `关闭`（`btn btn--ghost`）+ `复制诊断信息`（`btn btn--link`）。
- 不展示错误码、堆栈、英文原文；不出现「重装」。
- 关闭后设置页显示：`上次重置：今天 14:32 · {n} 项未完成`，`settings-note`（用 `--warn-text`）。

### 3.5 「手动清理路由」折叠块

只出现在「恢复系统路由」（`clear_routes`）失败行的下方，其它失败不显示。

- `<details class="reset-route-help">`
- `<summary>手动清理路由（高级）</summary>`
- 内容：
  1. `先确认当前默认网关：` + code `route -n get default`
  2. `只删除诊断信息里标出的那一条残留路由：` + code `sudo route -n delete -net <残留网段>`
     - 如果命令提示需要网关，按诊断信息里的网关补在末尾；不要删 `default`。
  3. 复制按钮：`复制命令`，复制 `sudo route -n delete -net <残留网段>`（保留占位符，不预填真实参数）
  4. `不要删除 default，也不要删除你不认识的路由。`
  5. `删除后重新运行「强制重置网络」做复查。`
  6. `Windows 用户不要执行上面的命令；请在系统设置里使用「网络重置」，或重启电脑。`
- 界面不展示完整真实参数；网段/网关由诊断信息给出，用户自己替换占位符。
- 命令块用 `reset-route-help__code`（mono 12px、横向可滚动、复制按钮 32px ghost）。
- 折叠块键盘可达；复制反馈 `已复制` / `复制失败`，2 秒复位。

### 3.6 数据要求

后端 `reset_network` 需要返回逐步结果：

```ts
type ResetStepId =
  | "stop_tun" | "stop_runtime" | "restore_proxy" | "sweep_processes"
  | "clear_routes" | "flush_dns" | "clear_plaintext" | "verify";

interface ResetStep {
  id: ResetStepId;
  ok: boolean;
  detail: string | null;
}

interface ResetNetworkResult {
  ok: boolean;
  verified: boolean;
  exit_ip: string | null;
  steps: ResetStep[];
}
```

- `steps` 必须按 §3.1 的 8 个 id、顺序全量返回；没有执行的步骤也要带 `ok: false` 与 `detail`，不要省略。
- 前端以顶层 `ok` 决定标题，以 `steps[].ok` 决定每行状态；不要自己推导。`verified` 只用于复查相关展示与诊断。
- `ok = false` 时，失败原因在对应步骤的 `detail` 里，不要在界面展示原始错误码。
- 顶层不再有 `detail`；所有失败原因都在对应 `steps[].detail` 里。
- 前端按 `steps` 渲染；如果 `steps` 缺失或不足 8 项，只显示顶层 `ok` 的总结果，**不要补造步骤或画假进度**，并提示复制诊断信息。实际命令应固定返回 8 项。

## 4. 样式与主按钮权重

### 4.1 类名

| 用途 | 类名 |
|---|---|
| 高级页入口按钮 | `btn btn--danger-ghost` |
| 取消 / 关闭 / 再试一次 | `btn btn--ghost` |
| 复制诊断信息 | `btn btn--link` |
| 确认弹层 | `modal-backdrop` + `modal modal--confirm reset-dialog` |
| 三段式 | `reset-confirm`、`reset-confirm__warning`、`reset-confirm__section`、`reset-confirm__label`、`reset-confirm__text` |
| 执行中进度 | `reset-progress` |
| 结果容器 | `reset-result`、`reset-result__title`、`reset-result__sub` |
| 步骤列表 | `reset-steps`、`reset-step`、`reset-step__icon`、`reset-step__body`、`reset-step__label`、`reset-step__detail`、`reset-step__status`、`reset-step__next` |
| 步骤状态修饰 | `is-ok`、`is-failed` |
| 路由折叠 | `reset-route-help`、`reset-route-help__code` |
| 设置页 | `settings-subhead`、`settings-row`、`settings-row__label`、`settings-row__value`、`settings-row__aside`、`settings-note` |

### 4.2 权重

- 重置流程里**没有 `btn--primary`**：入口、最终确认、重试全部是 `danger-ghost` / `ghost` / `link`。
- 主界面仍然只有控制台顶部一个实心主按钮。
- `btn--danger-ghost` 是高级页唯一的红色元素；「恢复直连」仍是灰色 ghost，两者层级清楚。
- 结果弹层也不放实心「完成」；`关闭` 用 ghost。

### 4.3 键盘与焦点

- 弹层用 `useFocusTrap`；初始焦点在「取消」。
- 确认前 Esc / 背景 / 右上角关闭；运行中全部禁用。
- 结果视图可用 Esc 关闭；焦点回到触发按钮（设置行或托盘打开前的焦点）。
- 结果列表用 `role="status"` + `aria-live="polite"` 播报总结，例如 `网络已重置，8 项全部完成`；不要逐行快速播报。
- 路由折叠块用原生 `<details>`/`<summary>`，键盘可展开。

## 5. 托盘入口

- 菜单顺序：`显示 Veyl` / 分隔线 / `强制重置网络…` / 分隔线 / `退出`。
- 点击行为：
  1. 显示主窗口并聚焦。
  2. 打开 `设置 → 高级`，滚动到「诊断」分组里的「强制重置网络」行。
  3. 打开同一个确认弹层。
- 不直接执行；带省略号表示下一步还有确认。
- 运行中再次点击：只聚焦运行中的弹层。
- 能力未就绪：不注册菜单项。
- 不加入应用菜单栏；不设全局快捷键。

## 6. 验收

- [ ] 设置 → 网络：「恢复直连」一键可用，无确认。
- [ ] 设置 → 高级 → 诊断：「强制重置网络」为 `btn--danger-ghost`；能力未就绪时整行不出现。
- [ ] 点击入口：弹层打开，初始焦点「取消」，Esc / 背景 / X 可关。
- [ ] 确认后：关闭入口禁用，显示进度；不能重复执行。
- [ ] 成功：八步结果、图标 + 文字状态、关闭；设置行出现「上次重置」。
- [ ] 失败：失败行 `未完成`、下一步、再试一次、复制诊断信息；没有执行的步骤也显示 `未完成`，说明由 `detail` 给出。
- [ ] 只有「恢复系统路由」失败时才出现「手动清理路由」折叠块；复制的是占位符模板，不是真实参数。
- [ ] 托盘：菜单顺序正确；点击打开 `设置 → 高级 → 诊断` 并滚到该行，再弹确认；无全局快捷键。
- [ ] 主界面眯眼看仍只有一个实心按钮。
- [ ] 界面文案不出现内部术语；代码 id 除外。
