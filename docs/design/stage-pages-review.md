## 0. 前提（2026-11-18 更新）

截图 18 / 20 当时是 `MyServersPage` 在没有选中服务器时渲染的向导：带着「我的服务器」左栏、导航高亮在「我的服务器」、**没有 `返回`**。

据此曾得出「只留 client 舞台一个宿主」的结论，并已落地。**2026-11-18 产品负责人推翻了这个结论**：建机向导要在原地打开——从哪进就在哪，两个宿主都保留；但必须**共用同一个组件与同一份状态**，而且**两边都有 `返回`**。原结论里「不能没有返回」「不能有两套间距」两条批评仍然有效，解法从「砍掉一个」改成「补齐两个、共用一套」，见 §1.1。

## 1. 必须改（P1）

### 1.1 创建流程有两个宿主，共享同一个向导

> 2026-11-18 产品负责人改口，**推翻本节原结论「只留 client 舞台」**。原结论的两条批评（不能没有返回、不能有两套间距）仍然成立，解法从「砍掉一个宿主」改成「两个都保留、共用一套」。

| 项 | 规则 |
|---|---|
| 组件与状态 | 两个宿主渲染**同一个** `MyServerWizard`，共用同一份表单状态（`newNodeOpen` + 已选地区/档位）。**不存在两份草稿** |
| 从「我的服务器」进入（左栏 `＋`、零台空态 `新建节点`） | destination **保持 servers**；左栏服务器列表保留；中间渲染向导；导航高亮在「我的服务器」；`返回` 回服务器列表 |
| 从连接页进入（无节点两选一） | destination 保持 client；无左栏；`返回` 回两选一 |
| 从试用到期屏进入 | 保持连接侧（现状）；`返回` 回到期屏 |
| 创建成功 | **留在进入时的宿主**：从 servers 进入就回服务器列表，并**选中刚建好的那台**（按返回的 `server_id`，不是「列表第一行」——排序会变）；从连接页进入就收敛成节点卡 + `连接`（`ai-first-product.md` §第一次选择自建节点第 5 步） |
| 创建失败 | 留在向导的失败态，不换宿主 |
| `Esc` | 与 `返回` **完全相同** |
| `Esc` 与登录弹窗撞车 | 登录弹窗开着时，`Esc` **只关弹窗**，不关向导——一次按键只解一层。弹窗关掉后焦点回到触发它的控件（`登录并继续`），不是回到输入框 |
| 已有未提交的选择时 `返回` / `Esc` | **直接关闭，不弹确认**——地区与档位重选只有几次点击，一个「确定要放弃吗」比丢失本身更烦；这与「切走即丢弃」是同一条规则。（**PM 2026-11-18 确认：保持这条，不要改回「先确认放弃」**） |
| 向导打开时点导航切到另一侧 | **先关闭向导并丢弃未提交的选择**，再切过去；切回时不恢复半填的表单 |
| 丢弃时还要清掉什么 | 除了地区/档位，**必须清掉「让 AI 帮我选」那条待选结果（`stageSelect`）**——否则切回来会看到上一轮 AI 建议的地区还挂在那里，用户以为它还是有效的 |
| 创建在途时点导航 | **不切**，导航同样禁用（沿用 N5「创建中锁返回」） |
| 向导期间左栏 | **可见但禁用**：行不可选中、不可点，`aria-disabled="true"`、45% 透明；`＋` 也禁用 |
| AI 上下文 | 两个宿主的 `screen` 都是 `new_node`——AI 不需要知道它挂在哪一侧 |

理由：

1. **归属感**：用户从「我的服务器」点新建，意思是「我要在这里多一台」。把他弹到连接页，等于把任务从资产列表里拽走，回来还得再找一遍。
2. **左栏不该消失**：服务器列表是「我有哪些资产」的上下文，建机时它仍然有用——比如看见同地区已经有一台。
3. **两个宿主不等于两套外壳**：共用组件、共用状态、同一条 `返回` 规则，差异只剩「左边有没有列表」。
4. 原结论的批评已被吸收：两个宿主**都有** `返回`；间距与排版来自同一个组件，不会各调一套。

**为什么切走要丢弃而不是保留草稿**：保留就要维护「回到半填的表单」这个状态，而两个宿主的可见性不同（一个有左栏、一个没有），恢复时容易对不上；表单只有三四个选择，重来的成本远低于状态机的成本。

**为什么左栏禁用而不是「点了就离开向导」**：点列表行的意思是「看那台服务器」，而此刻用户正在同一页里做另一件事。让列表看起来能点、点下去却把表单丢掉，是更坏的意外。禁用比「点了就毁」诚实——要离开，先按 `返回`。

> 2026-11-17 产品负责人改口径，本节按新口径重写。

# 补评（2026-11-17）：返回、空态与跨屏问题卡

> 依据截图 23（新建节点）、24（我的服务器 · 未登录）、25（我的服务器 · 已登录零台）。
> 这一轮只补上面没覆盖的三页；§1–§3 的结论仍然有效。

## 5. 「返回」控件

### 5.1 结论

**`← 返回`（14px 箭头 + 13/500 文字），无边框，独立一行放在标题上方 8px，与标题左对齐。**

```
← 返回
新建节点
────────────────
地区 …
```

- 不用「只有箭头」：箭头在表单页容易被读成「折叠/上一页」，加两个字成本很低。
- 不用「带边框的 ghost 按钮」：28 高的描边框和 20px 标题并排，会出现两个同等重量的方块，抢标题。
- 不用纯文字链接：现在的 `返回` 没有箭头、没有下划线，和正文同级，看不出可点——这正是产品负责人说的“看不懂能点”。

### 5.2 规格

| 项 | 值 |
|---|---|
| 位置 | 标题上方，独立一行；距标题 8；左边与内容列（`地区` 标签）对齐 |
| 图标 | 左箭头 14×14，1.4 描边，`currentColor` |
| 文字 | `返回`，13 / 500 |
| 间距 | 图标与文字 4 |
| 颜色 | 常态 `--ink-2`（#5B5850）；hover / focus `--ink` 且文字加下划线 |
| 命中区 | 高 44（`padding: 10px 8px` + `margin: -10px -8px 0`），宽度约 72 |
| 焦点 | `:focus-visible` 1px `--focus` 描边，offset 2 |
| 禁用 | 创建在途时禁用，30% 透明，光标默认 |

**为什么这里可以用 `←`**：`veyl-ui` 禁止的是「左栏 → 右详情」的主从导航用返回箭头；这里是**流程出口**（从建机回到两选一/来源页），不是层级回退，所以箭头是合适的，也不与 destination 的回根规则冲突。

### 5.3 对齐基线

现在「返回」和标题在同一 flex 行（`gap: 12`），标题被推到内容列右边，和下面 `地区` 的左边对不齐。改成两行后，标题回到内容列左边缘，三页（新建、未登录、零台）的标题都在同一条竖线上。

## 6. 未登录与零台：只留中间一套

### 6.1 结论

**左栏只保留标题行（`我的服务器 0 ＋`），不再写任何空态文字；空态与 CTA 全部由中间承担。**

| 页面 | 左栏 | 中间 |
|---|---|---|
| 未登录 | `我的服务器 0 ＋`（无链接、无提示） | `先登录` + 说明 + `登录` |
| 已登录零台 | `我的服务器 0 ＋`（无「还没有服务器」） | `还没有服务器` + 说明 + `新建节点` |

理由：

1. 现在同一屏出现两次「登录」/两次「还没有服务器」，一个是粉色链接、一个是黑按钮，读者要判断“点哪个才对”。一次页面只留一个动作。
2. 左栏的职责是**列表**，没有列表时它的全部信息就是计数 `0`；空态的解释属于主内容区。
3. 中间的按钮是这一屏唯一的主按钮，权重正确；左栏链接是同义竞争。

> 这会改两条已定稿：`account-menu.md` §3.2 的左栏链接、`servers-list-detail.md` §1.3 的左栏 `还没有服务器`。两份文档已同批改成「左栏不写空态」。

## 8. 问题卡跨屏：与发起它的页面绑定

现象：截图 23 在「新建节点」页，右栏还在等一个「报告问题」的追问（带倒计时和选项）。

**规则：**

1. 问题卡记录 `originScreen`（发起它的 `screen`，例如 `client`）。
2. 只在 `originScreen` 上可交互；切换 destination 后**折叠成一行只读提示**：`有一个问题在连接页等你回答`（13 / `--ink-3`），整行可点，点它切回 `client` 并恢复卡片。
3. 倒计时继续走；到期后显示 `这个问题已过期。`，选项禁用，不再恢复。
4. 不在其他页面渲染可点的选项，也不允许在那里提交答案——否则模型收到的 `context.screen` 与问题来源不一致，会把建机页的答案当成连接问题的答案。
5. 不静默丢弃：用户的答案与进度留在会话里，回来还能继续（未过期时）。

这是规则，不是新功能；实现上只需把问题卡与 `screen` 关联，并在离开时折叠。
