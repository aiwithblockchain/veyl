## 0. 结论

**activity bar 三个平级 destination：`客户端` / `节点组` / `我的服务器`。三者各自「左栏列表 + 中间主从详情」，右栏 AI 不变。**

```
客户端        我连哪一个、现在通不通。
节点组        这些节点怎么分组，当前用哪一组。
我的服务器    我有哪些机器，装好没有，花多少钱。
```

一句话关系：

```
我的服务器 ──产出──▶ 节点 ──加入──▶ 节点组 ──设为当前──▶ 配置（客户端）
   资产               端点            集合                用途
```

单向：服务器产出节点、节点进组、组被配置绑定。反向不成立——组不拥有服务器，配置也不回写组。

## 1. 信息架构：三个平行模块

### 1.1 三个模块各管什么

| destination | 用户来这里干什么（一句话） | 左栏 | 中间 | 右栏 |
|---|---|---|---|---|
| `客户端`（默认） | 选一套配置，连上或断开，看这条连接通不通 | 配置列表 | 网络控制台三段骨架 | AI 对话 |
| `节点组` | 把节点组织成组，并决定当前用哪一组 | 组列表：`免费` → `我的组` →（有未分组节点时）`未分组` | 选中组的详情 | AI 对话 |
| `我的服务器` | 买、装、看、退自己的服务器，把它们的节点交给组 | 服务器列表 | 服务器详情 / 新建向导 / 四段进度 | AI 对话 |

三个图标常驻，不隐藏、不置灰；切换 destination 不动连接、不发任何运行时命令。

图标语义（不新造图标集）：

- `客户端`：现有 `IconConsole`（控制台窗口）；
- `节点组`：新增「堆叠三层」图形（组是容器，不是一个机器）；
- `我的服务器`：复用现有 `IconServer`（机架）。

> 旧实现把 `IconServer` 给了组、把服务器放进组的中间区；三个 destination 之后这个分配反了，必须换：**机架图 = 机器**，组不能继续占用它。

### 1.2 关系：单向，不循环

```
我的服务器 ──装机成功──▶ 节点 ──加入（可多组）──▶ 节点组 ──设为当前──▶ 配置 ──连接──▶ 流量
   资产                  端点                     容器                用途

        ◀╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌ 只读：这台产出的节点在哪些组里（不产生写操作）
```

- 服务器**产出**节点；没有服务器也能有节点（免费种子、粘贴、手填）。
- 节点**加入**组；一个节点可以同时属于多个组，成员关系不是所有权，删组不删节点。
- 组被**配置**绑定；组本身不是连接对象，只有配置才连。
- 反向只有一条**只读**关系：服务器详情显示「这台产出的节点在哪些组里」（`remote-groups.md` §7.1 的 `group_ids`），它不产生写操作，也不构成循环。

### 1.3 为什么是三个一级模块

1. **`nav-hierarchy`（MD）**：一级导航（activity bar）与二级导航（列表、设置）必须清楚分开。服务器是**花钱、装机、售后**的并列对象，把它做成组列表底部的一行，等于把一级对象塞进二级位置——层级名字对了，位置说反了。
2. **`persistent-nav`（HIG / MD）**：核心导航在深层页面仍要可达。服务器做成组的中间区子视图时，从客户端到服务器要「切节点组 → 点底部行」两步，且从组详情看不见安装进度；三个 destination 后，任何一屏都只差一次点击。
3. **`avoid-mixed-patterns`（MD）**：同一层级不要混用 tab + 侧栏 + 底部导航。旧方案在一层里同时用了三种形状：activity bar（一级）、左栏（二级）、左栏底部一行打开的「中间区 destination 级视图」——第三种最难解释。三个平行 destination 只保留一种形状：activity bar + 左栏，并在三处完全重复。
4. **`navigation-consistency`（MD）**：导航位置在所有页面一致。三个模块的左栏宽度、标题行位置、`＋` 位置、底部「设置」全部相同，只换列表内容。
5. **`nav-state-active`（HIG / MD）**：当前模块必须高亮。三个图标各自的选中态一致（`--ink` + 左侧 2px `--cobalt`）。
6. **`empty-nav-state`（MD）**：某个导航目标不可用时解释原因，而不是悄悄隐藏。「我的服务器」未登录有自己的说明与登录入口，不必藏在别的模块里。
7. **`adaptive-navigation`（Material Adaptive）**：≥1024 用侧栏；<1024 时三个 destination 都收成 72px 图标 + 抽屉，形态规则完全一致。

### 1.4 为什么不是「一个 destination 里做两个 tab」

诚实地说：**如果三个模块都改成纯 tab、都不带左栏，那确实是单一模式**（`avoid-mixed-patterns` 反而满足）。但那样每个模块的「一列对象 + 一个详情」就得塞进 tab 里，列表只能变成下拉或第二层页面——`nav-hierarchy` 要的「一级 / 二级分开」反而更糟。

两种 tab 写法都不成立：

- **在 `节点组` destination 内部加 `组 / 服务器` 两个 tab**：这正是 `avoid-mixed-patterns` 明令禁止的「同层混用 tab 与侧栏」；而且会让这两个模块看起来比 `客户端` 低一级，与「两个并行模块」的产品判断相反。
- **三个模块做成三个 tab、取消 activity bar**：tab 条要同时承担「切换模块」和「当前模块内的列表标题」，两种语义叠在一行；240–280px 的列表也没有地方放。这不是更合规，只是把导航换了个位置。

所以：**tab 在这里不比 activity bar 合规**，它只是在「一个模块内部」才合规（比如设置页内部的分段控件）。

### 1.5 为什么不是「组列表底部一行 + 中间子视图」（旧方案，已作废）

旧方案把「我的服务器」降为组列表底部一行，点开是中间区子视图。它在**两模块**的前提下是自洽的（少一个图标），但产品 2026-11-14 判定两个模块并行之后，它有三处硬伤：

1. 一级对象占了二级位置（`nav-hierarchy`）；
2. 从客户端到服务器要两步，且中间隔着组（`persistent-nav`）；
3. 同层出现第三种导航形状（`avoid-mixed-patterns`）。

旧方案保留的部分：服务器详情仍然是「列表 → 详情」的主从结构，没有返回按钮，`Esc` 上一级——这些规则原样搬到独立 destination。

### 1.6 每个模块的左栏与中间

| 模块 | 左栏顶部 | 空态（一句话） | 加载态 | 未登录 |
|---|---|---|---|---|
| 客户端 | `Veyl` + `网络控制台`，`配置 ＋` | `还没有配置` + `新建配置` | 三行骨架（`aria-busy`） | 不设门禁：配置与节点都在本机 |
| 节点组 | `节点组 ＋` | `我的组` 段内 `还没有自己的组` + ghost `新建组`；`免费` 段永远在 | 三行骨架 + 中间组详情骨架 | 不设门禁：组与成员关系都在本机（免费组成员来自种子缓存） |
| 我的服务器 | `我的服务器 ＋` | 已登录零台：`还没有自己的服务器` + `新建服务器` + 一句 `买一台装好后，节点会自动加入「我的节点」。` | 三行骨架 + 中间骨架 | `登录后查看你的服务器` + `登录`（与 `my-servers.md` §7.5 同一句） |

**节点组左栏的三段**（顺序固定，`remote-groups.md` §3.4）：

| 段 | 内容 | 何时出现 |
|---|---|---|
| `免费` | `Veyl 免费节点`，只读，不可改名/改成员/删除 | 永远 |
| `我的组` | 自定义组，按创建时间；默认有 `我的节点`（第一个用户节点出现时自动建） | 永远（空时给空态） |
| `未分组` | 不属于任何组的节点；**不是组、不能绑定** | 仅当存在未分组节点 |

`我的服务器` 左栏每行 = 名称 15/500 + 第二行 12 `--ink-3` 的状态（`安装中 62%` / `可用` / `出错` / `销毁中`）；选中态与另外两栏同一套。

### 1.7 跨模块跳转（只保留四条）

每条都写清「带什么上下文、怎么回来」。跨模块跳转**不推栈**：离开的模块保持原来的选中项，回来还在原处。

**① 组详情 → `添加节点` → `从我的服务器添加` → 我的服务器（pick 模式）**

- 带：目标组 id + 组名。
- 形态：切到 `我的服务器` destination；中间区顶部一行上下文 `从「上海 1 号」添加节点` + 文字按钮 `取消`（不是 `←`）。左栏不变，每台可用服务器行尾出现 ghost **`加入「上海 1 号」`**；不可用的行把按钮换成文字原因（`安装中` / `节点没好` / `已在「杭州 2 号」`）。
- 行内动作与行本身是两个兄弟按钮（与配置行「悬停重命名 / 删除」同一结构），不嵌套按钮。
- 回来：加入成功后 toast `已把「东京 1 号」的节点加入「上海 1 号」`，并**自动切回 `节点组` 的该组详情**；`取消` 或 `Esc` 结束 pick 模式，留在 `我的服务器`（不强行跳走）。
- pick 模式是临时的：切到别的 destination 即取消；再回来是普通服务器列表。
- 零台服务器时，pick 模式下点 `新建服务器` 走购买；装好后自动加入目标组并切回组详情（`remote-groups.md` §7.2）。

**② 服务器详情 → `加入节点组`**

- 带：这台服务器产出的节点。
- 弹窗（480）列出全部自定义组，排除它已在的组；`当前节点组` 置顶并预选；末尾 `新建组…`（就地建组后立即加入）。
- 不列 `Veyl 免费节点`：免费组成员是种子，不能加人。
- 回来：留在服务器详情，toast `已加入「X」`；详情里的事实行从 `还没加入组` 变成 `已在「X」组`。

**③ 服务器详情 → `用来建配置`**

- 只在节点**已在至少一个组**时出现（否则主按钮是 `加入节点组`）。节点在多个组时先问「用哪个组」，默认 `当前节点组`（若在其中）。
- 带：选中的组；走既有新建配置流程的第 2 问预填。
- 回来：创建成功后切到 `客户端` 并选中新配置（没有返回按钮，用户在客户端）。

**④ 控制台底部 `组 · Y` → 组详情：可点。**

- 理由：这是日常使用里唯一出现组名的地方，也是「我现在用的哪组、去哪里换」的天然入口。做成不可点，用户只剩「记得去 activity bar 再找一遍」这一条路。
- 形态：`组` 12 / `--ink-3`；组名本身是按钮，常态 `--ink-2`，悬停 / focus 才下划线并转 `--cobalt`；不加箭头、不加图标（箭头会成为第二个导航信号）。可访问名 `打开节点组「Y」`。
- 带：组 id；落到该组详情，不自动激活、不改任何状态。
- 回来：`Esc` 不返回（destination 切换没有栈）；再点 `客户端` 图标回控制台，选中项与连接都不变。

> 2026-11-14 已裁定：**切组只在组详情**，控制台不放组选择器；第 ④ 条的可点文字保留（跳转到组详情，不换组）。`remote-groups.md` §7.3 已同步。

### 1.8 状态与身份：同一屏不出现两份同一事实

**每屏只回答一个问题**：客户端回答「通不通」，节点组回答「用哪组」，我的服务器回答「机器怎么样」。同一件事只有一处能改、只有一处能读完整值。

| 事实 | 唯一住处 | 明确不出现 |
|---|---|---|
| 连接状态、计时器、出口、流量 | 客户端 hero | 节点组、我的服务器 |
| 当前配置名 | 客户端底部节点卡第 1 行 | 另外两个模块 |
| **当前节点组** | **节点组**：组详情徽标 + 组列表行尾 ` · 当前节点组` | 客户端只写组名、不写「当前」徽标；我的服务器不显示 |
| 当前节点 | 客户端底部节点卡 | 节点组不标「正在用哪个节点」 |
| 组内成员（完整列表） | 节点组 · 组详情 | 我的服务器不列成员 |
| 服务器清单、安装进度、费用 | 我的服务器 | 节点组只显示组内节点，不显示机器 |
| 节点在哪些组（关系） | 以节点组为准（完整列表） | 我的服务器只给**一句结论** `已在「X」组`，不做列表复制——它是 `加入节点组` / `用来建配置` 两个动作的前提，必须在这一端说清 |
| 账号 / 登录状态 | 我的服务器（+ 设置） | 另两个模块不出现 |

- **activity bar 不加角标**：安装进度只在 `我的服务器` 里看。`tab-badge` 允许「未读 / 待处理」角标，但安装是持续状态、不是待处理事件；放角标等于把进度搬到活动栏，与「只在我的服务器」冲突。安装完成用一次 toast 通知（哪个模块都收得到），不在活动栏留痕。

### 1.9 导航栈规则

| 规则 | 内容 |
|---|---|
| 回根 | 再点一次已激活的 destination 图标 → 该模块根（客户端 = 控制台，节点组 = 组列表，我的服务器 = 服务器列表）。这是用户主动重置，不算 `back-stack-integrity` 说的「静默重置」 |
| `Esc` | 按层关：弹窗 / 选择器 → pick 模式 → 详情 → 列表；根上不做任何事 |
| 不用 `←` | 三个模块、所有子层都没有返回按钮 |
| 切 destination | 不动连接、不发运行时命令、不清空右栏；离开的模块保留选中项与滚动位置（`state-preservation`） |
| 持久化 | 只记「上次在哪个 destination」（`veyl.ui.destination`）；不恢复详情层、不恢复 pick 模式 |
| 窄屏 | <1024 三个 destination 都是 72px 图标 + 抽屉，抽屉里放同一条列表 |

### 1.10 首启（没有任何服务器时）

用户从 `Veyl 免费节点` 开始，不需要先买机器。

| 模块 | 首次进入 |
|---|---|
| 客户端 | 零配置引导（`veyl-ui` §4.2）：标题 + 三步说明 + `让助手帮我配` / `我自己配置` |
| 节点组 | 默认选中 `Veyl 免费节点`；`我的组` 段写 `还没有自己的组` + ghost `新建组` |
| 我的服务器 | 未登录：`登录后查看你的服务器` + `登录`；已登录零台：`还没有自己的服务器` + `新建服务器` + `买一台装好后，节点会自动加入「我的节点」。` |

## 3. 与客户端控制台的关系

### 3.1 激活发生在哪里

**只在组详情页**，主按钮 `设为当前节点组`。控制台、节点面板都不提供切组入口——否则同一个动作有两个按钮（`veyl-ui` §2.1 的口径：一屏一个主按钮，同一动作一个入口）。

**跨页副作用的处理**：组详情改的是**当前 active 配置**的组绑定，而用户在组页面看不到「当前 active 是哪套配置」；只给主按钮会让人以为在改组本身。因此详情底部在按钮上方固定一行上下文：

```
将用于「上海 1 号」                        ← 12 / --ink-3，主按钮上方 8
[ 测试全部 ]              [ 设为当前节点组 ]
```

- 这一行写当前 active 配置名，不新增控件、不占主按钮位。
- **没有 active 配置时：不显示 `设为当前节点组`**，同一位置写 `先创建一套配置`，附一个去 `客户端` 的文字链接。组本身不能被激活，没有配置就没有作用对象。
- **`config_launching` 期间**：主按钮禁用，下方一句 `正在连接，等这次连完再改。`
- **控制台不提供换组**（§3.2）：切组只有组详情这一个入口，避免同一个动作有两个按钮。

激活后的语义（界面承诺，契约由架构师定）：**当前配置的组变成这个组；组内第一个节点成为当前节点；正在跑的连接不受影响，下次连接生效（见 §3.3）。**

### 3.2 控制台怎么显示「当前组 · 当前节点」

**底部节点卡**（事实的唯一住处）：

```
配置 · 上海 1 号                     ← 第 1 行（今天已有）
组 · 我的节点                        ← 第 2 行，12 / --ink-3；组名可点（§1.7 第 ④ 条）
上海 01 · 1.2.3.4:8388 · SS           ← 第 3 行（今天已有）
[ 切换节点 ▾ ]        [ 测试连通 ]
```

- 第 2 行是**可点的弱化文字**（12 / `--ink-3`）：点击跳到该组详情（`节点组` destination），**不换组、不弹菜单**。
- 第 2 行没有组选择器、没有 `▾`；**切组不在控制台做**，唯一入口是组详情的主按钮（§3.1）。
- 没有 active 配置时，第 2 行不显示。
- 节点面板（`选择节点`）标题下加一行 `我的节点 · 3 个节点`，列表只显示本组节点；**不加组选择器**。
- hero 不加组：hero 第二行已经是流量范围，再塞组名就变成第二张身份卡。已连接但当前配置换过组时，hero 也不提示「正在用旧组」——连接归属已经由「当前连接：配置名」说明，组这一层不再重复。

### 3.3 切换组的三种情形与提示

**已连接时只登记，不重连**——与 `config-switch.md` §1 的规则一致：切换是导航/登记，断开只发生在用户点连接时。

| 情形 | 交互 | 文案 |
|---|---|---|
| 未连接 | 点主按钮直接生效 | toast `已设为当前节点组。` |
| 已连接 | 点主按钮**只登记**，不断开、不重连、不弹确认；主按钮文案不变（不承诺重连） | toast `已切到「Veyl 免费节点」，当前仍连着「上海 1 号」，下次连接生效。` |
| 正在连接 / 正在断开 | 主按钮禁用，下方一行说明 | `正在连接，等这次连完再改。` |

- 主按钮恒为 `设为当前节点组`，不出现 `切换并重连` 这类带后果的名字（`veyl-ui` §2.1：主按钮只写动作）。
- **不写「重新连接」**：切组不触发连接动作；用户下次点「连接 VPN」时才按新组连接。
- 禁用「正在连接 / 正在断开」的理由与配置切换不同：配置切换只挪 active 指针，而激活组会**改写正在使用的那套配置的节点集合**，在启动/停止途中改写会让「正在连的是哪一组」无法解释；等这次转移结束再改，只需一次点击。
- 不做行内确认条：只登记不改连接，没有代价要确认。

### 4.2 错误三段式

**添加节点失败**（统一一条，不按 reason 分叉；细分进日志）：

> `没能添加这个节点。`
> `地址或端口可能填错了，也可能节点已经失效。`
> `检查后重试；也可以从「我的服务器」添加一个。`

**激活失败**（只写库，不涉及连接）：

> `没能把这个组设为当前节点组。`
> `这套配置可能刚被别的窗口改过。`
> `重新点一次；还是不行，切回控制台再回来。`

- 已连接时激活失败**不影响正在跑的连接**：不要写「连接已断开」或引导用户断开。

### 4.3 用词

- 界面只用 `节点组` / `组` / `节点` / `我的服务器`；**不出现** `远端`、`proxy`、`TUN`、`分流`、`规则集`。
- 免费组就叫 `Veyl 免费节点`（沿用 `veyl-ui` §6 的固定用词），不另造 `Veyl 提供的组`。它是**组**，但名字里不带「组」字；段标题 `免费` 与 `我的组` 对照，已经说明了这一层的分类。
- 默认自定义组叫 `我的节点`（`remote-groups.md` §3.2），与 `我的组`（段名）、`我的服务器`（模块名）三个词各指一件事，不互相替代。
- 按钮与结果同词：`设为当前节点组` → `已设为当前节点组`；`加入节点组` → `已加入「X」`；`切` 只出现在 toast 的「已切到…」，不承诺重连。
- 不用「请」，不用感叹号。

## 6. 已定

1. **信息架构**：三个平级 destination —— `客户端` / `节点组` / `我的服务器`；各自左栏 + 中间主从详情（依据 `remote-groups.md` §7.1 与产品 2026-11-14 拍板）。旧的「组列表底部一行 + 中间子视图」作废（§1.5）。
2. **三模块的唯一关系**：服务器产出节点 → 节点进组 → 组被配置绑定，单向；服务器详情只有一条只读的「在哪些组里」（§1.2）。
3. **切组入口**：只在组详情，主按钮 `设为当前节点组`，按钮上方固定上下文行 `将用于「X」`；控制台只读显示 `组 · Y`，组名可点跳到组详情（§1.7 第 ④ 条、§3.1）。
4. **免费组粒度**：一个 `Veyl 免费节点`，组内按地区排列；将来要拆多个免费组时按段扩展，不改结构。
5. **激活语义**：替换当前配置的组绑定；**只登记、不重连**，下次连接生效（§3.3）。覆盖用户在配置里手加的节点是接受的代价——激活组就是换节点集合。
6. **免费组出口**：提供 ghost `复制为我的组`，复制成可编辑的自建组。
7. **跨模块跳转**：只保留 §1.7 的四条，其余一律通过 activity bar。

- **`ui-ux-pro-max` · `references/quick-reference.md` §9 Navigation Patterns**（逐条原文）：
  - `nav-hierarchy`：Primary nav (tabs/bottom bar) vs secondary nav (drawer/settings) must be clearly separated (MD)；
  - `avoid-mixed-patterns`：Don't mix Tab + Sidebar + Bottom Nav at the same hierarchy level；
  - `persistent-nav`：Core navigation must remain reachable from deep pages; don't hide it entirely in sub-flows (HIG, MD)；
  - `navigation-consistency`：Navigation placement must stay the same across all pages; don't change by page type；
  - `nav-state-active`：Current location must be visually highlighted (color, weight, indicator) in navigation (HIG, MD)；
  - `empty-nav-state`：When a nav destination is unavailable, explain why instead of silently hiding it (MD)；
  - `adaptive-navigation`：Large screens (≥1024px) prefer sidebar; small screens use bottom/top nav (Material Adaptive)；
  - `state-preservation`：Navigating back must restore previous scroll position, filter state, and input (HIG, MD)；
  - `back-stack-integrity`：Never silently reset the navigation stack or unexpectedly jump to home (HIG, MD)；
  - `tab-badge`：Use badges on nav items sparingly to indicate unread/pending; clear after user visits (HIG, MD)；
  - `nav-label-icon`：Navigation items must have both icon and text label; icon-only nav harms discoverability (MD) —— **本方案未满足，如实记录**：56px 活动栏是图标态，靠 `title` / `aria-label` 与左栏标题补足；<1024 的抽屉入口同样只有图标。若将来允许加宽活动栏，应补文字标签。
  - `Breadcrumbs`（Low）：3 层以上才需要路径导航 → 支撑「不做组/节点两级树」。
