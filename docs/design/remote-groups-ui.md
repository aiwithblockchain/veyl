# 节点组：界面设计

> 日期：2026-11-13（2026-11-14 定稿）
> 状态：**已定稿**。信息架构采用方案 A（组升格一级），其余按交叉审计后的结论；可直接进入实现。不 commit。
> 依据：用户 2026-11-13 原话（组管理在前、单节点在后；节点加进组；组激活后作为远端节点）、`veyl-ui` SKILL、`docs/design/my-servers.md` §7.1、`docs/design/simplified-config-create.md`。
> 契约与数据模型由架构师在 `docs/design/remote-groups.md` 定义；本文只定界面。
> 背景变化：SSH 从界面撤掉（用户不登录服务器，凭据由我们代管），服务器详情页随之变薄。

---

## 0. 结论

**activity bar 第二项改为 `节点组`（不新增第三个 destination）。左栏是组列表：`免费` 段 + `我的组` 段；中间是选中组的详情（组内节点 + 添加节点 + 设为当前节点组）。「我的服务器」从 destination 降为「添加节点」里的一个来源，并在组列表底部保留一行安装入口。**

一句话关系：

```
组（容器） ── 含 ──▶ 节点（连接端点） ── 激活后成为 ──▶ 当前配置的远端节点
```

## 1. 信息架构

### 1.1 为什么组要当一级对象

用户的原话就是对象次序：**「节点组的管理，然后才是单个节点的管理」**。界面跟着这个次序走，而不是把节点当主列表、把组当筛选条件。

- 组是**用户唯一要「激活」的对象**；节点只在组里被挑选。
- 组有两种归属：`Veyl 免费节点`（只读）与`我的组`（可编辑）。这个二分本身就是列表的分段依据，不需要再发明标签或颜色。
- 节点来源（免费池 / 我的服务器 / 粘贴订阅 / 手填）是**往组里加节点的方式**，不是一级导航。

### 1.2 已定：并入「服务器」destination，并把它改名为「节点组」

| 项 | 今天 | 改后 |
|---|---|---|
| activity bar | 客户端 / 服务器 | **客户端 / 节点组**（仍两个图标） |
| 左栏 | 服务器列表 | 组列表：`免费`段 + `我的组`段 |
| 中间 | 选中那台的详情 | 选中组的详情：组内节点、添加节点、设为当前节点组 |
| 我的服务器 | 一个 destination | 「添加节点」里的一个来源（二级）+ 组列表底部常驻入口；保留购买/装机/状态/删除 |

理由：

1. **同一块导航位置装同一种形状**：组列表就是主从布局的左栏，组详情就是中间，与 `my-servers` §7.1 已定的服务器 destination 完全同构，不需要新页面模型。
2. **activity bar 保持两个 destination**。`veyl-ui` §1.3 当前定的是两个；第三个图标会逼用户区分「组」和「服务器」两个都装着节点的容器，而两者的差别只在「买没买机器」，对一级用户不可解释。
3. **服务器页因 SSH 撤掉而变薄**：只剩名称、地区、状态、节点是否就绪、费用、销毁。把这么轻的东西占一个常驻一级入口，不如把它放在「加节点」会经过的路径上。
4. **付费流程没有丢**：买机器 → 装好 → 节点进组 → 组被激活，是一条完整路径；组列表底部固定一行 `我的服务器` 作为常驻入口（§1.5），不必先建组也能看到安装进度。

### 1.3 为什么不是「服务器页内做组 / 节点两级」

- 左栏 280px 里再放一棵可展开的树，等于在同一个导航里放两种选中模型（选组 / 选节点），而中间详情又需要「当前看的是哪个组」。选中态会开始打架（哪一层的行拿卡底和钴蓝竖条？）。
- 组内节点本来就要在中间给出行、测速、删除，左栏再复制一份列表，是同一个事实两个住处。
- 层级越浅越好：`ui-ux-pro-max` · Breadcrumbs 明确「3 层以上才上路径导航」；两级树把实际深度推到 3 层。

### 1.4 已评估、不采用的方案

**方案 B：保留「服务器」destination 不动，组放在设置页管理，控制台加一个组选择器。**

- **当时的优点**：不动 activity bar、不动服务器页，组的实现可以贴着已有控制台/设置落地；改动面最小。
- **不采用的原因**：组的「管理」与「使用」分处两地——设置页里建组、加节点，控制台里选组；要管一个组就得先离开主界面。设置页在 `veyl-ui` 里是配置类屏幕，把日常操作放进去，等于把组排到服务器之下，和用户「组在前」的表述相反。产品 2026-11-14 拍板采用方案 A。

**方案 C：第三个 destination（客户端 / 节点组 / 我的服务器）。**

- **当时的优点**：购买流程永远是一级入口，不埋在组里；服务器这个「资产」有独立位置。
- **不采用的原因**：activity bar 从 2 个变 3 个；左栏出现两套「装着远端节点的列表」，首次用户要在两个图标之间试；两个页面都要各自处理空态、加载、账号门禁。用户要看安装进度，用组列表底部那一行解决（§1.5），不需要再开一个 destination。

### 1.5 「我的服务器」在界面里的位置

**两个入口，同一个中间区子视图：**

| 入口 | 目标组 | 进入后 |
|---|---|---|
| 组详情 → `添加节点` → `从我的服务器添加` | 已知（当前组） | 装好或选中后，节点进这个组并回到组详情 |
| **组列表底部固定一行** `我的服务器` | 无 | 与今天的服务器页行为一致；`用来建配置` 走新建配置流程 |

- 底部固定行不随组列表滚动，位置在组列表与「设置」之间：
  - 有机器在安装：`我的服务器 · 安装中 1 台`（`安装中 N 台` 用 mono 数字）；
  - 没有安装中的：`我的服务器`。
  - 例：`我的服务器 · 安装中 1 台` / `我的服务器 · 安装中 3 台`。
  - 12 / `--ink-3` 的计数追加在 13 / `--ink-2` 的名称后，同一行，不换行；行高 32，与「设置」同为左栏底部动作。
- 点进去是**中间区的子视图**，不是 destination：activity bar 仍高亮 `节点组`，左栏仍是组列表。
  - 子视图结构：标题行 `我的服务器` + 服务器行列表。点一行**就地展开**详情（一次只展开一台，默认展开正在安装的那台），不推第二层页面。
  - **没有 `←` 返回按钮**；`Esc` 退出子视图，回到进入前的组详情（从底部行进则回到当前选中的组）。
  - 子视图内再点 activity bar 的 `节点组` 也回根（与根页规则一致）。
- SSH 撤掉后的详情按 `my-servers.md` §17.3 只剩：名称、地区、状态（`安装中` / `可用` / `出错` / `销毁中`）、节点是否就绪（`已就绪` / `未就绪`）、费用（只读），操作只有 `用来建配置` / `销毁` / `重新建一台`。**不显示 IP、端口、协议、加密方式、用户名、创建时间**，也没有 SSH 折叠行。
- 买完装好后，若入口带着目标组，节点自动进入那个组并回到组详情；从底部行进入的，按 `my-servers.md` 既有行为回新建配置流程。
- **服务器销毁后**：仍停留在详情页时显示 `这台服务器已销毁`；列表按 `my-servers.md` §7.4 不再保留这台机器。它产出的节点**留在组里**并标 `这台服务器已销毁`，见 §2.3。

```
┌ 中间区：子视图 ────────────────────────────────────────┐
│ 我的服务器                                             │
│ ┌───────────────────────────────────────────────────┐ │
│ │ 上海 1 号              安装中 62%          [展开] │ │
│ ├───────────────────────────────────────────────────┤ │
│ │ 东京 1 号              ● 可用                      │ │
│ │   地区 东京 · 节点 已就绪 · 费用 $5/月             │ │
│ │   [ 用来建配置 ]                        [ 销毁 ]   │ │
│ └───────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────┘
```

### 1.6 形态与宽度

| 形态 | 宽度 | 行为 |
|---|---|---|
| 宽屏 ≥1200 | 左栏 280，中间弹性，右栏 420 | 组列表 + 组详情 |
| 1200–1023 | 左栏 260/240 | 同上 |
| <1024 | 左栏 72 + 抽屉 | 抽屉里放同一条组列表，底部行放在抽屉底部；72px 栏本身不加，避免挤成两行 |
| 抽屉入口 | 72 | 组图标 + 组数量，不显示组名；有安装中时不加角标——72px 没有位置，进度在抽屉与中间子视图里看 |

右栏 AI 对话在三种形态下都不变，也不随组切换清空。

│  ┌──────────────────────────────────────────────┐  │

- 三个来源卡：`1px --hair-strong` 描边、`--r-sm`、16 内边距、标题 15/500、解释 13 `--ink-2`；间距 8。

- `Esc` 关闭；关闭不保存任何输入。

### 2.3 C：组内节点状态

**空组（自建组）**

```
这个组还没有节点
添加一个节点后，就能把它设为当前节点组。
[ 添加节点 ]      ← 唯一主按钮，居中偏左
```

**只有一个节点**：列表下方一行 12 / `--ink-3`：`组里只有一个节点，连不上时没有别的可换。` 只在恰好 1 个节点时出现，不重复在别处。

**节点不可用**：行内状态文字 `这次测不通`（`--warn-text`），状态点 `--amber`；行仍可点开。点开后行内展开三段式：

> `这个节点连不上。`
> `可能节点已经下线，或本地网络挡住了连接。`
> `先点「测试连通」；还是不行，换一个节点。`

**整组都不通**：详情顶部一条行内提示（不用 toast）：
`这个组的节点都连不上。换一组，或到组里重新测试。`
后接 ghost `测试全部`。

**服务器已销毁的节点**（节点来自「我的服务器」，那台机器被销毁）：

- 行内状态文字 `这台服务器已销毁`（`--ink-3`），状态点灰色空心；名称与地址照常显示，不置灰整行。
- **节点保留在组里，不自动移除**（`my-servers.md` §7.6.4：不静默删节点）。它不能被设为当前节点；被选中时行内一句 `这个节点已经不能用了。`
- 行尾出现 ghost `移除`（危险动作给二次确认？——**不给**：它已不可用，删除没有损失；按钮用 `.btn--danger-ghost`，无需确认）。
- **与 `重新建一台` 的关系**：组内**不提供**重建入口。重建/重买只发生在「我的服务器」子视图（`gone` 那台给 `重新购买`；已销毁的机器按 `my-servers.md` §7.4 不在列表里，走「添加节点 → 从我的服务器添加」重新买）。
- 重建或重买成功后产生的是**新节点**，会自动进入同一个组；旧的 `这台服务器已销毁` 行继续保留，直到用户点 `移除`。两行并存是刻意的：用户能看出「这个位置的原机器没了，新机器已经顶上」，而不是被悄悄替换。

**加载中**：三行骨架，与节点行等高（64），`aria-busy`。

## 3. 与客户端控制台的关系

### 3.1 激活发生在哪里

**只在组详情页**，主按钮 `设为当前节点组`。控制台、节点面板都不提供切组入口——否则同一个动作有两个按钮（`veyl-ui` §2.1 的口径：一屏一个主按钮，同一动作一个入口）。

**跨页副作用的处理**：组详情改的是**当前 active 配置**的节点来源，而用户在组页面看不到「当前 active 是哪套配置」；只给主按钮会让人以为在改组本身。因此详情底部在按钮上方固定一行上下文：

```
将用于「上海 1 号」                        ← 12 / --ink-3，主按钮上方 8
[ 测试全部 ]              [ 设为当前节点组 ]
```

- 这一行写当前 active 配置名，不新增控件、不占主按钮位；没有 active 配置时写 `还没有配置`，主按钮禁用。
- 控制台选择器方案已评估并否决（§1.4 方案 B）：组的管理与使用拆两处，代价更大。

激活后的语义（界面承诺，契约由架构师定）：**当前配置的节点来源变成这个组；组内第一个节点成为当前节点；正在跑的连接不受影响，下次连接生效（见 §3.3）。**

### 3.2 控制台怎么显示「当前组 · 当前节点」

**底部节点卡**（事实的唯一住处）：

```
配置 · 上海 1 号                     ← 第 1 行（今天已有）
组 · 我的组                          ← 第 2 行（新增，12 / --ink-3）
上海 01 · 1.2.3.4:8388 · SS           ← 第 3 行（今天已有）
[ 切换节点 ▾ ]        [ 测试连通 ]
```

- 第 2 行只是文字，不可点；**切组不在控制台做**。
- 节点面板（`选择节点`）标题下加一行 `我的组 · 3 个节点`，列表只显示本组节点；**不加组选择器**。
- hero 不加组：hero 第二行已经是流量范围，再塞组名就变成第二张身份卡。已连接但当前配置换过组时，hero 也不提示「正在用旧组」——连接归属已经由「当前连接：配置名」说明，组这一层不再重复。

### 3.3 切换组的三种情形与提示

**已连接时只登记，不重连**——与 `config-switch.md` §1 的规则一致：切换是导航/登记，断开只发生在用户点连接时。

| 情形 | 交互 | 文案 |
|---|---|---|
| 未连接 | 点主按钮直接生效 | toast `已设为当前节点组。` |
| 已连接 | 点主按钮**只登记**，不断开、不重连、不弹确认；主按钮文案不变（不承诺重连） | toast `已切到「Veyl 免费节点」，当前仍连着「上海 1 号」，下次连接生效。` |
| 正在连接 / 正在断开 | 主按钮禁用，下方一行说明 | `正在连接，等这次连完再改。` |

- 主按钮恒为 `设为当前节点组`，不出现 `切换并重连` 这类带后果的名字（`veyl-ui` §2.1：主按钮只写动作）。
- **不写「重新连接」**：切组不触发连接动作；用户下次点「连接 VPN」时才按新组连接。
- 禁用「正在连接 / 正在断开」的理由与配置切换不同：配置切换只挪 active 指针，而激活组会**改写正在使用的那套配置的节点集合**，在启动/停止途中改写会让「正在连的是哪一组」无法解释；等这次转移结束再改，只需一次点击。
- 不做行内确认条：只登记不改连接，没有代价要确认。

## 4. 状态与文案

### 4.1 全量

| 场景 | 位置 | 文案 |
|---|---|---|

| 账号未登录 | 列表段内 | `登录后查看你的服务器`（与 `my-servers.md` §7.5 同一句） |

### 4.2 错误三段式

**添加节点失败**（统一一条，不按 reason 分叉；细分进日志）：

> `没能添加这个节点。`
> `地址或端口可能填错了，也可能节点已经失效。`
> `检查后重试；也可以从「我的服务器」添加一个。`

**激活失败**（只写库，不涉及连接）：

> `没能把这个组设为当前节点组。`
> `这套配置可能刚被别的窗口改过。`
> `重新点一次；还是不行，切回控制台再回来。`

- 已连接时激活失败**不影响正在跑的连接**：不要写「连接已断开」或引导用户断开。

### 4.3 用词

- 界面只用 `节点组` / `组` / `节点` / `我的服务器`；**不出现** `远端`、`proxy`、`TUN`、`分流`、`规则集`。
- 免费组就叫 `Veyl 免费节点`（沿用 `veyl-ui` §6 的固定用词），不另造 `Veyl 提供的组`。它是**组**，但名字里不带「组」字；段标题 `免费` 与「我的组」对照，已经说明了这一层的分类。
- 与既有「Veyl 免费节点」（免费节点池）的关系：是同一个东西在不同层的名字——池是来源，组是它在界面里的容器。文档与界面都不再使用第三个说法。
- 按钮与结果同词：`设为当前节点组` → `已设为当前节点组`；`切` 只出现在 toast 的「已切到…」，不承诺重连。
- 不用「请」，不用感叹号。

1. **信息架构**：方案 A —— activity bar 第二项 `节点组`，左栏 `免费` + `我的组`，中间组详情；「我的服务器」降为「添加节点」来源，并在组列表底部常驻一行。方案 B / C 已评估不采用（§1.4）。

4. **激活语义**：替换当前配置的节点来源；**只登记、不重连**，下次连接生效（§3.3）。覆盖用户在配置里手加的节点是接受的代价——激活组就是换节点集合。
5. **免费组出口**：提供 ghost `复制为我的组`，复制成可编辑的自建组。
