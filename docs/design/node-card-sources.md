# 节点卡：试用节点与自建节点同池

> 日期：2026-11-17
> 状态：设计定稿，待实现。只出文档，不改代码。
> 依据：`veyl-ui` §2.2（一个事实一个住处）/ §3.1（状态色只做点、文字、描边）、`ui-ux-pro-max` §9 `nav-hierarchy` / `progressive-disclosure` / `avoid-mixed-patterns`、`ai-first-product.md` §全局配置与节点池、`acceptance-ui-refactor.md` T5。
> 本轮锁定：两类节点**同池同卡**，凭来源区分；到期只删试用节点，自建顺序不动；到期正连试用则硬断开，未连接则选中回落到剩余第一个；自建不受到期影响，加自建也不提前结束试用。
> 取代：`node-list-visual.md` §0.6「不做分组」——那是 2026-11-06 的底部上拉面板，节点数按 100 量级假设；现在的卡片是 400 宽、2–5 行的内联列表，假设不同。

## 0. 结论

1. **分组，不逐行贴标签。** 两类都存在时，卡片里出现两个分组小标题：`你的服务器`、`免费节点`；单一来源时**不显示任何分组标题**，与今天的卡片完全一致（`progressive-disclosure`）。
2. **自建在前，试用在后。** 会消失的东西放底部，删除时列表长度变化最小。
3. **卡片标题从配置名改成固定的 `节点`，`aria-label` 同改。** 现在标题是 `config.name`，而试用配置名就叫「免费节点」——一旦混入自建节点，标题就成了假话；只改可见文字，读屏仍会念错的。
4. **组标题右侧只给免费组写到期**：`7 天后到期`（拿不到剩余天数时写 `试用中`；已过到期时刻、节点还没被清理时写 `已到期`，见 §2.1）；不写组内计数，总数仍只在副行。
5. 卡片自身**不滚动**，所以分组标题**不做粘性**；节点多时整页滚动，与现状一致。

## 1. 头部

```
┌ 节点 ──────────────────────────────┐
│ 3 个节点                           │
├────────────────────────────────────┤
```

| 元素 | 现状 | 改为 |
|---|---|---|
| 标题 | `config.name`（试用配置叫「免费节点」） | 固定 **`节点`**；**section 的 `aria-label` 一起改**（现在是 `config?.name ?? "节点"`，`ConnectionStage.tsx:403`） |
| 副行 | `2 个节点 · 7 天试用`（只要有一个 seed 节点就写死） | `N 个节点`；**全部是试用**时保留 `· 7 天试用`；混合时只写 `N 个节点` |
| 测速入口 | 副行右端 `测速` | 不变 |

**为什么标题要改**：单配置模型下这个名字已经没有第二个住处，但它会在混合时骗人。用户在「免费节点」的标题下看到自己花钱建的服务器，会以为买错了。固定的 `节点` 是唯一不会过时的说法，也正好是现在 `config?.name ?? "节点"` 的兜底值。

**可见文字和无障碍名字必须一起改。** 卡片是 `<section class="stage-card" aria-label={config?.name ?? "节点"}>`（`ConnectionStage.tsx:403`）。只改 `<h2>` 的文字、不改 `aria-label`，读屏用户听到的仍然是「免费节点」——同一个问题在看不见的地方原样保留。两处都固定成 `节点`。

**为什么混合时不写「2 个免费」**：副行的职责是「几个」，来源由分组回答。同一件事在两处说，一旦分组顺序或计数口径变化就会对不上。

## 2. 分组

两类**同时存在**时：

```
│ 你的服务器                         │   12 / 500 / --ink-3
│ 东京 1 号                    38ms │
│ 新加坡 01                   121ms │
│ 免费节点              7 天后到期   │
│ 洛杉矶 02 [最快]              46ms │
│ 法兰克福 01                  238ms │
```

| 项 | 值 |
|---|---|
| 组标题 | 高 24、`padding: 0 16`、12 / 500 / `--ink-3`；上间距 4 |
| 免费组右侧 | 11 / `--ink-3`：`N 天后到期`（拿不到剩余时间时写 `试用中`）。**取整口径与 `servers-trial-hint.md` §3.2 完全一致**：按剩余时长**向下取整**（剩 6 天 9 小时 → `6 天后到期`），不足 24 小时写 `不到 1 天后到期`；**已过到期时刻、但节点还没被清理时写 `已到期`**（§2.1）。两处的数字必须相同 |
| 组标题与行 | 不额外加分隔线；行本身已有 `border-top: 1px var(--hair)` |
| 组内顺序 | **保持原有相对顺序**，不按延迟重排 |
| 无障碍 | 每组一个 `role="group"` + `aria-label`（`你的服务器` / `免费节点`），组内的行保持 `role="option"`。`listbox` 允许 `group` 作为子节点，读屏会在念到该组时先报组名 |

**为什么分组而不是逐行标签**：

1. 现在一行里已经有三个标签位（`最快`、`已销毁`、延迟），再塞一个来源词就成了四个，每一行都在吵。
2. 分组回答的是**整组人的共同命运**——「这一组 7 天后会消失」——逐行标签只能一个行地说一次，说不了这件事。
3. `avoid-mixed-patterns`：两类节点用同一种表达（分组标题），不要一行一个样式、一行一个颜色。

**为什么不逐行标来源**：逐行标签在「只有两类、且同类连续」时是纯粹的重复；而分组标题只在必要的时候出现一次。

### 2.1 `已到期`：只在混池时可见

到期文字一共三种，第三种是「已经过去」的状态：

| 状态 | 文字 | 出现条件 |
|---|---|---|
| 计时中 | `6 天后到期` / `不到 1 天后到期` | 免费组存在、到期时刻在未来 |
| 计时中（拿不到剩余时间） | `试用中` | 有免费节点，但 `expires_at` 还没写（首次连接之前） |
| **已过期、尚未清理** | **`已到期`** | `expires_at <= now`，而清理事务还没跑（时间窗见 §5.0）。**两处同时出现**：免费组标题右侧，以及**每个过期行的行内徽标** |

- **只出现在免费组标题右侧与过期行内**，也就是**只有两类节点同池时才可见**：组标题本身只在混池时渲染（§3），纯试用用户永远看不到这三个字——他要么看到整组消失，要么直接进到期屏。
- **组标题说整组，行内说这一行。** 两处不是重复：组标题承担「这一组马上要没了」；行内徽标承担「**这一行点不动了**」——行是禁用控件，禁用态必须在原地解释原因，不能让用户跑去组标题里找解释。
- **不加感叹号、不用红色**：组标题仍是弱化事实（11 / `--ink-3`），行内徽标沿用 `已销毁` 的那一颗（`.stage-node__badge`，10.5px，灰底 `--bg-hover`）。`veyl-ui` §3.1 要求状态色只用于点、文字、描边，这里连描边都不需要——用红色会让用户以为节点坏了，而不是「到期了」。
- **不用 `试用已到期`**：组名就在左边（`免费节点`），右边再补一次「试用」是同一个词说两遍。
- **与 `servers-trial-hint.md` 的「到期即隐藏」不冲突**：那条说的是「我的服务器」空态里那行提示，它读的是**试用状态本身**——到期之后没有「还剩几个免费节点」可说。这里读的是**池里还存在的行**，行还在就必须给个说法。

## 5. 到期

### 5.0 时间窗：到期那一刻节点不会立刻消失

到期是**一个时刻**，清理是**之后才发生的动作**。到点后 `trial_status` 立刻变成 `expired`，但节点还在库里，直到下一次清理真正跑完。

**三个触发点**：

| 触发 | 位置 |
|---|---|
| 启动 | 同步跑一次清理事务，保证界面首次读 `trial_status` 时节点已经移除（`src-tauri/src/lib.rs:286`） |
| 每 5 分钟 | 后台定时（`src-tauri/src/lib.rs:299-307`） |
| 连接成功后 | `note_trial_connection` 尾部（`src-tauri/src/tools/services.rs:6816-6822`） |

所以窗口最长约 5 分钟（App 一直开着、也没人点连接时）。这段时间里：

- **过期行留在列表里，但被禁用**：复用 `已销毁` 的禁用态（`opacity: .75`、`cursor: default`、名称 `--ink-3`），行内名称后加 `已到期` 徽标；点它不切换、不连接；
- **免费组标题右侧也写 `已到期`**（§2.1）——组标题说整组，行内说这一行；
- 副行 `N 个节点` 照旧把它们算进去（它们确实还在池里，只是不可用）。

**为什么不让界面先隐藏这些行**：界面自己藏、库还留着，就有了两套真相——屏幕上看不到的行仍然参与「剩余第一个」的回落、仍然出现在 AI 读到的节点列表里，副行计数也会对不上。**禁用而不隐藏**：行还在池里这件事要如实说，但用户不该被允许拿它去连接。

**为什么不让界面自己发起清理**：清理要删节点、改 `current_node_id`、写 `ended_at`，还可能断连——一次事务加多步副作用，只有 Host 做得了。界面频繁检查等于把事务的节奏交给渲染。

**用户行为准则：界面直接拒绝，连接请求不发**（2026-11-18 产品负责人拍板，**取代**上一版「可能先连上再被断开」的写法）：

| 位置 | 表现 |
|---|---|
| 过期行 | 禁用 + 行内 `已到期` 徽标；点它既不切换、也不连接 |
| 当前选中的就是过期行 | **主按钮禁用**，按钮下方给一行 `.stage-note`：`这个免费节点已到期，选一个别的节点再连接。` |
| 选中的是自建节点 / 尚未选中 | 主按钮照常可用——只有指向过期行的连接才被挡住。**没有选中时**，连接会回落到「配置的当前节点 / 池里第一个」；**回落目标若是过期行，按上一行同样处理**（禁用 + 提示），不能靠「反正没选中」放行 |

- **用户看不到 `正在连接` → `已连接` → `未连接` 的闪一下**：不是「发出去再断」，是这一次点击根本不产生连接请求。
- **前端拒绝是主路径，Host 的后置钩子仍保留作兜底**：`note_trial_connection` 尾部那次 `check_trial_expiry`（`services.rs:6816-6822`）不改——若有别的入口绕开界面（AI、重启前的在途请求等），连接落地后仍会被清理断开。两层不冲突：前端负责不让用户看到假连接，Host 负责保证没有已过期的连接活着。
- **提示语与 §5.3 分开写，不复用**：窗口里是 `这个免费节点已到期，选一个别的节点再连接。`（还没清理，换个节点就行）；清理完成后才是 `免费节点已到期，已从节点池移除。`（§5.3）。同一句放错时刻会有一半是假话。
- **只看不连**：行一直留到启动 / 5 分钟定时 / 下一次连接任一把清理跑完，跑完按 §5.2 变化（禁用行连同徽标一起消失）。

### 5.1 发生什么

| 场景 | 结果 |
|---|---|
| 正连着试用节点 | **硬断开**（验收 #3）；状态带变 `未连接`；主按钮 `连接` |
| 没连着、但选中的是试用节点 | 选中回落到**剩余节点的第一个**（即自建组的第一行）；**由 Host 在到期清理事务里写库**，界面照读、不自己挑 |
| 没连着、选中的是自建节点 | 选中不变 |
| 自建节点 | 顺序、位置、选中都不动（验收 #2） |
| 试用节点在到期前被删完 | 与到期同效：不提前结束试用计时，只是列表里没有免费组（验收 #4） |

### 5.2 卡片怎么变

- **免费组整组消失**：组标题、右侧到期文字、该组所有行一起移除；**不留空组标题、不留空行**。
- 剩余只剩自建 → 组标题**一并消失**，回到 §3 的「无分组」形态；自建行的相对顺序与位置感保持不变（不再多一行标题压在上面）。
- 副行 `N 个节点` 的数量立即更新。
- **不整屏替换**：`trial_expired` 屏只用于「一个节点都不剩」的情况；混合场景下节点还在，用户看到的是卡片变短，不是换了一屏。

### 5.3 选中回落：Host 写库，界面不做 fallback

到期清理是一个事务，顺序固定：删 `source = seed` 的节点 → 若 `current_node_id` 落在被删的节点上，就写回「剩余里 `position` 最小的那一行」，没有剩余则置 `NULL` → 写 `trial_state.ended_at`（`src-tauri/src/trial.rs:186-198`）。

**界面只读 `current_node_id` 并据此高亮，不做本地 fallback、不做「先猜一个再对齐」。** 理由：界面自己挑一个值，一旦和库不一致，用户点「连接」会连到屏幕上并没有选中的那一台；而两次读取之间，选中还会闪一下不同的行。回落的口径只有一个，在写库里。

- 因为组内顺序保持 `position` 顺序，「剩余第一个」在界面上就是 `你的服务器` 组的第一行——**两条口径天然对齐，不需要额外规则**。
- 回落的那一行显示正常选中态（左侧 2px 竖条 + 名称 600 + 卡底），与手动点选完全一样——**不为「回落」造一个特殊样式**，否则用户会以为自己误触了什么。
- 在摘要行位置给一句：`免费节点已到期，已从节点池移除。`（13 / `--ink-3`，`.stage-note`）。本会话内只出现一次；切走再回来不重复。

### 5.4 断开后的状态带

- 硬断开时状态带直接进 `未连接`，不经过 `断开中…` 的长时间停留（断开是系统触发的，不是用户点的，不需要假装在等）。
- 若断开失败：状态带按既有失败分支显示，主按钮 `重新连接`；卡片已经不含试用节点——**界面不出现「正在连接一个已删除的节点」这种状态**。

## 6. 边界形态

| 形态 | 标题 | 副行 | 组标题 | 行 |
|---|---|---|---|---|
| 只有 1 个试用节点 | `节点` | `1 个节点 · 7 天试用` | 无 | 1 行 |

## 7. 节点很多时

- **不做粘性标题。** 卡片自身不滚动（它是舞台里的一段内联内容，滚动的是整页）；把一个不会滚的容器里的标题做成 sticky，等于让标题浮在页面滚动之上，会和卡片边框脱开。
- 不把节点列表塞进卡内滚动区：那会造出「页面滚动 + 卡内滚动」两层，是最常见的滚动陷阱。
- 节点超过约 8 个时，卡片仍整段展开、整页滚动；**不折叠、不分页**——节点数在可用产品里不会到这个量级，为它做折叠是给不存在的场景付维护成本。

## 8. 必须改 / 建议改 / 不改

### 必须改（P1）

1. **卡片标题固定 `节点`**，不再用 `config.name`（否则混合后标题写「免费节点」而里面是自己买的服务器）。**`<h2>` 与 section 的 `aria-label` 一起改**（`ConnectionStage.tsx:403`），否则读屏仍念「免费节点」。
2. **两类同时存在时显示两个分组标题**，顺序 `你的服务器` → `免费节点`；只存在一类时全部不显示。
3. **副行只在「全部是试用」时保留 `· 7 天试用`**；混合时只写 `N 个节点`。
4. **到期移除整组**：组标题与到期文字一起消失，不留空组；只剩一类时组标题自动消失。
5. **选中回落由 Host 在到期清理事务里写库，界面不做本地 fallback**，只读 `current_node_id`（`trial.rs:186-198`）。
6. **选中回落不加特殊样式**，与普通选中态一致；摘要行给一句 `免费节点已到期，已从节点池移除。`
7. **免费组标题右侧支持 `已到期`**：`expires_at <= now` 且清理还没跑时写这三个字，只在混池时可见（§2.1）。
8. **窗口里过期行禁用并标 `已到期`，连接请求不发**：行不隐藏（节点还在池里，藏了就有两套真相），但点它不切换、不连接；当前选中（或未选中时的回落目标）是过期行时，主按钮禁用并给 `这个免费节点已到期，选一个别的节点再连接。`。节点消失只由 Host 清理触发（启动 / 每 5 分钟 / 连接成功，§5.0）。

### 建议改（P2）

9. 组标题高 24、12/500/`--ink-3`、`padding 0 16`；免费组右侧 11 / `--ink-3` 的到期文字。
10. 组内顺序保持原有相对顺序，不按延迟重排。
11. 到期文案在本次会话内只出现一次。

| 项 | 理由 |
|---|---|
| 行高 48、行的点击行为 | 现状已定；点行只换节点，不连接。 |
| `最快` / `已销毁` 徽标的位置与样式 | 与来源无关，留在行内；挪进组标题会让它离开被标记的那一行。 |

| 卡片不滚动、不做粘性 | 见 §7。 |
| 只有单一来源时不显示组标题 | 首次用户看到的第一屏不因此改变。 |
| 到期不整屏替换 | `trial_expired` 只服务于「一个都不剩」；混合时整屏替换会让用户以为自己的服务器也没了。 |
