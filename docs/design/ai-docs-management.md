## 2. AI 需要介绍的产品功能

按用户会问的问题分组。每组写清「要能答什么」，并列出背后支撑的工具（工具清单见附录）。

### 2.1 连接与接管

- **两种接管方式**：Tun 模式接管整台电脑的全部流量（首次连接要一次系统授权）；Proxy 模式只给本机代理地址，只有能填代理的软件才走。
- **两档流量范围**：智能（只让需要的网站走，其余直连）、全局（全部走）。没有「按服务挑」。
- **连接 / 断开 / 重新连接**的主按钮语义；连接中、切换中、断开中三个进行态。
- **「连上了但打不开」「有的软件没走 VPN」**：必须诊断后再答，不直接讲概念。

工具：`VpnConnect`、`VpnDisconnect`、`RuntimeStatus`、`RuntimeStart/Stop/Restart`、`ConfigSetMode`、`RouteGet`、`RouteSetMode`、`DiagRun`、`HttpCheck`。

### 2.2 节点

- **节点池只有一份**，没有「新建配置 / 切换配置 / 配置列表」。
- **三种来源**：Veyl 免费节点（仅供试用，稳定性不保证）、自有节点（分享链接、订阅地址、手动四项）、供应商（本期只能预览）。
- **节点数量与当前节点**必须先读 `ConfigDetail`；`DefaultProfileStatus` 只代表免费节点缓存，不能单独用来回答。
- **不可用节点**：说清是停机删除还是线路不通；建议销毁重建；销毁当天已用掉的不退，未用完的整天退回余额；AI 不能代销毁或代建。
- **探测**只认真实延迟，不认裸 TCP。

工具：`ConfigDetail`、`ConfigUpdate`、`NodeImport`、`NodeSwitch`、`NodeProbe`、`CatalogRefresh`、`CatalogSearch`、`DefaultProfileStatus`。

### 2.3 我的服务器与计费

- **按天计费**：建机成功且验证运行后扣第一天；此后每天同一时刻续扣；余额不足会停机销毁。
- **月价 = 日价 × 30**；档位与地区由目录决定，「这个地区不提供该档位」要说清。
- **余额与充值**：余额在账户菜单与设置两处；充值面额来自目录；余额是快照，可能旧，失败时明说「显示的是上次的余额」。
- **创建失败**：说明卡在哪一步、能不能重试、这次没扣费；只给一个能点的动作。
- **销毁**：未用完的整天退回余额，销毁当天已用掉的不退；AI 无工具入口，只给路径。
- **手机使用**：只付费节点、自有域名、在设置 › 账户里导出；给的是 App 列表与二维码，不是通用教程。

工具：`MyServers`、`MyServerFailure`、`StageSelect`、`ServerOptions`、`JobGet`。

### 2.4 账户与登录

- 两种身份：邮箱登录、设备身份；设备被停用 / 身份丢失时怎么恢复。
- 账户菜单里有什么（邮箱、余额、充值、在手机上使用、退出）。
- 退出登录会不会影响正在运行的服务（不影响）。

工具：无（走命令与界面），AI 只解释，不代操作。

### 2.5 手机与其它设备

- 「在手机上使用」的完整路径：设置 › 账户 → 选 App → 扫码导入；iOS 需要大陆以外的 Apple 账号装 sing-box。
- 导出只包含付费节点，配置里写的是自有域名。

### 2.6 设置与高级项

- **AI 服务商**：API 类型（openai 兼容 / anthropic 兼容）、Base URL、模型；DeepSeek 一键配置。
- **高级项**：默认配置源、本地代理端口、日志目录、恢复网络、运行时升级（只能用户明确要求才升）。
- 设置页只有顶部一个 `咨询 AI`，行内「问 AI」已于 2026-11-21 收敛（见 §1）。回答模板仍是「改了什么 / 什么时候改 / 改错会怎样」三句。

工具：`OpenSettings`、`NetConfigGet`、`CoreListVersions`、`CoreUpgrade`、`RuntimeLogs`、`DeepseekSetupKey`、`DeepseekSaveKey`。

### 2.7 故障与诊断

- 连接失败：先诊断再答，逐项说，只给一个动作。
- 问题报告：报告只存在本机；生成时脱敏日志会发给用户配置的 AI 服务；发不发由用户决定。
- 一键恢复网络（代理 / TUN / 路由 / DNS / 残留进程）的语义：做了什么、会不会断线。

工具：`DiagRun`、`IssueReport`、`NetRepair`、`RuntimeLogs`。

### 3.2 要回答的问题

**A. 边界**：三份文档各放什么？

- 系统提示词：身份、流程、措辞与安全底线——**每轮都进上下文**。
- 功能介绍：产品有哪些能力、每项怎么用、边界在哪——**按需进上下文**。
- FAQ：具体问句与标准答案——**按需进上下文**。

**已定（D1，见 §7）**：系统提示词只留角色、工作方式与文档指路；产品事实与操作细节进 `product.md` / `faq.md`，由 AI 按需读。哪些必须常驻、哪些可以挪出去的判定标准见 §7。

**B. 加载方式**：三选一或组合。

| 方案 | 做法 | 代价 |
|---|---|---|
| A 全量注入 | 三份都编进二进制，每轮拼进系统提示词 | 上下文变长、每轮都要付 token；FAQ 越长越挤占对话 |
| B 按需检索 | 三份编进二进制，新增一个只读工具（如 `HelpLookup`），AI 判断需要时取 | 多一次工具往返；离线仍成立；要设计检索粒度 |
| C 入口注入 | 系统提示词常驻；FAQ / 功能介绍只在该入口被点击时整段或按段注入 | 入口之外的自由提问拿不到；需要维护「入口 → 段落」映射 |

**已定（D2）：取 B 的变体——「指路 + 按需读取」。** 不新增 `HelpLookup` 之类的检索工具，改为把文档释放到应用数据目录、给 AI 注册六个基础文件工具（Read / Edit / Write / Bash / Glob / Grep），由它在需要时直接读 `{{PROMPT_DIR}}` 下的文件。已落地，见 §7.1。方案 C（入口注入）未采用：入口之外的自由提问拿不到文档。

**C. 版本管理**：三份文档各自独立版本还是跟着客户端版本走？

- 需要能回答：这份提示词是哪一版？FAQ 某条什么时候改的、为什么改？旧客户端加载旧文档会不会答错新功能？
- **已有什么**：
  - 内容哈希：每种语言目录一个 8 位版本号，会话创建时写进日志（`prompts.rs:109-136`、`mod.rs:369-375`）。
  - 两种语言同构校验：标题层级序列与占位符集合必须一致（`prompts.rs:215-234`）。
  - 版本只看内容：同样的内容重复释放得到同一个版本（`prompts.rs:265-274`）。
- **还差什么**：
  - 文档内没有 `version` 字段，也没有变更记录（`CHANGELOG`）——「某条什么时候改的、为什么改」查不到。
  - 没有 CI 校验（占位符已填、引用 id 存在、禁词检查）。
  - 发布方式未定（D3）。
- **仍在待决**：文档与客户端是**绑定发布**（同一版二进制）还是**可独立更新**（从服务端拉最新）。前者简单、离线友好；后者要处理「文档比客户端新」的错答。

### 3.3 约束（不参与讨论，作为前提）

- **离线可用**：开机没网时 AI 也要能答基础问题，文档不能只放在服务端。
- **禁词与措辞规则**沿用 `system.md` 的「怎么说话」，FAQ 不能破例。
- **不新增外部依赖**；文档加载走已有机制，不引入向量库。

## 4. FAQ 与功能介绍怎么写（待讨论）

### 4.1 条目形态（候选）

```
Q: 连上了但网页打不开，怎么办？
适用范围：已连接、有出口 IP
答案：先诊断（不猜）→ 按诊断结果说一句原因 → 只给一个动作
不要答：具体 IP、节点密码、错误码原文
关联：§2.1、§2.7
```

FAQ 只写**已经有人问过、且答案稳定**的问题；需要实时状态才能答的（「我现在连的是哪个节点」）不写进 FAQ，交给工具。

### 4.2 要定的事

- 一条 FAQ 的长度上限（建议 ≤120 字，超过拆条）。
- 是否给每条编号（编号是注入与版本管理的基础，建议给）。
- 「产品介绍」的粒度：按功能域分节（同 §2），每节回答「是什么 / 什么时候用 / 边界」。
- 两者与系统提示词冲突时以谁为准（建议：系统提示词的措辞与安全规则优先）。
- 写完由谁审：建议 ds-lead 出稿、PM 拍口径、fe-lead/be-lead 核对事实。

## 5. 点「问 AI」时额外注入什么（待讨论）

原则候选：**入口负责给事实，文档负责给背景，AI 负责措辞**。入口注入只放「此刻屏幕上真实存在的值」，不放教程。

| # | 入口 | 现在注入 | 建议补充 |
|---|---|---|---|
| 1 | 连接页芯片 | 当前接管方式、流量范围 | 当前是否已连接、出口地区（AI 就不用再问） |
| 2 | 连接失败 | 无 | 失败阶段与最近一次诊断的一行结论（或明确让 AI 跑诊断） |
| 3 | 设置 · 咨询 AI | 旧行为是打开即发整份设置快照（`settingsOverviewPrompt`） | **已定稿并落地（2026-11-22）**：用户提示词带当前分区的实际值（`settings.consult.fact.*`，15 条），直接让 AI 就这一区开口；跨分区才提醒换过去。不带 API Key，取不到的事实项省略。旧的整份快照不复活 |
| 4 | 报告问题 | 契约化开场 | 保持现状（开场已经写死隐私与追问） |
| 5 | 建机 · 让 AI 帮我选 | 一句意图 | 当前余额、可选地区与档位的摘要（或让 AI 调 `StageSelect`） |

## 7. D1 结论（2026-11-21 已定）

**边界**

- **系统提示词**：每个新建 AI 会话加载一次，定义 AI 的角色与工作方式，并告诉它「产品介绍在 `product.md`、常见问题在 `faq.md`」（按语言在 `resources/prompts/{zh,en}/`）。
- **两份文档是「指路」**：AI 需要时自己去读，不整段塞进系统提示词。两份文档互不重叠。
- **用户提示词优先**：本次会话若附带用户提示词（首启引导、某个入口的固定前缀），按用户提示词工作；没有就按系统提示词理解自己的角色与工作方式。
- **其它问题按模型自身推理**：可以调用基础工具与 Veyl 自定义的网络工具，也可以读写用户自己的文件（Word 等），不做限制。
- **不设优先级、不设兜底**：产品介绍与 FAQ 是两部分不相关内容；万一出现冲突，由 AI 自己解决并把差异告诉用户。

**两个文档的分工**

| 文档 | 范围 |
|---|---|
| `product.md` | 产品定位与设计；App 的功能、操作与设置；10 个「问 AI」入口对应的功能 |
| `faq.md` | 使用 VPN 过程中的场景与解决办法（连上了打不开、某些软件没走 VPN、速度慢等） |

两边不写同一个问题；需要实时状态才能回答的（「我现在连的是哪个节点」）两边都不写，交给工具。

**会话工作流的重排（已实现）**

- `first-run.md` 已退役（`5a7d8bc`），拆成 `system.md`（系统提示词，只承担「角色 + 方式 + 文档指路」）与 `kickoff.md`（首启用户提示词，正文是原 `first-run.md` 的「首次配置」整段）。
- 首启：用户配置好 AI Key 进入界面时，先加载系统提示词，再发 `kickoff.md` 作为用户提示词；AI 给出选项，引导用户选「自建节点」或「免费节点」。前端调 `ai_session_kickoff` 取这段（`prompts.rs:47-54`）。
- 不照搬 TweetPilot 的多会话类型，只保留「系统提示词 + 可选的一条用户提示词」。

**语言**

- 提示词按 `resources/prompts/zh/` 与 `resources/prompts/en/` 两套维护，随系统设置里的语言切换——但只对新建会话生效：语言在会话创建时解析一次，老会话不跟设置变（`mod.rs:363-364`、`:486-488`）。
- 参考 TweetPilot 的 `prompt_lang_dir()`：按语言前缀归一（`en-GB`、`en-AU` 都算 `en`），只支持 zh / en 两档。

### 7.1 落地前必须解决的两件事（已完成）

评审时 Veyl 的 AI 会话只注册了自研工具，**没有 claurst 默认的文件读写工具**——「指路」只会让 AI 假装读过。两件现在都已做：

1. **文档落到磁盘**：启动时把 `resources/prompts/{zh,en}/` 释放到 `<data_dir>/prompts/<lang>/`，绝对路径写进系统提示词（`{{PROMPT_DIR}}`）。内容变了才写盘（`prompts.rs:106-137`）。
2. **给 AI 读文件的能力**：注册 claurst 内置的六个基础工具（Read / Edit / Write / Bash / Glob / Grep），与 Veyl 工具合并进 `session_tools`（`mod.rs:78-116`）。2026-11-21 已拍板：不做只读限制，用户对自己的文件与终端操作不设限；提示词目录只是默认资料位置。

### 7.2 细节（2026-11-24 已定）

- 文档释放时机与路径：**已定**——`<data_dir>/prompts/<lang>/`，内容变了才写盘（`prompts.rs:106-137`）。
- 可读范围：**已定不限制**——AI 可以读用户目录里的文件（Word 等），提示词目录只是文档默认位置。注入风险的缓解见 `ai-prompt-loading.md` §4.1。
- 系统提示词：**已确认每轮重建**（`mod.rs:483-495`），不是会话创建时快照；语言在会话创建时定，之后不跟设置变。

### 7.3 参考：TweetPilot 的做法

- `build_butler_system_prompt` 按 `prompt_lang_dir()` 在 zh / en 两份 butler 提示词之间选；`build_product_guide_session_constraints` 是「角色 + 知识索引 + 安全策略 + 环境信息」的组合。

## 8. 系统提示词的组装方式：两段下发（已落地，`108e6e5`）

### 8.1 结论：做到了什么、做不到什么

- **做到**：稳定段（`system.md` 渲染 + 安全底线）只在会话创建时构建一次；环境与语言约束每轮走动态段；稳定段位于可缓存块，逐轮不变。
- **做不到**：去掉 claurst 默认提示词。受子模块不可改的约束，`QueryConfig` 没有 `replace_system_prompt` 字段，`query/src/runner/prompt.rs` 里硬编码为 `false`，所以原方案 B（replace 模式）作废。我们的内容继续以 `<custom_instructions>` 形式位于稳定块，claurst 默认提示词仍然存在。

### 8.2 现在的结构

| 段 | 内容 | 何时构建 | 落在哪 |
|---|---|---|---|
| 稳定段 `stable_prompt` | `system.md` 渲染 + 安全底线 | 会话创建时一次 | `query_config.system_prompt` |
| 动态段 `dynamic_prompt` | 环境段 + 语言约束 | 每轮 | `query_config.append_system_prompt` |
| claurst 默认提示词 | 能力说明、工具规范、权限等 | 子模块自己负责 | 稳定块（我们的内容包在 `<custom_instructions>` 里） |

段落顺序：正文 → 安全底线 → 环境 → 语言约束。claurst 每轮在 append 之后追加的段落（todo 提醒等）会排在语言约束之后。

代码位置：`claurst_session/mod.rs:143-175`（`stable_prompt` / `dynamic_prompt` / `apply_turn_prompt`）、`:399-409`（会话创建）、`:509-520`（每轮）。`compose_system_prompt` 降为 `#[cfg(test)]` 组合助手；`AivpnSession.prompt_dir` 字段已删。

### 8.3 为什么不是每轮重拼

地区、来源、系统推断每轮都可能变。把它们放进动态段后，变化只影响 `append_system_prompt`，稳定段保持逐字节一致，缓存前缀不会被打断。旧实现每轮用 `compose_system_prompt` 整体重拼，稳定块会随环境变化而变。

### 8.4 已废弃 / 未采用的路线

- **方案 B（replace 模式）**：作废。`QueryConfig` 无该字段，runner 硬编码 `false`；子模块不可改。
- **A′（把 `system.md` 放进 `append_system_prompt` 末尾）**：未采用。现在 `system.md` 留在稳定段，动态段只放环境与语言。

### 8.5 待定

- claurst 在 append 之后追加的段落会排在语言约束之后，所以「最后一句一定是语言约束」不再成立。是否需要应用侧再加约束，等 AI 工具审计结果出来再定。
