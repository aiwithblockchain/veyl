## 2. AI 需要介绍的产品功能

按用户会问的问题分组。每组写清「要能答什么」，并列出背后支撑的工具（工具清单见附录）。

### 2.1 连接与接管

- **两种接管方式**：Tun 模式接管整台电脑的全部流量（首次连接要一次系统授权）；Proxy 模式只给本机代理地址，只有能填代理的软件才走。
- **两档流量范围**：智能（只让需要的网站走，其余直连）、全局（全部走）。没有「按服务挑」。
- **连接 / 断开 / 重新连接**的主按钮语义；连接中、切换中、断开中三个进行态。
- **「连上了但打不开」「有的软件没走 VPN」**：必须诊断后再答，不直接讲概念。

工具：`VpnConnect`、`VpnDisconnect`、`RuntimeStatus`、`RuntimeStart/Stop/Restart`、`ConfigSetMode`、`RouteGet`、`RouteSetMode`、`DiagRun`、`HttpCheck`。

### 2.2 节点

- **节点池只有一份**，没有「新建配置 / 切换配置 / 配置列表」。
- **三种来源**：Veyl 免费节点（仅供试用，稳定性不保证）、自有节点（分享链接、订阅地址、手动四项）、供应商（本期只能预览）。
- **节点数量与当前节点**必须先读 `ConfigDetail`；`DefaultProfileStatus` 只代表免费节点缓存，不能单独用来回答。
- **不可用节点**：说清是停机删除还是线路不通；建议销毁重建；销毁当天已用掉的不退，未用完的整天退回余额；AI 不能代销毁或代建。
- **探测**只认真实延迟，不认裸 TCP。

工具：`ConfigDetail`、`ConfigUpdate`、`NodeImportText`、`NodeImportUrl`、`NodeCreate`、`NodeSwitch`、`NodeProbe`、`CatalogRefresh`、`CatalogSearch`、`DefaultProfileStatus`、`CategoryList`。

### 2.3 我的服务器与计费

- **按天计费**：建机成功且验证运行后扣第一天；此后每天同一时刻续扣；余额不足会停机销毁。
- **月价 = 日价 × 30**；档位与地区由目录决定，「这个地区不提供该档位」要说清。
- **余额与充值**：余额在账户菜单与设置两处；充值面额来自目录；余额是快照，可能旧，失败时明说「显示的是上次的余额」。
- **创建失败**：说明卡在哪一步、能不能重试、这次没扣费；只给一个能点的动作。
- **销毁**：未用完的整天退回余额，销毁当天已用掉的不退；AI 无工具入口，只给路径。
- **手机使用**：只付费节点、自有域名、在设置 › 账户里导出；给的是 App 列表与二维码，不是通用教程。

工具：`MyServers`、`MyServerFailure`、`StageSelect`、`CatalogOptions`、`JobGet`。

### 2.4 账户与登录

- 两种身份：邮箱登录、设备身份；设备被停用 / 身份丢失时怎么恢复。
- 账户菜单里有什么（邮箱、余额、充值、在手机上使用、退出）。
- 退出登录会不会影响正在运行的服务（不影响）。

工具：无（走命令与界面），AI 只解释，不代操作。

### 2.5 手机与其它设备

- 「在手机上使用」的完整路径：设置 › 账户 → 选 App → 扫码导入；iOS 需要大陆以外的 Apple 账号装 sing-box。
- 导出只包含付费节点，配置里写的是自有域名。

### 2.6 设置与高级项

- **AI 服务商**：API 类型（openai 兼容 / anthropic 兼容）、Base URL、模型；DeepSeek 一键配置。
- **高级项**：默认配置源、本地代理端口、日志目录、恢复网络、运行时升级（只能用户明确要求才升）。
- 每一项旁边都有固定「问 AI」，回答模板是「改了什么 / 什么时候改 / 改错会怎样」三句。

工具：`OpenSettings`、`NetConfigGet`、`CoreListVersions`、`CoreUpgrade`、`RuntimeLogs`、`DeepseekSetupKey`、`DeepseekSaveKey`。

### 2.7 故障与诊断

- 连接失败：先诊断再答，逐项说，只给一个动作。
- 问题报告：报告只存在本机；生成时脱敏日志会发给用户配置的 AI 服务；发不发由用户决定。
- 一键恢复网络（代理 / TUN / 路由 / DNS / 残留进程）的语义：做了什么、会不会断线。

工具：`DiagRun`、`IssueReport`、`NetRepair`、`RuntimeLogs`。

## 3. 三份文档怎么管理、怎么加载、怎么版本化（待讨论）

### 3.1 现状

| 事实 | 位置 |
|---|---|
| 只有**一份**系统提示词，编译期编进二进制 | `resources/prompts/zh/first-run.md` → `include_str!`（`claurst_session/mod.rs:42`） |
| 渲染时填两个占位符：工具清单（从注册表生成）、块清单（Rust 常量） | `mod.rs:58-88` |
| 每轮追加「环境」段（地区 / 来源 / 系统推断）与 `SAFETY_RULES` 九条 | `mod.rs:93-143`、`:360` |
| **没有**产品功能介绍文档、**没有** FAQ 文档（2026-11-21 已建占位：`resources/prompts/{zh,en}/product.md`、`faq.md`） | `resources/prompts/zh/` 下只有 `first-run.md` |
| AI **没有读文件的能力**：工具集里没有 Read / Glob / 搜索 | `tools/mod.rs:154-203` |
| 文件头写着「构建时与回访、失败、分流追问等段落拼接为 system.md」 | 实际没有这个拼接步骤，注释与实现不符 |

### 3.2 要回答的问题

**A. 边界**：三份文档各放什么？

- 系统提示词：身份、流程、措辞与安全底线——**每轮都进上下文**。
- 功能介绍：产品有哪些能力、每项怎么用、边界在哪——**按需进上下文**。
- FAQ：具体问句与标准答案——**按需进上下文**。

待决：哪些内容必须留在系统提示词里（例如「不承诺结果」「节点只有一个池」），哪些可以挪进按需文档，挪出去会不会让 AI 在流程中分心或答错。

**B. 加载方式**：三选一或组合。

| 方案 | 做法 | 代价 |
|---|---|---|
| A 全量注入 | 三份都编进二进制，每轮拼进系统提示词 | 上下文变长、每轮都要付 token；FAQ 越长越挤占对话 |
| B 按需检索 | 三份编进二进制，新增一个只读工具（如 `HelpLookup`），AI 判断需要时取 | 多一次工具往返；离线仍成立；要设计检索粒度 |
| C 入口注入 | 系统提示词常驻；FAQ / 功能介绍只在该入口被点击时整段或按段注入 | 入口之外的自由提问拿不到；需要维护「入口 → 段落」映射 |

待决：先定 B 还是 C，还是 B+C（入口注入保准，检索兜底）。

**C. 版本管理**：三份文档各自独立版本还是跟着客户端版本走？

- 需要能回答：这份提示词是哪一版？FAQ 某条什么时候改的、为什么改？旧客户端加载旧文档会不会答错新功能？
- 候选做法：文档内 `version` 字段 + 内容哈希；变更记录 `CHANGELOG`；CI 校验（占位符已填、引用 id 存在、禁词检查）；随客户端版本发布时把三份文档的版本写进日志，便于对账。
- 待决：文档与客户端是**绑定发布**（同一版二进制）还是**可独立更新**（从服务端拉最新）。前者简单、离线友好；后者要处理「文档比客户端新」的错答。

### 3.3 约束（不参与讨论，作为前提）

- **离线可用**：开机没网时 AI 也要能答基础问题，文档不能只放在服务端。
- **禁词与措辞规则**沿用 `first-run.md` 的「文案规则」，FAQ 不能破例。
- **不新增外部依赖**；文档加载走已有机制，不引入向量库。

## 4. FAQ 与功能介绍怎么写（待讨论）

### 4.1 条目形态（候选）

```
Q: 连上了但网页打不开，怎么办？
适用范围：已连接、有出口 IP
答案：先诊断（不猜）→ 按诊断结果说一句原因 → 只给一个动作
不要答：具体 IP、节点密码、错误码原文
关联：§2.1、§2.7
```

FAQ 只写**已经有人问过、且答案稳定**的问题；需要实时状态才能答的（「我现在连的是哪个节点」）不写进 FAQ，交给工具。

### 4.2 要定的事

- 一条 FAQ 的长度上限（建议 ≤120 字，超过拆条）。
- 是否给每条编号（编号是注入与版本管理的基础，建议给）。
- 「产品介绍」的粒度：按功能域分节（同 §2），每节回答「是什么 / 什么时候用 / 边界」。
- 两者与系统提示词冲突时以谁为准（建议：系统提示词的措辞与安全规则优先）。
- 写完由谁审：建议 ds-lead 出稿、PM 拍口径、fe-lead/be-lead 核对事实。

## 5. 点「问 AI」时额外注入什么（待讨论）

原则候选：**入口负责给事实，文档负责给背景，AI 负责措辞**。入口注入只放「此刻屏幕上真实存在的值」，不放教程。

| # | 入口 | 现在注入 | 建议补充 |
|---|---|---|---|
| 1 | 连接页芯片 | 当前接管方式、流量范围 | 当前是否已连接、出口地区（AI 就不用再问） |
| 2 | 连接失败 | 无 | 失败阶段与最近一次诊断的一行结论（或明确让 AI 跑诊断） |
| 3 | 设置 · 咨询 AI | 旧行为是打开即发整份设置快照（`settingsOverviewPrompt`） | **已定稿并落地（2026-11-22）**：用户提示词带当前分区的实际值（`settings.consult.fact.*`，15 条），直接让 AI 就这一区开口；跨分区才提醒换过去。不带 API Key，取不到的事实项省略。旧的整份快照不复活 |
| 4 | 设置 · 新建节点 | 无 | 一句「用户从设置里点进来，想新建节点」 |
| 5 | 报告问题 | 契约化开场 | 保持现状（开场已经写死隐私与追问） |
| 6 | 建机 · 让 AI 帮我选 | 一句意图 | 当前余额、可选地区与档位的摘要（或让 AI 调 `StageSelect`） |
| 7 | 创建失败 · AI 定位 | `serverId` 只在 `lastAction` 里 | 把 `serverId` 与失败阶段写进消息；或注入一行本次失败的摘要 |
| 8 | 手机使用 | 无 | 当前要导出的节点数量（全部是付费节点） |
| 9 | 预设问题 | 整句 | 保持现状；可考虑给每条预设挂一个 FAQ 条目 id |
| 10 | 节点「测不通」 | 节点名 | 节点名已带；不要追加状态码或地址 |

待决：额外内容是拼进**用户消息**（看得见、可追溯）还是走**系统提示词的「入口段」**（更省 token，但对用户不可见）。建议：事实用消息、规则用提示词。

## 7. D1 结论（2026-11-21 已定）

**边界**

- **系统提示词**：每个新建 AI 会话加载一次，定义 AI 的角色与工作方式，并告诉它「产品介绍在 `product.md`、常见问题在 `faq.md`」（按语言在 `resources/prompts/{zh,en}/`）。
- **两份文档是「指路」**：AI 需要时自己去读，不整段塞进系统提示词。两份文档互不重叠。
- **用户提示词优先**：本次会话若附带用户提示词（首启引导、某个入口的固定前缀），按用户提示词工作；没有就按系统提示词理解自己的角色与工作方式。
- **其它问题按模型自身推理**：可以调用基础工具与 Veyl 自定义的网络工具，也可以读写用户自己的文件（Word 等），不做限制。
- **不设优先级、不设兜底**：产品介绍与 FAQ 是两部分不相关内容；万一出现冲突，由 AI 自己解决并把差异告诉用户。

**两个文档的分工**

| 文档 | 范围 |
|---|---|
| `product.md` | 产品定位与设计；App 的功能、操作与设置；10 个「问 AI」入口对应的功能 |
| `faq.md` | 使用 VPN 过程中的场景与解决办法（连上了打不开、某些软件没走 VPN、速度慢等） |

两边不写同一个问题；需要实时状态才能回答的（「我现在连的是哪个节点」）两边都不写，交给工具。

**会话工作流的重排（待实现）**

- `first-run.md` 退役，改名 `system.md`，只承担「角色 + 方式 + 文档指路」。
- 首启：用户配置好 AI Key 进入界面时，先加载系统提示词，再给一条用户提示词——「用户刚进入 APP，引导他选择节点并回答相关问题」；AI 收到后给出选项，引导用户选「自建节点」或「免费节点」。
- 不照搬 TweetPilot 的多会话类型，只保留「系统提示词 + 可选的一条用户提示词」。

**语言**

- 提示词按 `resources/prompts/zh/` 与 `resources/prompts/en/` 两套维护，随系统设置里的语言切换（见待办）。
- 参考 TweetPilot 的 `prompt_lang_dir()`：按语言前缀归一（`en-GB`、`en-AU` 都算 `en`），只支持 zh / en 两档。

### 7.1 落地前必须解决的两件事（评审发现）

现在 Veyl 的 AI 会话只注册了 39 个自研工具（`run_query_loop` 拿到的就是 `self.tools`），**没有 claurst 默认的文件读写工具**。TweetPilot 的「指路」之所以成立，是它把详细文档装到 `~/.tweetpilot/prompts/...`，AI 用内置文件工具去读。Veyl 要做同样的事：

1. **文档落到磁盘**：启动时把 `resources/prompts/{zh,en}/` 释放到应用数据目录，并把绝对路径写进系统提示词。
2. **给 AI 读文件的能力**：注册 claurst 内置的六个基础工具（Read / Edit / Write / Bash / Glob / Grep）。2026-11-21 已拍板：不做只读限制，用户对自己的文件与终端操作不设限；提示词目录只是默认资料位置。

不解决这两点，「指路」只会让 AI 假装读过。

### 7.2 仍未定的细节

- 文档释放时机与路径：每次启动覆盖，还是版本变了才覆盖。
- 可读范围：**已定不限制**——AI 可以读用户目录里的文件（Word 等），提示词目录只是文档默认位置。注入风险的缓解见 `ai-prompt-loading.md` §4.1。
- 系统提示词是每轮重建（现状）还是会话创建时快照。

### 7.3 参考：TweetPilot 的做法

- `build_butler_system_prompt` 按 `prompt_lang_dir()` 在 zh / en 两份 butler 提示词之间选；`build_product_guide_session_constraints` 是「角色 + 知识索引 + 安全策略 + 环境信息」的组合。
- `product-guide-prompt.md` 只做索引，明确写「深入某模块时主动读取 `~/.tweetpilot/prompts/zh/product-guide/` 下对应文件」。
- 它有多套 session 类型（butler / product_guide / publish / task），每种一套系统提示词——我们明确不照搬。
