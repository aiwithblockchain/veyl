# 本次 UI / UX 重构需求

> 2026-11-16 · 产品负责人口述整理
> 本文只记本次重构的总要求；详细设计与内容逐项讨论后再补充到本文。

## 目标用户

会用 AI 的高端用户。他们对 VPN 的需求明确，是高净值用户。产品要做到让他们惊艳。

## 总体原则

**整个产品锁死为 AI 自动执行**，尽可能做到用户不用自己操作。

## 用户只需要做三件事

1. 充值
2. 配置自己的 AI
3. 做一次简单的登录

其余全部交给 AI。

## 首个界面（刚启动，没有 AI、没有登录）

- 一屏完成，不做多步向导。
- 核心是一个动作：**接入 AI**。一个 Key 输入框 + 主按钮「连接」。
- 标题（已定）：**Under the veil, it keeps your line open.** 英文；veil＝遮蔽与保护，line＝私有连接，it＝AI 在维持；不出现品牌名，不做「never drops」这类承诺。
- 辅助入口：「获取 Key ↗」「使用其他 AI 服务」。
- 登录不阻塞首屏：**只有购买服务器和查看账单时才需要登录**。
- 不提供「我懂网络，不用 AI」——产品不服务不用 AI 的情况。
- 转场即惊艳：点「连接」后用真实校验过程点亮，成功后进入主界面，AI 开始第一句话。
- 视觉已定：浅色底 `#FAFAF8`、文字 `#14161C`、强调色 `#F6537B`（取自 logo 粉）；状态色仍用绿 / 琥珀 / 红。强调色只用于连接线、进行中步骤、聚焦描边与链接，不做大面积填充。
- 首屏 logo：48px logo + 20px 产品名「Veyl」并排，居中列顶部；不用大图。

## 视觉基线（按 `ui-ux-pro-max` 定稿）
- **风格**：极简 / Swiss。浅色、留白充足、边界靠 1px 细线不靠阴影；一屏只动一个元素。
- **色板**：底 `#FAFAF8`；主文字 `#14161C`；次要 `#5B5850`；弱化 `#6E6A62`（对比度 ≥5:1，不用更浅的灰做文字）。
- **品牌粉分两档**：`#F6537B` 只用于连接线、进度、装饰；**文字与链接用 `#C2185B`**（5.4:1）；聚焦描边 `#E03A66`。
- **状态色**：绿 `#1B7A4E` / 琥珀 `#946200` / 红 `#A8382D`，只用于状态点、状态文字、描边。
- **字体**：系统 sans；数字与 Key 用 mono。首屏英文标题 24/600，正文 15/400，次要 13，小标签 11（正文不小于 11）。
- **间距**：4px 网格；首屏纵向节奏 48 / 24 / 16。
- **动效**：只允许连接线动；进度用线性、约 900ms；退场 160ms ease-out；`prefers-reduced-motion` 直接切到最终态。
- **表单**：输入框必须有可见标签（不能只靠 placeholder）；错误就地显示在输入框下方并用 `role="alert"`，不清空已填内容；焦点描边可见；点击目标不小于 44×44。

## 等待与进度动画

- 等待与进展的动画**从 logo 的品红核心取形**：三个圆点，任何时刻只有一个被高亮（6px、`#F6537B`），其余两个 4px 灰；高亮每 300ms 向右移一格，900ms 循环，旁边跟真实耗时（如 `35s`）。
- 用在所有真实进行中的状态：AI 思考、连接中、服务器创建、节点测速。
- 只表达真实进行中：没有真实动作时不出现；时间是真实计时，不做装饰性循环。
- `prefers-reduced-motion` 时三点静止（保留品红点与时间），不做跳动。

## 「使用其他 AI 服务」状态

同一屏内切换，不跳页；品牌、标题、页面留白都不变。

- 顶部返回链接 `← 使用 DeepSeek Key`（13px，`#C2185B`），点击回到默认态，焦点回到 Key 输入框；默认态的「获取 Key ↗」在这个状态下隐藏。
- 小标题 `其他 AI 服务`（17/600），下面一行说明 `OpenAI 或 Anthropic 兼容端点。`（13px，`#5B5850`）。
- 四个字段，纵向间距 16：
  1. `接口类型`：分段控件（`OpenAI 兼容` / `Anthropic 兼容`），高 36；轨道 `#F1EFEA`，选中项白底 + 墨色 600，未选中 `#5B5850`；默认 OpenAI。
  2. `Base URL`：占位 `https://api.example.com`；辅助文字 `http 只允许本机地址。`
  3. `模型`：占位 `如 gpt-4.1-mini`；辅助文字 `填服务商文档里的模型 id。`
  4. `API Key`：占位 `sk-…`；辅助文字 `只保存在本机；本机端点可以不填。`
- 主按钮 `连接`（墨色实心，48px，宽 400），必填项没齐时禁用；校验时按钮内是三点轮转。
- 错误就地显示在表单底部，`role="alert"`，不清空已填内容。
- 默认态与自定义态之间用 160ms 淡入淡出切换，**不做高度动画**（避免布局抖动）；`prefers-reduced-motion` 直接切换。

## 登录时机

- **只在购买服务器和查看账单时需要登录。**
- 接入 AI、连接、切换节点、让 AI 修复问题等日常操作都不要求登录。

## 主界面（接入 AI 之后）的核心模型

中间不是「给 AI 展示结果」的静态面板，而是**人与 AI 共用的一块操作面**。对话在右侧面板，可收起、可拖宽。

1. **AI 看得见界面**：它知道当前是哪一屏、有哪些可操作项、用户刚刚点了什么、选了什么。不是猜，是 UI 把「当前状态 + 可操作项 + 最近一次操作」作为上下文交给它。
2. **AI 能指路**：对话里说的同时，让中间对应的控件高亮 / 聚焦，不只靠文字描述位置。
3. **UI 操作能触发 AI**：用户点了按钮或选了选项，AI 收到这个事件直接接着做下一步，不需要用户再打一遍字。
4. **抹掉细节**：中间只留「现在是什么状态」和 1–3 个真正要用户做的动作；服务器规格、IP、日志等全部收进展开层或对话。

例子：AI 说「要开一台东京的机器，每天 3 元」，中间出现确认卡，两个按钮「开」和「换地区」。用户点「换地区」，AI 收到这个选择，给出三个地区；用户点「洛杉矶」，**AI 通过 `StageSelect` 把地区和规格写进舞台**（Host 校验目录后发 `stage-select`，舞台选中并高亮），用户再点 `创建` 才真正开始建机并扣当天费用——AI 不替用户点这个按钮。

前提：UI 上的按钮和选项必须有稳定标识，AI 的输出也要能指向某个标识。

### 外壳：三区

- **最左 56px 导航**：连接 / 我的服务器；底部是账户与设置。固定不收起。**没有节点组 destination**——全局只有一个节点池。
- **中间是舞台**：连接 destination 下独占整个中区，**没有列表列**。
- **列表列只在节点组 / 我的服务器下出现**，作为舞台左侧的第二列；离开这两个 destination 就收起。
- **右侧 AI 面板**：默认收起为边缘 tab，展开默认 **380**（可拖 320–640）、宽度记忆。
- 切换 destination 时中区宽度变化要平滑过渡，不能跳。

对话放在右侧而不是底部：底部展开会盖住舞台上的按钮，而 AI 指路时用户必须同时看见按钮和说明。

### 主界面必须展示的内容（合并后）

常驻三块 + 一个入口：

1. **连接区**：主按钮（连接 / 断开）+ 当前节点 + 连接状态 + 延迟。测速是节点列表里的动作，不常驻。
2. **资源区**：账号下的服务器与节点，默认收成一行摘要（如 `3 台服务器 · 5 个节点`），点开才是列表和测速。
3. **对话区**：右侧面板，默认收起为边缘一条 tab；展开 360–420 宽，可拖 320–640，宽度记忆。单会话，不设历史列表，重启从空白开始；过程与结果留在舞台，不堆在聊天里。
4. **账户入口**：未登录时只显示「登录」；登录后显示邮箱 + **余额**，旁边有**充值**；设置（含 AI Key）也在这里。AI Key 失效时入口带提示点。

### 全局配置与设置

- **全局只有一套网络配置**：不再有配置列表、新建配置、切配置。后端 config 表保留，作为这条全局配置的载体（不做数据迁移）。
- **设置以弹层出现**（IDE 式），默认独占整屏；点遮罩或关闭返回。
- 弹层顶部：标题 `设置`，右侧 **`咨询 AI`**。点击后**不关闭设置**：设置缩到左侧（宽 560），右侧展开助手（380），两边可同时操作；再点一次收起助手、设置恢复居中。
- AI 解释时可以**指向具体行**：`OpenSettings { section, row? }` 把对应行滚动到可见并高亮约 2 秒，不改变任何值。这样用户一边看控件一边听解释。
- 设置内分四段（主路径 = 前三段）：
  1. **AI**：默认 AI（DeepSeek Key）／其他 AI 服务。
  2. **连接**：接管方式（`Proxy 模式` / `Tun 模式`，**Proxy 在前**）、流量范围（智能 / 全局）、本地代理端口（只在 Proxy 模式出现）。
  3. **账户**：登录、余额、充值、账单。
  4. **高级**（排在最后，默认不进入）：运行核心、helper、日志、重置网络。主路径仍是 AI / 连接 / 账户三段。
- **接管方式的用词**：`Proxy 模式` / `Tun 模式` 直接出现在界面上，**而且必须出现**（2026-11-17 产品负责人拍板；`proxy` / `TUN` 已从 `veyl-ui` §6 的禁用清单里拿掉，只剩 `分流` / `规则集` 仍禁）。设置、左栏、建机卡、AI 选项、连接舞台的模式行统一用这两个名字，**不另造中文别名**；概念解释交给 AI（`stage-quick-toggles.md` §3），界面不写长篇说明。其它实现词（`selector` / `mixed` / `geosite`）仍只在高级设置与日志。
- 主界面顶部只显示结果（如 `Proxy 模式 · 智能 · 东京`）；连接舞台主按钮下方另有一行 `Proxy 模式 · 智能`，**就地可改**（规格见 `stage-quick-toggles.md`），设置 › 连接仍是完整入口（说明 + 端口 + 排查上下文），两处读同一份状态。
- **默认值：接管方式 = `Proxy 模式`，流量范围 = 智能**。全局配置第一次创建时直接写 `connect_mode = "system_proxy"`，不需要用户先做一次选择。地区识别不出来时退回全局，并由 AI 说明一句。
  - 2026-11-17 产品负责人真机测试后改：原来默认 `Tun 模式`。Tun 接管整台机器的流量、需要 root 授权，这个代价不该是默认值；Tun 改为**用户显式选择**才启用。
  - **授权提示只在用户主动选 Tun 时出现**：没选 Tun 之前不弹特权助手 / 管理员授权，启动时不弹、连接前也不弹。选 Tun 之后的首次连接才请求授权（`acceptance-ui-refactor.md` S2）。
- 接管方式切换会断线，必须二次确认；流量范围可热切换。
- AI 也能改这两项：接管方式走确认卡，流量范围可直接改。
- **AI 指路到设置**：`OpenSettings { section: "ai" | "connection" | "account" | "advanced", row?: string }` 打开设置并高亮对应段/行（`row` 省略时定位到段）；`display` 写「已打开设置 · 连接」。系统提示词里附一份设置目录，AI 才知道该指向哪一段。契约见 `commands.md` §9.1.1 与 `tools.md` §4.50。

### 全局配置与节点池

- **全局配置回答「怎么连」**：接管方式、流量范围、DNS 等连接参数，只有一套。
- **全局只有一个节点池**：免费节点和自建节点都放进来，没有第二个组、也没有「切组」这个动作。
- 新建或删除节点只改变这个池子，**不产生新配置、不重置设置**；当前节点从池子里选。
- 界面上的动作是「把某个节点设为当前」，不是「切到那套配置」。

### 第一次进入主界面（还没有任何节点）

先检查有没有可用的节点来源；没有就停在这里，**先不触发 AI**，给两个选择：

1. **先试用免费节点**（7 天）：节点来自我们预置的 2 台服务器。
2. **新建节点**：走自己的服务器。

免费节点规则：

- 只有 2 个节点，不承诺容量和稳定性；经常换配置属于预期内。
- 预置配置的**主源是控制面 Worker 在**自有域名**上直出的 `https://veyl.dessage.xyz/v1/seed`**（数据就在 Worker 源码里的一个 TS 模块，改完部署即生效，国内可达）；`https://meshnetprotocol.github.io/veyl_seed.json` 保留为**兜底源**，主源失败时才用。设计见 `docs/design/seed-publishing.md`。**启动时只有本地没有免费节点才拉取；已有就不动；诊断发现过期才刷新。** 失败给三段式提示。
- **试用 7 天，从第一次连上开始算**，只记在本地，不做服务端防刷。
- **有自建节点不提前结束试用**（2026-11-17 拍板）：买了服务器，7 天倒计时照走，不取消、不缩短。
- 到期后免费节点自动从全局节点池移除。**如果当时正连着免费节点，直接断开并提示**；不静默切换到自建节点（换网络必须由用户点）。
- 到期界面只写「试用已到期」，**只有一个「新建节点」按钮**，不提供「继续试用」。**但用户已经有自建节点时不显示这块屏**：直接进连接舞台，由用户自己选节点连接（2026-11-17 拍板）。
- 试用与自建节点落在同一套全局配置、同一个节点池里（收敛方案见 `docs/design/global-config-merge.md`）。
- 用户选完，AI 才接手后续动作；这个二选一不交给 AI 代做。

### 选中免费节点之后

- AI 接手：拉取预置配置 → 加入 2 个免费节点 → 逐个测速。
- 过程中舞台出现步骤流（拉取、加入、测速），结束后收成一句：`已加入 2 个免费节点，最快 42ms`。
- **测速完成后停在这里：不自动连接，也不自动把某个节点设成当前**。状态 `未连接`，节点卡显示 2 个节点与各自延迟，最快的一个预选并标「最快」，主按钮 `连接`；用户可以直接按「连接」，也可以先改选另一个节点。免费服务器质量不保证，替用户自动建立连接会直接影响他的网络，这条是禁止，不是「尽量」。
- **预选只在界面里，不写库**：全局配置创建时 `configs.current_node_id` 留空；用户点「连接」的那一刻才先把它设为当前（`node_switch`），再启动连接。预选也**不持久化**（不写本地存储）——重启后回到「没有选中」，只有点了连接才会留下痕迹。**预选只在试用步骤流完成时发生一次**：之后的启动自动测速不得把最快节点重新显示为选中，也不得从测速结果反推预选。「最快」标记的移动规则见 `docs/design/connection-stage-probe.md` §4：试用完成时标一次；**用户主动点「测速」后跟随本次结果移动**；**后台 / 自动测速只清除标记、不移动**（不让用户没看时结论自己变）。**没有预选时点「连接」**：落到配置的当前节点；当前也为空（重启后正是这种状态）则连节点池第一个——「最快」标记只是信息，不参与选择，也不等于选中。
- 连接后：状态带变 `已连接` + 计时，节点卡保留，可换节点、可测速。

### 新建节点

- 舞台一次显示两段：**地区**与**服务器类型**（3 档）。
- **地区全量来自 `my_server_catalog`，按大洲分组**（亚洲 / 北美洲 / 欧洲 / 大洋洲），显示目录返回的可用状态；不在界面写死地区，也不自己编地区名。
- AI 的推荐只能从目录返回的地区里选。
- 服务器类型沿用现有卡片信息：`入门 1 核 · 512 MB · 每天 $0.20 · 带宽每月 500 GB`、`标准 1 核 · 1 GB · 每天 $0.30 · 带宽每月 1000 GB`、`进阶 1 核 · 2 GB · 每天 $0.60 · 带宽每月 2000 GB`。
- **三档卡的排布**：宽度足够时一行三列（每列约 200px，内容不折行）；舞台窄于约 **560px** 时允许排成 2+1，**但卡片内容仍不得折行**。不要为了凑三列把卡片压到 176px 以下——那会让 `每天 $0.30` 与 `带宽每月 500 GB` 折行。
- 类型卡只写 `每天 $0.20` 这一种价格，不写退款说明。计费**先扣后用**：创建即扣第 1 天，销毁当天不退，这本身就是一次创建成本，也天然抑制反复销毁重建。
- AI 解释时照实说：今天销毁不退，之后没用完的整天会退回余额。
- 主按钮只有 `创建`；`让 AI 帮我选` 是次级的文字入口。AI 负责问需求、解释好处与计费，并替用户选好地区与类型：**这条写入走 `StageSelect` 工具**（`tools.md` §4.52），Host 校验地区与套餐都在目录里、且地区可用之后才发 `stage-select`，舞台选中并高亮 1.5 秒。只改选择、不建机、不扣费。
- **建机不开放给 AI 工具调用**：`my_server_create` / `checkout` / `destroy` / `rebuild` / `credentials` 都只有 UI 入口，没有对应的 AI 工具。理由是这条链上扣费、登录、充值、领取凭据四个动作必须由人完成；给 AI 一个 `MyServerCreate` 只是把确认卡套上一层壳，风险更大。AI 靠 `UiContext`（`commands.md` §9.1.1）知道舞台当前选了什么，靠 `action_card` 让用户在 1–3 个动作里挑，选择结果回传后舞台更新——**`创建` 始终由用户点**。
- **AI 不可用时手动路径完整**：地区、类型、价格都可见，能直接创建。
- 点 `创建` 之后依次：确认摘要（地区、类型、每天价格）→ 未登录就地登录 → 余额不足就地充值 → 开始创建。**确认卡上不写「今天扣多少钱」**，不提前强调扣费。
- 创建过程与结果沿用 §选中免费节点之后 的步骤流；完成后节点进入全局节点池并成为当前节点。
- 创建即扣第 1 天（先扣后用），不额外收创建费；销毁当天不退，未用完的整天退回余额。
- **余额校验**：创建前必须检查余额是否够 **7 天费用**（日价 × 7，与 `my_server_checkout` 同一门槛；实际仍只扣第 1 天）；不足时不发起创建，就地显示「余额不足，还差 $X。」并展开充值（`docs/design/login-and-payment.md` §4.4 / §4.13）。
- **失败处理**：创建过程中某一步失败时，舞台显示失败的步骤和原因，并给一个 **`AI 定位`** 按钮。AI 读取 `MyServerFailure` 返回的结构化失败（阶段、错误码、是否可重试）、订单失败与最近 20 条订单事件，用用户语言解释，给出重试 / 换地区 / 换规格中的一个动作。**控制面不保留建机原始日志**，AI 不得声称读过日志，也不要求用户上传日志。
- **只有创建成功才产生净扣费**：失败时自动销毁并退回当天已扣的费用，用户不为失败的创建付费。按现有「先扣、失败自动退」实现即可，不需要改支付时序。
- 已补齐：`MyServerFailure` 是只读工具（`tools.md` §4.51），返回 `failure.stage/code/message/retryable`、订单失败与事件序列；`log_available` 恒为 `false`。

### 第一次选择自建节点

岔路：**我帮你开一台**（主）/ **我已有服务器**（导入）。**导入配置放到最后实现**（2026-11-16 决定），当前只做「我帮你开一台」。

「我帮你开一台」一次只出一张卡，右侧 AI 解释，登录与充值就地展开：

1. **地区**：东京 / 洛杉矶 / 新加坡，带延迟与每天价格；AI 按用户所在地区预选。主按钮 `下一步`。
2. **规格与价格**：一到两档，写清每天价格与余额还能撑几天。未登录 → `登录并继续`（就地邮箱验证码）；余额不足 → `充值并继续`（就地充值）。
3. **确认**：摘要卡（地区、规格、每天价格、首日扣费）+ `开一台` / `换地区`。这是唯一要用户点钱的时刻。
4. **创建**：中间变成真实进度 `开机 → 装环境 → 生成节点 → 测速`，每步真实耗时，失败可见重试。
5. **完成**：收敛成节点卡 + `连接`。这台服务器进入「我的服务器」，成为当前节点来源；免费节点保留。（这一步只适用于从连接页进入的建机；从「我的服务器」进入的，创建成功回服务器列表、新服务器在第一行，见 `stage-pages-review.md` §1.1。）

约束：

- 第 1–3 步可返回；点了 `开一台` 之后锁住，不能中途改地区。
- 用户可以直接对 AI 说「换到洛杉矶」，舞台跟着变。
- 没有服务器的用户全程只需输入一次邮箱验证码，其余都是点选。
- 导入路径（粘贴 `ss://` 或填地址/端口/加密/密码）放最后实现，当前不出现。

### 连接失败时的诊断

- 连接失败，或「已连接但打不通」时，中间给一个主按钮 **`让 AI 检查`**，旁边保留「重新连接」。
- 点击后发一条固定前缀的消息：`连接失败了。请先跑一次诊断，按清单逐项说明，只给一个能点的动作，不要猜。`
- AI 先调 `DiagRun`，把失败项按顺序讲出来；失败的项在中间直接渲染成卡片和按钮（重连、刷新预置配置、恢复网络、换节点）。
- **不再做逐目标可达性检查**：`reachability` 块已从布局词汇表移除（`events.md` §4.13）。诊断只回答「这次连接为什么不行」，不对「某个网站能不能打开」逐个确认——那是旧设计的细节展示，新设计把它收进诊断卡。
- **预置配置的刷新只在这次诊断里做**：清单里 `config.seed_stale` 为真时才刷新。启动时的拉取只发生在「本地还没有免费节点」，已有就不动。

## 已锁定与暂缓

**已确认**：首启接入 AI、免费节点试用二选一、选中免费节点后的连接界面与三区外壳。

**暂缓**：我的服务器 destination 的列表与详情**先不设计**——展示内容取决于业务流程，等业务定下来再做。原型里这个图标点开没有页面是刻意的，不是缺失。

## 我的服务器

列表列 280 + 舞台；右侧助手按需展开。

- **列表行**：`新加坡 01` · 状态点 · `每天 $0.20`；第二行弱化显示 `可用` / `安装中` / `出错了` / `已欠费`（进行中只给阶段词，不给百分比）。按创建时间倒序。
- **空态**：`还没有服务器` + `新建节点`。
- **舞台（选中一台）**：名称 + 状态；事实四行——地区、规格、IP（可复制）、计费（每天价格 + 已付到哪天）。
- **没有主按钮**（2026-11-19 二次改：先撤了 `连接`，这次连 `去连接` 也撤掉）：服务器详情**不提供任何连接入口**。就绪（`healthy` / `active`）时底部只有 `销毁`；建机中只有 `销毁` + 四段进度；出错时右下多一个 `重新建一台`，实例已失效时是 `重新购买`。建好的机器在安装完成时就已进全局池，用户在控制台的节点卡里选它、连它——**连接只由控制台发起**。规格见 `servers-list-detail.md` §2.3、`my-servers.md` §7.4。
- **次级动作**：`重建`（仅失败时出现；**端点未接入前不展示**——控制面目前恒返回 `rebuild_not_supported`）、`销毁`（危险操作，描边红字 + 二次确认，文案写清「销毁后不再产生新费用，当天已扣不退」）。
- 创建中 / 失败时，进度或失败原因就地显示，失败带 `AI 定位`。
- **免费节点不出现在这里**：它们不是「我的服务器」，只出现在连接页的节点池里。
- 不做服务器与节点两级：一台服务器对应一个节点，详情里带一行节点信息即可。

## 退出确认

- **`Cmd+Q` 与菜单「退出 Veyl」在任何时候都出现**（路由 `QuitRoute::Menu`），不论是否已连接（2026-11-17 产品决定：退出是常驻菜单栏的应用，用户对「关窗口还是关进程」始终有选择权，不能因为此刻没连接就把这个选择吞掉）。两条例外：
  - 托盘菜单的 `退出`（`QuitRoute::Tray`）**直接退出**，不弹窗——用户是从托盘明确点的「退出」，不是在窗口里按快捷键。
  - 系统注销 / 关机（`QuitRoute::System`）**不被弹窗阻塞**：系统要求退出时直接走退出流程，不拦截。
- 弹窗 420 宽、圆角 14、白底、轻阴影；标题 `退出 Veyl？` 17/600。
- 正文两行，左标签右说明（13/600 标签，72px 固定列宽对齐），**按连接状态取词**：
  - 已连接：`后台运行` — `保持连接`；`退出` — `断开连接并恢复网络设置`
  - 未连接：`后台运行` — `留在菜单栏`；`退出` — `关闭 Veyl`
  - 不再用「……会……」的整句叙述（`docs/design/quit-dialog.md` §3、§6）。未连接时不能照抄「断开连接并恢复网络设置」——那一刻没有连接可断，说了就是假话。
- 按钮：`后台运行`（墨色实心，主，默认焦点）／`退出`（描边，次）；已连接时 `退出` 用描边红字让断网代价可见，未连接时用普通描边。不用系统默认的蓝色实心按钮。
- `Esc`、`×`、点遮罩都等于**取消退出**，回到应用。
- 两个动作都不带感叹号，也不写「确定要退出吗」这类套话。

## 后续清理（验收通过后执行）

这一轮 UI / UX 重构留下了不少被取代的东西：删掉的组件、退场的命令、改过的契约章节。它们不影响功能，但会让后来的人分不清「这是还在用的」还是「忘了删的」。清理是**独立收尾阶段**，与功能修改分开做。

### 触发条件

- 功能开发完成、**真机验收通过之后**才执行。
- **不与功能修改混在同一批提交里**：清理单独成批，出问题能整批回退。

### 范围

| 层 | 清理对象 |
|---|---|
| 前端 | 无引用的组件、hooks、样式段（`.console-*` 这类已删组件的残留要复核）、旧状态字段、只在 mock 里存在的分支 |
| 后端 | 不再被 UI / 工具 / 事件引用的命令、服务方法、迁移兼容代码、只在测试里使用的 helper |
| 契约 | 已被新设计取代但仍留在 `docs/` 的章节（例如已删除工具的残留说明、旧版路由或字段描述） |
| 资源与脚本 | 不再生成的产物、一次性迁移脚本、过期的验收 / 原型文件 |

### 判定标准

1. **全仓无引用**：`src/`、`src-tauri/`、`tests/`、`scripts/`、`docs/` 都搜不到使用点（含动态拼接的名字要人工确认）。
2. **契约与实现一致**：删掉的命令 / 工具 / 事件在契约里也有对应说明，不能只删一侧。
3. **删完测试仍全绿**：`check-contracts` 与既有测试套件都通过。
4. **不确定的不删**：拿不准是否仍在用的，列出来交 PM 决定；不擅自删除可能承载在途需求的东西。

### 不做的事

- 不重命名、不重构、不顺手改行为——**这一阶段只删不加**。
- 不借清理之机调整文案、样式或默认值；发现的问题单独记录，另行派工。

### 执行方式

1. 先出一份**候选删除清单**（路径 + 判定依据 + 引用搜索结果），交 PM。
2. 评审通过后**一次执行**，不零散删。
3. 删组件时**同步删它的 CSS 段与测试**，不留半套。
