## 0. 一句话

新建配置只问两件事——**怎么接管**、**节点从哪来**——然后给一页确认，保存完成。
「所有流量走 VPN / 本国直连」不再属于创建流程，而是控制台顶部、与连接按钮同一处的一个常驻开关。
地区由 AI 在对话里结合系统推断与用户说法决定并写入；判不出就按未知处理，不在界面上追问。

## 2. 目标与非目标

### 2.1 目标

1. 新建只问两件事，答完立刻能确认并保存。
2. 两个问题各自给出「什么场景选它」的完整解释，解释占版面，不做 tooltip、不折叠。
3. 「所有流量走 VPN / 本地直连」变成控制台顶部、与连接按钮同一处的常驻开关，随时可切、立即持久化。
4. 免费节点在池空、离线、内容异常时，创建流程仍能走出去，不卡在第二步。
5. 新建流程只影响新建；界面只展示两档流量范围（智能 / 全局），不出现「指定服务」。
6. 地区 = 系统推断 + AI 在对话中决定并写入；AI 不为了确认而追问；判不出时按「全部走 VPN」并解释。
7. 审视页是一页只读确认：五项事实、名称自动生成、主按钮按连接状态写准（创建并连接 / 创建配置）。

### 2.2 非目标

- 不实现「供应商广场」的购买 / 跳转 / 支付：本批只做静态占位列表（§6.3–6.4）。
- 不在创建流程里改名：名称自动生成、只读，改名属于配置详情（§10.1）。
- 不在创建流程或展示上暴露「只指定服务」（`proxy_selected`）；界面只有智能 / 全局两档，见 §12。
- 不做 IP 定位、不联网判断国家。
- 不做创建时的节点测速或自动挑最快节点。
- 新建配置本身不新增命令、不改 `config_create` 参数；地区链路的命令/工具/事件另计（§14）。
- 不改「改接管方式必须新建配置」这条既有规则。

## 3. 先把三件事分开

这是最容易做歪的地方。用户说的「接管方式」和「全局开关」是**两个正交维度**，节点来源是第三个。

| 用户概念 | 落库字段 | 允许值 | 一句话 |
|---|---|---|---|
| **接管方式** | `connect_mode` | `tun` / `system_proxy` | 谁来接管网络：整台电脑，还是只给代理地址 |
| **流量范围**（全局开关） | `routing_mode` | `proxy_all` / `direct`（`proxy_selected` 只留在数据层，界面不体现） | 接管之后，哪些流量真的进 VPN |
| **节点来源** | `source` / `nodeIds` | `"seed"` / 节点 id 数组 | 用谁家的服务器 |

两条独立轴，任意组合都合法：

| 接管方式 | 流量范围 | 实际结果 |
|---|---|---|
| TUN 模式（`tun`） | 全局（`proxy_all`） | 整台电脑的所有流量都走 VPN |
| TUN 模式（`tun`） | 智能（`direct`） | 本国网站直连，其余走 VPN |
| Proxy 模式（`system_proxy`） | 全局（`proxy_all`） | 能给代理的软件全部走 VPN，其余不变 |
| Proxy 模式（`system_proxy`） | 智能（`direct`） | 能给代理的软件里，本国网站直连、其余走 VPN |

**命名陷阱**：`routing_mode = "direct"` 的意思是「**本国网站直连、其余走 VPN**」，不是「全部直连」。
现有代码与单测都是这个语义（`rules/plan.rs:140-147`、`cn_direct_uses_cn_sets_and_route_local`）。
实现时不要把它映射成别的值。

**「全局」一词有两处**：接管方式的「全部软件」和开关的「全局模式」。
前者说**接管范围**，后者说**流量范围**。界面文案必须让两者不同屏相邻出现时也能分清：
接管方式用「TUN 模式（接管全部流量）」，开关用「全局模式」。**不要**在接管方式里写「全局」。

## 4. 映射表（两问 + 开关 → 现有字段）

### 4.1 用户动作 → 落库

| 用户看到的选择 | 字段 | 值 | 备注 |
|---|---|---|---|
| 接管方式 = TUN 模式（接管全部流量） | `connect_mode` | `"tun"` | 首次连接会请求一次系统授权 |
| 接管方式 = Proxy 模式（只给代理地址） | `connect_mode` | `"system_proxy"` | 需要在软件里填本机代理地址 |
| 节点来源 = Veyl 免费节点 | `source` | `"seed"` | 与 `nodeIds` 互斥 |
| 节点来源 = 其它节点（打开「供应商广场」） | `nodeIds` | `string[]` | 由供应商广场返回（§6.4；本批只展示，拿不到 id） |
| 开关 = 智能模式 | `routing_mode` | `"direct"` | 本国网站直连，其余走 VPN |
| 开关 = 全局模式 | `routing_mode` | `"proxy_all"` | 所有流量走 VPN |
| 名称 | `name` | 默认「配置 N」 | 规则见 §10 |
| 本机代理端口 | — | — | **不落配置**，来自全局设置 `proxy_port` |
| 默认节点 | `current_node_id` | 节点集第一个 | 契约既有行为，`commands.md` §3.2 |
| DNS | `dns` | `{ mode: "auto", local: [], remote: [] }` | 不预填常量，跟随地区 |
| 内网排除 | `tun_excludes` | `[]` | 创建时不问 |

`config_create` 的一次真实调用：

```ts

  name: "配置 1",
  connectMode: "tun",
  routingMode: "direct",
  source: "seed",
});

// Proxy 模式 + 供应商广场（未来页面返回 3 个 id）
config_create({
  name: "配置 1",
  connectMode: "system_proxy",
  routingMode: "direct",
  nodeIds: ["nod_…", "nod_…", "nod_…"],
});
```

### 4.2 展示反向映射

| `routing_mode` | 开关显示 | 辅助说明 |
|---|---|---|
| `proxy_all` | 全局模式 | 所有流量走 VPN。 |
| `direct` | 智能模式 | 本国网站直连，其它走 VPN。 |
| `proxy_selected`（仅旧数据） | **不显示开关** | 旧版本创建的配置，界面不做展示；用户重新建一套即可（§12） |

| `connect_mode` | 左栏标签 | 未连接读数「方式」 |
|---|---|---|
| `tun` | 全部软件 | 接管全部软件 |
| `system_proxy` | 本机代理 | 本机代理 |

> 左栏标签用短词（全部软件 / 本机代理），新建弹窗的选项标题用产品指定的 `TUN 模式` / `Proxy 模式`；
> 两套词指向同一件事，靠 §5.3 的括号解释对齐，不要再造第三套。

**左栏标签只由 `connect_mode` 决定**，不再看 `routing_mode`。今天 `system_proxy + direct` 显示「浏览器」，
是把两个维度揉在一起的残留；改完之后同一个配置不会因为切了一下开关就从「浏览器」变成「本机代理」。

### 5.2 版式规则

- **整卡可点**，不是小圆点可点；命中区 ≥ 64px 高。卡片内 `◉/○` 只是状态标记。
- 标题 15px/500；定位句与场景解释 13px/400 `--ink-2`；补充说明 13px `--ink-3`；组间 24px，卡间 8px。
  逐字的层内分工见 UI 稿 §1.4 / §2.3：标题说选什么，定位句给一句结论，补充说明讲代价与前提。
- 卡内不出现免费节点数量（§6.1）；`预览` 标记表示页面已存在、暂不能购买，不是「即将支持」。
- 解释**常驻在卡里**，不折叠、不挂在 `?` 图标后。用户要在做选择的那一刻读到它。
- 两组之间不画分割线，用 24px 留白分组（`veyl-ui` §3.3）。
- 默认选中：**TUN 模式 + Veyl 免费节点**。理由见 §10.5；两问都可当场改，默认只是少一次点击。
- 键盘：`Tab` 进组，`↑↓` 在组内切换，`Enter` 选中；`Esc` 关闭；焦点环可见
  （`ui-ux-pro-max` · Focus States · High）。
- 顶部两个点表示「第 1 步，共 2 步」，`aria-label="第 1 步，共 2 步"`；第二步是「审视配置」。
  （`ui-ux-pro-max` · Progress Indicators · Medium：多步流程要有进度指示。）

### 5.3 为什么用 Proxy / TUN 这两个词

产品已明确要这两个名字（2026-11-12），本文照办。但它们是一级用户看不懂的工程词，
所以**每个选项标题都带一个中文解释**：`TUN 模式（接管全部流量）`、`Proxy 模式（只给代理地址）`。
标题给懂的人，括号给不懂的人，两行都不省。

`veyl-ui` §6 目前把 `proxy` / `TUN` 列为界面禁词。这两处是产品指定的例外：
**只允许出现在新建配置的选项标题里**，正文、按钮、状态、设置页仍不得使用。
同步 `veyl-ui` 时把这条例外写清楚，不要顺手把禁词规则删掉。

内部讨论、代码注释、契约里的枚举仍是 `system_proxy` / `tun`，映射表（§4）保留两种叫法。

### 5.4 场景解释为什么是这两句

- 每张卡先给一句结论，再展开：`整台电脑都走 VPN。` 之后才列软件。
  顺序反过来（先列软件再总结）会让用户在读完四个名词后还得自己做归纳。
- 「浏览器、聊天、游戏、命令行」列的是**具体软件**，不是「全部流量」这种抽象说法。
  用户判断「我要不要整台电脑走」靠的是这些名词。
- 「第一次连接时，系统会请求一次授权」提前说明 TUN 的系统弹窗，避免用户以为应用坏了。
- 「Proxy 模式」那条必须说清**代价**：要去每个软件里填一次地址。只说「更灵活」等于没说。

## 6. 第 2 问：节点来源

### 6.1 Veyl 免费节点

- 语义：使用 Veyl 从**网络种子源**拉下来的节点池（`seed::source_url()`），创建时 `source: "seed"`
  绑定**当前池里的全部节点**，顺序按池内顺序，`current_node_id` 取第一个。
- **没有随包种子**。随包资源只有 `rules` / `runtime` / `launchd`；种子文件含真实节点密码，
  不能进开源仓库。因此「免费节点」在**首次启动且离线**时必然为空——这不是异常，是设计前提。
- 卡面只写「不用自己准备，先连上再说」；**不显示节点数量**。原因：
  `config_create` 绑定的是池减去用户排除项后的集合（`services.rs:2585-2603`），
  卡面显示的数字可能与实际绑定数不一致，写一个约数只会制造「怎么少了两个」的问题。
- 池的可用性从 `default_profile_status.node_count` 读，**离线、零网络请求**。
  该值 App 启动时已经取过（`App.tsx:254`），弹窗优先复用这份状态；为空时才补一次 `default_profile_status`。
- 对外的名字用「Veyl 免费节点」（2026-11-12 产品拍板）。设置页现有的「测试节点」是同一件事；
  同步文档时统一到这一个是非做不可的事，不能同一个东西两个名字（见 §13）。

### 6.2 池为空 / 拉取失败 / 离线

三种情况归到同一条失败路径，因为它们对用户是同一件事：**现在拿不到免费节点**。

| 情况 | 触发 | 结果 |
|---|---|---|
| 首次启动且离线 | 没有缓存，也没有网络 | 池为空；按「下一步」拉取失败 |
| 池为空 | 有缓存但内容为空 / 被清空 | 同上 |
| 拉取失败 | 断网、超时、上游不可达、内容异常 | 同上 |

原则：**只有用户按「下一步」且选中的是「Veyl 免费节点」、池又为空时才联网**。
打开弹窗、浏览选项都不触发网络请求——默认选中免费节点也不会。

状态机（卡片内部）：

```
idle
  ├──node_count > 0──▶ ready（下一步直接进审视页，不发网络请求）
  └──node_count = 0──▶ empty（下一步按钮文案不变，按下才取）

empty ──按「下一步」──▶ loading ──成功且有节点──▶ ready ──▶ 审视页
                           └──失败（离线 / 内容异常 / 写入失败）──▶ failed

failed ──点「重试」──▶ loading
failed ──改选「其它节点」──▶ 离开免费节点分支
```

`empty` 状态的卡片底部一行 12px `--ink-3`：`还没有免费节点，下一步时会去获取。`

| 状态 | 卡面 / 卡下方反馈 | 「下一步」 |
|---|---|---|
| `empty` | 卡底一行：`还没有免费节点，下一步时会去获取。` | 可用，按下即 `loading` |
| `loading` | 卡下方失败块位置显示 `正在获取免费节点…` + 行内转圈 | 文案变 `正在获取…` 并禁用 |
| `ready` | 无额外文字 | 可用，进入审视页 |
| `failed` | 卡下方失败块：三段式（见下）+ `重试` | 禁用 |

失败块**在第 2 问内、免费节点卡正下方 8px、宽度同卡**；不是 toast、不是弹窗、不是页面级横幅
（UI 稿 §6.1）。只在「Veyl 免费节点」被选中时显示；改选「其它节点」后隐藏，状态保留，切回来还在。

**失败文案（三段式，逐字）**：

> 没能取到免费节点。
> 可能没联网，或免费节点服务暂时不可用。
> 点「重试」；还是不行，就改选「其它节点」。

- 第一段说发生了什么，第二段说可能的原因，第三段说现在做什么。
- 不把契约里的 `offline` / `invalid_content` / `local_write` 暴露成三个不同句子：
  用户能采取的动作是同一个（重试或改选），细分只进日志。
- 「改选其它节点」是**用户自己点**，不做自动跳转、不自动降级成空配置。
- 失败时「下一步」禁用，但弹窗仍可取消、仍可改选另一张卡——不把整条路锁死。
- **本批的「供应商广场」只展示示例、不提供可选节点**，所以这条兜底只能让用户离开失败态，不能替他完成创建。
  这个限制写在 §19 第 1、2 条，文案不假装它是一条能建配置的路。

三条硬约束：

1. **不自动重试**。失败后只在用户点「重试」时再发请求，避免离线时反复打网络。
2. **不自动跳转**。不因为免费节点失败就把用户弹到「供应商广场」页；选择权在用户。
3. **不静默创建空配置**。池为空时绝不退化成「先建一套空配置」，那会让用户以为建好了，连的时候才发现没有节点。

**保存时的兜底**：即使用户看到 `ready`，`config_create` 仍可能因并发或排除项返回
`PRECONDITION_FAILED / seed_unavailable`。此时 UI **只重试一次**：
`default_profile_refresh()` → 成功且有节点 → 重新提交一次 `config_create`；
仍失败 → 停在审视页，行内显示同一条三段式文案，给「重试」与「返回上一步」。

**刷新是全局副作用**：`default_profile_refresh` 会更新整个节点池，可能让其它使用免费节点的配置换节点
（`commands.md` §8.2）。所以只在池为空时触发，**不因为用户选了免费节点就无条件刷新**。
其它配置的变化由既有的 `config-changed(reason = "seed_refreshed")` 提示，不在新建弹窗里重复播报。

### 6.4 接真实供应商后的返回契约

页面真正接入供应商后，它只负责**把节点弄进池并选出这一套要用的节点**，不负责建配置。
本批的静态列表没有返回值；下面是页面落地后的形状，先定住，避免以后改新建流程。

**输入**（前端路由状态，不是命令参数）：

```ts
type VendorPageInput = {
  returnTo: "new-config";
  step: "source";
};
```

**返回**：

```ts
type VendorPageResult =
  | { kind: "nodes"; nodeIds: string[] }   // 至少 1 个
  | { kind: "cancelled" };
```

| 情况 | 新建流程怎么做 |
|---|---|
| 返回 `nodes`（≥1 个） | 回到两问页，「其它节点」保持选中并显示「已选 N 个」；「下一步」可用；审视页只显示数量与第一个节点名 |
| 返回空数组 | 等同于取消，但保留「其它节点」选中：行内一句「还没选到节点」，不新建空配置 |
| 用户取消 / 页面关闭 | 回到两问页，**保留接管方式的选择**；不创建任何配置；页内已导入的节点留在池里（见 §19） |
| 页面内部报错 | 错误留在那个页面里；新建流程不感知。页面崩溃/被系统关闭按「取消」处理 |
| 保存时节点已被删 | `config_create` 返回 `NOT_FOUND` 并列出无效 id → 回到两问页、选中「其它节点」，提示「有 N 个节点已经不在了，重新选一次」；**不静默丢弃** |

**为什么返回节点 id，而不是配置 id**：
「接管方式」和「流量范围」是这一屏问的，如果供应商页面返回一个已经建好的配置，这两问的答案要么被丢弃，
要么得作为参数传进那个页面——同一个决定就有了两个主人。返回 id 让建配置仍然只有一处。

**为什么节点顺序就是顺序**：`config_create` 的 `nodeIds` 顺序即节点顺序，第一个成为当前节点
（`commands.md` §3.2）。页面返回的顺序就是用户看到的顺序，新建流程不重排。

## 8. 常驻开关：流量范围

### 8.1 它是什么 / 不是什么

- 是：**当前配置**的 `routing_mode` 的两态控制（`direct` ↔ `proxy_all`），写库并持久化。
- 不是：跨配置的全局设置。切换配置时，开关显示那套配置自己的模式。
  界面上叫「全局模式」，指的是**流量范围是全部**，不是「影响所有配置」。
- 不是创建流程的一部分：新建时只按地区给默认值（§10.5），创建后在控制台切。

### 8.2 位置

放在**控制台 hero 内部**，与「启动 VPN / 断开 VPN」同一个视觉块：状态在主行，开关在第二行。

```
┌──────────────────────────────────────────────────┐
│  已连接  12:41:07                 [ 断开 VPN ]    │  ← hero 主行
│  流量范围  [ 智能模式 | 全局模式 ]                 │  ← hero 第二行（新增）
│  国内网站直连，其它走 VPN。                        │
└──────────────────────────────────────────────────┘
│  流量 1.2 MB/s   延迟 42 ms   出口 203.0.113.7    │  ← 读数
│  ┌────────────────────────────────────────────┐  │
│  │ AI 编排区                                   │  │
│  └────────────────────────────────────────────┘  │
│  节点卡 …                                         │
└──────────────────────────────────────────────────┘
```

- **不新起一行、不新起一块**：它就是 hero 的第二行，和连接按钮同属一个控制区。
  这样「连不连」和「连上之后哪些走」在同一个地方回答。
- 固定骨架的一部分，**不在 AI 编排区里**：AI 不能移动、删除、替换它。
- 未连接时同样显示；此时读数区里的「范围」一行**删除**——同一个事实不能有两个住处。
- 没有配置时整块不显示（没有 hero 可控制）。
- 连接中 / 断开中禁用（`transitioning`、`stopping`），避免和建连抢状态。

### 8.3 各状态的文案

| 当前 `routing_mode` | 控件 | 右侧说明 |
|---|---|---|
| `direct` 且地区 = `cn` | `[ 智能模式 ] 全局模式` | `国内网站直连，其它走 VPN。` |
| `direct` 且地区为其它已知 `cc` | `[ 智能模式 ] 全局模式` | `本国网站直连，其它走 VPN。` |
| `direct` 且地区未知 | `智能模式` 选中 | `没识别出你在哪个地区，现在所有网站都会走 VPN。` |
| `proxy_all` | `智能模式 [ 全局模式 ]` | `所有流量走 VPN。` |

- 只有两档：**智能 / 全局**。没有第三段「指定服务」，也没有它的编辑入口。
- 旧数据里的 `proxy_selected` 不显示开关（§19.7）；本批不做展示、不做迁移。

- 未连接时，说明末尾追加 `连接后生效。`；已连接时不加——热切已经生效。
- 地区未知的提示**必须出现**：这时候「智能模式」的行为和字面意思相反，
  不说清楚就是让用户以为本地网站还在直连。提示用 `--ink-2` 正文，不用红色——
  它不是故障，是一个需要解释的降级。
- 已连接时以 `route_get.applied_region` 为准，未连接时用 `detected_region`；
  两者都是 `null` 才算未知（`commands.md` §10.1）。

### 8.4 交互与重连

| 情况 | 行为 |
|---|---|
| 未连接 | `route_set_mode { mode }` 只写库；`effective = "next_connection"`；说明行显示「连接后生效」 |
| 已连接，`direct` ↔ `proxy_all` | 走 Clash API 热切，`hot_switched = true`；**不断开、不确认**；说明行立即更新 |
| 同一模式 | 幂等，不写库、不发事件 |
| 切换请求报错（没有产生变更） | 控件回到原值，行内一句「没切成功，还是原来的范围。」；不弹 toast |
| 切换成功但重连失败（`reconnect = "reconnect_failed"`） | **不回退控件**：范围已经改了，失败的是重连。按既有失败态显示 hero 与错误信息，不另说「没切成功」 |
| 地区被 AI 修改（`region-changed`） | 未连接：下次连接直接按新地区生成；已连接：**不自动重连**，说明行追加「地区已改，下次连接生效」；已连接时仍以 `applied_region` 显示 |
| AI 通过 `RouteSetMode` 改了 | 订阅 `routing-changed`，按事件里的 `routing_mode` 更新控件；**不做本地乐观状态**，避免与 AI 打架 |

### 8.5 与状态区的关系

- **不复制连接状态**：hero 说连没连、通不通；开关只说流量范围。两者相邻但各说一件事。
- **不新增第二个主按钮**：开关是分段控件，不是实心按钮；主按钮永远只有 hero 那一个（`veyl-ui` §2.1）。
- **已连接但不通**（`dataPlaneDown`）时开关仍可用：换范围可能正是排障手段之一，不因故障禁用。
- **失败态**下开关仍显示、仍可改；下次连接生效。

## 9. 地区：系统推断 + AI 决定

### 9.1 现状与问题

- `detect_region()` 只看 `VEYL_REGION` → 系统时区 → 系统区域 → `LANG` → 未知（`rules/mod.rs:138-200`），
  **没有任何用户明示的入口**。
- GUI 环境里 `LANG` 常是 `en_US.UTF-8` 或缺失：中国用户会被判成美国，非中国用户也可能判错。
- 四个入口（建连、测速、`route_get`、`system_region`）直接读这个函数，没有一个可被用户修正的共享值。

### 9.2 新的地区链路

```
系统推断（时区 / 区域 / LANG） ──▶ 基线
        │
        ▼
AI 在对话里决定（系统推断 + 用户说法；判不出按未知）
        │
        ▼
SetUserRegion 写入 settings.user_region
        │
        ▼
effective_region(store) ──▶ 建连 / 测速 / route_get / system_region / 新建默认值
```

- **没有 UI 控件**：新建审视页、设置页都不提供地区选择；审视页只有一行只读展示（§7）。
  用户要改，只能在对话里说，AI 写入。
- `system_region` 保留只读，给界面展示与默认值；它不写库。

`effective_region` 的优先级：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | `VEYL_REGION` | 测试/开发覆盖，保持最高 |
| 2 | `settings.user_region` | AI 决定并写入的地区；写入后压过系统推断 |
| 3 | 系统推断（时区 → 区域 → `LANG`） | 没有 AI 写入值时使用 |
| 4 | 未知 | 全代理 + 解释 |

- **四个入口改成读同一个 `effective_region`**，不再各自 `detect_region()`。
- `system_region` 返回 `{ region, source: "system" | "ai" }`：`region` 是生效值，`source` 说明它来自 AI 写入还是系统推断。
- `route_get.detected_region` 也返回生效值；`applied_region` 仍是建连时的快照。
- 已连接时改地区**不自动重连**：说明行提示「地区已改，下次连接生效」（§8.4）。

### 9.3 AI 怎么决定

AI 结合**系统推断**与**对话内容**自行决定，不为了确认而追问用户。

| 情况 | 行为 |
|---|---|
| 用户在对话里明确说过国家/地区 | 以用户为准；调用 `SetUserRegion` 写入，覆盖系统推断 |
| 用户没说过、系统推断有值 | 用系统推断；AI 可以写入，也可以不写（不写就走实时系统值） |
| 用户没说过、系统也判不出 | 不写入；按未知处理（全部走 VPN + 解释），**不追问** |
| 用户之后纠正（「我在日本」） | 调用 `SetUserRegion`，写入并生效于下次连接 |

- **不追问**：提示词禁止为了确认地区单独发问。地区不是创建流程的问题，AI 不该为了它多开一轮。
- **用户明示优先**：用户说的与系统不一致时，以用户为准。
- **AI 未配置**：没有 `SetUserRegion`，`effective_region` 就是系统推断；界面没有替代入口。
  这是产品明确选择的方向，限制见 §19.3。

提示词（追加到系统提示）：

```
用户所在/常用地区：<label>（来源：系统推断 / AI 先前写入）。
系统原始推断：<system_label 或 未知>。
结合系统推断和对话内容决定地区：用户明确说过就以用户为准；
没说过就用当前生效值（AI 先前写入的优先，没有就用系统推断）；
系统也判不出就按未知处理（全部走 VPN）。
不要为了确认地区而追问用户。
只有对这个值有把握时才调用 SetUserRegion 写入；写入后会固定下来，
不再跟随系统时区变化。没把握就不写，继续用系统推断。
```

这段由 Host 每轮注入，`<label>` 取自 `effective_region`，`<system_label>` 取自系统推断；
AI 不自己读系统时区，也不自己查 IP。

### 9.4 契约与存储

| 项 | 形状 | 说明 |
|---|---|---|
| 设置键 `user_region` | `settings` KV，小写 cc | 不存在 = 没有 AI 写入值 |
| `system_region` | `{} → { region: string \| null, source: "system" \| "ai" }` | 只读；返回生效值与来源 |
| AI 工具 `SetUserRegion` | `{ region: string } → { region, source: "ai" }` | `PermissionLevel::Write`；唯一写入路径 |
| 事件 `region-changed` | `{ region, source, emitted_at }` | UI 同步开关与所有地区展示 |

- **没有 `region_preference` 命令**：UI 没有地区入口，也就不存在 UI 写入路径。
- `SetUserRegion` 校验：两字母 ISO 码，规范化成小写；`cn` 走 `Region::Cn`；非法 → `INVALID_ARGUMENT / invalid_region`。
- `user_region` 缺失、空串或非法（旧数据/手改库）一律按「没有 AI 写入值」处理，回落到系统推断，不报错。
- **没有清除动作**：本批不提供「恢复系统推断」的 UI 或工具；用户换地区时直接说新的，AI 覆盖即可。
- `SetUserRegion` 的展示：成功 `text = "地区已记下"`、`changed = "none"`（只改地区设置，不改配置/连接）、
  `facts = ["中国大陆"]` 这类地区名；失败 `text = "没能记下地区"`。不把来源（系统/AI）念给用户。

### 9.5 生成侧不变

| 地区 | 本地直连层 | 本地 DNS |
|---|---|---|
| `cn` | `geosite-cn` + `geoip-cn` | `223.5.5.5` / `119.29.29.29` |
| 其它已知 `cc` | `geoip-<cc>` | `1.1.1.1` / `8.8.8.8` |
| 未知 | **没有本地层**，除内网外全部走代理 | `1.1.1.1` / `8.8.8.8` |

证据：`rules/plan.rs:101-110`（`Unknown` 不再回落 `cn`）、`:140-147`、`:151-162`。
本次只改「地区从哪来」，不改「地区怎么用」；`local_layer` / `dns_servers` 不动。

### 9.6 「判不出地区」怎么解释

这是「智能」二字的字面反例：智能模式会变成「所有网站都走 VPN」。三处必须一致：

| 位置 | 文案 |
|---|---|
| 控制台开关右侧（地区未知 + 智能模式） | `没识别出你在哪个地区，现在所有网站都会走 VPN。` |
| 审视页（未知地区时默认就是全局模式） | `没识别出你在哪个地区，所以按全局模式创建；之后可以在控制台切换。` |
| 中间区原有那行直连口径（`middleArea.ts`） | 保持 `没识别出你在哪个地区，所有网站都走 VPN`，不另起一句 |

**默认值配合**：地区未知时，新建配置的 `routing_mode` 默认 `proxy_all`（沿用旧表单的地区默认规则），
不让用户进一个名字叫「智能」、行为却是「全局」的模式。用户之后手动切到智能，才出现上面那条提示。

**已知地区但规则包缺失的情况不解释**：`local_direct_basis` 只按地区取值（CN = 域名+IP、其它已知 = 仅 IP、未知 = `none`），
没有「规则集缺失」这个独立来源，界面无法可靠判定。**宁可不提示，也不写一句判不出来的话**；这类降级只进日志。
本节只处理「地区未知」这一种用户能理解、也能自己切换的情况。

### 9.7 迁移

- 没有 `user_region` 的老用户：继续按系统推断，行为与今天一致；不弹一次性提示。
- AI 第一次决定并写入后，系统时区变了也不覆盖；用户之后说出新地区，AI 覆盖。
- `VEYL_REGION` 仍压过一切，供测试与开发。

## 10. 默认值规则

### 10.1 名字

- 规则：**「配置 N」**，N 从 1 开始取当前未被占用的最小整数（`配置 1`、`配置 2`……）。
- **不带模式、不带节点来源**。理由：
  1. 左栏行已经显示接管方式（`全部软件` / `本机代理`）和节点数，名字再重复一次就有两个住处；
  2. 名字一旦带 `接管全部`，用户之后改流量范围（开关）时它不会跟着变，马上变成假话；
  3. 节点来源在节点面板里看得到，不需要占用名字。
- 名字自动生成、审视页只读（§7）；改名在配置详情里做，本批没有入口（§19.5）。
- 现有 `model.ts` 的 `公司 · 接管全部` / `公司 · 本机代理` 停止使用；`uniqueConfigName` 的
  `"配置" + " 2"` 形式也不适合，换成上面的「最小可用整数」。

### 10.2 端口

- **创建流程不产生、不询问端口**。`listenPort` 已从 `config_create` 移除（2.12.0），
  端口唯一来源是全局设置 `proxy_port`（`proxy_port_get` / `proxy_port_set`，§7.11）。
- 创建流程不显示端口：地址与端口的唯一住处是设置 → 连接（`veyl-ui` §2.2）。
  连接时若端口被占用，由运行时的 `port_fallback` 处理，不在创建时预检。

### 10.3 默认节点

- 免费节点：按池内顺序绑定全部节点，当前节点 = 第一个。
- 供应商广场：按页面返回顺序绑定，当前节点 = 第一个。
- **创建时不测速、不按延迟排序**：测速要联网、要时间，会把「两问就建好」变成等待；
  选完后节点面板里随时能测、能换（`node_probe_all`）。

### 10.4 DNS 与内网排除

- `dns`: `{ mode: "auto", local: [], remote: [] }`，不写常量，跟随连接时的地区。
- `tun_excludes`: `[]`；只在设置的高级项里改，不进创建流程。

### 10.5 默认接管方式与默认流量范围

| 项 | 默认 | 理由 |
|---|---|---|
| 接管方式 | `TUN 模式`（`tun`） | 旧表单默认也是 `tun`（组件已删除）；这是多数一级用户的目标 |
| 节点来源 | `Veyl 免费节点` | 最低门槛，先把「能连上」跑通 |
| 地区 | `effective_region(store)`；未知为 `null` | 系统推断或 AI 写入值；未知时按全代理 |
| 流量范围 | 地区已知 → `direct`；未知 → `proxy_all` | 沿用现有地区逻辑；未知时不制造「名不副实」的智能模式 |

默认值只是**少一次点击**，不是记忆上次选择：每次打开都回到这组默认。
「记住上次选了什么」会让第二次创建变成一个看不见的决定。

**新配置不继承当前配置的流量范围**：即使控制台此刻是「全局模式」，新配置仍按地区给默认值。
新建是一套新方案，不是复制当前方案；复制会让「我刚才明明选的是智能」和实际不一致。
用户保存后想改成全局，在控制台一次点击即可（§8）。

| 设置 → 高级「免费节点 · 检查更新」 | **同一个命令，两个用途**：设置页是完整五态 + 结果播报；新建弹窗只在池空时静默调用，只区分成功/失败，**不复述「已是最新」「已更新 N 个」**。同一个事实不在两处播报。设置页现有文案「测试节点」需要与本页统一（§13） |

### 11.2 AI 路径：带选项提问的「解释这个设置的含义」

AI 新建走对话，问题以带选项的卡片出现。卡片只有选项按钮时，「点了就选」没有任何解释价值；
所以每张**带选项**的卡片底部多一行固定文字按钮，回传的答案逐字是：

```
解释这个设置的含义
```

**它不是选择。** 收到这串字时：

| 不许 | 必须 |
|---|---|
| 推进流程、记成同意、当成沉默或跳过、调用 `ConfigCreate` | 用三句话回答，然后**把同一个问题逐字再问一次，选项不变** |

三句话（各占一行，总共最多 4 行）：

1. 每个选项选下去实际会发生什么（用户语言，不上术语）；
2. 什么情况下该选哪个（给判断依据；可以说选项名让用户对得上，但不整段复述原文）；
3. 选错了以后怎么改回来（改哪里、要不要重建）。

**它不是节点来源同意**：后端 `grants_seed_consent` 只认逐字等于 `Veyl 免费节点（仅供试用）` 的回答
（`questions.rs:69`）。用户看完解释仍要自己点那一项，免费节点才被授权。

**协议不变**：回答仍是任意非空文本（`commands.md` §9.6），没有新增字段、没有新事件，**不升 commands 版本**。
这一串字只是提示词里的保留值，Host 不解析；卡片上的那一行由前端加（`AskQuestionCard`），
模型不得自己把它写进 `options`——它是界面固定行，不是选项。

**Host 门禁**：Host 在本请求内记录「收到过解释串」，期间 `ConfigCreate` 回
`PRECONDITION_FAILED / explanation_pending`（`tools.md` 3.10.1 §4.24）；用户任意其它回答即清除该标记。
这样即使模型把解释误当确认，也建不出配置。

自由提问（无选项）没有这一行；用户打什么字就是什么，不做解释约定。

**确认卡例外**：确认卡（`创建` / `取消`，旧路径 `开始配置` / `取消`）没有设置可解释，界面不显示这一行。
判定口径与取消类词表以 `tool-display.md` §3.5 为准（两个选项、其中一个整串等于词表项）；下文不再重复词表。
如果用户在确认卡上手打这串字（输入框作答与点按钮在文本上无法区分）：不套三句模板，只用一句说清
「创建会做什么、取消会怎样」，然后重问同一个确认问题、选项不变。同一个请求里第三次收到解释串时，
不再展开三句，只说明「已经解释过两次，直接选一个就行」并请用户选择或跳过。

发这两问之前，AI 还各先说一句「这一问决定什么」，例如：
「这一步决定是只有浏览器走 VPN，还是聊天、会议、游戏这些软件也一起走。」卡片没有上下文，这一句就是上下文。
**只限这两张设置卡**：确认卡前已有复述，解释后的重问已有那三句解释，都不再加这一句。

## 12. `proxy_selected`：创建与展示都不出现

- **创建收紧为两档**：`routing_mode` 只接受 `direct` / `proxy_all`。
  `config_create`、`ConfigCreate`、`config_update`、`ConfigUpdate`、`RouteSetMode` 的枚举都收紧；
  传 `proxy_selected` → `INVALID_ARGUMENT / routing_mode_not_supported`（**已知但已下线的值**）；
  传其它任意字符串仍是 `invalid_routing_mode`（**不认识的值**）。这是**破坏性变更**，changelog 写明不向后兼容。
- **展示只有两态**：开关不渲染第三段，也没有「指定服务」的说明、编辑入口或相关文案。
- **不再依赖** `route_targets_set` 的编辑浮层；`category_list` 仍是独立命令（别处可能使用），但本功能不接。
- **不做老配置迁移/兼容分支**。数据层保留 `proxy_selected` 枚举与旧数据（避免破坏性 SQL 迁移），
  但不再产生新值；前端遇到旧值时开关不显示，用户重新建一套即可（§19.7）。
- 验收从头开始，只覆盖新建的两档；不为旧配置写用例。

| # | 用户/PM 的说法 | 本文用法 | 为什么 |
|---|---|---|---|
| 1 | `Proxy 模式` / `TUN 模式` | 原词 + 括号解释：`Proxy 模式（只给代理地址）` / `TUN 模式（接管全部流量）` | 产品已拍板用这两个词（2026-11-12）。`veyl-ui` §6 的禁词规则要为选项标题开例外；括号保证一级用户看得懂 |

| 3 | `本国直连` | `cn → 国内网站直连；其它地区 → 本国网站直连` | 「本国」= AI 写入或系统推断的那个国家/地区（§9），不是物理位置；与用户原话一致，也与中间区现有文案一致 |
| 4 | `全局开关` | 控件名 `流量范围`，选项 `智能模式 / 全局模式` | 「全局」与接管方式的「全部软件」只差一个字，同屏会混。控件名说维度，选项名说取值 |
| 5 | 开关是「全局」 | 实际是**当前配置**的 `routing_mode` | 数据模型就是每套配置一份；做成真全局需要新设置字段与迁移，且与 `route_set_mode` 的语义冲突。界面上用「全局模式」表达「全部流量」，不表达「所有配置」 |

第 1、2 条不再是待定项：按产品原词落地。需要同步的是 `veyl-ui` §6 的例外条款与设置页的三处旧文案，
不是把这两个词偷偷换掉。

```ts
// 传其它非法字符串 → invalid_routing_mode（不认识）
// 没有 region_preference 命令：地区没有 UI 写入路径

// commands.md §3.2：节点来源必填（schema anyOf）
config_create：source: "seed" 或非空 nodeIds，至少一个
// 都缺 / source: "empty" / nodeIds: [] → INVALID_ARGUMENT / source_required
// ConfigCreate 同步：enum 只有 seed、node_ids minItems 1、anyOf 二选一

// tools.md §4.47（新增）
SetUserRegion { region: string } → { region: string, source: "ai" }
// PermissionLevel::Write；唯一写入路径；ConfigCreate / ConfigUpdate / RouteSetMode 同步只收两档

// events.md §4.21（新增，事件表 #25）
region-changed { region: string | null, source: "system" | "ai", emitted_at }
```

**破坏性项（changelog 必须写明「不向后兼容」）**：

1. `config_create` / `config_update` / `route_set_mode` 不再接受 `proxy_selected`；
2. `ConfigCreate` / `ConfigUpdate` / `RouteSetMode` 三个 AI 工具同步不再接受 `proxy_selected`；
3. `system_region` 的返回从 `{ region }` 变成 `{ region, source }`（前端绑定同步改）。
4. `config_create` 必须带节点来源（`source: "seed"` 或非空 `nodeIds`），`source: "empty"` 与空数组被拒；
   `ConfigCreate` 同步（`source_required`）。界面与 AI 都不再能创建空配置。

> `ConfigSummary` / `RouteState` 的**返回类型**可以继续保留三值（旧行还可能读出来），
> 但前端的 `ConfigRouteMode` 收成两值，遇到 `proxy_selected` 时开关不显示；
> 「创建/更新不接受」与「读取时兼容旧值」是两件事，不要混。

**不新增「一步创建」命令**：审视页没有收集任何新字段，它就是一次 `config_create`。
再造一个 `config_create_simple` 会把校验、重名、激活规则复制一份，早晚 diverges。

**实现侧的缺口是 binding**：`bridge.ts` 需要补 `routeGet` / `routeSetMode` 两条绑定，
并把 `systemRegion` 从 `Promise<string | null>` 改成带 `source` 的对象。
`categoryList` / `proxyPortGet` / `defaultProfileStatus` / `defaultProfileRefresh` 已经接好；
`routeTargetsSet` 不再是本功能的依赖。

## 18. 不做的事

- 本批「供应商广场」只做静态预览：不做筛选、不做购买、不做跳转、不做导入。
- 不在免费节点失败时自动跳转、自动重试、自动降级成空配置。
- 不把地区做成纯 AI 猜测：系统推断是基线，用户明示优先；AI 不为了确认而追问。
- 不在界面上提供任何地区控件：没有选择器、没有「对 / 不对」、没有设置项；审视页那行地区只是只读展示（§7）。
- 不在创建流程里问 DNS、端口、内网排除、节点测速。
- 界面不出现「指定服务」；数据层保留旧值，但不再产生、不再展示。
- 不做「记住上次选择」或「按上次的默认高亮」。
- 不让 AI 替用户点这个弹窗；AI 仍走工具建配置，地区由 AI 在对话里决定。
- 不让 AI 或界面创建空配置：`ConfigCreate` 与 `config_create` 都必须带来源（`source: "seed"` 或非空 `nodeIds`），
  都缺、`source: "empty"`、空数组一律 `INVALID_ARGUMENT / source_required`（`commands.md` §3.2、`tools.md` §4.24）。
- 不按服务挑选：写入只有 `direct` / `proxy_all` 两档，`proxy_selected` 已下线；用户要「只有几个服务走 VPN」时如实说暂不支持。
- 不改「改接管方式必须新建配置」。
- 不在弹窗里播报免费节点刷新对其它配置的影响（那是设置页/左栏的事）。

## 19. 已知限制与待确认

1. **首次启动且离线时无法新建配置**。没有随包种子（种子含真实密码，不进开源仓库），免费节点必须联网拉取；
   本批「供应商广场」只是静态预览，拿不到节点。此时失败文案给重试，用户只能重试或取消，
   **没有任何节点来源可完成创建**。应用其余部分不受影响；联网后重试即可。这是本批最硬的一条限制。
2. **本批「供应商广场」不能生成配置**。它是静态预览：没有筛选、没有真实供应商、没有购买、没有跳转。
   需要自带节点的用户必须等页面接入真实供应商，或先用免费节点建一套。
3. **地区没有 UI 纠错入口，也不能「恢复跟随系统」**。地区只由 AI 在对话里决定并写入 `user_region`；
   AI 未配置、判断错误或用户没在对话里说，界面都无法改。用户只能在对话里纠正，AI 再调 `SetUserRegion`。
   这是产品明确选择的方向，不是遗漏。
4. **地区决策是提示词约束，不是 Host 强制**。`SetUserRegion` 无法判断模型是否真的结合了系统推断与对话；
   Host 只能在工具描述与提示词里约束，验收靠对话人工检查（N18 / N22）。
5. **改名没有界面**。名称在新建时自动生成、审视页只读；`config_update` 支持改名，但入口计划放在配置详情，
   本批不做。用户要改名只能等那个入口，或删掉重建。
6. **开关是每配置一份**。用户切换左栏配置时，开关会跟着变；这是数据模型决定的，不是「全局记忆」。
   如果产品要的是跨配置的全局默认，需要新增设置字段与迁移，属于另一份需求。
7. **旧数据里的 `proxy_selected` 不在新 UI 的展示范围**。数据层可以保留这个值（避免破坏性迁移），
   但开关只渲染 `direct` / `proxy_all`；遇到 `proxy_selected` 的配置时开关不显示，用户重新建一套即可。
   本批不做迁移、不做兼容分支。
8. **地区是一台机器一份**。没有多用户/多账户概念；换系统账户或共享机器时，AI 写入值跟着走。
   这与现有 `settings` 表的粒度一致，不另做。
