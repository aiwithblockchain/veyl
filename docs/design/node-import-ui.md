# 节点写入：手动添加节点的界面

> 日期：2026-11-24
> 状态：**已实现**（2026-11-25）。
> 上游：`docs/contracts/tools.md` 3.28.0 的 `NodeImport`；`docs/design/ai-tools-decisions.md` §2；`docs/design/create-config.md`。
> 界面规范：`veyl-ui` §2.1 / §3.2 / §3.3 / §6；表单交互依据 `ui-ux-pro-max` Forms：Error Placement（错误贴字段 + `aria-describedby`）、Inline Validation（失焦即校验）、Error Messages（`role="alert"`）。

---

## 0. 结论摘要

`NodeImport` 工具有三种来源（`url` / `text` / `manual`），界面上只覆盖了前两种加文件导入，**`manual` 完全没有界面**。本次补齐，并把手动入口放到节点真正被使用的地方。

**拍板结果**

1. **入口只在控制台底部的「节点」卡**：标题下的计数行右侧新增文字按钮 `添加节点`。设置 › 连接 里原来的「添加节点」行与弹层整段移除，一个动作只有一个住处。
2. **同一个弹层，两段切换**：`链接 / 订阅` 与 `手动填写`。链接段保留现有的粘贴与文件导入，行为不变。
3. **手动表单五项**：节点名、地址、端口、加密方式、密码。节点名必填。
4. **只用现有 `node_create`**：不改 Host、不改契约、不改 AI 工具面。

---

## 1. 事实：AI 有什么，界面有什么

| 写入路径 | AI 工具 | Host 命令 | 本次之前 | 本次之后 |
|---|---|---|---|---|
| 订阅 URL | `NodeImport(source="url")` | `node_import_url` | 有（设置 › 连接） | 有（节点卡 › 添加节点 › 链接） |
| 粘贴 `ss://` 文本 | `NodeImport(source="text")` | `node_import_text` | 有（同上，自动判断） | 有（同上） |
| 选文件导入 | 无 | `node_import_file` | 有 | 有（链接段内的次按钮） |
| 手动逐项创建 | `NodeImport(source="manual")` | `node_create` | **无** | **有（手动段）** |
| 拉取免费节点 | `CatalogRefresh` | `catalog_refresh` | 有（连接页） | 不变 |

补充事实（实现时按这些走）：

1. `node_create` 在 `src/agent/bridge.ts:1082` 有声明，`tauriBridge.ts:1368` 与 `mockAgent.ts:2179` 都有实现；Host 侧命令在 `src-tauri/src/agent/commands.rs:1714`。
2. `node_create` 省略 `configId` 时与导入一致：绑定全局配置，池空时懒创建（`services.rs` 的 `import_target`）。命令层支持零配置；界面在主界面走节点卡，在**零节点空态**（`StartChoice` / `TrialExpired`）另有一行 `已有自己的节点？手动添加`，打开同一个弹层——空态没有节点卡，这一行是它唯一的入口。
3. 节点进的是同一个全局节点池；Host 成功后会发 `node-list-changed`，`useVpnSession` 收到后自动重拉，节点卡无需额外同步。
4. 密码只进本地加密文件，`node_create` 的返回值不含密码。

## 2. 拍板结论

| # | 问题 | 结论 |
|---|---|---|
| D1 | 入口放哪 | **只放控制台节点卡**（`stage-card__subrow` 右侧，`测速` 之后）。设置 › 连接 的「添加节点」行与弹层删除。节点组 destination 未来落地时，组详情的添加入口复用同一个弹层。 |
| D2 | 与现有导入区的关系 | **同一个弹层的两种输入形态**，顶部分段切换：`链接 / 订阅` \| `手动填写`。文件导入留在链接段，不单独占一段。切换段不销毁已输入内容。 |
| D3 | 字段与校验 | 五项：`节点名`（必填，≤64 字）、`地址`（必填，≤253 字，域名或 IP，不带协议、不含空白与斜杠）、`端口`（1–65535 整数）、`加密方式`（原生下拉，取 `SUPPORTED_METHODS` 11 项，默认 `aes-256-gcm`；`2022-blake3-*` 的密码须是 16 / 32 字节 base64 密钥）、`密码`（必填，≤256 字）。 |
| D4 | 密码的落点与回显 | `type="password"`，**不做「显示密码」开关**；不落盘、不进日志、返回值不回显。本期没有编辑态，所以不存在「留空表示不修改」。 |
| D5 | 重复节点 | **提交前不预检**，与 `node_create` 的 `skip_duplicates = false` 一致。已知不一致：链接/订阅导入会跳过重复，手动添加不会；统一去重留到后续，不在本次改 Host。 |
| D6 | 建完之后做什么 | **只进节点池**：不切换当前节点、不连接、不设为当前。与现有导入一致。 |
| D7 | 编辑与删除 | 本期只做新建。改名字/地址、改凭据仍是另一条设计。 |

## 3. 界面设计

### 3.1 入口：节点卡

位置：`ConnectionStage` 节点卡（`.stage-card`）标题下的计数行，右侧动作区。

```
节点
12 个节点                         测速  添加节点
```

- `添加节点` 与 `测速` 同一套文字按钮样式（13px / 500 / `--link`），**不是第二个实心按钮**；主界面唯一实心按钮仍是 hero 的连接按钮。
- 没有节点时也显示；此时 `测速` 按现有逻辑隐藏，`添加节点` 保留。
- **零节点空态**（`StartChoice` 的「新建节点 / 先试用免费节点」与 `TrialExpired`）：没有节点卡，各自在底部加一行 `已有自己的节点？手动添加`（13px / 500 / `--link`），打开同一个弹层。主界面仍然只有节点卡一个入口，空态这一行是等效入口，不构成同一屏的第二个。
- 可访问名就是 `添加节点`；键盘 focus 描边沿用现有文字按钮样式。

### 3.2 弹层结构

- 沿用现有 modal 骨架：遮罩 + `role="dialog"` + `aria-modal="true"` + 标题 `添加节点` + 右上关闭。
- 宽度 `min(460px, calc(100vw - 48px))`，最大高度沿用 `.modal` 的 `min(86vh, 780px)` 并可滚动。
- 标题下一行说明按段切换：链接段是 `支持多行 ss:// 链接或 https 订阅地址；文件里的节点密码不要外传。`；手动段是 `在服务商后台找到地址、端口、加密方式和密码；密码只保存在本机。`
- 再下一行是分段控件（复用 `.settings-seg`，`role="group"` + `aria-pressed`）：

```
[ 链接 / 订阅 ] [ 手动填写 ]
```

#### 链接 / 订阅段（现有行为不变）

1. 多行文本框（`aria-label` 沿用「节点链接或订阅地址」），自动判断 https 订阅与 `ss://` 文本。
2. `从文件导入` 次按钮；选中文件后显示文件名，并提供 `重新选择` / `改用文本`。
3. 主按钮文案：文本 `添加`、订阅 `导入`、文件 `导入`；忙碌文案沿用现有的 `正在添加…` / `正在获取…` / `正在导入…`。
4. 结果、跳过原因、错误提示原样保留。

#### 手动填写段

```
节点名
[ 东京 01                    ]

地址                          端口
[ example.com 或 1.2.3.4 ]    [ 8388 ]

加密方式
[ aes-256-gcm              ▾ ]

密码
[ ••••••••                  ]

                        [ 取消 ] [ 添加节点 ]
```

- 字段纵向排列；`地址` 与 `端口` 同一行，地址自适应，端口固定 110px。
- 标签 12px / `--ink-3`；输入高 34px，边框与 `设置 › 连接` 的输入一致（`--line-strong`，focus 用 `--link`）。
- 占位符只做示例，不替代标签。
- 主按钮 `添加节点`；提交中禁用并 `aria-busy="true"`，文案 `正在添加…`。
- 每个字段的错误紧贴字段下方（12px / `--err-text`），并用 `aria-describedby` 关联；错误容器 `role="alert"`。
- 表单级错误（后端返回且无法归到某一字段）放在字段组下方，同样 `role="alert"`。

### 3.3 校验

客户端先校验，全部通过才发命令。提交时如果有多处错误，聚焦第一个错误字段；字段内容变化即清掉该字段错误，失焦时补一次校验。

| 字段 | 规则 | 文案（中文） |
|---|---|---|
| 节点名 | 必填，≤64 字 | `填一个节点名，方便在列表里认出它。` / `节点名最多 64 个字符。` |
| 地址 | 必填，≤253 字节；不含 `://`、空白、`/`、`\`；带端口（`host:port`）单独报错，裸 IPv6 例外 | `填服务器的地址。` / `地址只填域名或 IP，不要带 https://。` / `地址里不要带端口，端口填在右边的端口栏。` / `地址最多 253 个字符，检查一下有没有多贴了内容。` |
| 端口 | 必填，整数 1–65535 | `端口要填 1–65535 之间的整数。` |
| 加密方式 | 下拉内建，无需校验 | — |
| 密码 | 必填，≤256 字 | `填连接密码。` / `密码最多 256 个字符。` |

后端兜底：

- `details.reason === "unsupported_method"` → 归到 `加密方式` 字段。
- 其它 `INVALID_ARGUMENT` → 表单底部 `没有添加成功，检查地址后再试。`
- 网络/未知错误 → `errorText` 的通用兜底。

### 3.4 提交与结果

```
bridge.nodeCreate({ name, server, port: Number(port), method, password })
```

- **省略 `configId`**：绑定全局配置，池空时由 Host 懒创建。
- 成功：关闭弹层，toast `节点已加入节点池并绑定当前配置`（导入仍用「已添加 N 个节点」）；节点卡由 `node-list-changed` 自动刷新。**不选中、不连接**。
- 失败：弹层不关，错误就地显示，已填内容保留。
- 关闭方式：`取消`、右上关闭、Esc、点遮罩。提交中不允许关闭。Esc 由弹层自己处理；焦点陷阱用 `useFocusTrap`，关闭后焦点回到触发按钮。

### 3.5 与设置页的关系

- 设置 › 连接 里的 `添加节点` 行、导入弹层、相关 state/handlers/helpers 全部删除。
- 设置页不再出现任何节点导入入口；`configId` 这个 prop 如果只服务于导入，一并清理。
- 不保留隐藏入口，不做两处同开。

## 5. 验收建议

1. 只有四项信息（地址、端口、加密方式、密码）的用户，不经 AI、不拼链接，能在节点卡里建出节点，并在节点卡与连接页选中它；**零节点用户**从 `已有自己的节点？手动添加` 进入同一个弹层，不必先领免费节点。
2. 节点名留空、端口越界、地址带 `https://`、密码为空，逐个给出贴着字段的错误，并把焦点移到第一个错误字段。
3. 提交中按钮禁用并 `aria-busy`；成功后弹层关闭、toast 说明「已加入节点池」而不是「已连接」。
4. 链接/订阅/文件三条旧路径行为不回退；跳过原因与错误文案仍正确。
5. 设置 › 连接 不再有「添加节点」入口；主界面只有节点卡一个入口，零节点空态另有等效入口。
6. 中英文都过一遍，字段名与 `NodeImport` 工具描述一致（地址 / 端口 / 加密方式 / 密码）。
7. 建完不出现在「我的服务器」——它只进节点池，不产生托管机器。

## 6. 不做

- 不新增 Host 命令、不改契约版本。
- 不做批量手动录入（多行文本已经覆盖这种场景）。
- 不做节点编辑/删除（另开设计）。
- 不做「显示密码」开关。
- 不做提交前的重复节点预检（见 D5）。

## 7. 两类节点的能力边界（本设计必须知道的前提）

手动添加的节点是**用户自己的**，不是我们托管的。这决定了两件事：界面上要能看出区别，出问题时的建议也不能套用托管节点的那套流程。

### 7.1 数据层已经分得开

`NodeSummary.source` 有四个值（`src-tauri/src/store/configs.rs:23-27`）：

| `source` | 来源 | 谁能改它的凭据 |
|---|---|---|
| `seed` | Veyl 免费节点 | 我们（随种子更新） |
| `url` | 订阅导入 | **用户/服务商**，我们只读 |
| `manual` | 手动填写 | **用户**，我们只读 |
| `owned` | 我的服务器（Veyl 托管） | 我们（智能修复 / 更换连接密码） |

### 7.2 界面现在的分法不够

连接页只按 `source === "seed"` 二分（`src/components/ConnectionStage.tsx:430`）：`seed` 进「免费节点」，**其余全部进「你的服务器」**。于是订阅导入和手动添加的节点与托管服务器混在同一组里，没有任何可见标记说明「这台我们管不了」。

### 7.3 哪些流程对哪些节点开放

| 流程 | 门槛 | 自定义节点会怎样 |
|---|---|---|
| 智能分析 → 智能修复（轮换凭据） | 要求 `source === "owned"` 且有 `serverId`（`ConnectionStage.tsx:595`）；`nodeRotateCredentials` 的入口只在「我的服务器 › 详情」 | **进不去**，没有 server_id |
| 诊断面板 | 连接失败且非免费节点（`ConnectionStage.tsx:329`） | **能进**；只读，不改任何东西 |
| `DiagRun`（AI） | 通用检查，不依赖 server_id | **能跑**；只读 |
| 节点配置同步 / 凭据轮换 | 按 server 维度 | 与自定义节点无关 |

结论：**动作层面是安全的**——自定义节点触发不了任何"我们替你改"的流程。风险在**建议层面**：诊断结果里的 remediation 可能写着「重新拉取凭据」「智能修复」，而这两件事对自定义节点根本不成立，用户照做会找不到入口。

### 7.4 本设计范围内的最小动作

1. 手动添加的节点 `source = "manual"`（Host 已经这样落库），前端**能拿到这个值**，不需要新增字段。
2. 节点卡与连接页的行内标记（「自定义」）另行设计，不在本设计内实现；但**不要**在手动添加的文案里暗示我们能维护它——不写「自动更新」「自动修复」之类。
3. 诊断建议按 `source` 分流属于诊断面板的设计范畴，另开一份；本文只登记这条需求，避免以后被当成 bug 反复排查。**已开：`docs/design/node-diagnosis-by-source.md`。**
