# 节点写入：AI 能力与界面入口的覆盖差

> 日期：2026-11-24
> 状态：**待设计**。本文只描述缺口与要拍板的问题，不含实现方案。
> 用途：交给另一位工程师做设计与开发。
> 相关：`docs/contracts/tools.md` 3.28.0 的 `NodeImport`；`docs/design/ai-tools-decisions.md` §2；`docs/design/create-config.md`。

---

## 0. 结论摘要

`NodeImport` 工具有三种来源（`url` / `text` / `manual`），界面上只覆盖了前两种加文件导入，**`manual` 完全没有界面**。也就是说：一个手里只有「地址、端口、加密方式、密码」的用户，在界面上没有任何办法把节点加进来，只能让 AI 代做，或者自己拼一条 `ss://` 链接去粘贴。

---

## 1. 事实：AI 有什么，界面有什么

| 写入路径 | AI 工具 | Host 命令 | 界面入口 | 证据 |
|---|---|---|---|---|
| 订阅 URL | `NodeImport(source="url")` | `node_import_url` | **有**（设置 › 导入） | `src/components/Settings.tsx:1554` |
| 粘贴 `ss://` 文本 | `NodeImport(source="text")` | `node_import_text` | **有**（同上，自动判断） | 同上 |
| 选文件导入 | 无 | `node_import_file` | **有** | `Settings.tsx:1535` |
| 手动逐项创建 | `NodeImport(source="manual")` | `node_create` | **无** | `node_create` 全仓只有 `mockAgent.ts` 实现，没有任何组件调用 |
| 拉取免费节点 | `CatalogRefresh` | `catalog_refresh` | **有** | 连接页 |

补充两条容易误判的事实：

1. **不是「bridge 没接」**：`nodeCreate` 在 `src/agent/bridge.ts:1082` 有声明、`mockAgent` 有实现，Host 侧 `node_create` 命令也在。缺的只是界面。
2. **AI 加进来的节点在界面上是可见的**：节点进的是同一个全局节点池，不需要额外同步。

---

## 2. 缺口的影响

- 用户在别的服务商后台看到的是「服务器、端口、加密方式、密码」四项，这是最常见的自建节点形态。现在这类用户必须在客户端里**手动拼一条 `ss://` 链接**（`ss://base64(method:password)@host:port#name`）才能导入——对不懂的人等于做不到。
- AI 能做而界面不能做，违反「AI 是加速器、不是唯一入口」的产品原则：关掉 AI 的用户在这条路上是断的。

---

## 3. 要拍板的问题

| # | 问题 | 说明 |
|---|---|---|
| D1 | 入口放哪 | 候选：① 设置 › 节点导入区加一个「手动添加」入口；② 节点池 / 配置详情页的「＋」；③ 两处都有。现状下导入区在设置里，放一起最省事，但「加节点」是高频动作，埋在设置里不合直觉 |
| D2 | 与现有导入区的关系 | 是同一个区域的第三种输入形态（链接 / 文本 / 手动），还是独立的二级页面/弹层 |
| D3 | 表单字段与校验 | 至少 name / server / port / method / password。`method` 是否只给下拉（`aes-256-gcm` 等自有白名单，见 `services.rs` 的 `validate_manual`）；`server` 允许域名还是只允许 IP；端口范围 1–65535 |
| D4 | 密码的落点与回显 | Host 侧密码只进本地加密文件、不回传（与 AI 工具一致）。界面上是否允许「显示密码」、编辑时留空表示不修改 |
| D5 | 重复节点 | 手动创建不去重（`node_create` 的 `skip_duplicates = false`），界面要不要在提交前提示「已有同名/同地址节点」 |
| D6 | 建完之后做什么 | 只进节点池？还是同时设为当前配置的当前节点？现有导入只进池，建议保持一致 |
| D7 | 编辑与删除 | 这次只做「新建」，还是顺带支持改已有节点的名字/地址（改凭据是另一回事，已有「更换连接密码」） |

## 4. 约束（不需要重新讨论的前提）

- **接口已就绪**：`bridge.nodeCreate(input)` → Host `node_create` → service `node_create`，字段与校验见 `src-tauri/src/services.rs` 的 `validate_manual`。不需要改契约、不需要改 Host。
- **AI 工具不动**：`NodeImport(source="manual")` 已经存在且已评审，界面是补另一条入口，不改工具面。
- **界面规范**：`veyl-ui`（浅色、一个主按钮、字号阶梯 22/17/15/13/12、间距 4/8/12/16/24/32）。表单错误贴着对应字段，不要只放页顶。
- **密码永不回显**：与现有 `NodeImport` 一致，返回值不含密码；界面上也不落盘、不进日志。
- **状态归属**：节点进的是全局节点池，界面不需要额外同步逻辑。

---

## 5. 验收建议

1. 只有四项信息的用户，不经 AI、不拼链接，能在界面里建出节点，并能在连接页选中它。
2. 非法输入（端口越界、method 不在白名单、密码为空）逐个给出贴着字段的错误，不整页报错。
3. 提交中按钮禁用并 `aria-busy`；成功后节点出现在节点池，文案说明它「已加入节点池」而不是「已连接」。
4. 中英文都过一遍，字段名与 `NodeImport` 工具描述里的叫法一致（地址 / 端口 / 加密方式 / 密码）。
5. 建完不出现在「我的服务器」——它只进节点池，不产生托管机器。

---

## 6. 不做

- 不新增 Host 命令、不改契约版本。
- 不做批量手动录入（多行文本已经覆盖这种场景）。
- 不做节点编辑/删除（如果 D7 决定要做，另开一份设计）。
