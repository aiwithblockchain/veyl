# 连接舞台：手动测速入口

> 日期：2026-11-17
> 状态：设计定稿，待实现。只出规格与文案，不改代码、不改契约。
> 依据：`ai-first-product.md` §主界面（测速是节点列表里的动作，不常驻）、`veyl-ui` §2.1（一屏一个主按钮）/ §2.2（一个事实一个住处）、`commands.md` §9.1.1（UI 上下文）、现有 `ConnectionStage.tsx` 与 `useNodeProbes`。
> 一句话：**加一个轻量文字入口，不加第二个实心按钮；测速只更新延迟，不动选中、不换节点、不连。**

---

## 0. 结论

| 项 | 结论 |
|---|---|
| 入口 | 节点卡副行右侧的文字链接 `测速`，主按钮仍只有 `连接` |
| 行为 | 对当前配置的全部节点跑一轮真实测速；只更新行内延迟 |
| 最快标记 | 手动测速后**跟随本次结果移动**；后台/自动测速**只清掉标记、不移动** |
| 收尾句 | 手动测速后**去掉数字**，保留 `已加入 2 个免费节点`；不更新成新数字，也不整句隐藏 |
| AI | **进静态登记表** `client.probe`，点击时上报 `last_action`（需契约补一行，本文不改 `commands.md`） |

---

## 1. 位置与形态

```
┌ 节点卡 ───────────────────────────────────────┐
│ 免费节点                                      │  20 / 600
│ 2 个节点 · 7 天试用                    测速   │  13 / --ink-3 ｜ 13 / --link
│ ───────────────────────────────────────────── │
│ 东京 01   最快                        42 ms   │
│ 新加坡 01                             78 ms   │
└───────────────────────────────────────────────┘
                [        连接        ]
```

- 位置：节点卡头部（`.stage-card__head`）里，与副行 `N 个节点 · 7 天试用` **同一行、右端对齐**；不放在主按钮旁，不做图标按钮。
- 排版：头部内新增一条 flex 行 `justify-content: space-between; align-items: center; gap: 12`；副行可省略（`text-overflow: ellipsis`），`测速` 永远完整显示。
- 文字链接：13 / 500 / `--link`（`#C2185B`，深色 `#F48FB1`）；无底色、无边框；静止不加下划线，hover 与 `:focus-visible` 加下划线，focus 环用 `--focus`。
- 命中区 ≥44：按钮本体保持 18 高，用伪元素扩大点击区域——`button::after { position:absolute; inset:-14px -8px; }`，按钮 `position: relative`。视觉不增高，点击区约 46×~70。
- 卡片头部高度不变（`padding: 18px 16px 14px`）；窄屏不换行、不隐藏，只让副行先省略。
- 不用 `--cobalt`、不用状态色：这是一个动作链接，不是状态。

---

## 2. 状态

| 状态 | 入口显示 | 行内延迟 | 可点 |
|---|---|---|---|
| 空闲 | `测速`（`--link`） | 上次结果或 `—` | 是 |
| 测速中 | 三点动画 + `测速中`（`--ink-3`） | 该节点 `测速中`，已有结果的节点保留旧值 | **否**（`disabled`，防止重复触发） |
| 部分失败 | `测速` | 失败行 `—`（`--ink-3`），`aria-label="这次没测通"` | 是 |
| 全部失败 | `再试一次`（`--link`）；卡片底部一行 `这次都没测通。`（12 / `--warn-text`） | 全部 `—` | 是 |
| 正在切换节点 / 正在连接 / 正在断开 | `测速`（`--ink-3`） | 现状 | 否（`disabled`，`title="正在切换，稍后再试"`） |
| 已连接 | `测速`（`--link`） | 更新，不影响连接 | 是 |

- 三点动画沿用现有 `.dots`（4px，300ms 一格，900ms 循环）；`prefers-reduced-motion` 下静止并保留中点。
- 全部失败的一行只在卡内出现一次；下一次测速开始时移除。它不占用舞台底部的收尾句（那里是 `报告问题` 的地盘）。
- 没有「取消测速」：一轮节点数很少，跑完即可；中途切 destination 由现有控制器收尾。

---

## 3. 行为

1. 点击 → `nodeProbes.start(configId, 全部节点 id)`（现有控制器）；**一轮只跑一次**，运行中忽略重复点击。
2. 只更新 `nodeProbes.results` → 行内延迟与「最快」标记的输入；**不写 `current_node_id`**，不发 `node_switch` / `runtime_start`，不改 `pickedId`。
3. 已连接时允许：结果只刷新读数，连接、计时器、出口、流量都不受影响。
4. 结果只在本次会话内有效；重启后回到「进入连接屏自动测一次」的既有行为。
5. 测速期间切换节点或连接：不打断测速；但入口保持禁用直到这一轮结束，避免连点。
6. 全部失败时**不改选中**：当前节点仍可连接（连接走真实连接，不依赖测速结果）。

---

## 4. 「最快」的口径

**标记只由「用户主动触发的一次完整测速」或「试用步骤流」写入；后台/自动测速不移动标记，只把它清掉。** 这样屏幕上不会出现「行内 180ms、标记却在 238ms 那台」。

| 事件 | 标记 | 预选（选中态） |
|---|---|---|
| 试用步骤流完成 | 设为最快的那台 | 设为最快的那台（本地，不写库） |
| 用户点 `测速` 且至少一台成功 | **按本次结果重算并移动** | 不动 |
| 用户点 `测速` 但全部失败 | **清掉** | 不动 |
| 进入连接屏的自动测速 / 后台测速 | **清掉**（不移动） | 不动 |
| 用户切换节点 | **清掉** | 跟随新节点 |
| 节点增删 / 销毁 | **清掉** | 现状 |

- 并列：本次结果里若有多台同为最低整数 ms，**保留原来那台**；原来那台不在并列里时取配置顺序靠前的一台。避免每秒抖动。
- 清掉标记不等于「没有最快」：卡内仍能看到数字；下次手动测速会重新给出。
- 自动测速后清标记的理由：它会在用户没看的情况下改变结论；而标记是一句「现在最快的是这台」的断言，只能由用户刚触发的结果来支撑。

---

## 5. 收尾句

**选：手动测速后去掉数字，只留 `已加入 2 个免费节点`。**

- 原句 `已加入 2 个免费节点，最快 238ms` 是试用步骤流的**回执**，不是实时读数；行内数字一变它就过时。
- 不更新数字：会把「最快」这个事实放到两处（句子 + 标记/行），两处一旦不同步就是新矛盾。
- 不整句隐藏：`报告问题` 链接目前跟在同一段 `.stage-note` 里，整段隐藏会把诊断入口一起带走；而且底部会空出一块。
- 保留「已加入 2 个」这半句：它记录的是发生过的事，不会过时；「2 个」与卡片的 `2 个节点` 不冲突（一个说事件，一个说状态）。
- 首次手动测速发生时改写一次，之后不再变化；没有 `trialSummary` 的配置本来就没有这句话。

其它两种情况不变：

- 非试用配置：收尾句是 `已加入 N 个节点`，同样在手动测速后去掉 `，最快 Xms`。
- 无节点：`还没有节点`，没有测速入口。

## 6. AI 侧

**要进 `controlIds`：新增 `client.probe`。**

- 契约位置：`commands.md` §9.1.1 静态登记表的 `client` 行，`kind = "button"`；由架构师补，本文不改契约。未登记时前端上报会被整条剔除（不报错），所以必须一起改。
- 上报：点击 `测速` 时带 `last_action = { id: "client.probe" }`，不带 `value`（不是单选）。
- 只在入口**可点且已渲染**时放进 `controls`；测速中、切换中、连接中不列。
- 理由：AI 的「换更快的节点」建议依赖「用户刚测过」这个事实；没有这条，它只能让用户再说一遍「我刚测了」。测速是只读动作，不涉及权限与确认，适合上报。
- 不上报每台节点的延迟：那是 `NodeProbe` / 舞台快照的职责，不塞进 `last_action`，避免上下文超限与两套数字。

---

## 7. 文案原文

- `测速`
- `测速中`
- `这次都没测通。`
- `再试一次`
- `这次没测通`（行内 `—` 的无障碍名）
- `已加入 2 个免费节点`（手动测速后的收尾句）
- `正在切换，稍后再试`（禁用时的 `title`）

不用「开始测速」「立即测速」「极速」，不加感叹号。

## 8. 验收要点

| # | 检查 | 期望 |
|---|---|---|
| 1 | 空闲点击 | 入口变「测速中」+ 三点，不可再点；每行先显示「测速中」再落到数字 |
| 2 | 只读性 | 测速全程没有 `node_switch` / `runtime_start`；`current_node_id` 与选中行不变；连接状态不变 |
| 3 | 最快标记 | 手动测速后落在最低延迟那台；原来那台若不再最低则标记移走 |
| 4 | 自动测速 | 进入连接屏的自动测速**不移动**标记；有标记时被清掉 |
| 5 | 全部失败 | 全部行 `—`，卡内出现 `这次都没测通。` + `再试一次`，标记消失，选中不变 |
| 6 | 收尾句 | 首次手动测速后变成 `已加入 2 个免费节点`，`报告问题` 仍在原位 |
| 7 | 已连接 | 可以测，连接、计时、出口、流量都不变 |
| 8 | AI | 点击后下一轮 `context.last_action` 有 `client.probe`，且它出现在同一份 `controls` 里（契约补完后） |
