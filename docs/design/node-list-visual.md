# 节点列表与测速：视觉与交互

> 日期：2026-11-06
> 状态：设计定稿，未实现
> 上游：`docs/design/node-list.md`（信息架构、命令与事件契约）
> 分工：本文只负责视觉、排版、状态表现与交互细节；形态以架构稿 §3 的**底部上拉面板**为准。
> 遵守：`veyl-ui`。界面不出现 proxy / TUN / 分流 / 规则集；同屏只有一个主按钮；状态色只做文字与描边。

---

## 0. 结论

1. 节点卡的入口从「像文字的节点名」改成一个**有边界的可展开行**：名称 + `⌄` + `N 个节点` + 最近延迟。
2. 点它打开**底部上拉面板**：宽度等于中间区，最高 60%，覆盖 AI 编排区，节点卡与顶部按钮保留。
3. 列表行固定 44px，右侧一个**延迟徽标**区分五态；当前节点用左侧墨色竖条 + 「当前」文字标记。
4. **点一行立即切换**，面板不关；没有「选中预览 + 用这个节点」两步，也没有确认弹层。
5. 批量测速在面板底部（次级按钮）；面板关闭时节点卡显示「正在测速 12/23 · 点开可停止」。
6. 大列表只做搜索 + 超过 60 行时虚拟滚动；不做分组、不做自动最快。

---

## 1. 入口可发现性

### 1.1 两个方案

**方案 A：给节点名加 `⌄`，整块可点。**
保持现在「当前节点 / 节点名」的排版，只在名称后加一个 12px 箭头；命中区域扩大到名称周围。
优点是改动最小，节点卡信息层级不变。缺点是「当前节点」这个标签仍然把下方当成一段说明文字，
箭头又太小，用户第一眼看到的依旧是「东京 01」四个字，和截图里的问题只差一个箭头。

**方案 B（采用）：把当前节点做成一行有边界的展开行。**
在节点卡内部嵌一条高 44px 的选择器行：

```
┌──────────────────────────────────────────────┐
│ 东京 01  ⌄          23 个节点   38 毫秒      │
└──────────────────────────────────────────────┘
  1.2.3.4:20343 · aes-256-gcm
  [ 测这个节点 ]
```

行本身有 `--bg-panel` 的浅底、8px 圆角、整行一个命中区；名称 15px/500，右侧数量 11px、延迟徽标、箭头。
不再是「一段文字 + 两个按钮」，而是一个**选择控件**：名称是值，`⌄` 是「可以展开」，
`23 个节点` 是「里面有多少东西」，延迟是「当前值」。四个线索各说一件事，互不依赖。

### 1.2 为什么选 B

- **可发现性来自形状，不来自说明。** 用户不会读「节点名可点」，但会认出带箭头、有数量、有当前值的行是选择器。
- **命中区最大。** 整个 44px 行都能点，不必瞄准文字；长名称、带 `[美国2]` 后缀也不会把点击目标挤没。
- **不增加层级。** 它仍在节点卡内部，不是第二个卡片、不是新页面；与架构稿 §4「只加可见性，不改结构」一致。
- **只留一个 ghost 按钮。** 「选择节点」与整行是同一个动作，两个入口会让人犹豫「这两个是不是不一样」，所以删掉；
  「测这个节点」保留单测（与打开列表无关）。主按钮仍是顶部连接按钮。

### 1.3 视觉规格

| 项 | 规格 |
|---|---|
| 高度 | ≥44px（含内边距），整行一个 `<button>` |
| 背景 | 默认 `--bg-panel`；hover `--bg-hover`；聚焦沿用全局 focus-visible |
| 圆角 | `--r-sm`（6px） |
| 名称 | 15px / 500 / `--ink`，单行省略，超长显示 `…` |
| 数量 | 11px / `--ink-3`，`23 个节点` |
| 延迟 | 延迟徽标（见 §5），没有结果时不占位 |
| 箭头 | 12px，`--ink-3`，`aria-expanded=true` 时旋转 180°，120ms |
| 辅助文本 | 地址与加密方式保留在行下方，12px mono `--ink-3` |
| 语义 | `aria-haspopup="dialog"`、`aria-expanded`、`aria-controls` |

打开面板只有节点行一个入口：鼠标点击行、或聚焦后按 Enter / Space，都是它。不再另设「选择节点」按钮。

## 2. 折叠态：默认、批次中、单节点、空

### 2.1 默认

```
当前节点
[ 东京 01  ⌄        23 个节点   38 毫秒 ]
1.2.3.4:20343 · aes-256-gcm
2 分钟前测过
[ 测这个节点 ]
```

- 「2 分钟前测过」只在有延迟结果时出现；没有结果时整行省略，不留空位。
- 「测这个节点」只在有节点时出现；未连接也允许（单测走本机探测，见架构稿 §6.4）。

### 2.2 批次运行中（硬要求）

节点卡第二行被替换为：

```
正在测速 12/23 · 点开可停止
```

- 11px / `--ink-3`；「点开可停止」与前半句同色，不做链接色。
- 这一行与上面的节点行共享同一个打开动作；点它同样打开面板。
- 地址与加密方式在批次期间暂时让位——批次进度是此时更重要的信息。
- 批次结束时恢复地址行，并在其后显示「刚刚测过」。
- 批次属于别的配置时不显示，避免切了配置还看到上一套的进度。
- 「测这个节点」在批次进行中禁用（`aria-disabled`，保持可见），避免单测与批次抢同一批连接；
  面板里的「停止测速」是唯一的停止入口。

### 2.3 只有 1 个节点

- 节点行不再是按钮：没有 `⌄`、没有「23 个节点」、没有 hover 底色。
- 面板永远不会打开；不提供批量测速。
- 保留「测这个节点」——单节点也有「它通不通」的问题。
- 地址行与延迟徽标照常显示。

### 2.4 没有节点

- 节点行位置改为一行说明：`还没有节点`（13px / `--ink-3`），不可点、无箭头。
- 不显示「测这个节点」；卡里没有任何按钮。
- 不显示延迟徽标、不显示数量。
- 添加节点的入口仍归配置列表/引导页，不在节点卡里新增第三个按钮。

## 3. 底部上拉面板

### 3.1 形态与层级

```
┌ 节点 · 公司 ──────────────────────────── [关闭] ┐  ← 52px
│ [ 搜索节点                                    ] │  ← 44px
│ 共 23 个 · 18 个可用 · 3 分钟前测过   排序：延迟 │  ← 32px
├─────────────────────────────────────────────────┤
│ ● 东京 01  当前            [38 毫秒]   刚刚     │  ← 44px
│ ○ 东京 02                  [120 毫秒]  3 分钟前 │
│ ○ 洛杉矶 01                [超时]               │
│ ○ 法兰克福 01              [未测]               │
│ …                                               │
├─────────────────────────────────────────────────┤
│                                  [ 全部测速 ] │  ← 64px
└─────────────────────────────────────────────────┘
```

> 页脚左侧平时为空；只有重排时短暂显示 `正在按延迟排序…`。不是常驻的选中状态。

- 锚在中间区底部，**宽度 = 中间区**，向上展开，最高 60%（不足 320px 时取 320px，但不高于 60%）。
- 覆盖 AI 编排区；不覆盖顶部连接区与节点卡。不改变中间区布局，不参与路由。
- 顶角 12px（`--r-lg`），底角 0；背景 `--bg-card`；1px `--hair-strong` 顶边；`--shadow-float`。
- 不加半透明遮罩：中间区仍要在视觉上保持「还在这里」，只是被面板盖住下半部分。
- 打开动画 160ms：`translateY(8px) → 0` + 透明度；`prefers-reduced-motion` 时直接出现。

### 3.2 打开、关闭与焦点

- 打开：点节点行 / Enter 或 Space；打开时把当前节点滚入可视区（不置顶）。
- 关闭：Esc、点面板外、右上角关闭按钮。
- 打开后焦点进入面板：搜索框（节点 > 8）或列表（节点 ≤ 8）。
- 关闭后焦点回到节点行，不回到页面顶部。
- 面板开着时切换配置：面板直接关闭并回到新配置的节点卡；旧批次继续跑，切回来再恢复进度。

### 3.3 头部与汇总

- 标题：`节点 · 公司`，15px/500，配置名过长单行省略。
- 关闭按钮：14px 图标，44×44 命中区，`aria-label="关闭"`。
- 汇总：`共 23 个 · 18 个可用 · 3 分钟前测过`，11px `--ink-3`。
  - 没有测速结果时省略「3 分钟前测过」。
  - 全部失败时改为 `共 23 个 · 都没测通`。
- 排序：汇总行右侧一个文字按钮 `排序：手动` / `排序：延迟`，11px `--ink-3`，当前模式用 `--ink`。
  不放下拉菜单，点一下切换；批次进行中禁用，`title="测速结束后可排序"`。

### 3.4 搜索

- 44px 高，输入框无边框，底部 1px `--hair`；左侧 14px 搜索图标 `--ink-3`。
- 占位：`搜索节点`；匹配名称与地址，忽略大小写；客户端即时，无 loading。
- 有内容时右侧出现清除按钮（14px，44×44 命中区）。
- 节点 ≤ 8 时整行搜索不出现，给列表更多高度；节点 > 8 时固定显示。
- 搜索变化时列表回到顶部；当前节点不再强制滚入。
- 无匹配：列表区居中一行 `没有匹配的节点`，13px `--ink-3`，不显示批量按钮。

### 3.5 底部操作区

- 右侧只有一个 ghost 按钮：`全部测速`（有搜索时 `测这 12 个`；运行中 `停止测速`）。
- 左侧平时为空；只有重排期间短暂显示 `正在按延迟排序…`（11px `--ink-3`）。
- 切换成功不显示常驻文案：当前标记移动本身就是反馈；屏幕阅读器通过一个 sr-only
  `aria-live="polite"` 区域听到 `已切换到 东京 02` / `没切成，还在原来的节点`。
- 没有「已选择」「选择一行后可用」这类状态，也没有「用这个节点」。
- 按钮不是主按钮；同屏唯一主按钮仍是顶部连接按钮。
- 面板内不出现第二个常驻按钮。

## 4. 列表行

### 4.1 结构

```
[│] ● 东京 01   当前    [38 毫秒]    刚刚
 ↑   ↑    ↑       ↑         ↑          ↑
 当前 状态 名称   当前徽标  延迟徽标   时间/新鲜度
 竖条 点
```

- 行高固定 44px；整行一个可激活项，`role="option"`；列表是 `role="listbox"`。
- 左：2px 当前竖条（仅当前节点，`--ink`）。
- 状态点：6px，只表示延迟状态（见 §5），不表示当前。
- 名称：14px/400 `--ink`，单行省略；带 `[美国2]` 这类方括号片段时整体保留，不拆列。
- 当前徽标：`当前`，11px `--ink`，1px `--ink-3` 描边，无填充；紧跟名称，不与延迟徽标抢右端。
- 右端：延迟徽标 + 时间（`刚刚` / `3 分钟前`），11px `--ink-3`，时间列固定宽度避免跳动。
- 焦点行：只描 1px `--hair-strong` 内描边（列表拿到键盘焦点时为 1px `--ink-4`），不加底色；
  当前节点即使没有焦点也保留左侧竖条与「当前」徽标。强度等级见 §4.2。
- 行与行之间只用 1px `--hair`，不加卡片边界。

### 4.2 「当前」与「焦点」：只有两种状态

- **当前** = 正在使用的节点，持久事实。标记：左侧 2px 墨色竖条 + 「当前」文字；
  `aria-selected="true"`、`aria-current="true"`。
- **焦点** = 键盘或指针正在指向的行，临时事实。标记：只有 1px 内描边，**不加底色**；
  指针悬停时才出现 `--bg-hover` 浅底（悬停与焦点是两条独立规则）。不写 `aria-selected`。
- **强度从高到低：当前 > 悬停 > 焦点。** 焦点线不得使用 `--ink` / `--ink-3`，不得 ≥2px，不描成完整粗框。
  两者同时出现时，一眼先看到「当前」：墨条 + 文字徽标是形状与文字信号，焦点只是一条淡线，
  色弱用户也能靠形状区分。
- **没有「选中预览」这第三种状态。** 移动焦点不改变网络；点击或 Enter 才切换。
- 打开面板时焦点落在当前节点；当前节点不置顶——置顶会让排序结果失真（架构稿 §7.1）。

#### 点击即切换

- 点击任意**非当前**行：立即发起切换，面板不关。
- 被点的行立刻进入切换态：
  - 右端延迟徽标与时间整体替换为 `切换中…`（11px `--ink-3`）+ 6px 呼吸圆点；
  - 行背景保持悬停态（有指针时），焦点线仍是 1px 淡线；
  - 当前标记仍留在旧节点，直到成功。
- `切换中…` **最短显示 400ms**，让反馈可感知；接口更慢则一直显示到返回。
- 切换进行中：列表 `aria-busy="true"`，所有行的重复点击被忽略（不排队、不切换第二次）；
  行仍可滚动、可悬停，光标 `default`，不弹任何提示。
- 成功：
  - 当前竖条与「当前」徽标移动到新行（120ms 淡出/淡入）；
  - 新行的 `切换中…` 在 120ms 内交叉淡回延迟徽标与时间；
  - 面板不关、不滚动、焦点仍在该行；
  - 不额外显示成功文案；屏幕阅读器播报 `已切换到 东京 02`。
- 失败：
  - 当前标记不动；
  - 该行右端显示 `没切成，还在原来的节点`（11px `--err`，4 秒），随后交叉淡回原徽标与时间；
  - 不弹窗、不 toast；该行可以再次点击重试。
- 点击当前节点：无操作（不关闭面板、不显示反馈）。
- 批次测速进行中仍可切换；批次继续，结果按节点记录，不因切换作废。

### 4.3 区域

- 节点模型当前没有 `region` 字段，v1 **不新增列、不按名称猜地区**。
- 名称里已经带方括号片段的（如 `meshflux10 [美国2]`），整段按名称原样显示；
  方括号部分可用 12px `--ink-3` 排在同一条文本里，但**不可单独点击、不可用于分组或搜索过滤以外的推断**。
- 将来节点模型有 `region` 时，作为名称后的 11px `--ink-3` 后缀接入，行结构不变。
- 分组留到模型有分组字段之后（架构稿 §11）。

### 4.4 长名称与窄宽

- 名称 `text-overflow: ellipsis`，保证右端延迟徽标与时间列不被挤走。
- 中间区 < 520px 时：隐藏时间列，只保留延迟徽标；名称仍占剩余宽度。
- 数量、当前徽标、延迟徽标都不换行。

## 5. 延迟徽标

### 5.1 五态

| 视觉状态 | 徽标文字 | 文字色 | 描边色 | 动效 |
|---|---|---|---|---|
| 未测 | `未测` | `--ink-3` | `--ink-3` 30% | 无 |
| 测试中 | `测速中` | `--ink-3` | `--ink-3` | 6px 圆点 1.2s 呼吸 |
| 可连 | `38 毫秒` | `--ok` | `--ok` | 无 |
| 可连但过期 | `38 毫秒 · 12 分钟前` | `--ink-3` | `--ink-3` 30% | 无 |
| 超时 | `超时` | `--warn` | `--warn` | 无 |
| 连不上 | `连不上` | `--err` | `--err` | 无 |

- 徽标高 20px，内边距 0 6px，圆角 6px，1px 描边，**背景透明**，不做彩色填充。
- 字号 11px，数字用 tabular-nums；「38 毫秒」不在徽标里加空格以外的单位变体。
- 五态映射到架构稿 §5.1：
  - 未测 → `未测`
  - 测速中 → `测速中`
  - 可连（新鲜/过期）→ `38 毫秒` / `38 毫秒 · 12 分钟前`
  - 超时与连不上都落在 `reachable = false`。若 `error.code` 能区分超时与拒绝/解析失败，
    分别显示 `超时`（`--warn`）与 `连不上`（`--err`）；不能区分时统一显示 `超时`，不猜。
- 颜色只出现在 11px 文字与 1px 描边上，不做背景块、不做按钮填充；
  一屏的主要视觉重量仍是墨色。状态色不构成第二个主色。

### 5.2 有缓存但仍在跑（必须与「已测完」区分）

同一行可能既有旧数字，又正在被重测。规则：

1. 旧数字**不再作为主信息**：徽标位置显示 `测速中` + 呼吸圆点。
2. 旧值降级为徽标左侧的 `上次 38 毫秒`（11px / `--ink-3`），明确带「上次」。
3. 时间列从 `3 分钟前` 改为 `测速中`，不保留旧时间。
4. 汇总行同时显示进度并出现 `停止测速`；这三处共同说明「整批还在跑」，不是「这一行没变」。
5. 新结果返回后：徽标 120ms 过渡到新数字，`上次 …` 消失，时间变为 `刚刚`。
6. `prefers-reduced-motion` 时圆点不呼吸，但 `测速中` 文字与 `上次` 前缀仍在。

只靠数字变化区分新旧不够——用户看不出是没测还是测了没变；活动态必须由**形态**承担。

### 5.3 深色

- 徽标背景保持透明，描边与文字使用同一套 `--ok/--warn/--err/--ink-3` 深色值。
- 过期态与未测态在深色下不能只靠降低透明度，仍用 `--ink-3` 与虚线化描边区分。
- 当前竖条在深色下用 `--ink`，不使用彩色。

## 6. 批量测速

### 6.1 入口

- 面板底部 `全部测速`（ghost）。没有搜索时测全部；有搜索时测当前过滤结果，文案 `测这 12 个`。
- 节点 ≤ 1 时不显示。
- 打开面板不自动测速，不提供定时测速。

### 6.2 进行中

同时给两层信息，不二选一：

- **整体**：汇总行替换为 `正在测速 12/23`，下方 2px 细进度条（轨道 `--ink-3` 20%，进度 `--ink`）。
  进度条只做宽度过渡 120ms，不做流动动画。
- **逐行**：正在测的那一行徽标变 `测速中`（§5.2）；已完成的行原地更新数字，不移动。
- 一次并发 6 个，屏幕上同时最多 6 行显示 `测速中`；其余保持原状态。
- 失败的行直接变 `超时` / `连不上`，不弹窗、不 toast、不中断整批。
- 折叠态节点卡同步显示 `正在测速 12/23 · 点开可停止`。

### 6.3 取消

- `全部测速` 在运行中变成 `停止测速`，同一位置、同一 ghost 样式。
- 点击立即生效，无确认；已出的结果保留，未测的行回到 `未测`。
- 汇总短暂显示 `已停止 · 已测 12/23`，随后回到 `上次测速：刚刚`。
- 面板关闭不取消批次；停止入口在面板内与节点卡折叠提示两处都能到达。

### 6.4 排序

- 运行中锁定行顺序，行内原地更新。
- 结束后：`排序：延迟` 模式整表重排一次；`排序：手动` 模式顺序完全不变。
- 取消也视为结束，按同样规则重排一次。
- 排序是视图偏好，不写配置；切换按钮文案即当前模式（`排序：延迟`）。

**重排时的指针保护**（不加确认弹层）：

1. 指针停在列表行上时不立即重排；等指针离开列表，或停止移动 600ms 后执行。
2. 若 800ms 内指针始终不动，也执行；不无限期推迟。
3. 有切换请求在飞时不重排；等切换成功或失败后再执行。
4. 重排使用 180ms 的 FLIP 位移动画；焦点按 `node_id` 跟随，不按行号——
   键盘 Enter 永远作用于用户刚才聚焦的那个节点，而不是移动到指针下的新行。
5. 动画期间列表 `aria-busy="true"`，行激活被忽略；页脚左侧显示 `正在按延迟排序…`。
6. 动画结束立即恢复可点；不弹确认、不弹 toast、不要求二次点击。

### 6.5 测完

- 汇总：`共 23 个 · 18 个可用 · 刚刚测过`。
- 全部失败：`共 23 个 · 都没测通`，需要时按架构稿 §9 出现离线提示条。
- 不自动切换节点、不自动选最快。

## 7. 大列表

最小可行的一套，只做三件事：

1. **搜索**（§3.4）：名称 + 地址，即时过滤。
2. **虚拟滚动**：节点 > 60 时只渲染可视区 ±6 行，固定 44px 行高；滚动容器内边距不变。
3. **滚到当前**：打开时把当前节点滚入可视区，之后不强制跟随。

不做：

- 不按区域分组、不做折叠组（模型没有分组字段，按名称猜地区不可靠）。
- 不做多选、不做拖拽排序、不做「只保留最快」。
- 不做服务端搜索或分页；节点列表本来就在本地。

几百个节点时真正的瓶颈是渲染，不是请求数；虚拟滚动优先于任何「限制测速数量」的妥协。

## 8. 键盘与无障碍

| 位置 | 行为 |
|---|---|
| 节点行 | Enter / Space 打开面板 |
| 面板打开 | 焦点进入搜索框或列表，当前节点获得键盘焦点 |
| ↑ / ↓ | 移动焦点行，滚动跟随；只移动焦点，不切换 |
| Enter | 切换焦点行（等于用鼠标点它） |
| Esc | 关闭面板，焦点回节点行 |
| Tab | 关闭 → 搜索 → 排序 → 列表 → 全部测速 |

- 列表 `role="listbox"`；焦点用 `aria-activedescendant` 指向当前键盘行，列表容器持有 DOM 焦点。
- `aria-selected="true"` **只给当前节点**；当前行同时 `aria-current="true"`。焦点行不写 `aria-selected`。
- 切换中的行 `aria-busy="true"`，列表容器同时 `aria-busy`；切换成功/失败通过页脚的
  sr-only `aria-live="polite"` 区域播报一次，不逐行播报，避免几十行同时刷屏。
- 焦点行用全局 focus-visible 与 `--bg-hover` + 1px `--ink-3` 内描边，不新增色相。
- 切换请求进行中，重复 Enter / 点击被忽略；Esc 仍可关闭面板，切换在后台继续。
- 关闭按钮、搜索清除、排序切换都有可读 `aria-label`。

## 9. 动效与降级

| 动效 | 时长 | 降级 |
|---|---|---|
| 面板上拉 | 160ms（位移 8px + 淡入） | reduced-motion 直接出现 |
| 箭头旋转 | 120ms | 直接切换 |
| 行切换反馈 | 最短 400ms；徽标交叉淡 120ms | 直接替换 |
| 重排位移 | 180ms FLIP | 直接跳变 |
| 进度条宽度 | 120ms | 直接跳变 |
| 测速中圆点 | 1.2s 呼吸 | 静态圆点，文字仍在 |
| 延迟数字更新 | 120ms 颜色/透明度过渡 | 直接替换 |

除以上之外不加装饰性动画；线路图仍只在顶部状态区。

## 12. 验收清单

1. 节点行一眼能看出可展开：`⌄`、数量、延迟三者至少两个可见。
2. 整行命中区 ≥44px；hover / 聚焦 / 展开三态可区分。
3. 只有 1 个节点时没有箭头、数量、面板与批量测速。
4. 没有节点时节点行是说明文字，不是可点按钮。
5. 面板宽 = 中间区，最高 60%，顶部按钮与节点卡仍可见。
6. 当前节点有左侧墨条 + 「当前」文字；焦点行只有浅底与内描边；不存在第三种「预览」状态。
7. 五态徽标在浅色/深色都可读，且不靠颜色单独传达状态。
8. 「有缓存但仍在跑」显示 `测速中` + `上次 …`，不显示成已完成。
9. 面板关闭时节点卡显示 `正在测速 12/23 · 点开可停止`，点开能停止。
10. 运行中行不移动；结束后 `排序：延迟` 只重排一次。
11. 搜索过滤后批量按钮变成 `测这 12 个`。
12. 点一行后立刻切换，面板不关，当前标记移动；没有「用这个节点」。
13. 切换行显示 `切换中…` 至少 400ms；进行中重复点击被忽略；失败时当前标记不动。
14. 重排时焦点按 `node_id` 跟随，行激活被抑制，不加确认弹层。
15. 几十上百个节点时滚动流畅，只渲染可视区；无分组入口。
