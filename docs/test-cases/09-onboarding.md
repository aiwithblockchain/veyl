# 首次使用引导用例（P1.5 wave1）

> 覆盖 `docs/phase-1-5-requirements.md` §5（B. 首次使用引导）与 §11 的 B1–B5。
> 执行者：不需要懂代码；**应用一律由用户手动启动**。
> ⚠️ 本组会**清空应用数据**（Key、配置、会话）。开始前必须按 §0.1 备份，测完按 §6 恢复。

---

## 0. 准备

### 0.1 备份现有数据（**必做**）

```bash
DATA="$HOME/Library/Application Support/Veyl"
STAMP=$(date +%Y%m%d-%H%M%S)
if [ -d "$DATA" ]; then
  mv "$DATA" "$DATA.bak-$STAMP"
  echo "已备份到：$DATA.bak-$STAMP"
else
  echo "没有现有数据目录，可以直接继续"
fi
```

记下打印出来的备份路径，**§6 恢复时要用**。

### 0.2 启动应用（由用户手动启动）

开发构建：在项目目录执行 `./scripts/dev/dev-with-log.sh`，或双击 `src-tauri/target/debug/veyl`。
打包版：双击 `Veyl.app`。

### 0.3 通用证据命令

```bash
DATA="$HOME/Library/Application Support/Veyl"
DB="$DATA/veyl.db"

# 引导是否被标记为完成
sqlite3 "$DB" "SELECT value FROM settings WHERE key='onboarding_completed';" 2>/dev/null || echo "无记录"

# 是否已有 Key（只看文件是否存在，不读内容）
ls -la "$DATA/secrets.enc" 2>/dev/null || echo "无 secrets.enc"

# 是否已有配置
sqlite3 -header -column "$DB" "SELECT id,name,protocol,is_active FROM profiles;" 2>/dev/null || echo "无 profiles"

# 直连出口（对照用）
curl -sS --max-time 10 --noproxy '*' https://ifconfig.me/ip
```

## B1 全新安装启动 → 进入引导第 1 步

- **追溯**：R8 / §5.1、§5.2；验收 B1
- **前置**：§0.1 已完成（数据目录已移走）；应用**没有**正在运行
- **步骤**：
  1. 由用户启动应用
  2. 观察首屏：是**独立全屏引导页**，还是空聊天界面？
  3. 读第 1 步内容：是否有一句话说明 Veyl 是什么、需要准备什么
  4. 尝试在引导页里发消息或点其它入口
  5. 观察是否有「下一步」之类的推进方式
- **观察点**：
  - 首屏是引导，**不是空聊天**
  - 第 1 步可读，说明「能做什么 / 需要准备什么」
  - 引导不能被聊天打断（没有可用的对话框或发送入口）
  - 第 1 步**没有**跳过按钮
- **通过标准**：
  1. 首屏为引导第 1 步
  2. 第 1 步不可跳过
  3. 引导期间无法发起对话
- **失败时抓证据**：首屏截图 + 步骤 3/4 的操作截图

## B2 引导第 2 步点「打开平台」

- **追溯**：R9 / §5.3；验收 B2
- **前置**：已进入引导第 2 步（配置 DeepSeek Key）
- **步骤**：
  1. 观察页面上的文字：是否说明了 AI **用来做什么**与**不做什么**
  2. 点击主按钮「打开 DeepSeek 开放平台」
  3. 看系统是否用**默认浏览器**打开了 `https://platform.deepseek.com/`
  4. 回到应用，看页面上是否同时给出可复制的链接与分步说明（注册 / API Keys / 创建 / 复制 `sk-` 开头串 / 粘贴回来）
- **观察点**：
  - 浏览器打开正确的站点
  - 页面上有说明文字与五步操作指引
  - **应用没有要求任何账号密码**，也没有试图自动登录
- **通过标准**：
  1. 默认浏览器打开 `https://platform.deepseek.com/`
  2. 页面包含「AI 做什么 / 不做什么」的说明
  3. 提供可复制链接与分步指引
  4. 应用内没有任何账号信息输入项
- **失败时抓证据**：引导页截图 + 浏览器地址栏截图

## B3 粘贴无效 Key

- **追溯**：R9 / §5.3；验收 B3
- **前置**：已进入引导第 2 步
- **步骤**：
  1. 在输入框里粘贴：`sk-invalid-test-0000`
  2. 点「保存并验证」
  3. 等提示出现
  4. 观察输入框内容：是否还在、能否直接修改
  5. 再粘贴一个**不以 `sk-` 开头**的字符串（例如 `hello123`），点保存
- **观察点**：
  - 无效 Key 得到**明确**提示（无效 / 已过期 / 已吊销），不是「失败」二字
  - 输入框**保留**了刚才的内容，可直接改
  - 不以 `sk-` 开头的输入被前端直接拒绝，并说明原因
  - 界面上**不显示完整 Key**
- **通过标准**：
  1. 无效 Key 有明确原因提示
  2. 输入内容保留
  3. 非 `sk-` 前缀被拒绝且给出原因
  4. 任何位置都不出现完整 Key（只显示掩码）
- **失败时抓证据**：两次提示截图 + 输入框截图，并执行：

```bash
DATA="$HOME/Library/Application Support/Veyl"
grep -rn 'sk-invalid-test-0000' "$DATA/logs/" 2>/dev/null && echo "⚠️ Key 出现在日志里" || echo "日志中未出现完整 Key"
```

  > 只要最后这条打印了「Key 出现在日志里」，**无论界面表现如何都判 FAIL**。

## B4 跳过 Key 后仍能导入并连接

- **追溯**：R10 / §5.4；验收 B4
- **前置**：已进入引导第 2 步；手上有一份可用的节点配置文件（种子 JSON）
- **步骤**：
  1. 点「跳过」（或「稍后再说」）
  2. 观察是否能进入主界面
  3. 观察主界面上是否**持续显示**一条可关闭的引导条，指向缺失的那一步
  4. **点引导条上的关闭按钮**，确认它消失；再确认「去配置」之类的入口仍能从设置页找到
  5. 观察底部输入框：是否禁用、是否有一行说明与「去配置」入口
  6. 用「导入配置」（拖放或选择文件）导入种子 JSON
  7. 在控制台点「连接」（或让它连某个节点）
  8. 连接成功后检查系统代理与出口
  9. 点「诊断网络」，观察是否给出结构化结果、是否**没有** AI 解释
  10. 点「断开」，确认网络恢复
- **观察点**：
  - 无 Key 也能完成：导入 → 连接 → 诊断 → 断开
  - 输入框禁用且有说明，不是静默不可用
  - 诊断有结构，但没有 AI 文字解释
- **通过标准**：
  1. 跳过 Key 后可进入主界面
  2. 引导条存在，且**步骤 4 已实际关闭成功**
  3. 导入成功（提示节点数）
  4. 连接成功：`HTTPEnable=1` 且出口与直连不同
  5. 诊断返回结构化结果，无 AI 解释
  6. 断开后 `HTTPEnable=0`、出口恢复直连
- **失败时抓证据**：

```bash
scutil --proxy | grep -E 'HTTPEnable|HTTPPort'
pgrep -fl 'sing-box run'
curl -sS --max-time 10 --noproxy '*' https://ifconfig.me/ip   # 直连
PORT=$(scutil --proxy | awk '/HTTPPort/{print $3}')
[ -n "$PORT" ] && curl -sS --max-time 15 --proxy "http://127.0.0.1:$PORT" https://ifconfig.me/ip   # 经代理
```

  外加：引导条截图、输入框禁用状态截图、诊断结果截图。

- **提醒**：判断「代理生效」只能靠 `scutil --proxy` 的配置值**加上** `--proxy` 的实际出网结果，两者缺一不可；裸 `curl` 的结论无效。

## B5 完成引导后重启 → 直接进控制台

- **追溯**：§5.1；验收 B5
- **前置**：B4 已完成（引导已结束，主界面为控制台）
- **步骤**：
  1. 完全退出应用（`Cmd+Q` → 选「退出」；若没有连接，应直接退出）
  2. 由用户重新启动应用
  3. 观察首屏
- **观察点**：首屏是**控制台**（总览 + 节点状态），不是引导第 1 步
- **通过标准**：
  1. 直接进入控制台
  2. 不再出现引导
  3. 之前导入的**配置还在**；**Key 仍为「未配置」状态**（B4 走的是跳过流程，本来就没有 Key —— 不要写成「Key 还在」）
- **失败时抓证据**：

```bash
DATA="$HOME/Library/Application Support/Veyl"
DB="$DATA/veyl.db"
sqlite3 "$DB" "SELECT key,value FROM settings ORDER BY key;"
sqlite3 -header -column "$DB" "SELECT id,name,is_active FROM profiles;"
```

## 6. 恢复现场（**必须做**）

```bash
DATA="$HOME/Library/Application Support/Veyl"
# 把 <备份路径> 换成 §0.1 打印出来的那个目录
mv "$DATA" "$DATA.p1-5-onboarding-test"
mv "$DATA.bak-<时间戳>" "$DATA"
```

恢复后启动一次应用，确认原来的 Key / 配置 / 会话都回来了。

> 如果不恢复，后续用例（尤其 A 组与 F 组）会跑在一个没有配置的空环境里，结论不具代表性。
