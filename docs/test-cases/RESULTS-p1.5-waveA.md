### A2 Cmd+Q → 后台运行 → **FAIL（阻断级，2026-11-03 10:40）**

**现象**：用户按 `Cmd+Q` 后**没有弹出任何对话框**，应用**直接退出**；`sing-box` 与系统代理原样留在原地。

**退出后实测（10:40:53）**：

```
应用进程        未运行
sing-box       52359 仍在运行（配置文件 profile-…json 仍被引用）
HTTPEnable     1     HTTPProxy 127.0.0.1  HTTPPort 58732
HTTPSEnable    1
SOCKSEnable    1
config/        2 个文件仍在
runtime.pid    仍为 52359
经代理出口      与直连不同（值不写入记录）
```

**违反的通过标准**：
1. 必须弹出**阻塞式**对话框 —— 未弹 ❌
2. 选「后台运行」后进程应存活 —— 应用直接退出 ❌
3. 连接应保持 —— 应用没了，只剩孤儿运行时与指向它的代理 ❌

**当前是「断网风险状态」**：代理指向 `127.0.0.1:58732`，而该端口由孤儿 sing-box 持有。
sing-box 一旦退出，所有流量将打到死端口 —— **用户会在毫无提示的情况下断网**。

**根因（PM 已定位并派 Bob）**：`ExitRequested` 用 `code.is_some()` 判断「是不是我们自己调的退出」，
但 Cmd+Q 实际带了 code，于是直接放行：既没有 `prevent_exit`，也没有走 §4.6 的清理流程。

**证据**：上述命令输出；`runtime.pid` 与 `pgrep` 均指向 52359。

**处置**：立即停止后续用例（A3–A6、B、F、G）；等修复后的新基线全量重跑。

## 2.2 本轮 A2 的判定方式（变更）

**日志是首要证据，界面是次要证据。**

1. 用户按 `Cmd+Q` 前先 `tail -f` 应用日志
2. 按后第一时间看是否出现 **「菜单退出被拦截」**
3. **没出现 → 立即 FAIL**，保留日志，不等对话框
4. 出现 → 再看对话框是否弹出、文案与按钮是否正确

理由：两次失败界面表现完全一样（直退、无对话框），但根因不同（`code` 误判 vs `ExitRequested` 未触发）。只看界面会把它们混成一条。

日志路径：

```bash
LOG="$HOME/Library/Application Support/Veyl/logs/app-$(date +%F).log"
tail -n 0 -f "$LOG"
```

## 3.1 环境恢复（A2 失败后立即做）

**顺序不能反**：先关代理，再停 sing-box。反过来会有一瞬间「代理指向已死端口」。

```bash
# 1) 先关所有网络服务的代理
networksetup -listallnetworkservices | tail -n +2 | while IFS= read -r svc; do
  case "$svc" in *"*"*) continue ;; esac
  networksetup -setwebproxystate "$svc" off
  networksetup -setsecurewebproxystate "$svc" off
  networksetup -setsocksfirewallproxystate "$svc" off
done

# 2) 确认代理已关
scutil --proxy | grep -E 'HTTPEnable|HTTPSEnable|SOCKSEnable'

# 3) 再停孤儿运行时
pkill -f 'sing-box run'

# 4) 清理残留（可选，重启应用也会做）
rm -f "$HOME/Library/Application Support/Veyl/runtime.pid"

# 5) 确认网络恢复
curl -sS --max-time 10 --noproxy '*' https://ifconfig.me/ip
```

> 也可以直接**重启应用**：启动时的 `recover_stale` + 遗留进程回收会一并处理。
> 但**不要**在代理还开着的时候先杀 sing-box。
