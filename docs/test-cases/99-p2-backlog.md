# P2 再测清单（P1 不排期）

> 这些不是「忘了」，而是明确留到后续阶段。P1 只保证不会因为它们未实现而阻塞发布。

| 项 | 阶段 | 为什么不在 P1 | P1 需要保留的能力 |
|---|---|---|---|
| 多版本共存与回滚 | P2 | P1 只留一个活动版本，回滚无意义 | `runtime_installs` 表按版本存；状态机预留 `standby` / `active` 字段 |
| 远程签名清单 + 灰度 | P2 | P1 清单内置在包里 | 清单格式已含 `upstream_version` / `sha256` / `source_url`，只需加签名与 `rollout` |
| 流量统计与配额 | P2 | P1 无计费 | 日志已含字节数（TC-SEC-004 要求记录字节数），后续可聚合 |
| 自建节点（公网 IP） | P2 | 需要端口探测与节点侧部署 | 目录服务的节点字段已支持自定义 `server` |
| 打洞与非公网节点 | P4 | 需要信令与 NAT 类型检测 | 无 |
| 传统支付 | P3 | — | 无 |
| 区块链支付与凭证 | P4 | — | 无 |
| TUN 全局代理 | P2 评估 | P1 明确不做 | 系统代理抽象成 trait（测试计划 §10 第 8 项），TUN 可平行实现 |
| 自动更新 | P2 | P1 手动下载 | 版本号与运行时版本已可从设置页读到 |
| 移动端 | 未定 | — | 无 |
| 账号体系 | 未定 | P1 只有匿名设备 | `devices` 表结构已可扩展 |
| 目录服务限流策略细节 | P2 | P1 只验「有限流」这一事实 | — |
| 移动端/多用户/企业版 | 未定 | — | 无 |
