## 主流程的关键断言说明

**为什么 TC-MAIN-003 要单独断言「助手回答不得早于 running」**
系统提示第 1 条明确禁止谎报连接成功。模型完全可能在工具还没返回时就先说「已连接」。这条断言防的正是这个——它比任何功能缺陷都更伤用户信任。

**为什么 TC-MAIN-005 要逐字段比对代理**
「恢复」的实现很容易写成「把代理关掉」，而用户原本可能就配置了公司代理。逐字段比对能抓到这个错误，只断言「有网了」抓不到。

**为什么 TC-MAIN-006 要断言「不出现二次 core_install」**
切换节点时重新下载运行时是明显的浪费，且在弱网下会导致切换失败。这条防的是编排逻辑把「确保运行时」写成无条件的。

## 时间测量口径

| 指标 | 起点 | 终点 | 目标 |
|---|---|---|---|
| 冷启动 | 进程启动 | 主窗口可交互 | < 3 秒 |
| 首次连接 | 用户消息发出 | 状态变为 running | ≤ 15 秒（运行时就绪后） |
| 从说「连接」到 running | 同上 | 同上 | 9.5 指标口径，用于统计成功率 |

测量方式：应用结构化日志打 `event=connect_start` / `event=connect_done` 带毫秒时间戳与 `duration_ms`。**不要用测试脚本的外部计时**，它包含 UI 渲染抖动，不可复现。
