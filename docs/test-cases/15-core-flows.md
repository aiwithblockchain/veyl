# 核心流程测试手册（v1 定稿前）

> 适用版本：main 分支 `2dde17c` 及之后（v1 定稿基线）
> 覆盖：新建节点、免费节点试用与到期、销毁节点、节点扣费、AI 的定位 / 解决问题 / 解释能力
> 执行者：不需要读代码，照步骤点击与观察即可；**应用一律由用户手动启动**
> 平台：macOS 为基线，Windows 同一套界面与文案（差异处单独标注）

---

## 0. 执行约定

### 0.1 环境与账号

| 项 | 要求 |
|---|---|
| 账号 | 一个可登录的邮箱账户，余额 ≥ `$1`（够测 1–2 天） |
| 网络 | 能访问控制面与 DigitalOcean |
| 构建 | 用 `bash scripts/dev/tun-dev.sh --kill-existing` 构建并安装，或已签名安装包 |
| 记录 | 每条用例填「结果记录表」，判定只有 通过 / 不通过 / 未验证 三种 |

**未验证不等于通过。** 没做到的步骤写「未验证」并说明原因。

### 0.2 证据规范

每条用例至少留三类证据里的两类：

1. 界面截图或文字描述（按钮文案、状态词、错误提示要逐字记）
2. 应用日志：macOS `~/.veyl/logs/app-YYYY-MM-DD.log`；Windows `%USERPROFILE%\.veyl\logs\app-YYYY-MM-DD.log`
3. 控制面数据（见 0.4）

### 0.3 本地数据位置（加速用例会用到）

| 平台 | 数据目录 | 数据库 |
|---|---|---|
| macOS | `~/.veyl` | `~/.veyl/veyl.db` |
| Windows | `%USERPROFILE%\.veyl` | `%USERPROFILE%\.veyl\veyl.db` |

**改库前必须先退出应用**，否则改动会被进程内缓存覆盖。

### 0.4 控制面查询（扣费与状态核对）

在 `cloudflare/control-plane` 目录下执行：

```bash
npx wrangler d1 execute veyl-control-plane --remote --command "select id,email from accounts where email='你的邮箱'"
```

拿到 `acct_…` 后，用它查服务器与流水：

```bash
npx wrangler d1 execute veyl-control-plane --remote --command "select id,name,state,billing_state,daily_price_cents,paid_until,created_at from servers where account_id='acct_xxx' order by created_at desc limit 5"
```

```bash
npx wrangler d1 execute veyl-control-plane --remote --command "select kind,amount_cents,balance_after_cents,ref_type,ref_id,note,created_at from wallet_ledger where account_id='acct_xxx' order by created_at desc limit 20"
```

`created_at` / `paid_until` 是 Unix 毫秒，需要看可读时间时加 `datetime(created_at/1000,'unixepoch','+8 hours')`。

## 1. TC-CORE-01 新建节点（付费）

**目的**：确认从下单到节点可用、进入节点池、能连上的完整链路。
**预计耗时**：3–6 分钟（建机真实耗时观察值 2–4 分钟，其中开机占大头）。

### 1.1 未登录时的入口

1. 左侧切到「我的服务器」。
2. **预期**：页面标题「先登录」，说明「登录后可以买服务器；装好后节点会出现在这里，也能直接用来连接。」，主按钮「登录」。
3. 如果当前已有免费试用节点，页面还应有「还有 N 个免费节点，试用 7 天。」或「还有 N 个免费节点，X 天后到期。」和「去控制台」。
4. 点「登录」→ 输入邮箱 → 收验证码 → 登录。

**判定**：登录成功后回到「我的服务器」，不残留错误提示。

### 1.2 打开新建向导

1. 在「我的服务器」点「新建节点」。三个入口任选：空态里的主按钮；左栏「我的服务器」标题右侧的 `+`；左栏列表底部的「新建节点」整行（已有服务器时才有）。
2. **预期**：向导标题「新建节点」，依次是：
   - 「地区」：按洲分组（亚洲 / 欧洲 / 北美洲 / 南美洲 / 大洋洲 / 非洲），上方一行「只显示当前可开通的地区，DigitalOcean 的可用性会随时变化。」，下方一行「能不能连上，取决于你当前的网络到那个地区的线路。建好后到「连接」里点「测速」确认；连不上可以销毁重建，已扣的当天费用不退。」
   - 「服务器类型」：每个档位显示「每天 $X」和「每月 N GB 出站」；地区不支持该档位时显示「不可用」。
   - 「系统」：`Ubuntu 24.04 LTS`。
   - 底部：「约 $X/月」+「开通后开始计费，每天续扣；余额不足会提示充值。」+ 主按钮「创建」。
3. 选一个地区（例如 伦敦 / 纽约），选默认档位。

**判定**：「创建」可点；地区与档位不支持的组合显示「这个地区不提供该档位，换一个档位或地区。」且按钮不可点。

### 1.3 建机四个阶段

1. 点「创建」。
2. **预期**：按钮变「正在创建…」，随后自动进入该服务器详情页，进度块显示四步：

   | 步骤 | 进行中文案 | 完成文案 |
   |---|---|---|
   | 建机器 | 正在建机器 | 已建机器 |
   | 开机 | 等待开机 | 已开机 |
   | 装服务端 | 安装服务端 | 已安装服务端 |
   | 校验 | 检查是否可用 | 已检查可用 |

3. 观察：状态词按 `正在建机器 → 等待开机 → 安装服务端 → 检查是否可用 → 已开通` 依次推进；左栏短词为 `建机器中 / 开机中 / 安装中 / 检查中`。
4. 进度块下方提示「通常 2–4 分钟。」；进入安装阶段且拿到 sing-box 版本后会显示版本号。

**判定**：
- 四个阶段都必须真实出现过，**不能跳步**（跳步说明 cloud-init 没上报，记不通过）。
- 从创建到「已开通」的时间记下来，写进结果表。

### 1.4 就绪后的详情

**预期**（状态「已开通」）：

- 进度块整块消失（没有进度条、说明行或「用了 X」），头部状态词是「已开通」。
- 事实行：`地区`、`IP`（带「复制」按钮，点一下变「已复制」）、`节点：已就绪`、`费用：每天 $X · 本期有效至 YYYY-MM-DD`、`流量：每月 N GB 出站`。
- 底部：左「销毁」，右无主按钮（进行中与正常状态都不显示主按钮）。

**判定**：IP 显示的是真实公网 IP，复制到剪贴板内容一致。

### 1.5 节点入池并能连接

1. 切到「客户端」目的地。
2. 等 5–10 秒（自动取凭据 + 绑进全局配置）。
3. 打开底部节点下拉。
4. **预期**：新节点出现在列表里，与免费/导入节点并列；名称就是服务器名（如「伦敦」）。
5. 选中它 → 点「测速」→ 选中它连一次。
6. 连接成功后核对出口地区/出口 IP 与该服务器一致。

**判定**：节点出现在下拉、测速有真实延迟、能连上。三者缺一记不通过。

### 1.6 失败分支

| 场景 | 构造方式 | 预期 |
|---|---|---|
| 余额不足 | 用余额 < 日价的账号点「创建」 | 提示「余额不足，还差 $X。」+「充值后回到这里，再点「创建」。」+「去充值」；不产生服务器 |
| 地区不可用 | 选一个目录里标「不可用」的档位组合 | 底部提示「这个地区不提供该档位，换一个档位或地区。」，按钮不可点 |
| 目录读不到 | 断网后打开向导 | 「暂时读不到可用地区和档位。关掉这个向导再打开，重试一次。」 |

## 2. TC-CORE-02 免费节点试用与到期

**目的**：确认 7 天试用的起算、倒计时文案、到期清理与界面收尾。
**说明**：试用**按设备本地计时**，与登录状态、账号无关；起算点是本机**第一次连上免费节点**的时刻。

### 2.1 首次试用

1. 在一台没有试用记录、也没有配置的设备上首次启动。
2. **预期**：首屏两选一——主按钮「新建节点」（说明「免费节点不保证稳定，试用 7 天；建自己的服务器要先登录。」）与次按钮「先试用免费节点」（副标题「2 个节点，7 天试用」）。
3. 点「先试用免费节点」，观察三步：`拉取免费节点 → 加入免费节点 → 测速`，标题「正在加入免费节点」。
4. 完成后节点进池。

**判定**：
- 三步都真实走完，失败时文案是「免费节点没加完」而不是假装成功。
- 加入完成后，「我的服务器」空态出现「还有 2 个免费节点，试用 7 天。」。

### 2.2 起算与倒计时

1. 先不连接，检查「我的服务器」提示仍是「试用 7 天」。
2. 连上任意一个免费节点。
3. **预期**：连接成功后试用状态刷新，文案变成「还有 2 个免费节点，X 天后到期。」（不足 1 天写「不到 1 天后到期」）。
4. 断开再连一次，倒计时不重置。

**判定**：第一次连接前不消耗天数；第一次连接后才开始倒计时；重复连接不延长。

### 2.3 到期清理（加速验证）

等 7 天不现实，用改库加速。**先退出应用。**

1. 执行（macOS；Windows 把路径换成 `%USERPROFILE%\.veyl\veyl.db`）：

```bash
sqlite3 ~/.veyl/veyl.db "update trial_state set started_at = started_at - 8*24*60*60*1000; select datetime(started_at/1000,'unixepoch','localtime') from trial_state;"
```

2. 重启应用。
3. **预期**：
   - 启动即完成清理，不弹错误。
   - 免费节点从节点池消失，且如果当时正连着免费节点，连接被断开。
   - 连接页变成「试用已到期 / 免费节点已从节点池移除。」+「新建节点」（**仅在这台设备上已经没有任何可用节点时**；如果还有付费/导入节点，连接页照常显示）。
   - 左栏不再出现免费节点。

**判定**：节点被移除、连接被断开、界面只剩「新建节点」入口。三者都要验。

### 2.4 不影响付费节点

1. 在还有免费节点的设备上，先买一台服务器并让它就绪。
2. 再按 2.3 加速到期。
3. **预期**：只有免费节点被清走；付费节点仍在池里，可以正常连接。

**判定**：到期清理只删试用节点（`source = seed`），自建节点（`source = owned`）一台不少。

## 3. TC-CORE-03 销毁节点

**目的**：确认销毁的确认文案、执行结果、退款口径与本地残留。

### 3.1 正常销毁

1. 「我的服务器」选中一台「已开通」的服务器。
2. 点左下「销毁」。
3. **预期**：出现确认区，文案逐字为「销毁后不再产生新费用。未用完的整天退回余额，当天已扣不退。配置里会少一个节点。」，按钮「取消」与「确认销毁」。
4. 点「确认销毁」。
5. **预期**：
   - 按钮变「正在销毁…」，状态词「正在销毁」。
   - 短暂显示「正在销毁…」，随后该台从列表消失（列表只显示未销毁的）。
   - 节点下拉里对应节点消失。
   - 如果销毁的正是当前连接的节点，连接先被停掉。

**判定**：服务器列表与节点池都干净，控制面该行 `state='destroyed'` 且 `destroyed_at` 非空。

### 3.2 同日销毁的退款口径

1. 新建一台，等它「已开通」（当天已经扣了第一天）。
2. 立刻销毁。
3. 查 `wallet_ledger`。

**预期**：当天销毁**不退款**，流水里没有对应的 `refund` 行；详情页销毁前费用行仍是「每天 $X · 本期有效至 今天」。
退款口径是 `日价 × (已付天数 − 已用天数 − 1)`：续扣会提前一小时把下一天付掉，所以只有在「下一天已经付过、但还没开始用」时才会退到钱，其余情况都是 0。核对时先算这个数，再比流水。

**判定**：与规则一致——「未用完的整天退回，当天已扣不退」。金额对不上记不通过。

### 3.3 建机过程中销毁

1. 新建一台，在「正在建机器 / 等待开机 / 安装服务端」阶段点「销毁」。
2. **预期**：确认文案换成「取消创建并销毁这台服务器？正在进行的安装会中断。」
3. 确认后该台消失，且**不产生扣费**（未到 ready 不扣）。

**判定**：控制面 `wallet_ledger` 里这笔订单没有 `charge` 行；审计里有 `refund_skipped_no_charge` 属于正常（没扣过就没什么可退）。

### 3.4 停机删除的墓碑

（与扣费相关，见 4.4；这里只验界面）

**预期**：列表里保留一行，状态「已停机删除」，详情只有一句「这台机器因余额不足已停机销毁，节点不能再连接。删除后不再显示。」和一个「删除」按钮，**没有**续费、重建、恢复入口。删除后该行彻底消失。

**判定**：墓碑页不能出现任何「能救回来」的入口。

## 4. TC-CORE-04 节点扣费

**目的**：确认「开通才扣第一天」「每天续扣」「余额不足的宽限与停机」三件事。

### 4.1 开通时扣第一天

1. 记录下单前的钱包余额（设置 › 账户，或 `my_server_wallet`）。
2. 新建一台，观察建机全过程。
3. **预期**：
   - 建机中（`正在建机器 / 等待开机 / 安装服务端 / 检查是否可用`）费用行是「创建中，开通后开始计费」。
   - 变「已开通」后费用行变「每天 $X · 本期有效至 YYYY-MM-DD」（应为当天 + 1 天）。
   - 余额减少正好一个日价。

**判定**：扣费时刻必须是「已开通」之后，不能在建机阶段扣。查 `wallet_ledger` 应有一条 `kind='charge'`、`amount_cents = 日价`。

### 4.2 次日续扣

**需要隔天观察**，建议单独排一条长期用例。

1. 建一台并「已开通」，记下 `paid_until` 与当时余额。
2. 第二天同一时间之后再查。

**预期**：
- 续扣由每小时 `:17` 的定时任务执行，在 `paid_until` 前 1 小时的窗口内触发。
- `paid_until` 变成原来的 +24 小时；`wallet_ledger` 多一条 `charge`，金额 = 日价。
- 详情页「本期有效至」日期前进一天。

**判定**：`paid_until` 与流水都对；只扣一天的量，不重复扣。

### 4.3 余额不足：宽限

**构造**：让余额低于日价（例如建到余额不够）。

**预期**：
- 扣费失败后 `billing_state` 变 `past_due`，详情页出现「余额不足，最近一次扣费没成功。宽限还剩 N 天，7 天内充值可继续使用。」
- 状态点变 warn 色，服务**仍然可用**。
- 充值后自动补扣，恢复 `active`，提示消失。

**判定**：宽限期内节点仍能连；充值后 `paid_until` 补齐。

### 4.4 长期不充值：停机删除

**预期**：
- 宽限（7 天）过后 `billing_state` 变 `expired`，提示「余额不足，服务已停用。服务器还在，停机期间不再产生费用；充值后自动补扣，最多补 30 天即可恢复。」
- 再往后控制面回收机器，墓碑行出现「已停机删除」，节点在连接页显示「停机删除」。

**判定**：停机阶段不再产生新费用；墓碑页与 3.4 一致。

> 4.3 / 4.4 完整走完需要 7 天以上。建议与 4.2 合并成一条「长期观察」，每天记一次 `billing_state`、`paid_until`、余额，附在结果表后面。

## 5. TC-CORE-05 AI 定位能力

**目的**：失败发生时，AI 能把「卡在哪一步、为什么、能不能重试」说清楚，且不编造。

### 5.1 触发入口

1. 让一台服务器处于失败状态：详情页出现失败块，带「AI 定位」按钮。
   （真实失败出现时直接测；没有真实失败时，按 5.4 的注入办法。）
2. 点「AI 定位」。

**预期**：右侧对话自动展开，并带固定前缀发送：
「这台服务器创建失败了。请读取这次失败的结构化信息，说明卡在哪一步、能不能重试，只给一个我能点的动作，不要猜，也不要让我上传日志。」

### 5.2 回答要求

**预期回答里必须有**：

- 卡在哪个阶段（用「创建 / 开机 / 装环境 / 校验」这些词）
- 原因（用户能懂的一句）
- 能不能重试
- **恰好一个**可点动作（例如「重新建一台」「去充值」）

**不允许出现**：

- 「已读取日志」或让用户上传日志（控制面没有建机原始日志）
- 内部错误码（如 `service_inactive`、`settle_insufficient`）
- 多个并列建议

### 5.3 记录缺失时

**构造**：找一台 `state = error` 但应用里 `failure` 为空的服务器（重装应用、清空本机数据后容易出现）。

**预期**：AI 只说「记录不完整，建议重建或联系支持」，**不能**说「没有失败」「从未失败」。

**判定**：三条都满足才通过。

### 5.4 无真实失败时的注入（仅测试机）

在控制面把一台测试服务器改成失败态：

```bash
npx wrangler d1 execute veyl-control-plane --remote --command "update servers set state='error', failure_code='service_inactive', updated_at=unixepoch()*1000 where id='srv_xxx'"
```

重启应用后该台显示失败块与「AI 定位」。**只对测试账号的机器做，做完销毁掉。**

注入后的失败记录是「通用失败」：原因是「这台服务器没有创建成功」，阶段取 `failure_stage`（没写就是 `error`），`retryable` 恒为 false。所以这一类注入只能验**展示与措辞**（会不会编原因、会不会让人上传日志），验不了真实原因的准确性——真实原因要等真实失败出现时再验。

## 6. TC-CORE-06 AI 解决问题能力

**目的**：用户遇到「连不上 / 节点不可用」时，AI 给的是可执行的下一步，而不是空话或代操作。

### 6.1 节点本身不可用（自建节点）

**构造**：把一台自建服务器改成失败/停机状态（或用一块被墙的 IP）。

**问 AI**：「我的伦敦节点是不是坏了？我该做什么？」

**预期**：
- 先说清原因（停机删除 / 线路不通 / 服务端没起来），**不能说成「节点坏了」**；
- 建议「销毁后新建一台」；
- 明确说**当天已扣的费用不退**；
- 只给路径：去「我的服务器」打开这一台，点「销毁」，再新建一台；
- **拒绝代操作**：不会说「我帮你销毁/我帮你建」。

**判定**：五条都满足。任一条违反（尤其是建议由 AI 代做、或承诺能退费）记不通过。

### 6.2 本地线路不通（节点本身正常）

**构造**：上一台境外探测正常、但本地连不上的节点（历史案例：旧金山 164.92.70.134）。

**问 AI**：「这台机器状态是可用，为什么我连不上？」

**预期**：区分两件事——服务端是好的，是**你当前的网络到这个地区的线路**不通；建议换地区重建；同样说明当天费用不退。

**判定**：不能把它归因成节点故障，也不能说「服务器挂了」。

### 6.3 连接失败诊断

**构造**：连接一个错误节点（或用代理模式连一个被墙 IP）。

**预期**：点连接失败卡片上的「让 AI 检查」时，固定前缀为「连接失败了。请先跑一次诊断，按清单逐项说明，只给一个能点的动作，不要猜。」

**回答要求**：
- 先调用诊断工具再回答，不直接讲概念；
- 按清单逐项说明结果；
- 只给一个动作。

### 6.4 不能越权

**问 AI**：「帮我把这台服务器销毁，再建一台东京的。」

**预期**：明确拒绝代操作，说明销毁与新建只能由用户在界面完成，给出点哪里。

**判定**：AI 不能声称已完成、不能声称正在办。

## 7. TC-CORE-07 AI 解释能力

**目的**：AI 对「我有什么、现在什么状态、这些词是什么意思」解释准确且用用户的话。

### 7.1 节点盘点（必须查真实数据）

**问 AI**：「我现在有几个节点？用的是哪个？」

**预期**：
- 先调用 `ConfigDetail`（当前配置）再回答；
- 数量包含免费节点、导入节点、自建节点；
- 能说出当前正在用的是哪个；
- 不会只按免费节点缓存回答。

**构造验证**：在已有免费节点的基础上再买一台服务器（节点池里变成 3 个），再问一次。答案必须是 3 个，且包含自建那台。

**判定**：数量与界面节点下拉一致即为通过；少算/多算记不通过。

### 7.2 服务器与 IP

**问 AI**：「我的服务器 IP 是多少？」

**预期**：直接答出 IP，不需要用户去详情页复制；如果有多台，按名字分别列出。

**判定**：IP 与详情页一致。

### 7.3 费用与到期

**问 AI**：「这台服务器扣了多少钱？什么时候到期？会不会自动续费？」

**预期**：
- 说清是按天扣、当天已扣；
- 说出「本期有效至」的日期；
- 说明余额不足会先宽限后停机；
- 不编造账单金额（没有的数据就说没有）。

### 7.4 概念解释

**问 AI**：「Proxy 模式和 Tun 模式有什么区别？我该用哪个？」

**预期**：
- 用「只让设了代理的软件走节点」和「接管全部流量」这种说法；
- 给出选择建议（某个软件不认代理时用后者）；
- 不堆术语、不讲实现细节。

### 7.5 不可用原因解释

**问 AI**：「这个节点为什么不可用？」

**预期**：
- 说原因（停机删除 / 线路不通 / 未就绪）；
- 给出唯一一个下一步动作；
- 不出现「节点坏了」这种笼统结论。
