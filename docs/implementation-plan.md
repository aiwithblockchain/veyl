## 1. 种子消费对象（已确认：换成 `veyl_seed.json`）

**决定：客户端只消费 `veyl_seed.json`。**（产品负责人 2026-11-03 确认）

现在的 `default_profile.rs` 解析的是上游那份**完整 sing-box 配置**（含 `selector` / `urltest` / DNS / route）。切换之后：

- **丢掉**上游现成的 selector 分组与 DNS/route 配置
- **换来**节点与配置解耦，可以按用户生成不同分流

代价是**配置生成要自己从头开始写**，包括节点切换用的 `selector`。这个代价必须付——不换就做不了「分流千人千面」。

### 不做迁移，直接删

**产品还没有用户，旧数据与旧逻辑一律删除，不留兼容层。** 这省掉一整类临时分支与双写。

**删掉：**

| 对象 | 位置 |
|---|---|
| 单节点 `profiles` 表与读写 | `store/migrations/001_init.sql`、`store/profiles.rs` |
| `bootstrap.json` 的完整配置解析与包校验 | `default_profile.rs`（解析层与 `selector`/`urltest` 白名单那套） |
| 旧的 seed 导入 | `seed_import.rs` |
| 旧首次引导 | `src/components/Onboarding.tsx` |
| 旧节点列表 | `src/components/ProfileList.tsx`、`StatusPanel.tsx` 里与之耦合的部分 |

数据库直接重建：删掉现有迁移，写一份新的 `001_init.sql`，从零开始。

**保留（这些是基础设施，不是旧配置逻辑）：**

| 保留 | 为什么 |
|---|---|
| `runtime/` 全套 | 安装、启动、停止、健康、原子升级都与配置格式无关 |
| `default_profile.rs` 的 `fetch` | HTTPS 强制、禁跨域重定向，直接复用 |
| `proxy/macos.rs` | 系统代理与备份恢复 |
| `secrets/` | 凭据加密存储 |
| `agent/` 与工具通道 | AI 会话与 `AskUserQuestion` |

节点切换的 `selector` 由我们自己生成，不再依赖上游。

## 2. 分批

### 批 1 · 数据地基

| 项 | 内容 |
|---|---|
| 删除旧逻辑 | 按 §1 的删除清单清掉单节点模型、`bootstrap.json` 解析、旧引导与旧节点列表；数据库重建 |
| 配置模型 | 新增「配置」实体：名字、连接方式、分流策略、节点集、当前节点、端口 |
| 种子 | 解析 `veyl_seed.json`，落盘缓存，按内容哈希检测更新 |
| 节点导入 | URL（base64 多节点订阅）解析；手动编辑五个字段 |
| 凭据 | 密码只进 `secrets.enc`，库里只留引用 |
| 命令 | `config_list` / `config_create` / `config_update` / `config_delete` / `config_activate` / `node_import_url` / `node_create` |

**完成标准**：能通过命令创建一套配置（种子节点或自建节点），并能从中生成一份可启动的 sing-box 配置。

---

### 批 2 · 界面骨架

| 项 | 内容 |
|---|---|
| activity bar | 最左侧，本期只有「客户端」一个图标（2026-11-13 增加第二项；2026-11-14 定为「节点组」，见 `docs/design/remote-groups.md` §7.1） |
| 左栏 | 配置列表：名字 · 节点个数 · 端口；空态；新建 |
| 中间骨架 | 顶部单按钮（启动/断开）、中间留空、底部节点详情 |
| 底部交互 | 节点名可点展开全部节点；选中只改详情，按「切换到此节点」才切 |
| 测试按钮 | 测当前节点连通性 |

**完成标准**：空列表 → 新建 → 出现配置 → 点顶部按钮能连接。全程不依赖 AI。

---

### 批 3 · 配置生成（分流与 DNS）

| 项 | 内容 |
|---|---|
| 规则集 | 预置 `.srs` 随包，按用户国家 + 目标服务按需加载 |
| 分流生成 | 本地直连 / 全部走 VPN / 指定服务走 VPN，三种模式生成 `route.rules` + `final` |
| 免重启切换 | 用 `selector` 热切，不改配置 |
| DNS | 本地 2–3 候选直连、境外 2 候选经代理；分类与路由同源 |
| 自定义规则 | 用户加的域名 / IP 覆盖，叠在预置之上，**不随种子更新被覆盖** |

**完成标准**：三种分流模式都能生成正确配置并实际生效；切换模式不断流。

---

### 批 4 · 首次流程与 AI 编排

| 项 | 内容 |
|---|---|
| 提问 | 两/四问，走 `AskUserQuestion`（一级线一次能力提问、二级线一次、三级合流追问） |
| 二选一 | `source_choice`：用测试节点 / 用我自己的节点 |
| 块系统 | 六个块：`empty_hint` / `proxy_card` / `source_choice` / `reachability` / `issue_card` / `update_hint`（AI 可写前五种，`issue_card` 只由系统叠加） |
| 布局持久化 | AI 输出的布局描述落库，下次直接还原 |
| 系统提示词 v1 | 把整套流程写成 AI 可执行的指令，能力清单与 `capabilities.md` 同源 |
| 文案约束 | 界面不出现 proxy / TUN / 分流 / 规则集 |

**完成标准**：新用户从空白开始，走完提问、拿到配置、连上、看到可达性检查，全程不需要手动操作。

### 批 5 · TUN 与特权助手

| 项 | 内容 |
|---|---|
| TUN 入站 | 按 `docs/tun-mode.md` 的固定参数与四处差异 |
| 特权助手 | `SMAppService`（macOS 13+）/ `SMJobBless`，与 App 同证书签名 |

### 批 6 · 问题管理与恢复

| 项 | 内容 |
|---|---|
| 采集与登记 | 探测与运行时事件 → 结构化记录，同类合并计数 |
| 展示 | `issue_card`（中间）+ 问题列表 |
| 转交 | 用户确认后一次性投喂诊断包 |
| E3 重置网络 | 五步顺序，复用 `proxy_backup` |
| 启动自检 | 发现「代理还在但运行时没跑」→ 主动提示恢复 |
| 卸载清理 | **与 E3 共用同一段代码** |

**完成标准**：断网状态下、AI 不可用时，用户仍能看见问题并一键恢复；卸载后网络干净。

### 批 8 · Windows TUN（下一项）

**状态：已列入下一项，但前置条件未满足前不开工。** 设计判断见 `docs/windows-tun.md`。

| 项 | 内容 |
|---|---|
| 服务模型 | 应用 per-user 安装、不要求管理员；**首次需要 TUN 时**提权安装 LocalSystem 常驻服务；拒绝后可重试、不重装；命名管道通信 + 对端 Authenticode 验签 |
| 驱动 | Wintun（官方 `wintun.dll`，随 `sing-box.exe` 同目录、同架构） |
| 运行时 | Windows zip 拉取、校验、解压；`build-msi.ps1` 安装运行时与服务 |
| 安装/卸载 | per-user 应用安装器 + 独立的提权服务安装器；卸载删服务、删适配器、恢复代理/DNS，与 E3 共用清理代码 |
| 平台配置 | `strict_route`、`stack`、`interface_name`、内网排除反推 |
| 签名 | Windows 代码签名证书（EV/OV）或 Azure Trusted Signing；时间戳；MSI 签名 |

**开工前置（缺一不可）：**

1. Windows 代码签名证书或云签名账号（当前无法确认是否已有）。
2. Windows 10/11 x64 真机（管理员权限、可反复装卸）；CI 不能验证 TUN。
3. **提权时机已定**（2026-11-04 修正）：安装不要求管理员，AI 判定需要 TUN 后才提权安装常驻 LocalSystem 服务；拒绝后可重试，不重装。
4. 法务确认 Wintun（预编译 DLL 专有许可）与 sing-box（GPL-3.0）的分发条款。

**粗估**：1 人 4–6 周（不含证书采购与身份验证的 1–3 周）。

## 5. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **TUN 特权助手**是最不确定的一块 | 阻塞二级用户 | 尽早做技术验证，先跑通最小可用的授权 + 起 TUN，再谈优雅 |
| 分流规则集体积与加载 | 影响首启速度 | 已定按需加载，不全量 |
| 种子格式切换会丢上游现成配置 | 需要自己重建 selector/DNS/route | 已确认按 `veyl_seed.json` 走，见 §1 |
| 删旧逻辑时误删仍在用的部分 | 返工 | §1 有明确保留清单；删之前先确认不在清单里的东西确实没人引用 |
| 系统提示词质量 | 决定首次体验 | 提示词要有版本号，能独立更新（`docs/upgrade.md`） |
| 文档仍在演化 | 实现容易照着旧文档写 | 每批开工前先对齐当天的文档状态 |
