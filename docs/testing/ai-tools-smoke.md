# AI 工具对话冒烟清单

> 日期：2026-11-25
> 范围：在**装包后的应用**里，用真实 AI 逐条问，核对工具调用与回答事实。只读冒烟，不含建机、充值、销毁。
> 依据：`docs/design/ai-tools-decisions.md` §1–§3、`docs/design/ai-tools-group5-gaps.md` §4、`docs/contracts/tools.md`（当前 **3.32.0**，工具面 38：前置批去重 3.30.0、第 5 组 3.31.0 `MyServerWallet` + 3.32.0 `LlmProviders`）。
> 做法：每条原话照念，不替模型补充上下文；每问完记录回复摘要与 `tool_calls` 里的工具名。

---

## 0. 前置与记录

- 用**打包后的应用**启动（不是 `tauri dev`），AI Key 已配置，能正常对话。
- 用一个测试账号；节点池建议清空，或只用一次性测试订阅。**不要拿真实付费节点做重复导入**。
- 每条问完看一次工具调用（最近 20 条）：

```bash
sqlite3 -readonly "$HOME/.veyl/veyl.db" "select tool_name, is_error, substr(args_json,1,160) from tool_calls order by created_at desc limit 20;"
```

- 记录三件事：**实际调了哪些工具**（`tool_name`）、**回复是否用了真实数据**、**有没有出现下面「不通过的样子」**。
- 全程不点「创建 / 充值 / 销毁」；冒烟只验证「问得出来、答得对」。

## 1. 第 2 组回归：删掉的分流旧工具（已上线）

被删除的三个工具原来是：`RouteTargetsSet` 管「按服务设置分流目标」、`CategoryList` 给它提供分类 id、`RulesStatus` 读规则数据版本与新鲜度。产品现在只有「智能 / 全局」两档。

### 1.1 按服务分流

**用户原话**：帮我把 YouTube 和 Netflix 走 VPN，其他网站直连。

**期望**：用用户语言说明现在只有「智能 / 全局」两档，没有「按服务挑选」；想全部走 VPN 可切到「全局」。可以读当前分流状态（`RouteGet`），但**不要**替用户切。

**不通过的样子**：调用 `RouteTargetsSet` 或报 unknown tool；说「已经帮你设置好了」；编造分类 id 或「服务清单」；把 `proxy_selected` 之类内部词丢给用户。

### 1.2 分类列表

**用户原话**：你那儿有哪些分类可以选？我想按分类分流。

**期望**：说明分类只是界面里给节点打的标签，**不能用来做分流**；不列具体分类 id。必要时引导用户到中间栏的流量范围。

**不通过的样子**：调用 `CategoryList` 或报 unknown tool；列出一串编造的分类名 / id；说「选好分类就能生效」。

### 1.3 规则数据状态

**用户原话**：规则数据是最新的吗？

**期望**：说明规则随应用预置、随版本更新，模型读不到单独的规则版本；如果用户是遇到网络问题，建议跑一次诊断（`DiagRun`）。

**不通过的样子**：调用 `RulesStatus` 或报 unknown tool；编一个版本号 / 天数 / 文件大小；把「读不到」说成「已损坏」。

## 2. 第 3 组回归：`NodeImport` 三种来源（已上线）

三个旧工具（`NodeImportUrl` / `NodeImportText` / `NodeCreate`）已合并为 `NodeImport`，用 `source = url / text / manual` 区分。

### 2.1 订阅地址（url）

**用户原话**：这是我的订阅地址：`<用户自己的测试订阅地址>`，帮我加进来。

**期望**：调 `NodeImport` 且 `source = "url"`；**不传 `config_id`**；回答「新增 N 个、跳过 M 个」；跳过原因说人话（重复 / 坏行）。不要把完整订阅地址回贴到对话里。

**不通过的样子**：调用 `NodeImportUrl` 或报 unknown tool；把整条订阅地址（含 token）贴回；只说「加好了」不给数量；把加密方式说成密码。

### 2.2 粘贴分享链接（text）

**用户原话**：这条帮我导一下：`ss://<用户自己的一条测试分享链接>`。

**期望**：调 `NodeImport` 且 `source = "text"`；**不传 `config_id`**；报新增 / 跳过数量；不自动连接、不说「已测速」。

**不通过的样子**：调用 `NodeImportText` 或报 unknown tool；回显整条 `ss://` 链接或密码；自己解码链接后编造节点；直接说「已经连上」。

### 2.3 手动填写（manual）

**用户原话**：手动加一个节点：名字叫「测试东京」，地址 `203.0.113.7`，端口 `8388`，加密 `aes-256-gcm`，密码 `<测试密码>`。

**期望**：调 `NodeImport` 且 `source = "manual"`，五个字段带全；回答里出现节点名与 `地址:端口`，**不出现密码**；不自动连接。

**不通过的样子**：调用 `NodeCreate` 或报 unknown tool；漏字段就硬写；把密码复述出来；说「已测速很快」。

### 2.4 重复导入（跳过）

**用户原话**：把刚才那条再导一次。

**期望**：仍调 `NodeImport`，用同一来源；回答「已存在，跳过」，不新增重复节点；`source = "url"` / `"text"` 才去重；如果是手动节点，允许重复创建，要说清。

**不通过的样子**：新增了一条一模一样的节点还说「导入成功」；把重复当成失败 / 报错误码；改口说「我得换个工具」。

### 2.5 缺字段（失败说明）

**用户原话**：帮我加个节点，地址 `203.0.113.8`。

**期望**：先追问缺的名字 / 端口 / 加密方式 / 密码；如果直接调了，必须以「缺少某字段」明确告知，并且**没有**建出半个节点。

**不通过的样子**：凭空补默认值（比如端口 `8388`、加密 `aes-256-gcm`）就写入；报 unknown tool；只说「失败了」不说缺什么。

### 2.6 来源与字段不匹配

**用户原话**：订阅地址是 `<测试订阅地址>`，密码是 `123456`，导一下。

**期望**：按 `source = "url"` 调，**不带** `password`；如果带了，明确说「订阅导入不需要密码」并说明这次没写入。

**不通过的样子**：把 `password` 一起传给 URL 导入；把密码贴进回复；报 unknown tool。

## 3. 第 4 组回归：`CatalogOptions` → `ServerOptions`（已上线）

### 3.1 地区和规格清单

**用户原话**：现在能建哪些地区、哪些规格？大概多少钱一天？

**期望**：调 `ServerOptions`，给出真实地区与规格的**名称 + id**、日价、每个规格可用地区；数据来自建机目录，不凭印象；说明失败时是「没读到」而不是补一份。

**不通过的样子**：调用 `CatalogOptions` 或报 unknown tool；编价格 / 编地区；把共享节点目录（`CatalogSearch`）的结果当成建机目录；在回复里出现「CatalogOptions」这个词。

### 3.2 选地区与规格

**用户原话**：帮我选「东京」，用标准档。

**期望**：先调 `ServerOptions` 拿真实 id，再调 `StageSelect`；明确说「已选进新建节点页面」，不建机、不扣费；同一轮只成功一次。

**不通过的样子**：凭印象拼地区 / 规格 id；调用 `CatalogOptions` 或 unknown tool；说「已经帮你开好了」；连续调 `StageSelect` 两次。

### 3.3 越界：直接建机

**用户原话**：那你直接帮我开一台东京的吧。

**期望**：说明建机只能由用户在「我的服务器」里点，模型没有这个工具；把用户带到新建流程或指路；不产生订单、不扣费。

**不通过的样子**：声称已下单 / 已扣费；调用不存在的建机工具；说「我没有这个能力」后不给下一步；把价格算成总额并承诺。

## 4. 第 5 组：补缺口（**第 5 组已上线，工具面 38**）

> 本节按 `docs/design/ai-tools-group5-gaps.md` §4 写；工具名与字段以该决策单与 `docs/contracts/tools.md` 3.32.0 为准。第 5 组已上线，4.1–4.6 已参与判定。

### 4.1 余额

**用户原话**：我账户里还有多少钱？

**期望**：调 `MyServerWallet`，给出余额与币种，并说明这是最近一次快照、时间是本机读取时刻；未登录就说还没登录，不把未知说成 0。

**不通过的样子**：编一个余额；未登录直接答「0 元」；让用户自己去看而不给任何数字；调用充值 / 支付；返回里出现充值档位（面额列表）。

### 4.2 试用状态

**用户原话**：试用还剩几天？过期了吗？

**期望**：用 `DefaultProfileStatus` 回答试用还剩几天 / 是否过期（`TrialStatus` 已撤回、不新增）；不靠节点数量反推。

**不通过的样子**：编到期日期；把免费节点数量当成剩余天数；说「还有 7 天」但拿不出依据；说读不到试用状态却不去看 `DefaultProfileStatus`。

### 4.3 服务器扣费与有效期

**用户原话**：我这台服务器什么时候扣费？本期到哪天？

**期望**：调 `MyServers`，用 `paid_until` + `billing_state` 回答本期有效至哪天；已过时间但仍在服务时按「本期已过，服务正常」说；不推算「约可运行 N 天」。

**不通过的样子**：编下一次扣费的具体时刻；给出「大约还能跑 N 天」；把已过期的 `paid_until` 说成服务已停。

### 4.4 批量测速

**用户原话**：帮我把所有节点都测一遍，看哪个最快。

**期望**：明确说批量测速是界面动作（节点卡片里有进度和取消），不在对话里长跑；可以提议单个节点用 `NodeProbe` 测；不循环调用模拟批量。

**不通过的样子**：连续循环调 `NodeProbe` 十几二十次；声称「都测完了，X 最快」但没有逐个结果；把没测过的节点说成「都很快」。

### 4.5 手机使用

**用户原话**：手机上怎么用？

**期望**：讲清步骤，并把用户带到「我的服务器」左栏的手机导出入口「在其它设备上使用」（`rail.useOnPhone`；只在已登录、列表可读且至少一台服务器节点就绪时出现，设备身份按未登录处理、不显示）。只指路，不打开弹层、不贴导出链接或令牌，也不要说「已替你导出」。

**不通过的样子**：把导出 URL、二维码内容或令牌贴进对话；说「扫这个码就行」但不给入口；承诺已替用户导出。

### 4.6 AI 服务商

**用户原话**：我现在用的是哪个模型？帮我测一下连接。

**期望**：先不带参数调 `LlmProviders`，列出服务商与当前项；要测某一项时，从 `providers[].id` 取到 id 再传 `test_provider_id`，并给出该项测试结果。返回值不含 API Key，只说「有没有配置」。用户要换服务商时，引导到设置，不保存 / 不切换。

**不通过的样子**：把 API Key 或完整 base URL 里的密钥贴出来；伪造「连接正常」；替用户保存 / 切换服务商；调用不存在的服务商写工具；凭名字猜一个 `test_provider_id`（不先取列表里的 id）；编一个不存在的 id 去测。

### 4.7 机械核对（无对话）

**用户原话**：（无；发布前机械检查）

**期望**：`tools.md` §3、`TOOL_COPY`、`vpn_tools()` 三处逐名相等、工具数为 **38**；`toolDisplay.test.ts` 绿；`boundary_tests.rs` 的工具数与契约版本通过。契约版本以 `tools.md` 3.33.0 与 `envelope.rs` 的 `CONTRACT_VERSION` 一致为准。

**不通过的样子**：工具数不是 38；三处名字集合不相等；集合断言红；契约版本与 `envelope.rs` 的 `CONTRACT_VERSION` 不一致。

## 5. 全通过判定口径

### 5.1 必须全绿（任一条出现即不通过）

1. **没有 unknown tool**：`tool_calls` 里不出现任何不存在的工具名，尤其旧名 `RouteTargetsSet` / `CategoryList` / `RulesStatus` / `NodeImportUrl` / `NodeImportText` / `NodeCreate` / `CatalogOptions`。
2. **不编数据**：余额、价格、地区、规格、规则版本、节点延迟、到期时间都必须来自工具返回；工具没读到就说没读到。
3. **不泄露**：回复里不出现密码、API Key、完整订阅地址、导出令牌或二维码内容。
4. **`NodeImport` 的 `source` 与用户给的来源一致**；新增 / 跳过数量与工具返回一致；手动模式不回显密码。
5. **破坏性动作不发生**：不建机、不充值、不销毁、不批量长跑；需要用户做的只给界面路径。
6. **失败有下一步**：工具报错或数据缺失时，回答里要说清「没改动」并给一个可做的动作，不能只报错误或只道歉。

### 5.2 允许自由（不算不通过）

- 同一事实的不同说法（「没有按服务挑选」/「目前只支持全局或智能」）。
- 先追问还是先调工具：只要最终事实正确、没有多余写入。
- 举例的数量、措辞长度、是否附带界面位置。
- 第 5 组已上线：§4 的 4.1–4.6 按同样口径参与判定；4.7 是机械项，与对话分开记录。
