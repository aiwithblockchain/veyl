# 默认 DeepSeek 链路：验收手册

> 日期：2026-11-16
> 范围：默认 DeepSeek（基础模式）能否正常对话、是否默认关思考、老记录是否升到新模型名；反向回归其它端点。不含其它 provider 的功能验收。
> 原则：全部在应用内点击完成；只有失败时才看日志。

## 目的

确认「只填一个 DeepSeek Key 就能用」这条路成立：模型是 `deepseek-flash`、思考默认关闭、带工具的两轮对话不报 400。

## 前置

- 一个可用的 DeepSeek API Key（真实账号，有余额）。
- 一台测试机用来做「全新安装」：**先退出应用**再备份（`cp -R ~/.veyl ~/.veyl.bak`——里面有 Key、配置与历史；运行中复制 SQLite 可能不一致），然后把 `~/.veyl` **移走**（`mv ~/.veyl ~/.veyl.old`），不要直接删。
- 日志目录：release `~/.veyl/logs/`；debug 构建在仓库根 `logs/`。

## 用例

| 编号 | 前置 | 操作 | 期望 | 失败时看哪里 |
|---|---|---|---|---|
| A1 | 全新安装 | 启动 → 引导页只填 DeepSeek Key → 保存并验证 → 发「你好」 | 正常回复；**界面没有思考块**；设置里模型显示 `deepseek-flash` | 界面错误原文；日志尾部 |
| A2 | A1 完成 | 紧接着追问「刚才我说了什么」 | 第二轮正常返回，不报错 | 同上 |
| A3 | A1 完成（有 Key 的安装即可） | 设置 → AI 服务 → 编辑内置 DeepSeek → 模型填 `deepseek-chat` → 保存（界面会显示 `deepseek-flash`，但库里落的是旧值）→ 关掉设置再打开 / 重启应用 → 发一条消息 | 设置页仍显示 `deepseek-flash`；消息正常 | 设置页实际显示的模型名 |
| B1 | A1 完成 | 发「列一下我的配置」触发 `ConfigList` → 回答后追问「第二个是什么」 | 工具卡片出现并返回结果；两轮都不出现 400 | 界面错误里是否含 `thinking` / `400` |
| B2 | B1 完成 | 发「现在是什么连接状态」触发 `RuntimeStatus` → 再追问一轮 | 同上；工具结果被正确使用 | 同上 |
| C1 | 自建/代理 | 新增 provider：base 不是 `api.deepseek.com`、模型名以 `deepseek` 开头 → 发一条消息 | 正常回复且无思考块（走包装层）；若网关严格拒绝 `thinking` 字段而返回 400，**记录现象即可**（已知 P2） | 错误原文里的字段名 |
| D1 | 有 OpenAI Key | 切到 OpenAI provider → 发一条消息 | 与改动前一致 | 界面错误原文 |
| D2 | 有 Moonshot Key | 同上 | 与改动前一致 | 同上 |
| D3 | 本机 Ollama | 同上（本地端点免 Key） | 与改动前一致 | 同上 |
| D4 | 无 | 打开 设置 → AI 服务 → 新增/编辑 | DeepSeek 预设与 placeholder 都是 `deepseek-flash`；其它 provider 的模型名未被改 | 界面 |
| D5 | D1–D3 任一条完成 | 再切回 DeepSeek 发一条 | 正常，无思考块 | 同上 |

> A3 用新构建就能造出旧记录：保存是原样落库，只有读取时归一，所以不需要旧构建。可选补充（更贴近真实升级）：用改动前的旧构建保存过 Key，再换成本构建启动，结果应相同。

## 执行顺序

A1 → A2 → A3 → B1 → B2 → C1 → D4 → D1 → D2 → D3 → D5

## 已知限制（不是回归）

1. **Anthropic 协议的 DeepSeek 不走关思考包装层**：只能靠 OpenAI 兼容端点。
2. **切换 provider 后，历史里可能残留其它模型此前的思考块**：那是旧消息，不影响新回答。
3. **`caps.thinking` 仍为 true**，但默认链路不再产生 thinking 事件——界面看不到思考块是预期结果。
4. **自建网关若严格校验请求字段**，可能因 `thinking` 被拒（C1 的现象），不是默认链路的问题。
5. **内置 DeepSeek 的模型归一只在官方 base 下生效**（base 为空，或 host 是 `api.deepseek.com`）：把内置项指到自建/代理 base 时，`deepseek-chat` 会原样保留、不会被纠正。内置项的模型本身是可改的，用户主动选的其它模型不会被改写。

## 失败时要给我三样

1. 用例编号；
2. 界面上的原话或截图（错误气泡可直接复制）；
3. 同一时间段的日志几行：

```bash
ls -t ~/.veyl/logs | head -3
```

```bash
tail -n 40 ~/.veyl/logs/app-$(date +%F).log
```

> 日志里**没有请求体**，所以「到底发没发 `thinking`」只能间接判断：没有思考块且不报 400 即视为通过；怀疑没生效时，抓 C1 的错误原文最直接。
