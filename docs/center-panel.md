# 中间区域设计：千人千面

> 日期：2026-11-03
> 产品负责人定稿的核心设计原则。适用于第二页的中间区域。

---

## 1. 三层分离

中间区域不是一个写死的页面。它分成三层，每层的决定权和可变性完全不同：

| 层 | 由谁决定 | 是否可变 | 说明 |
|---|---|---|---|
| **能力层** | 工程实现 | **固定，所有用户共享** | 连接、断开、换节点、诊断、恢复网络……所有人用的是同一套后台能力 |
| **编排层** | AI，通过对话产生 | **千人千面，随时可改** | 中间显示哪些块、什么顺序、什么内容，由 AI 按这个用户的情况决定 |
| **样式层** | 设计规范 | **固定统一，AI 不可改** | 按钮、卡片、状态色、字号、间距全部预定义 |

一句话概括：

> **能力共享且稳定，显示与操作千人千面且随时可变，样式统一不可变。**

同一个原则也用在我们与 AI 的分工上：

> **确定性参数由工具返回，AI 只负责判断与表达。**

用户在哪个国家、当前连没连、运行什么版本——这些是可测、可缓存、可离线读取的事实，交给工具比交给模型可靠。AI 拿到参数后只做三件事：一致就确认、不一致就问、为空就问。**不让它去猜，也不让它去算。**

这就是为什么必须先把「功能集合」定死——AI 再怎么编排，也只能在已有的功能里挑。

---

## 2. 功能集合与分类

完整的能力清单、分类与实现状态见 **`docs/capabilities.md`**。下面是按「是否常驻」做的界面口径。

### 2.1 固定骨架：上中下三格

中间区域从上到下永远是三段。**AI 只能改中间那一段。**

```
┌─────────────────────────────────┐
│  启动 VPN                 状态   │  ← 固定
├─────────────────────────────────┤
│                                 │
│        AI 编排区                 │  ← 可变
│                                 │
├─────────────────────────────────┤
│  东京 01 ▾ · 1.2.3.4:20343      │  ← 固定
│  aes-256-gcm                    │
│  [ 切换到此节点 ]  [ 测试连通 ]   │
└─────────────────────────────────┘
```

| 位置 | 内容 | 谁能改 |
|---|---|---|
| **顶部** | 一个主按钮，两种状态：`启动 VPN` / `断开 VPN`，右边是连接状态 | 谁都不能改。**永远只有一个按钮** |
| **中间** | 按这个用户的情况挑块、排序、填参数 | 只有 AI 能改 |
| **底部** | 当前选中节点的详情（名称、地址、端口、加密方式），`切换到此节点`、`测试连通` | 谁都不能改，内容随选中节点变化 |

**底部的节点名可点，展开这个配置下的全部节点。** 选中某个之后详情跟着变，再按 `切换到此节点` 才真正切过去。

**顶部最右侧还有一个对话图标**，用来展开/收起右栏。它**不是控制台的一部分**，是窗口级的面板开关，不计入「永远只有一个按钮」的约束，也不归 AI 编排。详见 `.claude/skills/veyl-ui/SKILL.md` §1.2。

**「选中」和「切换」是两件事**：选中只是看，不改变任何网络状态；按了按钮才切。这样用户可以先翻一遍所有节点再决定，而不是点一下换一个。

选择放在底部而不是中间，是因为**换节点必须不依赖 AI**——AI 挂了、网断了，用户仍然要能换一台服务器。放进 AI 编排区就做不到了。

**为什么要有固定骨架：**

- **千人千面有了边界。** 没有边界的话，每个用户界面结构都不同，出问题时连「我的界面长什么样」都没法描述。
- **AI 编排失败或不可用时，界面仍然完整。** 顶部的连接按钮、底部的节点信息不依赖 AI。
- **两个最高频的动作永远在同一个位置。** 用户不用找「连接在哪」「我连的是哪台」。

### 2.2 AI 编排区的设计总纲

> **中间只放一件「我们替不了他、但他必须自己完成或知道」的事。其余留白。**

顶部已经给了按钮，底部已经给了节点详情，中间再堆东西就是重复。三类人恰好各自只有一件事：

| 用户 | 那一件事 | 中间放什么 |
|---|---|---|
| **一级** | **没有** | 几乎空白，一行说明 |
| **二级** | **授权**（TUN 要管理员权限，替不了） | 也是几乎空白——授权走**系统级弹窗**，不占中间 |
| **三级** | **参数**（他要自己填进软件） | 本机代理地址卡；若选了接管全部，同上，走弹窗 |

一级用户**要的就是简洁快速**，中间几乎空着是对的。顶部按钮加底部节点详情已经撑起视觉，不需要填满。

### 2.3 三种状态 × 三类人

**未连接**

| 一级 | 二级 | 三级 |
|---|---|---|
| 一行：「点上面的按钮就能用」+ 说明哪些网站会直连 | 同上。授权引导以**系统级弹窗**出现，不进中间 | 本机代理地址卡：`127.0.0.1:7890`，可复制，注明支持 HTTP 与 SOCKS5 |

**已连接**

| 一级 | 二级 | 三级 |
|---|---|---|
| 出口国家 +「浏览器现在能用了」 | 出口国家 +「所有软件都能用了」 | 出口国家 + 代理卡常驻 + 分流清单 |

三类人都加同一块：**可达性检查**——用户提过 ChatGPT、Claude Code 之类的，连上之后逐个确认能不能开。这块对谁都有价值，说的话一样。

**失败**

**这一格不分人。** 三类人看到完全相同的卡：发生了什么、为什么、现在做什么。

失败的时候谁都一样无助，这时候再按等级区别对待，只会让事情更复杂。

### 2.4 为什么授权必须是系统级弹窗

TUN 授权是唯一「不做就完全没法用」的一步，而且它会被一个**陌生的系统对话框**打断。

放在中间当一张卡，用户会划过去；一旦划过去，他就卡在一个自己不知道为什么用不了的状态里。所以做成系统级弹窗：

- **弹窗之前先解释**：用一句人话说清这次要授权什么、为什么、授权之后能干什么。用户看到陌生的系统框会点「取消」，这句话是用来防这个的
- **不提供「稍后再说」**：这条路径没有第二个出口，给他一个缓兵之计只会让他在几步之后撞墙
- **始终拒绝**：明确告诉他接管方式无法启动、当前无法连接，**不显示假的已连接**（`docs/tun-mode.md` §8）

### 2.5 块词汇表

这是 AI 能用的**全部**块。表里没有的，AI 不能自己造。

| 块 | 何时出现 | 内容 | 依赖 AI |
|---|---|---|---|
| `empty_hint` | 已配置、未连接，且没有别的话要说 | 一行：点上面的按钮就能用 + 哪些网站会直连 | 否 |
| `proxy_card` | 三级选了本机代理，常驻 | `127.0.0.1:7890`，可复制，注明支持 HTTP 与 SOCKS5 | 否 |
| `source_choice` | 面板已生成、但还没有任何节点 | 「用 Veyl 提供的测试节点（仅供试用）」/「用我自己的节点」两个选项 | 否 |
| `reachability` | 已连接 | 对用户提过的目标逐个确认能不能打开 | 是 |
| `issue_card` | 问题管理模块里有 P0/P1 | 发生了什么 / 为什么 / 现在做什么；带「让 AI 定位」与「重置网络」入口 | 否（本地规则也能插） |
| `update_hint` | 种子有新版本、且不影响当前连接 | 一句话 + 稍后提醒 | 否 |

**不是块的东西：**

| 东西 | 在哪 |
|---|---|
| 连接 / 断开按钮 | 顶部，固定 |
| 节点详情、节点选择、切换、测试 | 底部，固定 |
| TUN 授权 | **系统级弹窗**，不进中间（§2.4） |
| 对话 | 右栏 |

**规则：**

- AI 只能引用上表里的块，引用不到的一律忽略并记日志
- `issue_card` 由**本地规则**也能插入——AI 挂了、网断了，用户仍然要有自救入口
- 块的外观由设计规范固定，AI 只填内容与参数

### 2.5.1 三层映射：能力 → 块 → 布局

这是整个中间区域的**唯一权威映射**。任何一层对不上，实现就是错的。

```
能力（capabilities.md）    能力 ID → 后端命令
      ↕
块（本节）                 块类型 → 依赖哪些能力
      ↕
布局（AI 输出）             AI 只能引用已存在的块
```

#### 固定骨架元素

AI **不能**增删改这些。它们是「一句话不说也能用」的保证。

| 元素 | 依赖能力 | 后端 | 何时可点 |
|---|---|---|---|
| 顶部 `启动 VPN` | A1 建立连接 | `runtime_start` | 有激活配置且有节点 |
| 顶部 `断开 VPN` | A2 断开连接 | `runtime_stop` | 已连接或连接中 |
| 顶部状态文字 | A4 连接状态 | `runtime_status` + 状态事件 | 始终 |
| 底部节点详情 | B1 列出节点 | `config_detail`（⚠️ 需新增） | 有选中节点 |
| 底部节点下拉 | B1 | `config_detail` | 配置内节点 ≥ 2 |
| `切换到此节点` | B2 切换节点 | `runtime_start(node)` | 选中 ≠ 当前 |
| `测试连通` | **D6 测试单个节点连通性** | `node_probe`（⚠️ 需新增） | 始终可点 |

#### 编排区块

| 块 | 依赖能力 | 后端 | 出现条件 |
|---|---|---|---|
| `empty_hint` | 无（纯文本，参数由 H1 提供国家） | — | 已配置、未连接。**常驻的那行「有问题问右侧的助手」并在这个块里**，不单独成为一个元素 |
| `proxy_card` | A5 代理参数 | `proxy_params`（⚠️ 需新增） | 三级选本机代理 |
| `source_choice` | C1 默认配置 / B4 导入 | `config_create`（⚠️ 需新增） | 无任何节点 |
| `reachability` | D1 自检 | `probe_run`（⚠️ 需新增） | 已连接 |
| `issue_card` | J1–J4、E1–E3 | `issue_*`、`net_repair`（部分需新增） | 存在 P0/P1 问题 |
| `update_hint` | C2 / C3 | `default_profile_status` | 种子有新版本 |

#### 新增一个块的完整清单

用户能看到的按钮和元素，**只能**通过这条路增加。少改任何一处都会导致「AI 引用了但渲染不出来」或「渲染出来了但点了没反应」。

| 步骤 | 改哪里 |
|---|---|
| 1. 有能力吗？ | 没有就先在 `capabilities.md` 加一条能力，并实现后端命令 |
| 2. 登记块类型 | 本节 §2.5 表格加一行 |
| 3. 补映射 | 本节 §2.5.1 加一行：依赖哪些能力、调哪个命令 |
| 4. 实现渲染 | 前端加一个块的渲染组件，样式来自设计规范 |
| 5. 让 AI 知道 | 系统提示词里的块清单**与本节同源**，必须同步 |

**第 5 步最容易漏**：块做出来了但提示词里没写，AI 就永远不会用它；提示词里写了但块没做，AI 一引用就渲染失败。

> **用户不能发明块。** 千人千面的范围是「AI 在已有块里挑、排、填参数」，不是「用户想加什么加什么」。用户提新需求时只有两种结果：已有能力只是没做块 → 我们加块；能力也没有 → 进能力清单排队。

> **位置与顺序可以放开，样式不行。** 详见 §5「边界」。

### 2.6 不放中间

AI 服务商配置、默认配置源、端口设置、日志与版本——归设置页。四级用户的节点发布本期不做，将来也放设置页，不占左栏。

## 3. 编排协议

**AI 不生成界面，只做挑选、排序、填参数。**

每轮对话结束时，AI 输出一份布局描述，落进配置文件：

```json
{
  "version": 1,
  "blocks": [
    { "type": "empty_hint" },
    { "type": "reachability", "props": { "targets": ["ChatGPT", "Claude Code"] } }
  ]
}
```

规则：

- AI 只能引用**已存在的块类型**。引用不到的一律忽略并记日志。
- AI **不能改样式**：所有块的外观由设计规范固定，AI 只填内容与参数。
- 布局描述**持久化到配置文件**，下次登录直接还原，不再走一遍对话。

## 4. 首次登录的流程

```
0s    右栏自动打开，AI 主动问第一问
      中间：空。顶部按钮在，但按不了（还没有节点）

20s   走完提问，AI 生成配置
      中间：source_choice —— 「用 Veyl 提供的测试节点（仅供试用）」/「用我自己的节点」

30s   选「用 Veyl 提供的测试节点（仅供试用）」
      中间：empty_hint，一行说明
      底部：测试节点的名称、地址、端口、加密方式

35s   点顶部「启动 VPN」
      二级 / 三级选接管全部的：系统级弹窗授权，弹窗之前先用一句话解释

45s   已连接
      中间：reachability，对用户提过的目标逐项确认
      三级选了本机代理的：proxy_card 常驻
```

布局写进配置。下次打开直接是这一套，不再提问。

**注意中间在 0–20s 是空的。** 这不是没加载完，是确实没什么要说——所以空态要有一句话，不能是纯空白。

## 5. 边界

- 后台能力**所有用户共享**，不因为用户层级不同而分成两套。
- AI 可变的是**显示与操作编排**，不是能力本身。
- 「不用 AI」的用户看的是固定骨架，不经过编排层。

### 5.1 位置可以放开，样式暂按固定处理

> **状态：待定。** 产品负责人 2026-11-03 表示「样式先不处理」。本阶段**按固定执行**，不作为终局结论。

随着底层能力增加，界面能力也会增加。将来用户可以自己往中间加块、调顺序——**但只能在 §2.5 的映射表里加，不能凭空造**。**块的选择、顺序与位置**将来可以放开。

**视觉样式本阶段固定，由设计规范统一。** 下面是当时提出的三个理由，供将来重新讨论时参考：

1. **信任**。这是个把全部流量交出去的工具。界面乱糟糟的产品，用户不敢用。
2. **无障碍是硬约束**。对比度、字号、点击热区都有下限，让用户随意设一定会踩穿。
3. **支持成本**。「我设成红色以后按钮看不见了」这种问题，解释成本远高于收益。

如果将来要放开，建议先给**预设**而不是自由：主题（浅/深）、密度（紧凑/舒适）、布局模板（极简/标准）。先看用户到底要的是位置还是颜色，再决定放开到哪一层。
